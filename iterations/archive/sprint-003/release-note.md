# sprint-003 发布说明

> 发布状态：已发布为 sprint-003 归档说明；实际版本发布仍按 `/release-propose` → `/release-prepare` → `/release-publish` 链路执行。

## 治理变化

- 新增证据化根因分析治理：已确认根因必须有证据链；证据不足时必须输出人工补证操作步骤。
- 新增 root-cause evidence 校验脚本，用于 BUG 和 BUG 来源 Change 的结构化门禁。

## 业务影响

- 修复管理后台用户管理列表展示：角色以无边框、无浅底色的图标文字标签展示，状态标签沿用空间管理页无边框圆形 check 图标语义表达，最近登录时间、创建时间和更新时间统一展示，并新增更新时间列。
- 增强需求中心 `capture.md` Markdown 右侧抽屉：提供附件式信息层级、阅读态预览、编辑/分栏模式、表格/代码/公式工具和固定保存栏；顶部信息层级收敛为 Header + 文档属性 Strip，Header 展示对象 ID、当前文档名、标题和“优先级 · 负责人负责 · 阶段”副标题，第二个 spec 信息条不再展示，frontmatter 以“文档属性”独立折叠展示，编辑区只编辑正文，保存仍保留完整 Markdown；所有 Markdown 抽屉阅读态共用工作型阅读密度，`trace.md` 等只读文档表格单元格单独收敛字号、行高和 padding，阅读区字体族统一为产品 body/heading，分栏右侧预览使用紧凑阅读样式，阅读态代码块提供低视觉权重复制按钮并复制无围栏代码原文；预览态 task list 渲染为可勾选复选框，勾选/取消后标记未保存且仍需保存按钮写回 Markdown；未保存确认仅在可编辑 `capture.md` 发生用户真实改动后触发，`trace.md` 等只读文档、未编辑内容和保存成功后关闭不提示；表格、代码和公式按光标或选区插入，分栏态右侧预览即时刷新；保存失败时保留编辑内容或勾选后的草稿状态并提示可重试；分栏态左右内容顶端对齐且不展示额外英文区块标题；抽屉 header 支持放大全屏/恢复；图片上传入口在真实接口补齐前保持受控失败且默认不展示 idle 状态。
- 不修改 API、DB、客户端生成物或生产部署拓扑；根目录本地开发 Compose 允许后端对 `issues/` 中采集池 `capture.md` 做受控写入。
