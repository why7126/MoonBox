# web-catalog-chat-workbench Specification

## Purpose
规定个人 Chat 工作台在前台目录中的入口权限、会话生命周期、对象关联、真实执行呈现、额度反馈、对话与轨迹双视图、首次输入创建和原型验收契约，确保用户可安全管理 Codex 会话并清楚区分历史、当前运行与可执行状态。

## Requirements
### Requirement: 个人工作台入口与权限

系统 MUST 提供 /chat 独立工作台，按本人、有效空间成员和对象权限过滤会话；保留既有需求中心抽屉，通过显式入口携带对象进入Chat，不自动执行输入。

#### Scenario: 访问他人会话

- **WHEN** 用户猜测其他所有者或空间的会话标识
- **THEN** 系统拒绝读取消息、Diff或续写且不泄漏内容

#### Scenario: 从需求中心继续

- **WHEN** 用户点击在Chat工作台继续
- **THEN** 系统携带授权对象提示，保留旧抽屉语义，不迁移模拟消息或自动启动执行

### Requirement: 会话历史与关联

系统 MUST 支持搜索、置顶、重命名、归档恢复和受限删除；主对象零或一个，引用多个，修改只影响之后轮次。

#### Scenario: 归档与恢复

- **WHEN** 用户归档已终止会话后重新恢复
- **THEN** 归档期间只读，恢复后重验权限再允许输入

#### Scenario: 变更关联

- **WHEN** 用户调整主对象或辅助引用
- **THEN** 历史快照不被重写，超过一个主对象被拒绝

### Requirement: 真实执行呈现与当前控制

系统 MUST 展示真实回复、事件、历史轮次和本轮Diff；无修改显示空态，断连显示未知，查看历史仍能停止当前运行。

#### Scenario: 查看历史时停止

- **WHEN** 用户选择历史轮次而另一个轮次仍在运行
- **THEN** 当前运行停止入口保持可达且目标明确

#### Scenario: 无文件修改

- **WHEN** 执行端确认结束且工作区无变化
- **THEN** 显示无变更空态，不出现固定Diff样例

### Requirement: 额度与容量反馈

系统 MUST 在额度或容量不足时停止接受新执行，保留已有历史查看和符合条件的清理；用户不绑定个人认证。

#### Scenario: 容量已满

- **WHEN** 服务端拒绝新增并返回容量不足
- **THEN** 页面保留历史和清理入口，显示原因，不删除旧内容以掩盖错误

### Requirement: 原型与Ops验收契约

系统 MUST 按已确认风格迁移实现；prototype仅为设计输入，最终验收以design、来源acceptance、1440px及交互截图、computed style、Mock/API边界和REQ最终一致性共同判定。

#### Scenario: 提交UI验收

- **WHEN** 页面实现完成准备验收
- **THEN** 提供Skeleton首轮确认、深浅窄屏和动作族证据，禁止以原稿模拟成功替代真实验收

### Requirement: 可读的事件时间线与安全表格
系统 MUST 将相邻同消息的输出片段归并显示，并在消息、工具、状态和序号缺口处保留边界；展示所选轮次当前状态与历史事件状态的区别，保留默认折叠的原始事件及每窗口最多1000条与后续窗口读取说明。回复表格 MUST 使用安全渲染并在窄屏内部滚动。
#### Scenario: 流式输出分片
- **WHEN** 同一消息分多次输出且跨事件读取批次
- **THEN** 展示连续文字，重放不重复，不跨工具或消息边界归并
#### Scenario: 查看已完成轮次
- **WHEN** 历史事件包含执行中
- **THEN** 当前状态展示已完成，历史记录明确标为历史状态
#### Scenario: 回复含Markdown表格
- **WHEN** 回复包含表头和分隔行
- **THEN** 展示语义表格与列对齐，不执行HTML、图片或危险链接

### Requirement: 对话与轨迹一致展示
系统 MUST 提供对话与轨迹双视图，共享轮次身份，工具开始与结束按执行轮次和工具标识配对，历史缺失详情显示未采集。消息入口 MUST 定位本轮轨迹，停止仍只作用于当前活动轮次。

#### Scenario: 查看工具结果
- **WHEN** 用户选择已记录的工具节点
- **THEN** 展示脱敏参数、结果、退出码和可用计时，未采集字段不伪造，超长内容明确截断

#### Scenario: 窄屏阅读
- **WHEN** 用户在窄屏查看对话与轨迹
- **THEN** 详情上下排列，表格局部滚动，输入框不产生页面横向溢出

### Requirement: 首次输入与延迟创建

系统 MUST 在未选择会话时允许输入本地草稿，首次发送才创建会话；新建动作不弹前置窗口。单仓库自动选择，多仓库在输入区选择。服务不可执行时只禁用发送，不丢弃输入。

#### Scenario: 首次发送

- **WHEN** 用户进入工作台输入内容并发送
- **THEN** 系统校验所选空间仓库、幂等创建个人会话并提交一轮输入，成功后展示会话并同步地址栏

#### Scenario: 响应丢失后重试

- **WHEN** 创建或发送请求响应丢失，用户重试同一输入
- **THEN** 系统保留草稿及两个请求标识，复用同一会话与轮次，不因重复点击创建重复执行

#### Scenario: 创建幂等权限

- **WHEN** 重放创建标识但权限撤销、参数冲突或会话已删除
- **THEN** 系统重新检查并拒绝请求，不泄漏他人会话且不复活删除数据

### Requirement: 紧凑会话页头

系统 MUST 直接展示会话标题行，不展示重复空间工具栏或固定加载的项目连接栏；展开/收起执行详情按钮位于标题行动作区，保持既有视图切换状态。空间与主题保留在共享侧边栏菜单。

#### Scenario: 默认仓库开始输入

- **WHEN** 用户进入有唯一授权仓库的工作台
- **THEN** 系统自动选择该仓库并允许直接输入，无顶部连接占位；首次发送仍校验服务与权限

#### Scenario: 窄屏切换视图

- **WHEN** 用户在窄屏点击标题行的展开/收起按钮
- **THEN** 标题和动作不造成横向溢出，视图切换保留草稿，输入卡保持可见

### Requirement: 标题编辑与统一历史切换

系统 MUST 将已创建会话标题作为重命名入口，复用既有重命名弹窗；其他会话只从历史弹窗选择，不提供标题下拉。权限提示在历史弹窗展示，不常驻于对话页，原授权检查保留。

#### Scenario: 编辑标题

- **WHEN** 用户点击已有会话标题并保存合法名称
- **THEN** 页面标题与历史同步更新；失败保留输入，取消不修改；空草稿不会为了改名提前创建记录

#### Scenario: 查看其他会话

- **WHEN** 用户打开历史弹窗
- **THEN** 可选择本人有权访问的会话并看到权限说明，主界面无个人会话固定标签

### Requirement: 输入框按需显示状态提示
系统 SHALL 在正常可输入状态省略常驻执行说明，仅在有必要状态或错误时显示提示，发送按钮保持右对齐。

#### Scenario: 正常与异常提示切换
- **WHEN** 执行服务就绪且会话无阻断条件
- **THEN** 输入框不显示常驻执行说明或空提示节点
- **AND** 出现服务未就绪、归档、运行未终止、缺少仓库或发送错误时保留对应提示
- **AND** 桌面与窄屏发送按钮始终右对齐
