# web-catalog-chat-workbench Specification

## Purpose
规定个人 Chat 工作台在前台目录中的入口权限、会话生命周期、对象关联、真实执行呈现、额度反馈、对话与轨迹双视图、首次输入创建和原型验收契约，确保用户可安全管理 Codex 会话并清楚区分历史、当前运行与可执行状态。
## Requirements
### Requirement: 个人工作台入口与权限

系统 MUST 提供 /chat 独立工作台，按本人、有效空间成员和对象权限过滤会话；保留既有需求中心抽屉，通过显式入口携带对象进入Chat，不自动执行输入。系统 MUST 在本地会话过期或受保护 Chat API 返回认证失败时清理前端会话并重定位到登录页，不继续展示需要鉴权的数据；系统 MUST 区分认证失败、权限不足、网络异常和服务端异常。

#### Scenario: 访问他人会话

- **WHEN** 用户猜测其他所有者或空间的会话标识
- **THEN** 系统拒绝读取消息、Diff或续写且不泄漏内容

#### Scenario: 从需求中心继续

- **WHEN** 用户点击在Chat工作台继续
- **THEN** 系统携带授权对象提示，保留旧抽屉语义，不迁移模拟消息或自动启动执行

#### Scenario: 登录失效后刷新 Chat 工作台

- **GIVEN** 用户本地仍保留前端会话且停留在 `/chat`
- **WHEN** Chat 工作台初始化或刷新时受保护 API 返回 401 认证失败
- **THEN** 系统清理前端会话并重定位到 `/login`
- **AND** 系统不得继续展示需要鉴权的会话、空间、项目、能力或消息数据
- **AND** 系统不得进入循环跳转或无限重试

#### Scenario: 本地会话已过期

- **GIVEN** 本地会话包含可判定的过期时间
- **WHEN** 用户直接访问 `/chat` 且会话已过期
- **THEN** 系统清理该会话并展示登录页
- **AND** 系统不得先渲染受保护工作台再依赖业务请求失败退出

#### Scenario: 权限不足不误判为登录失效

- **GIVEN** 用户仍处于有效登录态
- **WHEN** Chat 工作台请求因空间、仓库、会话或对象权限不足返回 403
- **THEN** 系统展示权限不足或访问受限提示
- **AND** 系统不得清理有效登录态或强制跳转登录页

#### Scenario: 网络异常和服务端异常不误登出

- **GIVEN** 用户仍处于有效登录态
- **WHEN** Chat 工作台请求发生浏览器网络异常或服务端 5xx
- **THEN** 系统展示可恢复错误或重试入口
- **AND** 系统不得清理有效登录态

#### Scenario: 重新登录后恢复授权范围内访问

- **WHEN** 用户因 Chat 工作台登录失效被重定位到 `/login` 并重新登录成功
- **THEN** 系统允许用户回到授权范围内的 Chat 工作台或默认前台入口
- **AND** 系统不得携带 Token、Cookie、Authorization header、完整请求体或完整响应体作为恢复参数

### Requirement: 会话历史与关联

系统 MUST 支持搜索、置顶、重命名、归档恢复和受限删除；主对象零或一个，引用多个，修改只影响之后轮次。系统 MUST 支持需求中心卡片动作按治理对象复用 Chat 会话：同一 REQ、BUG、Change 或 SPRINT 再次触发 Chat 时，优先返回最近的未归档、未删除且当前用户有权访问的对象会话；多个可用会话按最近 turn 更新时间、最近消息更新时间、会话 `updated_at` 和稳定创建事实降级排序。

#### Scenario: 归档与恢复

- **WHEN** 用户归档已终止会话后重新恢复
- **THEN** 归档期间只读，恢复后重验权限再允许输入

#### Scenario: 变更关联

- **WHEN** 用户调整主对象或辅助引用
- **THEN** 历史快照不被重写，超过一个主对象被拒绝

#### Scenario: 从治理对象进入最近会话

- **WHEN** 用户从需求中心卡片携带对象类型、对象 ID、标题、阶段和动作类型进入 Chat
- **THEN** 系统必须校验对象权限和会话权限
- **AND** 系统必须过滤已归档、已删除或无权访问的会话；忙碌会话保留为查看执行候选
- **AND** 系统必须优先返回可访问的当前执行会话；空闲时返回最新可用对象会话，仅在无可用会话且无未决对象执行时明确原因后创建新的对象会话
- **AND** 返回结果不得泄漏无权会话标题、消息摘要、candidate 内容或对象正文

#### Scenario: 排序字段缺失时稳定降级

- **WHEN** 同一对象存在多个可用会话且部分排序字段缺失
- **THEN** 系统必须按明确降级顺序选择会话
- **AND** 系统必须保留可排障的脱敏选择摘要
- **AND** 前端不得用本地列表顺序覆盖服务端选择结果

#### Scenario: 忙碌会话与草稿
- **WHEN** 本人原对象会话仍在执行
- **THEN** 系统 MUST 返回查看原执行入口并保留隔离草稿，不静默创建会话或发送命令

#### Scenario: 其他用户占用对象
- **WHEN** 同项目同对象存在其他用户未决执行
- **THEN** 系统 MUST 拒绝新的治理发送，仅展示对象忙碌，不泄漏其他用户会话标识、标题或内容

#### Scenario: 原执行会话已归档或删除
- **WHEN** 原会话不可复用但对象执行尚未核验结束
- **THEN** 系统 MUST 保持对象写入受控，核验终态后才允许建立新会话

#### Scenario: Sprint 主对象身份与安全解析
- **WHEN** 用户从归档入口以规范 Sprint ID 准备对象会话
- **THEN** 系统 MUST 按授权用户、空间、仓库、SPRINT类型和ID关联并选择会话
- **AND** 系统 MUST 从受信迭代事实源解析，不按Change目录或会话标题推断，不以归档数据掩盖活动源损坏
- **AND** 归档后历史会话 MUST 可在权限内解析唯一对应的归档对象

### Requirement: 真实执行呈现与当前控制

系统 MUST 展示真实回复、事件、历史轮次和本轮Diff；无修改显示空态，断连显示未知，查看历史仍能停止当前运行。

#### Scenario: 查看历史时停止

- **WHEN** 用户选择历史轮次而另一个轮次仍在运行
- **THEN** 当前运行停止入口保持可达且目标明确

#### Scenario: 无文件修改

- **WHEN** 执行端确认结束且工作区无变化
- **THEN** 显示无变更空态，不出现固定Diff样例

### Requirement: 额度与容量反馈
系统 MUST 区分默认无限运营策略、显式有限运营策略与部署资源保护；资源不足时保留历史和符合条件的清理入口，显示阶段、原因、已保存范围及安全恢复路径；用户不绑定个人认证。

#### Scenario: 容量已满
- **WHEN** 服务端因有效运营配额或实际资源不足拒绝新执行
- **THEN** 页面保留授权历史及清理入口，准确显示分类且不自动删除内容；准备失败明确执行尚未开始，运行中断不声称操作未发生

### Requirement: 原型与Ops验收契约

系统 MUST 按已确认风格迁移实现；prototype仅为设计输入，最终验收以design、来源acceptance、1440px及交互截图、computed style、Mock/API边界和REQ最终一致性共同判定。

#### Scenario: 提交UI验收

- **WHEN** 页面实现完成准备验收
- **THEN** 提供Skeleton首轮确认、深浅窄屏和动作族证据，禁止以原稿模拟成功替代真实验收

#### Scenario: 深色工作台根层背景不露底

- **GIVEN** 用户访问 `/chat` 且工作台处于深色主题
- **WHEN** 页面向上滑动、触发边界 overscroll 或宿主短暂暴露浏览器根层
- **THEN** `html`、`body`、`#root` 与 Chat 工作台根容器的背景必须保持一致或等价深色
- **AND** 页面底部不得露出浅色全局背景
- **AND** Chat 输入区、会话内容区、侧边栏和执行详情面板下方不得出现透明穿透
- **AND** 验收证据必须包含 1440px 截图和 `html`、`body`、`#root`、`[data-testid=chat-shell]` 的 computed style

#### Scenario: 工作台根层背景不污染其他页面

- **WHEN** 用户从 `/chat` 离开到登录页、官网首页、管理后台或浅色主题工作台
- **THEN** 系统必须恢复对应页面的既有根层背景和滚动行为
- **AND** 深色工作台背景类、data 属性或 CSS 变量不得残留污染非工作台页面

### Requirement: 可读的事件时间线与安全表格
系统 MUST 将相邻同消息的输出片段归并显示，并在消息、工具、状态和序号缺口处保留边界；展示所选轮次当前状态与历史事件状态的区别，保留默认折叠的原始事件及每窗口最多1000条与后续窗口读取说明。回复表格 MUST 使用安全渲染并在窄屏内部滚动。
#### Scenario: 流式输出分片
- **WHEN** 同一消息分多次输出且跨事件读取批次
- **THEN** 展示连续文字，重放不重复，不跨工具或消息边界归并
#### Scenario: 查看已完成轮次
- **WHEN** 历史事件包含执行中
- **THEN** 当前状态展示已完成，历史记录明确标为历史状态
#### Scenario: 回复含Markdown表格
- **WHEN** 回复包含表头和分隔行
- **THEN** 展示语义表格与列对齐，不执行HTML、图片或危险链接

### Requirement: 对话与轨迹一致展示
系统 MUST 提供对话与轨迹双视图，共享轮次身份，工具开始与结束按执行轮次和工具标识配对，历史缺失详情显示未采集。消息入口 MUST 定位本轮轨迹，停止仍只作用于当前活动轮次。系统 SHALL 使同轮次已经保存的助手文字在对话中可读，包括停止、未知和恢复轮次；已有最终正文优先，降级文字明确标识部分输出及缺口，不以文字存在推断执行完成。恢复和读取 SHALL 保持幂等、会话权限及轮次隔离。

#### Scenario: 查看工具结果
- **WHEN** 用户选择已记录的工具节点
- **THEN** 展示脱敏参数、结果、退出码和可用计时，未采集字段不伪造，超长内容明确截断

#### Scenario: 窄屏阅读
- **WHEN** 用户在窄屏查看对话与轨迹
- **THEN** 详情上下排列，表格局部滚动，输入框不产生页面横向溢出

#### Scenario: 有输出后停止
- **WHEN** 停止轮次已有助手输出事件但缺失持久化助手正文
- **THEN** 对话显示已保存的部分文字，刷新后仍可读，状态保持已停止

#### Scenario: 输出后状态未知
- **WHEN** 轮次在保存助手输出后进入未知状态
- **THEN** 对话显示部分文字及未知提示，不宣告命令完成或自动重发命令

#### Scenario: 恢复与重复处理
- **WHEN** 未知轮次恢复为完成、失败或已停止，并重复处理事件或恢复请求
- **THEN** 正文只归属该轮次且不重复；终态由权威执行事实决定，同 item 快照替代增量而不二次追加

#### Scenario: 正常最终答案
- **WHEN** 正常完成轮次存在持久化最终答案及过程增量
- **THEN** 对话优先显示最终答案，不把过程文字重复拼入或错误标识为最终结论

#### Scenario: 无助手输出
- **WHEN** 失败或停止轮次没有助手文字
- **THEN** 保留真实状态，不伪造正文或成功提示

#### Scenario: 分页与事件缺口
- **WHEN** 目标历史轮次跨消息或事件分页，或保存的事件有缺口或裁剪
- **THEN** 按稳定轮次身份有界读取已保存文字，不跨轮次拼接、不重复正文，并明确部分内容与截断边界

#### Scenario: 未授权读取
- **WHEN** 用户尝试读取他人会话的正文或降级输出
- **THEN** 系统拒绝访问，降级路径不绕过会话权限，观测摘要不保存原始正文或凭证

系统 SHALL 对虚拟输出与持久消息使用相容的稳定身份和确定性总排序，同轮用户在助手之前，不因保存时间跨秒、恢复或分页转换而倒置。排序键与显示时间分离，历史不可靠时间明确降级，不编造时间事实。

#### Scenario: 跨秒提问和回复
- **WHEN** 用户消息比轮次创建晚一秒或多秒，随后生成助手回复
- **THEN** API 和 Web 均按轮次与轮内顺序展示用户在前，时间来源保持真实

### Requirement: 首次输入与延迟创建

系统 MUST 在未选择会话时允许输入本地草稿，首次发送才创建会话；新建动作不弹前置窗口。单仓库自动选择，多仓库在输入区选择。服务不可执行时只禁用发送，不丢弃输入。

#### Scenario: 首次发送

- **WHEN** 用户进入工作台输入内容并发送
- **THEN** 系统校验所选空间仓库、幂等创建个人会话并提交一轮输入，成功后展示会话并同步地址栏

#### Scenario: 响应丢失后重试

- **WHEN** 创建或发送请求响应丢失，用户重试同一输入
- **THEN** 系统保留草稿及两个请求标识，复用同一会话与轮次，不因重复点击创建重复执行

#### Scenario: 创建幂等权限

- **WHEN** 重放创建标识但权限撤销、参数冲突或会话已删除
- **THEN** 系统重新检查并拒绝请求，不泄漏他人会话且不复活删除数据

### Requirement: 紧凑会话页头

系统 MUST 直接展示会话标题行，不展示重复空间工具栏或固定加载的项目连接栏；展开/收起执行详情按钮位于标题行动作区，保持既有视图切换状态。空间与主题保留在共享侧边栏菜单。

#### Scenario: 默认仓库开始输入

- **WHEN** 用户进入有唯一授权仓库的工作台
- **THEN** 系统自动选择该仓库并允许直接输入，无顶部连接占位；首次发送仍校验服务与权限

#### Scenario: 窄屏切换视图

- **WHEN** 用户在窄屏点击标题行的展开/收起按钮
- **THEN** 标题和动作不造成横向溢出，视图切换保留草稿，输入卡保持可见

### Requirement: 标题编辑与统一历史切换

系统 MUST 将已创建会话标题作为重命名入口，复用既有重命名弹窗；其他会话只从历史弹窗选择，不提供标题下拉。权限提示在历史弹窗展示，不常驻于对话页，原授权检查保留。

#### Scenario: 编辑标题

- **WHEN** 用户点击已有会话标题并保存合法名称
- **THEN** 页面标题与历史同步更新；失败保留输入，取消不修改；空草稿不会为了改名提前创建记录

#### Scenario: 查看其他会话

- **WHEN** 用户打开历史弹窗
- **THEN** 可选择本人有权访问的会话并看到权限说明，主界面无个人会话固定标签

### Requirement: 输入框按需显示状态提示
系统 SHALL 在正常可输入状态省略常驻执行说明，仅在有必要状态或错误时显示提示，发送按钮保持右对齐。

#### Scenario: 正常与异常提示切换
- **WHEN** 执行服务就绪且会话无阻断条件
- **THEN** 输入框不显示常驻执行说明或空提示节点
- **AND** 出现服务未就绪、归档、运行未终止、缺少仓库或发送错误时保留对应提示
- **AND** 桌面与窄屏发送按钮始终右对齐

### Requirement: 输入区执行配置选择

系统 SHALL 在 Chat 工作台输入区展示 Agent、模型和推理配置选择入口。当前首版 Agent 可用项只有 Codex，界面 SHALL 清楚表达当前执行主体；模型和推理配置 SHALL 由服务端能力配置或前后端共享能力约束驱动，不得仅以前端硬编码列表作为可用性事实源。

#### Scenario: 单 Agent 状态

- **WHEN** 用户进入 Chat 工作台且当前只有 Codex 一个 Agent 可用
- **THEN** 输入区展示 Codex 执行主体
- **AND** 控件以只读、禁用下拉或单项选择器表达，不暗示存在其他可用 Agent

#### Scenario: 模型和推理配置来自服务端

- **WHEN** 页面加载执行配置能力
- **THEN** 系统展示服务端认可的默认模型和推理配置
- **AND** 模型与推理选项包含显示名、稳定值、可用状态和禁用原因

#### Scenario: 长模型名与窄屏布局

- **WHEN** 模型名较长或用户使用窄屏视口
- **THEN** 配置控件通过截断、tooltip、菜单详情、换行或更多菜单保持可读
- **AND** 不遮挡输入框、发送按钮、停止按钮或执行状态

### Requirement: 配置发送与历史追溯

系统 SHALL 在用户发送消息时提交当前 Agent、模型和推理配置，并由后端重新校验会话权限、空间权限、执行端能力和配置可用性。系统 SHALL 在轮次事实源保存请求配置、实际生效配置和降级原因摘要；历史轮次 SHALL 展示该轮实际生效配置，且当前选择不得改写历史配置。

#### Scenario: 发送配置进入执行链路

- **WHEN** 用户选择模型和推理配置后发送消息
- **THEN** 发送请求携带 Agent、模型和推理配置标识
- **AND** 后端重新校验配置可用性与权限
- **AND** 轮次记录保存请求配置和实际生效配置

#### Scenario: 服务端降级

- **WHEN** 服务端因额度、权限、执行端版本或策略使用不同配置
- **THEN** 页面展示实际生效配置和脱敏降级原因
- **AND** 请求日志、Task Trace 和错误提示不得泄漏内部路径、完整配置、密钥、Token、Authorization、Cookie 或 `.env` 内容

#### Scenario: 历史轮次查看

- **AND** 发送、停止、错误提示和轨迹入口互不遮挡

### Requirement: 多材料观测与脱敏

系统 SHALL 为图片或文件添加/移除、Skill 选择/移除、发送结果、材料校验、对象存储写入、Skill 解析、上下文构造、执行提交和结果处理记录脱敏观测摘要。需求中心卡片触发的只读分析、治理写动作、操作查询、Workflow Sync、恢复和归档投影也 SHALL 记录脱敏观测摘要。行为事件、请求日志、Task Trace 和流程节点写入失败 SHALL 不阻断主流程，但系统 SHALL 保留脱敏降级摘要以便排障；Workflow Sync 失败 SHALL 阻断命令完成声明。

#### Scenario: 需求中心动作观测脱敏

- **WHEN** 用户从需求中心卡片触发只读分析或七类写动作
- **THEN** usage_events、request_logs、task_traces 和 task_trace_spans metadata 只允许保存对象类型、对象 ID、动作类型、状态、错误码、耗时、计数和脱敏摘要
- **AND** 不得保存完整 Prompt、文件正文、请求体、响应体、模型回复、Authorization、Cookie、Token、密钥、本机绝对路径或未脱敏治理材料
- **AND** 直接 API 调用不得伪造界面行为事件

#### Scenario: 写任务流程节点覆盖

- **WHEN** 七类写操作被提交
- **THEN** Task Trace 或等价流程节点 SHALL 覆盖门禁校验、产物写入、标题校验、Workflow Sync、事实源重读、恢复判断和结果返回
- **AND** 分析动作若保持只读且无多步骤写任务，可以只保留 Chat/请求观测并说明不接入写任务 Trace 的原因

#### Scenario: 观测 metadata 脱敏

- **WHEN** 系统记录图片、文件、Skill 或对象治理动作相关行为事件、请求日志、Task Trace 或流程节点
- **THEN** metadata 只包含事件名、对象类型、对象 ID、动作类型、会话 ID、turn ID、candidate ID、结果、数量、大小、类型、错误码、耗时和脱敏摘要
- **AND** 不包含完整图片、文件正文、完整请求体、完整 Prompt、完整回复、完整 candidate 正文、Authorization、Cookie、Token、密钥、本机绝对路径、对象存储内部完整 key 或真实客户敏感数据

#### Scenario: Task Trace 节点覆盖

- **WHEN** 一轮包含图片、文件、Skill 引用或生成类治理动作的 Chat 执行被提交
- **THEN** Task Trace 或等价流程节点覆盖材料校验、对象会话查找、新建会话、追加 turn、创建 candidate、上下文构造、执行提交和结果处理

### Requirement: 原型驱动 UI 合同与验收证据

系统 SHALL 在实现需求中心卡片动作反馈、Chat 抽屉、Action Modal、确认弹窗或执行状态容器前完成 UI Contract、UI Skeleton 和动作按钮矩阵。实现完成前 SHALL 提供 1440px 桌面视口、窄屏、深浅主题、关键交互截图或等价证据，并记录关键 computed style、Mock/API 边界和 linked REQ 最终一致性。

#### Scenario: 需求中心动作 UI Skeleton 先行

- **WHEN** Change 开始实现需求中心卡片八动作入口、Chat 抽屉或执行反馈容器
- **THEN** 先完成页面壳、卡片动作区、浮层容器、状态容器、产物入口、错误提示和可测 selector
- **AND** 未完成 Skeleton 证据前不得关闭细节实现任务

#### Scenario: 动作按钮矩阵验收

- **WHEN** UI 任务准备验收
- **THEN** 系统 SHALL 提供动作按钮、modal 类型、目标 selector、组件族、状态和证据入口的矩阵
- **AND** 同一动作族的按钮、loading、disabled、error、取消、外部点击和提交后反馈 SHALL 使用一致组件语义

#### Scenario: UI Skeleton 先行

- **WHEN** Change 开始实现 Chat 输入区、消息区、对话/轨迹切换、历史弹窗或轨迹入口 UI
- **THEN** 先完成页面壳、布局区域、组件层级、状态容器、可测选择器和 1440px 验收焦点
- **AND** 未完成 Skeleton 证据前不得关闭细节实现任务

#### Scenario: 参考稿复刻验收

- **WHEN** UI 任务准备验收
- **THEN** 提供 selector 映射、动作按钮矩阵、computed style 采样和分批截图或等价 DOM/组件证据
- **AND** 归档前确认 linked REQ 与最终 Change 设计、截图、Mock/API 边界和实现证据一致

### Requirement: 消息角色标签与对话滚动边界

系统 MUST 将消息角色标签限制在所属消息卡片定位上下文内，保留可访问语义和视觉隐藏行为；非空白对话内容超出可视区域时 MUST 在消息区域内部滚动，不能因标签定位产生页面级额外滚动或破坏底部输入区布局。

#### Scenario: 长对话保持内部滚动
- **WHEN** 用户在桌面视口打开超出消息可视区的长对话并滚动至消息首尾
- **THEN** 页面滚动高度与可视高度差不超过 1 CSS px，页面 scrollTop 不因消息区滚动而变化，消息内容首尾可达

#### Scenario: 隐藏标签保留局部定位和语义
- **WHEN** 系统渲染用户与助手消息角色标签
- **THEN** 绝对定位标签的定位祖先为所属消息卡片，角色语义仍可由辅助技术读取且标签不视觉露出

#### Scenario: 会话切换与底部布局稳定
- **WHEN** 用户切换空白、短消息和长对话并操作输入区
- **THEN** 输入区可见可编辑，底部背景完整，悬浮元素无异常位移或遮挡，发送与显示能力正常

### Requirement: 治理候选与事实源完成边界

Chat 工作台 SHALL 将执行工作区、assistant 输出和治理 candidate 作为候选或执行证据；卡片阶段、文档入口和完成态 SHALL 以治理事实源、Workflow Sync 结果和事实源重读投影为准。

#### Scenario: candidate 应用前版本校验

- **WHEN** 用户或后端自动应用治理 candidate
- **THEN** 系统 SHALL 校验 candidate manifest、revision、binding revision 和当前事实源版本
- **AND** 校验失败时 SHALL 返回 conflict、stale 或等价待恢复状态
- **AND** 不得把候选差异、assistant 回复或工作区文件直接展示为完成事实

#### Scenario: 应用后刷新事实源投影

- **WHEN** candidate 文件写入完成
- **THEN** 系统 SHALL 执行对应 Workflow Sync
- **AND** 同步成功后 SHALL 重读治理事实源并刷新需求中心卡片投影
- **AND** 同步失败或重读失败时 SHALL 保留操作身份和安全错误摘要
- **AND** 前端不得刷新卡片阶段为成功态

#### Scenario: 本地部署默认真实仓库工作区

- **WHEN** 本地常驻部署生成仓库绑定
- **THEN** 系统 SHALL 默认声明 `workspace_mode: source`
- **AND** 执行器 SHALL 直接使用 `source_root` 当前工作树作为工作区
- **AND** 系统 SHALL 不创建 `<workspace_root>/<conversation_id>` 会话副本、不执行副本同步、不要求候选二次应用
- **AND** 共享生产仓库、多人同时编辑或强隔离审阅场景 MAY 显式配置 `workspace_mode: copy`
- **AND** copy 模式 SHALL 保留既有隔离副本、候选应用和未应用成果保护语义

### Requirement: 旧治理面板清理不得删除正常会话
系统 MUST 只清理具有明确旧治理面板标识或明确旧评审对话框身份的元素，不得因普通聊天正文包含旧面板关键词而删除正文、会话外壳或无关对话框。

#### Scenario: 普通消息提及确认应用
- **WHEN** 带可访问标签的聊天区域包含确认应用等普通文本
- **THEN** 清理后会话外壳、消息与输入区保持存在

#### Scenario: 明确旧面板与正常消息并存
- **WHEN** 明确旧面板包含旧入口文案且旁边有正常消息
- **THEN** 只清理旧面板，重复调用不继续删除正常节点

### Requirement: 每轮可信状态统一投影
系统 SHALL 为每轮提供唯一主状态入口，分别保存执行、业务证明、正文完整性与读取状态，遵守REQ-0046 FR-008优先级，不从助手措辞推断成功。

#### Scenario: 模型结束而业务未完成
- **WHEN** 模型已结束但后端处于校验、应用或回读
- **THEN** 展示实际业务阶段；待定不伪装活动进度，普通聊天不展示业务校验通过，工具次数不使用已读文案

#### Scenario: 失败和正文缺口
- **WHEN** 执行失败、停止、未知或存在正文缺口
- **THEN** 保留原终态并独立去重提示缺口，无正文不声称保留输出，正常流式不增加缺最终答复警告，校验拒绝不被正文成功措辞覆盖

#### Scenario: 读取失败与历史完成
- **WHEN** 已有可信完成快照但更新失败或占用事实矛盾
- **THEN** 保留历史完成并标记更新失败或待确认，不用陈旧权限放行写动作，不把本次完成解释为REQ交付或可归档

### Requirement: 轮次身份与统一详情
系统 SHALL 使用conversation_id、turn_id及可信operation_id定位详情和恢复尝试，保留历史失败与原文，不用对象最新成果补齐缺失关联。

#### Scenario: 多轮与迟到响应
- **WHEN** 切换会话、历史分页、重连或迟到旧响应到达
- **THEN** 只更新匹配身份及有效版本，旧确认失效，不覆盖其他轮次，不删除正常正文和输入区

#### Scenario: 局部原型验收
- **WHEN** 状态区域实现待验收
- **THEN** prototype仅为设计输入，需Change设计、REQ验收、Skeleton确认、双视口截图、computed style、Mock/API声明及REQ最终一致性证据共同签认

### Requirement: 跨入口当前动作一致性

系统 SHALL 以同一结构化验收事实判定产品与CLI归档准入，并保留历史完成证明。合法后续阶段须有可信关联和当前证据，未知占用、真实冲突及证据过期不得放行。卡片仅显示一次阻塞摘要，历史核验细节默认折叠。

#### Scenario: 后续合法交付承接历史评审

- **WHEN** REQ或BUG已有可信评审成果且后续Change完成有效验收
- **THEN** 产品与CLI按当前归档动作作出一致判断，不因旧评审摘要变化永久阻断
- **AND** 历史操作与原终态保持不变，后续实质变更由当前证据覆盖

### Requirement: 会话消息统一排序与分页收敛
系统 MUST 使用跨轮稳定平局键与轮内角色顺序形成总序，在 SQL 分页前纳入虚拟助手，前端使用同一正向规则。游标读取 MUST 保留权限校验，重复页和迟到响应不得造成重复、永久漏项或跨会话污染；数据停止变化后已加载范围复核 SHALL 收敛至服务端同范围全集。

#### Scenario: 同秒多轮与拆页
- **WHEN** 同秒多轮以页大小1加载，且同轮消息被拆到不同页
- **THEN** 完整合并无重复遗漏，用户先于同轮助手，多轮顺序稳定

#### Scenario: 旧轮迟到输出
- **WHEN** 加载历史期间已越过游标的轮次新增输出或完成持久化
- **THEN** 范围复核补齐该输出，保留稳定身份位置且旧响应不能覆盖新内容

#### Scenario: 切换会话和重复恢复
- **WHEN** 旧响应在切换会话后到达或同轮重复恢复
- **THEN** 旧会话响应丢弃，同轮恢复幂等，新轮重试保持独立身份

### Requirement: 消息时间来源与历史降级
系统 MUST 区分轮次开始、消息保存、输出事件与更新时间；不得用排序键伪造回复发生时间。历史时间不可确认时 SHALL 标明未知，保留原始数据。

#### Scenario: 历史回复时间不可靠
- **WHEN** 历史助手仅有旧轮次投影时间且无可靠事件时间
- **THEN** 页面明确时间未确认，仍按正确因果顺序展示，不改写原始记录

#### Scenario: 流式转持久化与刷新
- **WHEN** 输出从事件投影转为持久消息并刷新页面
- **THEN** 身份及位置一致，时间来源可解释，部分输出和执行终态仍依据权威事实

### Requirement: Sprint 归档命令准备与执行分层
系统 MUST 在 Sprint 会话准备完成且对象允许交互时，仅预填准确的归档命令，等待用户主动发送；发送后重新检查最终归档门禁，结果依据真实成果回读。

#### Scenario: 空草稿精确预填
- **WHEN** 用户进入空闲 Sprint 对象会话且输入为空
- **THEN** 输入框 MUST 填入 /sprint-archive 与目标规范 Sprint ID 组成的完整命令
- **AND** 系统 MUST NOT 自动发送、创建candidate或turn、启动归档或改变Sprint归档状态

#### Scenario: 现有草稿与一次性消费
- **WHEN** 输入已存在相同命令或不同草稿
- **THEN** 相同命令 MUST 保持一份，不同草稿 MUST 默认保留并提供保留与填入选择
- **AND** 只有用户明确填入后才替换文本，附件与Skill上下文 MUST 保留
- **AND** 意图 MUST 按项目及会话隔离，处理后消费一次，刷新重挂载不能再次覆盖

#### Scenario: 忙碌与并发准备
- **WHEN** 对象有未决执行或用户重复点击准备会话
- **THEN** 系统 MUST 遵守既有执行保护并对同一准备操作幂等，不通过新建会话绕过占用
- **AND** 本人可见执行会话只供查看，不注入命令；他人执行信息 MUST 按权限过滤

#### Scenario: 主动发送后最终检查
- **WHEN** 用户主动发送 Sprint 归档命令
- **THEN** 系统 MUST 重新检查最新范围、权限、签署、文档一致性及Workflow Sync条件
- **AND** 条件不足 MUST 返回真实阻塞，不能伪造签署或成功；中断恢复不能重复已成功副作用
- **AND** 会话准备、模型文本或脚本退出码 MUST NOT 单独作为Sprint完成证明

#### Scenario: 观测与敏感信息边界
- **WHEN** 用户点击入口、准备会话或主动发送归档命令
- **THEN** 系统 MUST 区分行为、请求、准备及实际执行阶段，使用脱敏关联标识
- **AND** 预填 MUST NOT 被计为归档执行成功，日志不得存储完整草稿、Prompt或凭证

### Requirement: 持续保存与安全恢复交互
系统 MUST 复用Chat状态组件，分离执行终态、保存完整性与恢复准入；正文按页加载，动作有加载、禁用和错误状态。原型仅为设计输入，最终验收依赖design、来源acceptance、Skeleton确认、1440px与关键交互截图、computed style、Mock/API边界及REQ最终一致性。

#### Scenario: 已保存结果与未知尾段
- **WHEN** 运行中断或浏览器重连
- **THEN** 能读取已提交页并看到未确认尾段，不将未加载说成无结果，历史失败不被恢复成功覆盖

#### Scenario: 重复恢复操作
- **WHEN** 用户多次点击恢复或原状态未知
- **THEN** 忙碌时禁止重复提交且服务端幂等；未知只可核验，按钮受真实准入约束而不是演示成功

#### Scenario: 响应式与原型验收
- **WHEN** 完成UI交付
- **THEN** 1440/1024/390深浅主题、键盘焦点与局部滚动通过，提供实际API与恢复证据，不将Mock作为真实通过
