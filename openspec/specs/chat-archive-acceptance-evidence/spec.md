# Chat 归档验收证据规格

## Purpose
规范 Chat 归档验收的证据要求，区分产品同轮完成、目录迁移窗口与宿主恢复。验收核对历史引用授权、唯一标准归档目录、规格单次合并、工作流同步及命令终态，保留中断原因，确保归档结论可追溯。
## Requirements
### Requirement: 归档验收证据区分执行层级

治理验收 MUST 分别记录真实产品对象 Chat 轮次、隔离回归和宿主恢复的结果；只有同一产品轮次出现可信命令完成结果、归档事实与状态同步结果时，才能将产品端归档闭环记为通过。

#### Scenario: 产品轮次完整归档

- **WHEN** 已完成任务和交付证据门禁的 source 工作区 Change 在对象 Chat 首次执行归档
- **THEN** 验收记录核对该轮次的命令结果、唯一归档目录、规格合并、Workflow Sync、最终回复和用量状态，并分别标记可观察结果。

#### Scenario: 产品轮次中断后宿主恢复

- **WHEN** 产品轮次在目录移动后中断，而宿主使用唯一归档续跑完成同步
- **THEN** 验收记录将宿主恢复列为独立事实，产品端闭环保持待复验，且不重复合并规格。

### Requirement: 归档迁移窗口保留可核对的权限与目录证据

Chat source 工作区归档验收 MUST 核对 OpenSpec CLI 临时旧归档目录到项目标准归档目录的迁移窗口；只有同一产品轮次在窗口后继续完成标准目录校验与 Workflow Sync，才可把这段执行记为通过。

#### Scenario: 临时目录迁移后继续归档

- **WHEN** 已授权的归档轮次将唯一 Change 暂置 `openspec/changes/archive/`，随后标准脚本迁至 `openspec/archive/`
- **THEN** 验收记录核对轮次持续执行、旧目录消失、唯一标准归档目录存在、规格合并一次及 Workflow Sync 完成。

#### Scenario: 迁移窗口中断

- **WHEN** 轮次在临时目录出现后停止或权限撤销
- **THEN** 验收记录保留产品失败状态，宿主恢复单独记载，产品首次归档结论保持待复验。

### Requirement: 复制窗口的首次产品归档必须完成同轮闭环

Chat source 工作区归档验收 MUST 区分旧归档目录与同名标准目录短时共存的复制窗口、产品轮次完成事实和事后宿主恢复；只有同一产品轮次完成标准归档、规格合并与 Workflow Sync 才可判为首次产品归档通过。

#### Scenario: 同名目录复制完成并继续归档

- **WHEN** 已授权归档轮次的完整唯一旧目录与正在复制的同名标准目录短时共存
- **THEN** 验收核对该轮次继续执行、旧目录消失、唯一标准目录完整、规格合并一次、Workflow Sync 完成和命令成功终态。

#### Scenario: 复制窗口中断

- **WHEN** 产品轮次在同名目录复制期间停止、权限撤销或进入未知终态
- **THEN** 验收保留该产品失败事实，宿主恢复单独记录，首次产品归档结论保持待复验。

### Requirement: 归档收尾必须保留产品轮次终态与原始中断原因

Chat source 工作区归档验收 MUST 在文件移动和规格合并后核对同一产品轮次的命令完成、Workflow Sync 与终态；未知轮次对账不得覆盖原始安全原因码。

#### Scenario: 归档收尾完成

- **WHEN** 已授权产品归档轮次完成标准目录移动和规格合并
- **THEN** 同轮继续完成证据校验、Workflow Sync、命令结果与成功终态，并保留可核对的轮次标识。

#### Scenario: 收尾中断

- **WHEN** 归档命令已开始但轮次在状态同步前停止或转入未知
- **THEN** 验收保留原始原因码和未完成事实，宿主恢复单独记载且不算产品成功。

### Requirement: 历史引用在合法归档过渡期保持同轮可核对

Chat source 工作区归档验收 MUST 核对主对象在 OpenSpec CLI 旧目录过渡期的历史引用再授权、归档权限、命令完成、标准目录与 Workflow Sync；不得以宿主恢复替代产品同轮通过。

#### Scenario: 唯一旧目录过渡并完成归档

- **WHEN** 已授权的归档轮次把完整唯一的主对象 Change 移至 CLI 旧归档目录
- **THEN** 同轮历史引用仍可核对，随后完成标准目录、规格合并、Workflow Sync 和命令成功终态。

#### Scenario: 旧目录事实冲突或中断

- **WHEN** 旧目录缺失、身份冲突或轮次在过渡期中断
- **THEN** 保留失败原因与文件事实，拒绝冒认产品成功，宿主恢复单独记录。

### Requirement: 关联 Issue 首次归档须完成同轮阶段迁移

Chat source 工作区对关联 Issue 执行首次归档时，验收 MUST 核对同一产品轮次内的规格合并、唯一标准归档目录、Workflow Sync、Issue promote 和最终完成状态；宿主续跑应单独记录。

#### Scenario: 关联 Issue 同轮归档完成

- **WHEN** 已完成任务和交付证据门禁的关联 Issue 在对象 Chat 首次执行 `/opsx-archive`
- **THEN** 标准脚本退出 0，Change 移入唯一标准归档目录，Issue 迁入 archive，注册表与当前态索引同步，产品轮次为 completed。

#### Scenario: 关联 Issue 归档中断

- **WHEN** 产品轮次在 Change 目录迁移、Workflow Sync 或 Issue promote 阶段中断
- **THEN** 验收保留原始失败事实；事后恢复不替代首次产品归档通过。

### Requirement: 关联 Issue 首次归档中断后使用独立复验样本

当首次归档轮次中断且产品终态为 stopped 或 unknown 时，验收 MUST 保留原轮次事实，并使用新的已关联 Issue 样本取得完整同轮成功证据，不能把文件迁移或宿主恢复替代产品成功。

#### Scenario: 新样本同轮完成

- **WHEN** 已完成任务与交付门禁的新关联 Issue 在对象 Chat 首次执行归档
- **THEN** 标准脚本退出 0，Change 规格与唯一归档目录同步，Issue 迁入 archive，注册表与 Sprint 状态同步，产品轮次为 completed。

#### Scenario: 新样本再次中断

- **WHEN** 新样本归档轮次在任一阶段中断
- **THEN** 保留错误、工具事件和文件事实，不将其计为 AC-001 通过。

### Requirement: 关联 Issue 首次归档再次中断后使用第三份独立复验样本

当首次归档轮次中断且产品终态为 stopped 或 unknown 时，验收 MUST 保留原轮次事实，并使用新的已关联 Issue 样本取得完整同轮成功证据，不能把文件迁移或宿主恢复替代产品成功。

#### Scenario: 新样本同轮完成

- **WHEN** 已完成任务与交付门禁的新关联 Issue 在对象 Chat 首次执行归档
- **THEN** 标准脚本退出 0，Change 规格与唯一归档目录同步，Issue 迁入 archive，注册表与 Sprint 状态同步，产品轮次为 completed。

#### Scenario: 新样本再次中断

- **WHEN** 新样本归档轮次在任一阶段中断
- **THEN** 保留错误、工具事件和文件事实，不将其计为 AC-001 通过。

### Requirement: 包装脚本同步证明使用独立首次归档样本

归档证明修复验收 SHALL 使用独立已准备样本取得同轮归档与可信核验结果，不能用宿主恢复代替首次产品执行。

#### Scenario: 包装归档完成

- **WHEN** 独立样本在产品Chat首次完成归档包装脚本
- **THEN** 验收 SHALL 分别核对轮次终态、归档文件、可信完成证明及看板阶段，并保存脱敏证据

### Requirement: 包装脚本首次归档样本串行执行

归档证明首次验收 SHALL 在独立样本执行与结果核对期间暂停其他治理写入，避免共享注册表和Sprint投影竞争影响首次结果。

#### Scenario: 包装归档完成

- **WHEN** 独立样本在产品Chat首次完成归档包装脚本
- **THEN** 验收 SHALL 分别核对轮次终态、归档文件、可信完成证明及看板阶段，并保存脱敏证据
