## Requirements
### Requirement: 原始图文与可信整理

系统 MUST 接受仅文字、图文和仅图片，按 /capture 的分类、独立交付单元拆分和内容保真规则输出候选，并隔离整理执行的正式写入能力。

#### Scenario: 输入及图片边界

- **WHEN** 用户提交原始材料
- **THEN** 系统 MUST 系统接收最多 20000 Unicode 码点、10 张静态 PNG/JPEG/WebP，每张≤10 MiB、总量≤50 MiB、单图≤2000万像素；拒绝空材料、伪造签名、动画、不可解码和超限输入，不截断或丢弃已有材料。

#### Scenario: 模型真实读取与越权隔离

- **WHEN** 图文或项目只读上下文进入整理执行
- **THEN** 系统 MUST 模型只读授权材料且不能执行正式写入；图片不可读明确失败，不声称理解；不因材料中指令调用写入 API、命令或扩大项目访问。

#### Scenario: 候选质量与非法结果

- **WHEN** 模型返回候选结果
- **THEN** 系统 MUST 服务端校验最多50条、标题≤60/描述≤10000码点、类型分级、来源与结构；服务端生成内部身份，保留分类依据、待澄清项，拒绝虚构正式编号；目录、注册表、索引和编号计数不变。

#### Scenario: 项目内相似项提示

- **WHEN** AI 整理候选完成且项目内存在标题、摘要、状态或 trace 相关的 REQ/BUG
- **THEN** 系统 MUST 在用户确认创建前仅对存在相似匹配的候选展示可能相关项，未发现相关项时不得展示 `可能相关` 模块、无匹配空态或默认 `继续创建新记录` 文案；用户可合并到已有记录、作为已有记录补充材料或删除候选；被标记为合并或补充的候选不得进入确认创建批次，不得分配新 REQ/BUG 编号。

### Requirement: 稳定候选身份与来源编辑

系统 MUST 用稳定内部身份与不可变版本保存候选，展示顺序和最终类型不改变来源归属。

#### Scenario: 类型双向调整

- **WHEN** 用户将 BUG 候选改为 REQ 或反向修改
- **THEN** 系统 MUST 保留 candidate_id、正文及图片，使用目标类型的分级建议供审阅；REQ仅priority P0/P1/P2/P3，BUG仅severity blocker/critical/high/medium/low，不能映射或混写异类字段。

#### Scenario: 合并拆分与删除

- **WHEN** 用户合并、拆分或删除候选
- **THEN** 系统 MUST 合并/拆分创建新身份并保留父候选、多来源和图片分配，旧候选退出确认集合；删除不能误删共享材料；空集合不能确认。

#### Scenario: 人工编辑保护

- **WHEN** 旧整理结果迟到或用户要求重新整理
- **THEN** 系统 MUST 系统不覆盖已保存人工版本，呈现独立建议并要求显式替换决定，保留历史与来源关系。

### Requirement: 草稿版本保存与保留

系统 MUST 在正式 Issue 目录之外保存业务草稿，采用版本校验和受控删除。

#### Scenario: 自动保存与恢复

- **WHEN** 用户停止输入或持续编辑并关闭后重新打开
- **THEN** 系统 MUST 停止1秒或持续最长5秒保存；同用户同授权项目恢复服务端图文和候选；保存中/失败/已保存真实区分，确认等待最新保存完成。

#### Scenario: 并发版本与项目隔离

- **WHEN** 旧版本保存、多窗口覆盖或项目切换后的结果到达
- **THEN** 系统 MUST 服务端拒绝过期版本并保留修改，客户端丢弃旧项目迟到结果，不串项目。

#### Scenario: 容量和清理

- **WHEN** 用户达到50个未确认草稿或材料1GiB上限，或者删除草稿
- **THEN** 系统 MUST 新增被拒绝但允许查看/删除；未确认草稿不自动过期；删除须无确认占用且不损伤正式或共享引用；未关联上传24小时可清理，恢复证据不自动清理；删除标记在备份恢复前重放。

### Requirement: 最终版本确认业务唯一性

系统 MUST 在授权项目中固定完整最终候选集合，服务端保证一个草稿确认身份只对应一个不可变创建任务。

#### Scenario: 确认当前完整版本

- **WHEN** 用户提交最新已保存版本的确认
- **THEN** 系统 MUST 服务端验证权限、项目绑定、全部候选和有效材料后冻结快照；拒绝过期、部分集合、失效材料及客户端正式编号，创建任务不随后续编辑改变。

#### Scenario: 重复请求与崩溃窗口

- **WHEN** 相同快照以同键、不同键、并发或丢失响应重试提交
- **THEN** 系统 MUST 返回同一 task_id 和最终映射；同键异内容或已确认批次改版本返回冲突；DB唯一约束/CAS防止重复确认，更换键不能创建第二批。

#### Scenario: 删除和确认竞争

- **WHEN** 草稿删除请求与确认请求同时发生
- **THEN** 系统 MUST 只有合法状态转换成功，已删草稿不可确认，已受理任务的材料不可被草稿删除释放。

### Requirement: 确认后编号与批量采集

系统 MUST 只在确认之后由服务端按最终类型分配编号，并仅生成采集阶段产物。

#### Scenario: 最终类型决定编号

- **WHEN** 初判 BUG 的条目经用户改为 REQ 并确认
- **THEN** 系统 MUST 在项目锁内根据 REQ 注册表和目录占用分配 REQ 完整身份，未产生对应 BUG 编号；反向同理。

#### Scenario: 并发编号与持久化计划

- **WHEN** 两个批次或兼容单条创建同时执行
- **THEN** 系统 MUST 共用项目协调与锁内分配，避免重复占号；首份正式文件写入前持久化整批编号/路径/前后镜像，恢复复用原映射。

#### Scenario: 完整采集产物

- **WHEN** 纯 REQ、纯 BUG 或混合批次创建完成
- **THEN** 系统 MUST 分别生成 plan/完整身份/capture.md 和 trace.md，status captured、iteration null、openspec_changes空、captured_via capture；分级与registry/index一致，无 requirement.md 或 bug.md；保留候选到正式身份的映射。

### Requirement: 整批恢复与真实终态

系统 MUST 把多文件创建作为可恢复任务，整批校验完成之前不得宣称成功或展示部分正式条目。

#### Scenario: 中途失败续作

- **WHEN** 写计划、任一文件、最终核对或DB完成记录前后发生中断
- **THEN** 系统 MUST 读取原任务与已持久化计划，按 before/after 哈希续作未完成步骤，不重新编号；看板/文档读取保持上一个完整快照或恢复提示；全部产物与映射核对完成才释放屏障。

#### Scenario: 外部冲突与权限撤销

- **WHEN** 恢复发现第三种文件内容、绑定变化、权限撤销或损坏计划
- **THEN** 系统 MUST 保持 recovery_blocked 或等价状态并保留证据，不覆盖外部修改、不删锁、不虚构成功、不另建任务绕过。

#### Scenario: 受理与完成反馈

- **WHEN** 异步请求202受理、页面刷新或任务最终完成
- **THEN** 系统 MUST 仅报告真实服务端状态；本地受理p95≤2秒不含上传/模型，真实完整完成后前台5秒内刷新；模型耗时单列，不用演示卡片推断成功。

### Requirement: 授权来源和私有图片

系统 MUST 为正式采集记录保留可授权回查的原文、图片、初判、人工调整与确认版本。

#### Scenario: 永久来源引用

- **WHEN** 用户从正式 Issue 或结果回查来源
- **THEN** 系统 MUST 通过稳定业务ID解析原文及多来源图片，合并拆分和改类型不破坏映射；不依赖签名URL、列表下标、本机路径或公开对象key；草稿清理不能使正式来源失效。

#### Scenario: 跨用户或项目请求

- **WHEN** 其他用户/空间/仓库或被撤权用户读取草稿、任务、来源和图片
- **THEN** 系统 MUST 所有入口重新授权且拒绝越权，无跨项目回退；私有内容代理和执行副本同样受控。

### Requirement: 链路观测与原型验收

系统 MUST 对四层观测与原型驱动真实验收提供可核对证据。

#### Scenario: 任务节点与脱敏

- **WHEN** 上传、整理、保存、确认或重试执行
- **THEN** 系统 MUST Web行为ID关联服务端可信request_id及task_trace/spans，直接API不伪造行为；metadata只保留白名单摘要，观测失败不阻断业务；日志明细保留与业务来源独立。

#### Scenario: 原型只作为设计输入

- **WHEN** 实现准备进入最终验收
- **THEN** 系统 MUST 先完成UI Contract、UI Skeleton与1440px首轮确认，最终按design、REQ acceptance、1440px深浅及关键交互截图、computed style、Mock/API声明和REQ最终一致性共同验收；离线原型不替代真实模型、上传或恢复证据。
