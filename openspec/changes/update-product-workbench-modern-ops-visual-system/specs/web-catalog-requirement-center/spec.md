## MODIFIED Requirements

### Requirement: 前台框架与主题

系统 MUST 使用 MoonBox 前台框架承载需求中心，并保持统一的侧边栏、品牌、主题、会话展示和页面结构。

#### Scenario: 需求中心使用现代 Ops 工作台 Shell

- **WHEN** 用户打开需求中心
- **THEN** 页面必须展示现代 Ops 工作台 Shell
- **AND** 需求中心导航项必须高亮
- **AND** 侧边栏必须展示登录后产品工作台的信息架构分组
- **AND** 品牌区必须展示 MoonBox、工作台版本或等价产品状态标记
- **AND** 前台品牌区的 Logo、产品名、副标题、版本标记和展开/收起按钮视觉规格必须与后台侧边栏品牌区保持一致，同时副标题可保留前台工作台业务语义
- **AND** 当前导航项必须使用现代 Ops active 态表达，不得只依赖旧品牌叙事样式
- **AND** 侧边栏、导航密度、字体字号、图标尺寸、折叠按钮、收起态行为和用户菜单视觉层级必须与管理后台 Shell 保持一致
- **AND** 前后台用户菜单必须使用区别于侧边栏的浮层背景、边框、阴影和 hover 态
- **AND** 退出登录必须在前后台用户菜单中单独成组并使用一致危险色
- **AND** 侧边栏必须支持展开与收起形态，收起后必须保留图标、悬停提示和当前菜单高亮
- **AND** 窄屏下必须避免品牌区、版本标记和页面标题互相挤压；可隐藏版本标记以优先保证主标题和主操作可读
- **AND** 需求中心右侧内容标题区必须采用与后台用户/空间管理一致的内容页标题布局，英文小标题必须显示为 `Requirement Operations`，不得使用额外底部分隔线、sticky 顶栏感、半透明背景或 blur

#### Scenario: 主题切换使用现代 Ops Token

- **WHEN** 用户在用户菜单内切换明暗主题
- **THEN** 页面必须即时应用现代 Ops 深色或浅色 Token
- **AND** 深浅主题下文字、面板、边框、状态色、focus、disabled 和 loading 状态必须清晰可读
- **AND** 主题切换不得改变业务状态

### Requirement: 前台需求中心生命周期看板

系统 MUST 在 MoonBox 前台提供需求中心看板，以 9 个阶段统一展示 Requirement 与 Bug 从采集到归档的生命周期。

#### Scenario: 用户打开需求中心看到现代 Ops 9 阶段看板

- **WHEN** 用户进入 MoonBox 前台需求中心
- **THEN** 页面必须展示采集池、规划中、待评审、已通过、迭代规划、待开发、研发中、验收中、已完成 9 个阶段
- **AND** Requirement 与 Bug 必须共享阶段框架
- **AND** 每个阶段列头必须展示阶段标题、命令副标题或产品化阶段说明以及两位数对象数量
- **AND** 九阶段看板必须采用现代 Ops 暗场大盘式列比例，列宽、列间距、列头高度、标题/副标题字号、count 状态牌、列体 padding 和空列承载感必须保持稳定且可扫描
- **AND** 九阶段列容器必须作为暗场布局容器弱化实线面板感，列头必须保持冻结能力，且看板应采用 header/body 分离布局与列体内部纵向滚动，使任务卡从列头下方开始展示并避免被大面积遮罩覆盖；不得使用强分隔线或实心面板背景，列头标题与副标题必须保持紧凑字号和上间距
- **AND** 非空列必须主要通过任务卡表达承载，空列必须由同一列体结构渲染阶段差异化的真实占位文案，不得只依赖 CSS 空伪类；空列必须使用大面积低对比虚线承载框，底色贴近页面暗场且仅保留轻量承载区域感，虚线边框必须为冷灰且不得混入品牌金色或大面积斜线纹理，空列占位标题和说明文字必须使用现代 Ops 技术感字体 token
- **AND** Requirement 卡片默认状态线必须保持金色强调，Bug 卡片可保留危险色强调
- **AND** 页面必须通过横向看板结构表达 9 个阶段
- **AND** 看板必须提供可理解的横向滚动边界或边缘提示
- **AND** 空列必须展示轻量虚线占位或等价空状态，不得导致列宽跳动
- **AND** 空列承载区必须保持现代 Ops 细线质感，不得呈现无结构的大面积空白
- **AND** Requirement 卡片与 Bug 卡片必须通过类型色或状态边清晰区分
- **AND** 卡片必须使用现代 Ops 信息密度、状态边、meta pill、文档分隔区、footer 动作分区和弱层级更新时间
- **AND** 卡片中的研发、测试和人工验收进度行必须对齐附件 `.card-metrics` 样式，整体使用技术感等宽字体和 10.5px 字号，进度标签与 `x/x` 数值必须拆分为不同视觉层级：标签低对比、数值次级高对比且加粗；进度项之间必须使用纯间距分隔，不得显示 `·`、`Â·` 或其它特殊符号；进度项仍必须保留打开任务进度抽屉的按钮能力
- **AND** 卡片 footer 阶段动作必须先进入附件式 Action Modal 组件族承载交互状态，再复用既有阶段流转能力；Action Modal 必须覆盖分析、生成、完善、评审/确认修复、加入迭代、生成 Opsx、开始开发/修复、查看进度、完成/归档等状态，并提供 loading、checklist、dropzone、tabs、progress 或 confirm 等对应反馈
- **AND** 分析类 Action Modal 的解决方案要点必须支持逐项勾选与取消勾选，默认全选，底部确认按钮必须随选中数量实时更新，并在 0 项选中时禁用
- **AND** 已完成阶段卡片必须作为只读归档结果展示，不得显示研发、测试、人工验收进度信息，也不得显示 `查看归档` 或其它 footer 动作按钮；归档证据入口应由 `archive.md` 与 `trace.md` 文档入口承载

#### Scenario: 统计区与筛选区采用现代 Ops 样式

- **WHEN** 需求中心完成数据加载
- **THEN** 页面必须展示统计卡，覆盖总量、需求、Bug、阻塞或风险等关键指标
- **AND** 统计卡必须支持趋势、风险或状态提示，但不得引入营销式装饰
- **AND** 工具栏必须包含搜索、类型 segmented、筛选 Popover、active badge 和刷新图标按钮或等价组合
- **AND** 筛选 Popover 必须保持紧凑工具控件密度，不得遮挡看板主路径或形成低密度表单面板
- **AND** 筛选、刷新、loading、错误和空态不得改变主布局高度或遮挡看板
- **AND** AI 入口必须固定在右下角且不遮挡窄屏搜索、筛选和看板主路径

### Requirement: 原型驱动 UI 验收

系统 MUST 将 REQ-0023 的产品原型和附件视觉方向作为设计输入，并在实现、验收和归档阶段保持文档一致。

#### Scenario: Change 设计承接现代 Ops 原型拆解

- **WHEN** OpenSpec Change 创建完成
- **THEN** `design.md` 必须包含 UI Contract
- **AND** UI Contract 必须声明事实源优先级、品牌分层、Token、组件、交互状态、权限规则、Mock/API 边界和 computed style 验收点
- **AND** `design.md` 必须包含 UI Skeleton
- **AND** UI Skeleton 必须覆盖页面结构、区域边界、组件层级、状态容器、数据依赖、可测选择器和 1440px 验收焦点
- **AND** `tasks.md` 中 UI Skeleton 任务必须早于细节实现任务

#### Scenario: 视觉验收覆盖现代 Ops 关键状态

- **WHEN** `/opsx-apply` 完成 UI 实现
- **THEN** 必须产出 1440px 桌面视觉证据
- **AND** 视觉证据必须覆盖默认首屏、侧边栏展开/收起、用户菜单、筛选 Popover、看板横向滚动、空列、错误态、卡片 hover、右侧抽屉、AI 入口、深浅主题和窄屏状态
- **AND** computed style 证据必须覆盖关键字体、字号、行高、间距、圆角、边框、背景、颜色、z-index、overflow 和 position
- **AND** `/opsx-archive` 前必须确认 REQ 文档、Change 设计、最终实现和验收证据一致
