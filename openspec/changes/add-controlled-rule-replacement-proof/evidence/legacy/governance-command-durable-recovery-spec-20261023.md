# 归档恢复规则修改确认增量规格

## MODIFIED Requirements

### Requirement: 归档连续证明的条文冲突范围
系统 SHALL 在产品与 CLI 共用只读恢复准入，旧基线变化只接受完整连续的已完成归档哈希证据。中间归档须唯一、增量结果有效，且与本对象条文不相交、具备完整兼容追加证明，或具备当前版本的规则修改确认及独立验收。未知变化、相关范围冲突、缺损证据、权限或并发变化继续阻断。显式刷新保留旧记录和衔接证据，不重置已经合并的状态。

#### Scenario: 其他链路先完成归档
- **WHEN** 其他独立 Change 已完成归档且连续哈希链与当前正式规格完全一致
- **THEN** 两入口一致允许当前动作或安全续接，不重复模型调用、规格合并或 Issue 迁移

#### Scenario: 规则修改已确认
- **WHEN** 每项修改均属于明确增加的允许情形，旧保护保留，空间所有者确认当前版本且验收人员独立签署
- **THEN** 系统 SHALL 逐边核对确认与完成的归档事实，并复核当前效果，不自动替当前对象完成归档

#### Scenario: 无法证明的规格变化
- **WHEN** 哈希链缺失、同条文修改缺有效确认、归档未完成、结果篡改或准备过程发生并发变化
- **THEN** 两入口一致拒绝并保留旧记录及现场，提示具体阻断

#### Scenario: 破坏性或不明修改
- **WHEN** 删除、重命名、弱化保护、重复标题、未知操作、缺少有效 delta 或不明差异
- **THEN** 系统 SHALL 拒绝承接，不以标题、模型意见或人工确认绕过保护

#### Scenario: 旧版已完成历史
- **WHEN** 归档链包含旧版已完成的受控替代证明
- **THEN** 系统 SHALL 按其原版本只读验证并保留历史事实，不要求重新签发旧运维收据，也不把旧批准当作新版确认

#### Scenario: 中断续接
- **WHEN** 合并或迁移阶段中断且已写入结果可回读
- **THEN** 系统 SHALL 沿原操作只完成剩余步骤；无法确定结果时保持阻断
