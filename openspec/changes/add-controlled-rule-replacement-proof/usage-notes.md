# 规则替代审阅使用说明（待发布）

本文是当前 Change 的交付说明，不改变已发布产品手册的版本事实。

在 Chat 项目操作区可打开“审阅规则替代证明”；归档命令出现兼容证明阻断时，也可从该阻断项进入同一抽屉。抽屉展示目标条文、前后差异、不可豁免义务、证据绑定与独立签署说明。空间所有者可以独立批准、拒绝或撤销当前精确版本；其他成员只能使用当前权限允许的能力。批准只记录授权，不发送命令或自动归档。

批准超过 24 小时、证据变化或当前权限变化后，需要重新核验并审阅。领取后的归档不能靠撤销回滚。最终执行仍检查验收签署、任务、范围及完整历史链。失败后保留草稿、已上传附件与 Skill；结果未知时重试同一对象命令，由系统回读原操作。

首次可信启用是独立区域，需要有效部署制品授权和所有者确认。正式信任未配置时不能使用测试凭据替代。正式 BUG-0063 与 sprint-012 的处理仍需对应执行授权。

发布时将上述用户说明投影到该正式版本的 Chat 手册，再运行 Mintlify 生成与公开安全校验。当前 latest 绑定已发布版本，本次不改历史快照或发布指针。

## 首次启用完整入口

在 Chat 的规则替代审阅内点击“查看启用条件”，按三个阶段生成并导出精确清单、导入独立运维签名收据，再由空间所有者确认转换。部署参数、离线工具及中断恢复步骤见 docs/02-deployment.md 的“首次可信启用”章节。成功页面给出机制归档身份，其他业务提案和 Sprint 独立签署不随之批准。
