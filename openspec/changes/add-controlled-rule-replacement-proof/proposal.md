# 规则修改说明与安全归档提案

## 背景

REQ-0050 的旧实现引入运维制品审阅、首次启用和项目级常驻审批入口，完成一次可解释的规则修改需要跨部署、产品及验收多条链路。产品方案已于 2026-10-23 重拟并复评，原实施事实与已产生的审计/归档记录保留为历史。

## 变更内容

- 从当前产品流程删除旧版专属运维制品授权、策略首次启用、清单导出/导入和项目级常驻审阅按钮；历史记录只读保留，进行中操作先回读，不自动迁移为新确认。
- 在对象归档阻断项展示旧新规则、修改内容、现行仍有效的归档条件与验收结果。移除额外的空间所有者规则确认按钮；验收人员仍独立签署。
- 归档前复用原归档权限、验收、完整历史链与并发检查；删除/重命名/弱化保护、断链、篡改和结果不明继续阻断。查看和重新检查不自动发送或归档。
- 既有已完成历史及旧版证明仍可读；当前准入不得依赖旧确认、运维收据、首次启用状态或新增独立兼容证明。

## 能力影响

- 修改 `controlled-rule-replacement-proof`：以规则差异说明和现行验收、归档门禁代替额外批准；保留历史验证。
- 归档预检和恢复沿用 BUG-0063 已生效的正常验收与完整链，不发行新版规则修改证明；本 Change 不再修改已有受保护条文，因此自身归档不依赖新能力自证。原修改提案仅留在历史证据中。

## 交付与切换

本 Change 在归档前完成新旧方案替换；原 28 项旧验收和上一版规则确认样本只代表历史实现，新版以 REQ-0050 的 AC-L01—L12 为准。先在代码工作区撤去确认入口和新确认写入，不发行新的规则修改证明，同时保留旧版完成记录的只读验证；完成测试前不部署或放宽当前运行服务的归档门禁。旧产品操作仅在确有记录时验证恢复；BUG-0063 的 Codex 会话不作为产品恢复样本。同步 API、数据库、Web、安全及验收文档。BUG-0063 已归档，其历史不因本 Change 改写；sprint-012 关闭保持独立。
