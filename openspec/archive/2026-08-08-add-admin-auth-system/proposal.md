## 背景与动机

管理后台已经承载用户创建、冻结、删除、重置密码和头像上传等敏感能力，但现有后台 API 仍使用 `x-admin-role: admin` 占位鉴权。现在需要补齐真实后台认证边界，避免只有前端路由守卫、后端接口仍可被绕过的安全缺口。

## 变更内容

- 新增管理后台超级管理员账号密码登录能力。
- 新增 access token 与服务端会话记录，支持过期、撤销、退出登录和账号状态变化后的会话失效。
- 新增后台登录页、退出入口和后台路由守卫。
- 替换 `/api/v1/admin/**` 的 `x-admin-role: admin` 占位鉴权，改为基于 token、服务端会话、账号状态和后台角色的正式认证授权。
- 新增环境变量首次幂等创建唯一系统内置超级管理员，并在生产环境禁止空密码、示例密码或弱密码。
- 同步 API、数据库、部署环境变量、安全规范和测试验收。

## 能力范围

### 新增能力

- `web-admin-auth-system`: 管理后台登录认证系统，覆盖后台账号密码登录、access token、服务端会话记录、退出登录、后台路由守卫、后台 API 鉴权替换和超级管理员初始化。

### 修改能力

- `api-governance`: 后台登录、退出和受保护管理接口需要在 API 契约、错误码和公开端点清单中体现。
- `database-compatibility`: 新增服务端会话记录和超级管理员初始化字段/约束后，需要保持 SQLite 与 MySQL 兼容。
- `deployment-governance`: 新增或收敛后台认证相关环境变量，并约束生产弱密码。

## 影响范围

- Backend：新增后台认证 API、会话服务、密码哈希、认证依赖、超级管理员初始化和 `/api/v1/admin/**` 鉴权替换。
- Web Admin：新增后台登录页、登录态管理、退出登录和路由守卫。
- API：新增登录/退出/当前用户接口，更新 401/403 错误语义和认证 Header。
- Database：新增或调整服务端会话记录结构，确保 SQLite/MySQL 兼容。
- Security：禁止明文密码、token、session id 泄露到日志、URL、错误上报、埋点或审计明文。
- Docs/Tests：同步 API、数据库、部署、安全文档，并补充后端 pytest、前端 Vitest/Testing Library 和必要 E2E/集成验收。
