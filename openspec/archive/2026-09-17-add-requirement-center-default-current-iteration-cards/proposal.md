## 背景

需求中心当前已承载 REQ、BUG、Sprint 与 OpenSpec Change 的治理看板，但入口默认范围仍容易让历史、未纳入迭代或非当前工作的卡片与当前 Sprint 混在一起，降低产品负责人和研发协作者的扫描效率。

REQ-0034 已评审通过并纳入 `sprint-006`。本变更将需求中心默认视图调整为当前迭代优先；返修后不新增“当前迭代/全部/历史/未纳入迭代/归档”范围按钮组，也不新增筛选模块下方提示模块，而是在既有 Sprint 多选下拉中默认选中当前 Sprint 集合和“未纳入 Sprint”。

## 变更内容

- 需求中心首次进入或重置默认视图时，默认展示当前迭代相关卡片和未纳入 Sprint 的 REQ、BUG、独立 Change 卡片。
- 当前迭代识别以 Sprint 生命周期事实源为准，不能依赖前端缓存、标题文案、目录名或卡片临时状态。
- 当存在多个当前迭代候选时，既有 Sprint 多选默认选中全部当前 Sprint 和“未纳入 Sprint”；用户可在同一下拉中取消或选择单个 Sprint。
- 当无当前迭代、当前迭代和未纳入 Sprint 均无卡片、Sprint 事实源解析失败、接口失败或权限不足时，展示稳定空态或脱敏错误态，不新增范围提示模块兜底。
- 用户可通过清空 Sprint 多选查看全部对象，通过选择历史或归档 Sprint 查看对应范围；手动刷新保留用户显式 Sprint 选择，空间或项目切换后重新计算默认当前迭代和未纳入 Sprint。
- 保持需求中心 9 阶段映射、卡片动作、文档入口、权限边界、独立 Change 去重和归档可见性规则不变。
- 原型驱动 UI 验收覆盖默认当前 Sprint + 未纳入 Sprint 选中、多当前 Sprint 多选、无当前 Sprint、清空/选择 Sprint 交互、1440px、窄屏、深浅主题和文本溢出。

## 能力影响

### 新增能力

无。

### 修改能力

- `web-catalog-requirement-center`: 调整前台需求中心筛选与搜索体验，在既有 Sprint 多选内表达默认当前迭代、清空/重置语义和 UI 验收要求。
- `web-catalog-requirement-center-real-data`: 强化真实上下文聚合和筛选契约，要求当前迭代识别、统计、卡片范围、权限过滤、异常态和稳定刷新基于同一授权事实源。

## 影响范围

- 前端：需求中心默认 Sprint 多选状态、Sprint 筛选联动、空态/错误态、多视口 UI 验收和筛选重置行为。
- API：可能复用既有需求中心上下文；若实现发现缺少当前迭代候选、Sprint 状态或范围字段，需同步 API 文档、OpenAPI 和客户端类型。
- 数据库：不新增表、迁移、索引或保留周期。
- 安全：范围候选、数量、搜索提示和错误详情必须只来自当前用户有权访问的需求中心上下文。
- 观测：需求适用于 `usage_events` 与 `request_logs`；实现需验证行为事件与请求日志只记录脱敏筛选上下文，不保存治理文档全文、本机路径、完整请求/响应体、密钥或 token。
