# 根因确认与诊断升级规格

## ADDED Requirements

### Requirement: 根因确认范围与停止决策

Agent MUST 分别记录机制确认、历史精确归因和修复有效性，按声明命题及直接证据确定状态；不得以文档完成或缺失值为零确认根因。

#### Scenario: 机制闭合而历史精确占比未知

- **WHEN** 当前同请求证据与真实触发路径支持机制，但历史请求无阶段记录
- **THEN** 仅确认有证据的机制，保留历史占比未知，不自动推进评审或宣称修复

#### Scenario: 关键触发条件仍缺失

- **WHEN** 只有微基准或未经准入验证的夹具
- **THEN** 保留 probable 并继续授权范围内最小补证，不通过缩减命题假装闭合

### Requirement: 观测缺口升级与诊断恢复

Agent MUST 识别缺失字段，选择隔离或受控在线诊断，关联同请求身份并区分嵌套计时；结束时核对恢复及残留。永久观测实现沿用正式开发门禁。

#### Scenario: 已有诊断授权但需要服务中断

- **WHEN** 现有审计无子阶段，加载临时计时涉及共享服务重启
- **THEN** 不重复索要诊断授权，协调未覆盖的中断安排，最小采样后恢复并验证健康

### Requirement: 当前结论与历史证据分层

Agent MUST 在当前文档显示唯一有效结论、范围和未知事项，历史记录标识时间及替代关系，保留原始证据不改写旧结论。

#### Scenario: 后续证据使 probable 变为 confirmed

- **WHEN** 当前结论更新
- **THEN** 同步主文档与验收摘要，旧结论移入明确的历史区并可追溯，不将诊断完成标记为修复验收通过
