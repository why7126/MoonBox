# 自动验收与证据归档设计

## 背景与目标

验收输入是 Change 的逐 AC 计划；输出是 Change 内的 `evidence/acceptance/<run-id>/manifest.json` 与摘要。Issue `acceptance.md` 保存最终判定，Change trace 和 Sprint 报告只引用证据，不复制原始会话。

## 关键决策

1. 使用独立 `/opsx-accept` 编排阶段。apply 完成后自动进入；modify 仅使受影响输入失效；archive 只消费已通过的就绪报告。
2. 脚本接受声明式计划。每条 AC 指定输入文件、聚焦命令或产品轮次、必要文件效果及证据等级。脚本不运行任意 shell 字符串，命令使用 argv；不自动创建正式 BUG/Change 或越过 Sprint、评审门禁。
3. 产品轮次从授权本机 SQLite 数据库只读查询终态和 `execution.tool` 事件。只提取序号、阶段、退出码和命令匹配结果；不保存 prompt、消息正文或原始事件 payload。同轮成功必须同时有 completed 轮次、completed/exit 0 的目标命令及计划声明的效果。
4. 每条 AC 的计划片段和输入文件内容形成指纹；以前通过且指纹一致时可复用。新证据与旧证据一起进入新 run 清单；过期项重跑。不存在输入声明或证据缺失时不能复用。
5. 预检及轮次等待有明确超时；一次环境预检失败即停止依赖检查。默认不自动重试有副作用命令；可安全重试的瞬态检查由计划声明且次数有上限。
6. 状态只在全部 AC 通过后写 `passed`；失败、受阻和未观察分开记录。Workflow Sync 不再仅因 archive 事件把待验收直接提升为 passed，也不在无失效证据时将 passed 重置。

## 风险与处理

- 产品事件结构变化：取证解析失败时标记 blocked，保留轮次 ID，不推断成功。
- 本地 SQLite 锁与容器故障：只读短连接、有界等待和失败分类，不重启共享运行时。
- 历史 Change 没有新验收计划：兼容既有归档规则；新 Change 使用计划与清单，迁移不伪造历史结论。
- 未经授权的归档样本：技能只准备/检查样本；有副作用的产品归档须已有用户授权和治理门禁。

## 回滚

可移除新技能与脚本，并停止新计划生成；既有证据包仍可按 Markdown/JSON 读取。Workflow Sync 回退前须保留已签认 Issue 验收状态。
