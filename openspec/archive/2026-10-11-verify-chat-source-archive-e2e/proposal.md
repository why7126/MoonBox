# Chat source 工作区归档端到端验收样本提案

## 背景与原因

BUG-0026 的首次产品归档样本在规格合并和目录移动后中断，缺少同轮次完成态与同步收据。需要一个经授权、可追溯的全新纯治理 Change，在真实产品对象 Chat 中验证首次归档闭环。

## 变更内容

- 建立归档验收证据的治理规格，要求区分产品轮次、宿主恢复和隔离回归。
- 以本 Change 自身作为一次性首次归档样本，记录任务、规格合并、目录移动、Workflow Sync、最终回复和用量结算的实际结果。
- 不修改产品代码或现有业务功能；如产品轮次再次中断，保留失败证据并停止验收结论。

## 能力范围

### 新增能力

- `chat-archive-acceptance-evidence`：定义 Chat source 工作区归档的可复核验收证据边界。

### 修改能力

无。

## 影响范围

仅新增本 Change 的治理文档与归档后的规格，不变更 API、数据库、UI、部署、安全权限、客户端生成、请求日志、行为事件或 Task Trace 采集字段。`product_data_collection_observability: N/A`；`affected_layers: []`；原因是本次只记录现有链路的脱敏验收事实；验证为产品轮次与文件事实源对照。
