# 修复管理后台当前用户自冻结和自删除保护

## 背景

来源缺陷：`BUG-0008-admin-users-self-freeze-delete-not-forbidden`。

管理后台当前登录用户可以对自己的账号执行冻结或删除操作，缺少后端强制拒绝和前端危险操作保护。该缺陷可能导致后台管理员误操作后失去后台访问能力，并造成账号管理、审计追踪和运维恢复风险。

当前实现已保护系统内置超级管理员和已删除用户，但没有把“当前会话主体不得冻结或删除自己”定义为后端权限边界和前端交互约束。

## 变更内容

- 后端在冻结、删除后台用户接口中识别当前登录用户与目标用户是否相同。
- 当前登录用户冻结或删除自己时，后端必须返回 `403 Forbidden`，且不得修改用户状态、删除时间或撤销当前会话。
- 前端用户管理列表在当前账号行保留冻结、删除按钮但置为禁用状态，并通过禁用原因说明不可自操作。
- 保持对其他非系统用户的冻结、解冻、删除、重置密码等既有操作能力。
- 保持系统内置超级管理员保护不回归。
- 补充 API 集成测试与前端用户管理回归测试。

## 非目标

- 不改变后台用户角色模型。
- 不新增批量冻结、批量删除或账号恢复能力。
- 不调整个人资料、修改密码、头像上传或登录接口语义。
- 不放宽系统内置超级管理员保护。

## 回滚计划

如修复引入回归，回滚本 Change 中对后端冻结/删除权限判断、前端当前账号操作态和相关测试的改动即可恢复旧行为。回滚后需重新确认 `BUG-0008` 风险仍存在，并不得在未替代修复前归档该 BUG。
