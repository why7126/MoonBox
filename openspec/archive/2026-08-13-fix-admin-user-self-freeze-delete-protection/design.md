# 技术设计

## 根因

`BUG-0008` 的直接原因是后台用户状态变更接口只校验调用方具备后台管理员权限，并把 `actor["id"]` 传入 repository 做审计，没有在目标 `user_id` 与当前登录用户 ID 相同时拒绝冻结或删除。

前端用户管理列表已维护当前会话用户，也能从用户列表拿到每行用户 ID，但操作列只根据 `is_system_superadmin` 和 `status === "已删除"` 判断不可操作，没有把当前账号作为危险操作保护条件。

## 修复方案

### 后端权限边界

- 在冻结和删除接口层增加当前用户自操作判断。
- 当 `actor["id"] == user_id` 且操作为冻结或删除时，抛出 `PermissionError` 或等价 `HTTPException(403)`。
- 拒绝请求不得进入 `set_status` 状态更新逻辑，避免撤销当前会话或写入删除时间。
- 解冻、重置密码、编辑等非本缺陷范围操作保持既有规则；如后续需要限制自重置或自编辑，应另行 capture。

### 前端交互

- 在用户管理表格操作列计算 `isCurrentUser = currentSessionUser?.id === user.id`。
- 当前账号行保留冻结和删除按钮位置，但按钮必须禁用并提供不可自操作原因。
- 当前账号行可以保留编辑/个人资料相关入口；若保留重置密码入口，必须不改变本 Change 范围内的验收目标。
- 当前账号行不额外显示“当前账号”文案；不可自操作原因由禁用按钮说明承载，避免操作列额外占位。

### 测试

- 后端 API 集成测试：
  - 当前后台管理员冻结自己返回 `403`。
  - 当前后台管理员删除自己返回 `403`。
  - 自冻结/自删除后当前用户状态、`deleted_at` 和会话可用性不变。
  - 冻结/删除其他非系统用户仍按既有流程工作。
- 前端 Vitest/Testing Library：
  - 当前账号行展示冻结/删除按钮但处于 disabled，且不会打开确认弹窗。
  - 其他非系统用户仍可打开冻结/删除确认弹窗。

## API 与文档影响

- API 路径不变。
- 错误码语义新增：当前用户自冻结、自删除返回 `403 Forbidden`。
- 需要同步 `docs/03-api-index.md` 或认证/后台用户管理文档中与后台用户状态操作相关的权限边界说明。
- 若 OpenAPI 响应模型无变化，可不重新生成客户端类型；若实现调整 OpenAPI 描述，应同步生成物。

## 风险

- 仅前端隐藏按钮不足以防止直接 API 调用，后端 403 是必须项。
- 当前账号判断应使用用户 ID，不使用用户名或昵称，避免重名或展示字段变化导致误判。
- 当前 Sprint 容量已达 100%，本 Change 实现应保持 S 级范围，避免扩展到账号恢复或批量操作。
