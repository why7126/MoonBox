# 对象会话准备性能与安全复用规格

## ADDED Requirements

### Requirement: 对象会话准备的有界安全复用

系统 MUST 减少同请求无变化区间的重复治理快照成本，保持完整字节新鲜度、源投影一致性、权限、生命周期、Sprint准入、占用、协调恢复与幂等语义。复用不得仅依据TTL、mtime或进程内锁推断外部工作区未变化；不能证明稳定时MUST保留安全重读。

#### Scenario: 复用空闲会话

- **WHEN** 已授权写动作通过准入且已有空闲会话
- **THEN** 返回原契约的正确会话和草稿，准备完成后才允许发送，不重复执行可安全共享的快照工作

#### Scenario: 写入使准备上下文失效

- **WHEN** 协调、同步、外部写入或版本推进改变源/投影
- **THEN** 使依赖上下文失效并安全重读或按原契约拒绝，禁止使用过期快照授予执行资格

#### Scenario: 权限或阶段不满足

- **WHEN** 对象无权限、错误阶段、Sprint不匹配、执行占用或存在待审候选
- **THEN** 保留原拒绝或引导，不以性能优化绕过准入，不重复创建会话或动作

### Requirement: 会话准备导航性能验收

系统 MUST 在固定版本/规模/资源/负载的同条件对照中满足准备及导航目标，失败和离群样本完整保留；历史请求无阶段数据时不得推算其精确归因。

#### Scenario: 暖态准备与导航

- **WHEN** 完成一次不计入统计的预热，前后各至少10个顺序有效请求
- **THEN** 准备中位数不超过2000ms且较基线降低至少50%、最大不超过4000ms；点击至路由切换中位数不超过2500ms、最大不超过4500ms

#### Scenario: 冷态与并发

- **WHEN** 以应用缓存冷态前后至少5个样本及3独立对象并发前后各10批验证
- **THEN** 冷态准备中位数不超过4000ms、最大不超过6000ms且较基线不退化超过10%；并发中位数和最大值不退化超过10%，无新增错误、重复会话或动作

#### Scenario: 计时证据不足

- **WHEN** 响应与准备请求身份不匹配、关键阶段缺失或前后条件不一致
- **THEN** 不判性能验收通过，补齐同请求证据且不重复累加父子阶段、不把缺失记零

### Requirement: 快速打开与发送时最终检查

系统 MUST 在卡片点击后立即进入 Chat 并保留可编辑草稿。轻量打开仍检查身份和对象读取权限；完整协调恢复、最新文件快照、生命周期、Sprint、占用及候选门禁推迟到发送请求，执行入队前完成。未完成打开或草稿冲突未处理时不得提交。

#### Scenario: 打开或最终检查失败

- **WHEN** 打开失败、打开后对象状态变化或最终检查拒绝
- **THEN** 保留草稿并提供可恢复反馈；不得启动模型、绕过权限或误报已经提交

#### Scenario: 生成候选与幂等

- **WHEN** 用户发送 req-generate 或 bug-generate
- **THEN** 复用原受控候选准备能力并绑定当前授权会话，重复请求不创建重复候选或执行

#### Scenario: 草稿交接

- **WHEN** 当前对象会话已有不同的未发送草稿
- **THEN** 要求显式选择保留既有草稿或使用当前草稿，不静默覆盖；离开页面后迟到响应不得抢回导航
