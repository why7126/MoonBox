# 会话准备导航延迟修复验收方案

## 验收状态

实现自检及受控/自然采样已完成，证据见verification.md与evidence/implementation/；正式验收状态由acceptance-plan.json的逐AC清单判定。以下保留已评审目标。

## 性能契约

2026-10-30 当前方案按用户授权改为“快速打开，发送时最终检查”。下列暖冷/并发指标用于用户进入 Chat 的入口路径：旧版点击同步等待写准备，新版调用轻量 open-chat。二者业务旅程可比较，但接口工作量不同，不能据此宣称完整写准备加速。导航阈值不变；新增分别记录打开接口、草稿就绪、最终检查耗时。最终检查不含模型执行时间。打开成功不授予执行资格。


以下为本次制定的验收目标，并非实测保证。依据现有自然请求约6.38–7.05秒且快照约97%的成本分布，要求显著降低用户等待；是否可达由修复后同条件实测证明，不用历史21.27秒作对照分母。

- 基准：固定部署资源、数据库、同规模治理树、对象状态、动作、认证与网络；记录版本、文件数/字节数、缓存状态及后台负载。原诊断规模约6818文件/20.2MB仅作参考，验收前冻结实际数据集，修复前后相同。
- 暖态：明确一次预热且不计入统计，前后各至少10个顺序有效请求。准备接口中位数≤2000ms、较基线中位数降低≥50%，最大值≤4000ms，三项同时满足；计时从服务端收到请求至响应发出，浏览器同ID关联复核。
- 导航体验：同一浏览器条件下，点击至Chat路由切换中位数≤2500ms、最大值≤4500ms；历史内容加载和Chat可交互时间另列，不混入本BUG阈值，打开时明确展示准备状态，发送时重新检查，不把路由到达当作执行准入完成。
- 冷态：仅清理本修复管理的进程/请求缓存，不宣称清除OS缓存；前后至少5个独立冷态样本，准备中位数≤4000ms、最大值≤6000ms，且较同条件基线不退化超过10%。
- 并发：同一数据集3个独立对象并发，前后各10批；报告单请求中位数与最大值，修复后均不得较基线退化超过10%，无新增5xx/锁错误/重复会话或动作；任一正确性失败直接不通过。
- 阈值适用基准规模和资源。数据规模/配置改变须重新固定对照；不达标先分析与返修，调整目标需要显式说明证据并重新评审，不能事后降低标准。
- 记录全部失败、取消、超时及离群样本；缺失值不填零，不剔除慢请求。只有有效请求计入时长统计，错误样本单独计数且不能用重试成功抹除。非故意错误用例出现新增失败则验收不通过。


## 正确性与证据矩阵

| AC | 验收内容 | 证据要求 |
|---|---|---|
| AC-01 | 同请求归因 | 响应/准备/审计ID一致，阶段树、文件规模、读取/重试计数、未归属时间；无父子重复累加 |
| AC-02 | 暖冷/并发与导航性能 | 上述全部门槛，前后固定版本和条件；暖态10、冷态5、3并发10批；真实浏览器暖态10次导航 |
| AC-03 | 已有与新会话 | 目标、复用、草稿正确；重复点击无重复会话；分别统计 |
| AC-04 | 一致性与外部写入 | 读取中写、相同元数据字节变化、源投影差异、持续更新、范围/版本隔离；不复用过期状态 |
| AC-05 | 权限与流程 | 无权限、错误阶段、Sprint错误/非成员、占用、待审候选仍拒绝或保留原引导 |
| AC-06 | 交互与幂等 | 失败、取消、重试、重复点击的状态与实际动作计数，页面可恢复，打开中允许编辑但禁止提交；最终检查失败保留草稿 |
| AC-07 | 只读及直接查看 | 不误走写动作门禁，历史加载另测；既有权限过滤保持 |
| AC-08 | 协调与诊断 | 目标/相关对象恢复等价，安全失效/回退；诊断脱敏、原件恢复与健康/入口核验 |
