# 快速打开工作台与发送时最终检查方案

## 当前决定与实施门禁

用户选择在 BUG-0057-requirement-card-chat-navigation-latency 和本 Change 内推进快速打开工作台、发送时最终检查，不新建 Issue。该方案为原导航延迟问题的修复方向调整，不改变限定机制确认范围；历史21.27秒请求的精确归因继续未知。

用户明确授权保持sprint-016容量30人天、不调整其他任务，记录超额风险并自主完成实现、验证和本地部署。原5人天追加3人天初估，合计32/30（106.7%），属于规则允许带风险规划的100%至120%区间；不是硬阻塞。缓冲耗尽且存在交付延迟风险，不能以估算代替实测或降低门禁。此前容量硬阻塞判断撤回。

本方案作为原BUG修复范围的明确修订生效；原慢请求和旧验收失败证据保留，页面打开与发送准入分开验收。实现中保持Change applied和首次完成事实，完成返修后再同步待复验。

## 目标流程

1. 点击卡片后立即进入Chat页面框架，展示当前对象及命令草稿；客户端上下文仅用于展示，不作为授权。
2. 服务端完成空间、仓库、对象访问与个人会话归属检查，复用或创建会话；历史消息继续按当前权限返回。打开会话不授予治理执行资格。
3. 草稿可编辑，历史、会话列表和关联信息独立加载。加载失败保留草稿并提供重试；切换项目、对象或离开页面后，旧请求不能覆盖当前会话与草稿。
4. 用户发送后立即展示“正在检查执行条件”。服务端依据本次实际命令及最新事实，完成写权限、源投影一致性、生命周期、Sprint、历史结果核对、占用、候选和额度检查。
5. 准入成功后进入排队和执行；失败给出具体原因及可用处理入口，保留草稿。网络超时与结果未知不能当作明确失败，不自动生成新的执行身份重发。

## 实现边界与复用依据

- 当前RequirementCenterPage等待object-sessions返回后才导航；需将导航意图交接给Chat，区别页面已打开、会话已加载、执行已准入。
- chat/service.py的request_turn、governance/preparation.py的prepare_command_snapshot以及chat/admission.py的enqueue已有发送准入、材料复核、执行保护和幂等机制，应复用并补齐迁移检查，不能机械删除入口逻辑。
- 当前准备中的reconcile覆盖项目内相关执行。移至发送边界前，应证明历史终态恢复与相关对象冲突行为等价；只查当前对象不视为等价。
- 采集阶段生成文档使用governance-preparations，区别于普通object-sessions。须单独覆盖受控候选创建、草稿修改、候选复用和实际会话一致性；不得将其改成普通文本发送后取得写权限。
- 原有只读查看、查看执行、Sprint归档及开发阶段任务抽屉分别保留语义；本轮不增加自动发送，不调整权限策略，不新增数据库迁移或部署拓扑。
- can_send不能被展示为永久执行授权；所有客户端状态均不能替代发送端最新检查。

## 验收设计

以下为待落地的新行为验收设计，不代表已运行或已通过。原样本与失败结果只读保留。

| 项目 | 通过条件与证据 |
|---|---|
| 页面快速响应 | 准备请求人为延迟时页面仍先出现对象和可编辑草稿；记录点击至框架、编辑可用、历史首屏三个时间点，不用仅URL变化证明可用 |
| 导航性能 | 沿用原点击至路由中位数≤2500ms、最大≤4500ms作为上限，另验页面可编辑；暖态至少10样本，保留取消、失败和慢样本 |
| 打开成本 | 单独采集轻量打开接口暖冷及3并发数据，原完整准备指标不能直接套用或移除；同规模同资源对照后形成正式验收计划 |
| 发送准入 | 同请求计量检查、数据库等待、队列接收等阶段；无回执前不展示已执行，不能用打开变快掩盖发送回退 |
| 权限与最新事实 | 打开后撤权、改变阶段或Sprint、源投影漂移、相关对象执行冲突，发送仍拒绝；不得产生实际执行 |
| 候选生成 | 采集阶段生成动作只在用户发送后创建受控准备；失败保留草稿，重复提交不重复候选或轮次 |
| 草稿与会话 | 已有会话复用、新会话幂等；切换对象/项目、刷新、取消、重试和迟到响应均不串草稿或错误导航 |
| 历史与恢复 | 无权对象内容不泄露；历史加载失败不清空草稿；相关历史终态核对与未知状态保护不回退 |
| 产品证据 | 1440px与关键失败/加载/发送状态截图，目标选择器及必要样式证据；测试与自然浏览器证据分别标注 |

数值目标未覆盖的发送准入与历史加载耗时，先固定同条件基线，再确定正式目标；不能在结果出来后降低门槛。旧AC-02失败继续保留，完整新验收就绪前禁止归档。
