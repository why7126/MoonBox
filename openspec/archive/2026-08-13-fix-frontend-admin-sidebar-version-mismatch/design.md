# 设计说明

## 根因

后台用户管理页侧边栏直接硬编码 `<em>v1.0.5</em>`，未复用 `src/shared/product-version.ts` 中的 `PRODUCT_VERSION`。前台需求中心已通过共享常量展示 `v0.1.0`，因此两个入口形成版本事实源分叉。

`v1.0.5` 可追溯到后台用户管理原型补丁版本语义，但正式产品侧边栏不应展示原型补丁号。

## 修复方案

1. 在后台用户管理页引入共享产品版本常量。
2. 将后台侧边栏版本展示从硬编码 `v1.0.5` 改为共享版本值。
3. 在后台用户管理测试中断言侧边栏展示共享版本。
4. 保留前台需求中心既有版本展示测试，形成前后台一致性回归。

## 影响面

- Web 前端：`AdminUserManagementPage`、后台用户管理测试。
- 共享常量：仅读取 `PRODUCT_VERSION`，不改变常量值。
- 不涉及后端 API、数据库、权限、部署、OpenAPI 或 Orval 客户端生成。

## 测试策略

- 运行后台用户管理页测试，覆盖后台侧边栏版本展示。
- 运行前台需求中心测试，确认前台侧边栏版本展示不回归。
- 运行前端构建或相关类型检查，确认共享常量导入路径有效。

## 风险与缓解

- 风险：后台测试只断言存在版本文案，未来仍可能改回硬编码。
- 缓解：测试应从共享常量导入期望值或至少与 `PRODUCT_VERSION` 保持一致，避免固化第二事实源。
