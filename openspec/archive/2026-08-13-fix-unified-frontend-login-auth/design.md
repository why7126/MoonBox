# 技术设计

## 根因

当前实现将“登录系统”和“进入后台”耦合在后台管理员认证链路中。前台 `/login` 调用后台登录接口，后台登录接口拒绝非后台管理员角色；需求中心前台接口也依赖后台管理员鉴权，导致普通前台用户无法登录和访问前台。

## 修复方案

### 统一登录

新增或调整认证入口，使 `/login` 使用统一登录语义：

- 校验用户名和密码。
- 仅允许状态为“正常”或“待激活”的用户登录。
- 待激活用户首次登录成功后更新为“正常”。
- 创建可服务端校验、可撤销、可过期的统一登录会话。
- 返回当前用户摘要，包含角色、状态、是否系统超级管理员、是否可进入后台。

### 前台访问

前台需求中心等前台接口使用统一登录态校验：

- 普通前台用户可访问其前台业务范围。
- 后台管理员和超级管理员登录后也默认进入前台。
- 前台接口不得要求用户具备后台管理员角色。

### 后台访问

后台入口和后台 API 继续执行后台权限校验：

- 只有后台管理员或超级管理员可看到“进入后台”入口。
- 点击“进入后台”后，前端进入后台路由前需有可用会话。
- 后台 API 服务端必须校验当前用户具备后台权限。
- 普通前台用户访问后台页面或后台 API 必须被拒绝。

### 前端状态

前端本地 session 需要从“仅保存 username 的前台镜像”升级为可表达统一登录态的结构：

- 保存服务端返回的登录态摘要和访问凭证。
- 需求中心上下文请求携带统一登录凭证。
- 后台相关请求仍通过后台权限校验，不因统一登录而放宽。
- 登出、修改密码成功、账号不可用或会话失效时清理前台与后台相关本地状态。

## 测试策略

- 后端集成测试覆盖普通前台用户登录、待激活自动激活、后台管理员登录、超级管理员登录、冻结/删除拒绝、后台 API 拒绝普通前台用户。
- 前端测试覆盖 `/login` 成功默认进入前台、用户菜单后台入口显隐、普通前台用户无法进入后台、需求中心上下文使用统一登录凭证。
- 回归现有后台认证、修改密码、用户菜单、需求中心真实数据和登录页密码显隐测试。

## 风险与缓解

- 风险：统一登录会话与后台会话边界混淆。缓解：服务端后台 API 始终调用后台权限校验。
- 风险：待激活自动激活影响前台用户状态机。缓解：仅在密码正确且状态为“待激活”时激活，并写审计或等价状态变更记录。
- 风险：前端本地缓存残留旧 admin session。缓解：统一清理和迁移本地 session，认证失败时清理不可用状态。
