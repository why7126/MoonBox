# 修复统一登录与前后台权限边界

## 背景

`BUG-0006-frontend-login-needs-real-frontend-auth` 已确认：MoonBox 前台 `/login` 入口复用了后台管理员认证链路，导致角色为“前台用户”的账号即使密码正确，也无法登录前台，并提示“账号不可用或无后台权限。”

产品目标是：前台和后台用户均需要登录后才能访问系统；账号状态为“正常”或“待激活”时允许统一登录，待激活用户首次登录成功后自动激活为“正常”；登录后默认进入前台；只有后台管理员或超级管理员在前台用户菜单展示“进入后台”入口，并在进入后台或调用后台 API 时继续执行后台权限校验。

## 变更内容

- 将 `/login` 建模为统一用户登录入口，而不是后台管理员登录入口。
- 统一登录允许“正常”或“待激活”的前台用户、后台管理员和超级管理员登录。
- 待激活用户首次登录成功后自动激活为“正常”。
- 登录成功后默认进入前台需求中心。
- 前台用户菜单根据当前用户角色展示或隐藏“进入后台”入口。
- 普通前台用户不得进入后台页面或调用后台 API。
- 需求中心等前台接口接受统一登录态，不再要求用户具备后台管理员角色。
- 后台 `/api/v1/admin/**` 接口继续只允许后台管理员或超级管理员访问。
- 登录失败提示改为前台场景下的受控认证失败提示，不暴露内部权限实现细节。
- 更新 OpenAPI、API 文档、认证文档、前端登录/需求中心/后台入口测试和后端认证集成测试。

## 非目标

- 不新增注册、忘记密码、第三方登录、邮箱验证码或手机号验证码。
- 不实现细粒度项目空间 RBAC；本 Change 只处理统一登录与前后台入口权限边界。
- 不改变冻结、删除、重置密码和会话撤销的安全原则。
- 不扩大普通前台用户的后台权限。

## 回滚方案

如统一登录修复导致前台或后台登录不可用，可回滚本 Change 中的认证接口、前端登录调用、路由守卫和测试改动，临时恢复后台管理员登录链路；同时保留 BUG 和 Change trace，记录回滚原因，并重新评估统一登录接口拆分方案。

## 影响范围

- 后端 API：认证接口、会话解析、前台接口鉴权、后台权限校验。
- Web 前端：`/login` 提交、前台 session、用户菜单后台入口、需求中心上下文请求、后台入口守卫。
- 测试：后端集成测试、前端登录/需求中心/后台入口测试。
- 文档：`docs/03-api-index.md`、`docs/standards/authentication.md`、OpenAPI 生成物。
