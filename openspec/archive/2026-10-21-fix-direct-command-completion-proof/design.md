# 直接命令完成证明与安全恢复设计

## 历史签认与当前准入分离

当前执行保护允许被合法后续同步或新操作替换，原轮次的签认记录仍按会话和请求身份读取。读取时重验权限、绑定、对象可见性和证明格式；相关成果仍一致且业务校验通过才展示历史核验通过，否则只说明历史记录保留。该路径只读，始终不提供恢复版本与恢复能力，不影响当前操作准入。恢复 POST 仍须匹配当前操作身份、版本与完整门禁，禁止借历史签认确认新的执行。

## 背景与现状

根因依据 BUG-0060 root-cause.md E1—E13：snapshot 的全局摘要覆盖无关对象；journal 记录总哈希，最终协调要求成功同步哈希等于当前快照；旧确认阶段在保护未解除时继续覆盖卡片。BUG-0055 已有 Change 且当前结构可验证，不代表历史身份、权限及相关依赖均已满足恢复条件。同步后文档写回操作被观察到，但该工具前后摘要相同，不能认定其就是历史失效来源。

## 修复方案

### 动作契约与证明版本

为 req/bug generate、complete、review、opsx，sprint-propose 和 opsx apply/modify/archive 建立动作注册表：对象身份、相关依赖、预期输出、业务验证器与专用门禁。未支持动作 fail closed。复用既有评审/归档专用证明，不用新的通用成功标志覆盖它们。

版本化记录包含 schema_version、operation/对象/动作身份、执行版本、同步时间、最终核验时间、输入依赖投影、输出文件清单及内容摘要、验证器版本/结果、历史证明引用。文件新增/删除/内容变化均可定位；不存凭证和无关文件正文。完整目录摘要仅作诊断，不独立决定成果有效性。

共享文件按对象条目与真实依赖提取，同时保留全局唯一性、引用完整性和 Sprint 容量检查。说明字段只有明确白名单及语义验证通过才可再签认；任务、规格、状态、身份、验收规则等实质字段保持依赖约束。不能按扩展名忽略所有 Markdown，也不能忽略整个注册表。

### 收尾状态机

业务写入 -> 正式同步记录 -> 最后文档回填 -> 相关输入/输出核验 -> 持久化完成证明 -> 条件确认执行保护 -> 读回卡片和下一动作准入。CLI 与产品消费同一完成契约。--check/--dry-run保持只读；单个退出0、模型文本或静态ready不能生成正式证明。

核验到确认间复读相关指纹，使用 operation/version 条件更新，相关变更或新执行占用立即拒绝。提交证明与保护/投影交接需持久可恢复，重启只重做核验及幂等投影，不重复业务应用。实现选择现有事务/锁边界，不引入跨文件原子性的虚假保证。

### 安全恢复与历史兼容

先校验终态、权限/绑定、操作对象身份、当前依赖、同步一致性和新运行占用。缺少历史清单时保留原记录，明确标记历史归因未知，受控重建当前核验依据并附新证明引用；无法充分验证则维持保护。禁止重放bug-opsx、重建已有Change、手改数据库或卡片阶段。旧证明不能解除新执行保护，重复请求、重启和迟到回调幂等。

BUG-0055 原现场恢复在部署验证后执行：只读定位原执行和已有 fix-chat-turn-message-order，记录恢复前状态，调用通用核验入口，再读回卡片及下一动作准入。仅改变安全确认所需状态，保留原失败和时间语义。该对象不得作为代码特殊分支。

### 错误与展示契约

区分证明缺失、损坏/未知版本、相关输入冲突、允许说明/无关变化待核验、业务校验失败、权限/绑定变化、暂不可用、新执行占用。响应提供稳定原因类别、可恢复性、必要脱敏差异、核验时间和原执行引用；错误码纳入既有API字典而非前端猜测文本。恢复动作由后端能力决定。

轮次运行结束与业务确认分开呈现；在所属轮次详情展示原因与核验入口，卡片只呈现简要阶段/阻塞结果，不重复大型状态面板。产品和CLI相同相关输入得到相同判定。实施前建立按钮→确认/结果状态→selector→证据矩阵，覆盖可用、提交、成功、冲突、缺证、无权限、重试与键盘焦点；1440px及窄视口核对布局和computed style。

## 测试策略

先完成入口环境、身份、权限、依赖与证据前检；实现稳定后集中验证，按受影响指纹增量复验。正常样本串行；并发用例定向注入无关对象、共享条目、相关字段及签认竞争。每类动作有正反例；覆盖退出0但无证明、检查冒充同步、证明损坏、中断重启、重复恢复及旧回调。

部署实际发送接口入队、执行、成果写入、正式同步、最终收尾、保护确认、卡片刷新、下一动作准入与CLI逐段比对。独立正常样本、失败拒绝、BUG-0055历史恢复分别签认；合成回归、真实轮次、UI和部署指纹分层记录，不能只证明准备成功或按钮可点。具体逐AC映射见 acceptance.md。

## 风险与取舍

依赖范围过窄可能漏真实冲突，因此共享约束单独校验并设置反例；过宽导致无关阻塞，按对象条目回归。旧版本和历史缺证不能静默升级为可信；证据不足局部阻断恢复，不停止其他可执行工作。UI和API、SQLite/MySQL兼容必须随实现同步，避免后端通过而产品入口失效。

## 产品数据采集与链路观测

product_data_collection_observability: applicable；affected_layers: API、证明持久化、执行保护、request_logs、task_traces/task_trace_spans、Web及CLI恢复。validation: 计划验证原执行关联、阶段结果、重试分类、脱敏、必要保留周期及OpenAPI/客户端一致性，当前未执行。复用 docs/standards/product-data-collection-observability.md；后台核验不伪造用户行为。N/A：对象存储、管理端新页面和未启用客户端不在本次范围。DB字段/迁移是否新增在实施中按现有存储确认，必须具备SQLite/MySQL兼容证据。

## 知识承接与发布

复用治理恢复与归档证据分层实践、BUG-0052已归档契约和sprint-010 S10-A002。先回归、部署版本核对、通用产品/CLI验收，再受控历史恢复；通过全部适用AC后进入归档就绪，正式发布独立处理。回滚保留证明、在途操作和历史记录，未知版本保持阻断。

## UI 动作与证据契约

沿用现有 TurnActivity 展开详情和 recovery-actions 样式，不新增独立底部面板。直接命令终态读取后按业务状态展示“结果待核验/成果已核验”；运行失败/停止历史不改写。

| 动作 | 交互类型 | selector | 状态及验收 |
|---|---|---|---|
| 展开轮次 | 现有折叠详情 | turn-status-trigger | 键盘展开/收起，保持正文阅读 |
| 核验当前成果 | 详情内即时请求，无额外弹窗 | direct-completion-verify | 可用、提交中、成功、冲突、无权限；只重核不重放 |
| 查看核验原因 | 详情内文本 | direct-completion-detail | 历史缺证、相关冲突、读取失败；允许换行 |

样式采样：详情宽度、文字颜色/行高、按钮disabled、窄视口overflow。真实后端返回状态；隔离测试Mock与部署证据分别标识。实施批次为详情组件、轮次接入、真实视觉与交互核验。


## 实施动作与门禁矩阵

| 动作族 | 相关身份与输出 | 保留的验证入口 |
| --- | --- | --- |
| req/bug-generate | 本对象注册表条目、正文与 trace | draft 状态及必需正文 |
| req/bug-complete | 同上及需求/缺陷子文档 | pending_review 和必需子文档 |
| sprint-propose | 本对象与 Sprint 范围、估算 | in_sprint、唯一性、总容量 |
| req/bug-opsx | 本对象、关联 Change、Sprint、涉及的正式能力规格 | proposed、关联身份、proposal/design/tasks |
| opsx-apply/modify | 关联 Change 交付文件与任务 | applied、任务全完成、执行完成时间 |
| req/bug-review | 已有评审候选、应用和完成证明 | 沿用专用评审签认；通用恢复入口拒绝替代 |
| opsx-archive | 已有归档恢复记录与规格基线 | 沿用专用归档签认；通用恢复入口拒绝替代 |

同步步骤保存 schema v1 的相关路径与摘要；最终核验单独写 final_verification，不修改原步骤。普通 Markdown 仅忽略 updated_at，trace 仅排除明确的验证记录/验证摘要/规划验证记录/变更记录说明段；状态、关联、任务与其余正文仍受保护。

直接命令的终态轮次与 guard 是持久交接意图，控制器从数据库恢复到既有 completion_handoffs 队列。队列按对象和 guard_version 去重，以租约和条件更新领取，最多三次瞬态复验。它只核验，不重放模型、同步或业务写入；CLI 和产品恢复共享同一个 verifier。

历史 req/bug-opsx 缺少同步时清单时，核验当前业务成果，并保护执行前的规则、正式规格及 Issue 原始输入；仅允许可验证的 Change 关联和显式来源字段收尾。历史文件归因继续标为 unknown。新规则或规格、正文冲突、权限变化均阻断。

## 最终部署增量边界

最后的分类修正仅更新应用代码层；基于本轮标准构建的后端/worker/executor镜像保留同一依赖、安全配置与启动契约，使用同一 Compose 配置重启。实际服务文件哈希写入部署证据。回滚以此前镜像身份为准，不修改完成证明原步骤或手工清除 guard。
