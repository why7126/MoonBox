## 背景

MoonBox 管理后台已经通过用户管理页验证了 CRUD 列表页的筛选、表格、分页、弹窗和 toast 体验，但这些能力仍散落在单页实现中。随着后续后台页面增加，需要沉淀统一模板和组件边界，避免复制页面级 JSX/CSS、交互漂移和验收问题复发。

## 变更内容

- 新增管理后台 CRUD 列表页模板能力，覆盖页头、主操作、筛选栏、表格、分页、状态反馈、确认弹窗和表单弹窗。
- 建立后台列表页通用组件边界，使新页面可以传入业务字段、筛选项、表格列、操作按钮、状态标签和表单内容。
- 将用户管理页作为首个模板化适配和验收样板，要求适配后核心能力与视觉体验无回退。
- 将 `admin-list` 与 `admin-modal` 知识库横切 gate 纳入 OpenSpec 设计和任务，覆盖分页 DOM、fixed toast、DS confirm、禁用 `window.confirm`、computed width 和低视口滚动。
- 不新增 API、数据库、对象存储、认证权限或跨端能力。

## 能力影响

### 新增能力

- `web-admin-crud-list-template`: 管理后台 CRUD 列表页模板、通用组件边界、复用约束和横切 UI 验收要求。

### 修改能力

- `web-admin-user-management`: 用户管理页需要作为首个后台 CRUD 列表页模板化适配样板，并保持现有能力、视觉和交互无回退。

## 影响范围

- Web 管理后台：新增或重组列表页模板和可复用组件，用户管理页需要适配到模板体系。
- 测试：前端测试和浏览器验证需要覆盖筛选、分页、状态操作、toast、弹窗宽度和低视口滚动。
- 文档：后续实现与归档需同步后台列表页模板相关长期说明或最佳实践承接。
- API / 数据库 / 对象存储 / 部署：本 Change 不新增契约或结构；若实现阶段发现必须调整，应先记录并补充对应设计、任务与文档。
