## 背景

REQ-0006 已评审通过并纳入 `sprint-001`。当前管理后台用户管理页已经具备后台 CRUD 列表页的真实场景：筛选、真实分页数据、行级操作、状态变更、表单弹窗、确认弹窗、临时密码弹窗、头像上传回显和 fixed toast。REQ-0006 的目标不是新增某个业务实体，而是将这些列表页模式收敛为可复用模板和组件边界，让后续后台 CRUD 页面在同一视觉密度和交互规则下交付。

约束：

- 不写普通 Web 前台、小程序、移动端或桌面端能力。
- 不引入新的 UI 框架；继续使用现有 React、Tailwind 和 shadcn/ui 体系。
- 不新增 API、数据库、对象存储或认证权限能力。
- OpenSpec 设计必须引用 REQ trace 中的 `knowledge_base_refs`。

## 目标与非目标

**目标：**

- 建立后台 CRUD 列表页模板结构，覆盖页头、主操作、筛选区、表格区、分页区和状态反馈。
- 抽取或规范通用组件边界，支持业务页面传入字段、列、筛选项、操作、状态标签和表单内容。
- 将用户管理页适配为首个模板样板，并确保现有用户管理能力、视觉密度和交互无回退。
- 让 `admin-list` 与 `admin-modal` 横切 gate 在设计、任务和验收中可追溯。

**非目标：**

- 不建设完整跨端 Design System。
- 不覆盖仪表盘、详情页、流程编排页或非 CRUD 列表型后台页面。
- 不定义具体业务实体的数据模型、API 字段或数据库结构。
- 不替换后台认证、权限、会话或审计机制。

## 设计决策

### D1. UI 策略：DS component extraction

采用 DS component extraction 策略：从用户管理页中识别可复用的列表页结构和交互行为，沉淀为后台 CRUD 列表页模板与通用组件；用户管理页仅保留业务字段、接口调用和业务规则。

备选方案：

- CSS Port：只复制用户管理页样式到新页面。放弃原因是无法降低重复实现和交互漂移风险。
- 全新 Design System：重新定义后台组件体系。放弃原因是 REQ-0006 首期只覆盖 CRUD 列表页，完整 DS 超出范围。

### D2. 组件边界

模板层负责稳定页面骨架和状态分发，组件层负责可复用 UI 行为，业务页面负责数据获取、字段定义和业务规则。

建议边界：

- `AdminCrudListPage` 或等价组合模式：页头、主操作、筛选区、表格区、分页区、空/加载/错误状态和全局反馈槽位。
- 筛选组件：接收筛选项定义、提交、重置和加载状态。
- 表格组件：接收列定义、行数据、状态标签、行级操作和横向滚动策略。
- 分页组件：总数左侧；翻页、页码、“每页显示”文案和条数下拉右侧。
- 弹窗组件：表单弹窗与确认弹窗分离，禁止业务实现绕过设计系统确认弹窗。
- toast 反馈：使用 fixed toast，不挤压列表、分页、弹窗或抽屉内容。

### D3. 用户管理页适配策略

用户管理页作为首个验收样板。适配时先提取页面骨架、筛选/表格/分页/弹窗/toast 行为，再将用户字段、用户 API、头像上传、临时密码、超级管理员保护等业务规则留在用户管理功能层。

验收重点是“无可感知回退”：列表数据、筛选、分页、状态操作、头像回显、临时密码弹窗、超级管理员保护和审计相关交互均不得被模板化过程破坏。

### D4. 冲突处理

原型与验收优先级按 HTML > PNG > context.md > acceptance.md > ui-design.md > openspec/specs。

- `prototype/web/prototype.html` 展示了后台 Shell、页头、筛选、表格、分页、fixed toast 和 880px 表单弹窗，是本 Change 的布局意图来源。
- `prototype/web/context.md` 明确不要求当前阶段导出 PNG，因此缺 PNG 不阻断。
- `acceptance.md` 的 AC-XCUT 要求优先级高于局部实现便利，尤其是分页 DOM、fixed toast、DS confirm、禁用 `window.confirm`、computed width 和低视口滚动。
- `ui-design.md` 要求近直角、细线、克制金色强调和后台信息密度；模板不得引入强装饰或营销式页面结构。

### D5. 知识库引用

本 Change 必须承接以下知识库：

- `docs/knowledge-base/best-practices/admin-list-page-consistency.md`
- `docs/knowledge-base/best-practices/admin-modal-width-css-cascade.md`

落地方式：

- specs 中新增可测试场景。
- tasks 中加入前端测试、浏览器 computed style 与低视口验证。
- 实现前复核 AC-XCUT-001 至 AC-XCUT-011。

## 风险与取舍

- 模板抽象过早导致组件过重 → 以用户管理页作为首个样板，只抽取列表页通用结构，不把业务规则塞进模板。
- 模板抽象过窄导致后续页面仍复制代码 → 组件 props 必须覆盖字段、筛选、列、操作、状态标签和表单内容。
- UI 横切问题复发 → 在任务中强制浏览器验证分页 DOM、fixed toast、DS confirm、computed width 和低视口滚动。
- 用户管理页适配引发回退 → 保留现有用户管理测试，并新增模板适配回归用例。

## 迁移计划

1. 梳理用户管理页中的可复用结构和业务专属逻辑。
2. 创建后台 CRUD 列表页模板和通用组件边界。
3. 将用户管理页迁移到模板组合模式。
4. 补齐前端测试与浏览器验证。
5. 更新相关文档或在归档时明确无 API/DB/部署变更。

回滚策略：若模板抽象影响用户管理页稳定性，可先保留用户管理页业务层实现，将模板组件降级为内部组合组件，确保现有用户管理功能不回退后再继续抽象。
