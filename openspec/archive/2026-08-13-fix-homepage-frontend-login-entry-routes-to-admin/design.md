# 设计说明

## 根因

首页两个前台 CTA 复用 `openAdmin()`，该函数直接 `pushState("/admin")`，触发应用顶层后台路由。无后台会话时，系统展示 `AdminLoginPage`，导致前台入口误入后台登录页。

现有首页测试将跳转 `/admin` 写成期望，进一步固化了错误行为。

## 修复方案

1. 将首页 CTA 处理函数调整为前台登录入口语义，例如写入 `#login` 或等价前端登录状态。
2. 保留登录页 `hashchange`、返回首页、输入框聚焦和前端原型提交边界。
3. 登录页提交在当前前端原型边界内进入前台需求中心 `/requirements`；不得静默无响应，不得发起真实认证请求，不得跳转 `/admin`。
4. 保留 `/admin` 作为后台明确路由，由 `App.tsx` 继续根据后台会话展示管理后台登录页或后台页面。
5. 保留需求中心用户菜单中具备权限用户的「进入后台」入口。

## 测试策略

- 更新 `homepage.test.tsx`：两个首页 CTA 点击后应展示 `MoonBox login` 表单，路径不得变为 `/admin`。
- 保留 `/#login` 直达与返回首页测试。
- 保留登录表单前端原型提交不发起真实请求的测试。
- 增加登录表单提交后进入 `/requirements` 的断言，避免按钮静默无响应。
- 保留后台认证路由测试，确认 `/admin` 明确入口仍进入后台登录页。
- 运行前端测试与构建。

## 边界

- 不新增真实前台认证接口。
- 不新增真实登录会话、Token 或权限态；当前只提供前端原型进入需求中心路径。
- 不修改后台认证 API。
- 不修改数据库、对象存储、Docker 或部署配置。
- 不改动管理后台权限校验。
