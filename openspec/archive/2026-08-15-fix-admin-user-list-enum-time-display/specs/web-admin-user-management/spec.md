## MODIFIED Requirements

### Requirement: 管理后台用户列表
系统 SHALL 在管理后台提供用户管理列表页，用于查看平台用户账号及其账号生命周期状态。

#### Scenario: 查看用户列表
- **WHEN** 后台管理员进入用户管理页面
- **THEN** 系统从后台用户 API 读取真实用户分页数据，并展示头像、用户名、昵称、角色、状态、空间数、最近登录时间、创建时间、更新时间和操作列
- **AND** 角色字段 SHALL 以轻量标签化样式展示，不得仅作为普通纯文本单元格渲染；角色标签 SHOULD 避免实线边框和专属浅底色造成表格视觉噪声
- **AND** 状态字段 SHALL 通过清晰的标签语义、图标或可区分样式表达“待激活”“正常”“已冻结”“已删除”等状态，并 SHOULD 与空间管理页状态标签保持一致的无边框图标语义表达，其中“正常”状态 SHOULD 使用圆形 check 图标
- **AND** 最近登录时间、创建时间和更新时间 SHALL 使用统一 `yyyy-mm-dd hh:mm:ss` 展示策略，空值 SHALL 展示为 `—`
- **AND** 默认列表 SHALL 不展示 `status=已删除` 的逻辑删除用户

#### Scenario: 筛选用户
- **WHEN** 后台管理员输入用户名或昵称关键词，或选择角色、状态筛选条件
- **THEN** 系统将当前筛选条件提交给后台用户 API 并自动刷新用户列表，且角色筛选仅包含“后台管理员”和“前台用户”
- **AND** 状态筛选 SHALL 仅提供“全部状态”、“待激活”、“正常”和“已冻结”，不得提供“已删除”筛选项
- **AND** “全部状态” SHALL 不展示 `status=已删除` 的逻辑删除用户
- **AND** 后台用户 API 返回的 `total` SHALL 使用与当前列表相同的逻辑删除筛选规则计算

#### Scenario: 用户列表分页
- **WHEN** 用户列表超过当前每页条数
- **THEN** 系统使用后台用户 API 返回的用户总数展示左侧用户总数，并展示右侧上一页、下一页、页码、“每页显示”文案和条数下拉框

#### Scenario: 用户列表审计时间展示
- **GIVEN** 后台用户 API 返回 `created_at` 和 `updated_at`
- **WHEN** 后台管理员查看用户管理列表
- **THEN** 列表 MUST 在创建时间后展示更新时间列
- **AND** 创建时间和更新时间 MUST 使用同一格式化策略
- **AND** 不得要求后端新增字段或修改数据库结构才能展示更新时间
