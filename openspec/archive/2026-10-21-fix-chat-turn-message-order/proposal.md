# Chat 同轮消息顺序与时间语义修复提案

## 背景

[BUG-0055-chat-turn-message-order-inversion](../../../issues/bugs/review/BUG-0055-chat-turn-message-order-inversion/bug.md) 已评审并纳入 sprint-011。轮次创建与用户消息保存跨秒时，助手被投影为更早的轮次时间，导致回复排在提问之前。根因证据 E1—E6 已确认原始样本机制；扩展场景待回归。

## 变更内容

- 建立轮次与轮内确定性总顺序，API 分页与 Web 正向展示使用相同排序键。
- 显示时间与排序分离，保留历史事实并明确时间来源；虚拟输出、流式增量和持久消息保持身份与位置。
- 新增向后兼容的游标读取与已加载范围复核，处理跨页、重复页及迟到输出。
- 覆盖普通、REQ、BUG、纯 Change 会话及历史样本；不按对象或归档命令特判。

## 能力影响

### 新增能力

无独立能力模块。

### 修改能力

- `web-catalog-chat-workbench`：扩展对话与轨迹一致展示，新增消息因果顺序、时间来源和并发分页契约。

## 影响范围

后端 assistant_output、Chat 消息 API/DTO、Web ConversationMessages、OpenAPI/客户端及接口与集成测试。沿用消息/轮次/事件表，默认无 schema 迁移；若性能验证需要索引，实施前补充设计、双数据库迁移与回滚。同步 API、数据库时间语义及 Web 使用说明。权限、执行保护、对象存储和部署拓扑不变。

## 风险与回滚方案

sprint-011 本项 5 人天，总量29.5/30人天，仅余0.5人天；复杂度增长先重算容量。前后端作为同一版本交付，回滚配套应用版本，不删除消息、不批量改写历史时间、不重放历史归档；回滚可能恢复旧排序缺陷，须明确提示。新增 API 字段保持兼容，旧 page 参数继续可用。
