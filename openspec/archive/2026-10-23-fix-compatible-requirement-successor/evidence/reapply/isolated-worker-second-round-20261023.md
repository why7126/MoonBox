# 隔离产品归档复验：第二轮结果

本轮依据用户对**一次限定隔离验证**的授权，在可回收的独立项目中重建 API、治理控制器和 Chat worker。仅隔离 worker 挂载容器管理入口与只读登录凭据文件；正式项目和正式服务未改动。隔离样本 `sprint-102` 只有一个已归档 Change，签署字段是明确标注的测试标记，不是正式验收签署。

发送前，样本的 Sprint 关闭准入、关闭前引用扫描以及归档三项脚本预检均通过。产品对象会话复用成功，唯一发送的 Chat 轮次为 `b1708115-8981-40fc-9a36-2ba428ac0329`，命令为 `/sprint-archive sprint-102`。该轮次最终为 `failed / trusted_archive_unverified`；Sprint 仍在活动目录，未产生归档目录。用量事件明确记录模型实际使用 **0 Token**。此前两次 HTTP 发送尝试均在创建轮次前返回 503，未产生额外轮次。

失败后只读进入同一隔离 worker，重放归档前置身份、Sprint 最终准入与 `ArchiveDriver` 初始化，得到 `archive_tools_not_trusted`。目录权限采样显示 `scripts` 和隔离项目目录只读，但其祖先隔离根目录仍可写。归档工具的信任检查要求脚本目录及所有祖先不可写，因此这次失败是**隔离部署挂载路径配置问题**；三项预检在另一个只读探针容器通过，不能代表实际 worker 已通过信任检查。没有证据表明 BUG-0063 的兼容追加逻辑失败，也不能据此宣称其产品验收通过。

本轮授权的一次产品轮次已用完。AC-014/015 仍缺成功的同轮次产品证据，BUG-0063 与 REQ-0050 的归档准入维持阻断。下一次采样前，应把 API 和 worker 放在同一配置视图，使隔离项目及脚本路径的全部祖先只读，同时仅把数据库、状态和工作区挂载到独立可写路径；先在**实际 worker 镜像**中通过工具信任检查，再发起产品轮次。不得以只读探针或单项脚本通过替代这项检查。
