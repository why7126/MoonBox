# 隔离产品归档复验：Chat worker 信任边界

本轮在可回收隔离项目中创建 `sprint-102` 样本，仅包含一个已归档 Change，并使用明确标注的测试签署标记。产品发起前的完整范围、历史证据、签署和关闭前引用扫描均通过；此标记不代表正式独立验收人员签署。

部署验证先在只读容器内完成：归档工具信任检查、数据库连通、当前身份和 Sprint 最终准入、三项写入前校验均通过。随后经产品对象会话发送一次 `/sprint-archive sprint-102`。真实 Chat 轮次 `24087814-4063-44dc-825f-e8fe2f35bc1f` 最终为 `failed / trusted_archive_unverified`，样本 Sprint 仍在进行中，归档目录没有生成；预留 1,000,000 Token 已结算，实际模型使用 **0 Token**。

本轮根因定位到部署角色：归档命令由 Chat worker 直接运行；测试服务中的 worker 仍为宿主进程，读取的是可写隔离副本。对该副本脚本执行与产品相同的 `ArchiveDriver._trusted` 检查，确定返回 `archive_tools_not_trusted`。只读控制器的通过结果不能替代 worker 的信任检查。后续只读诊断曾在隔离数据库领取一条 `claimed` 操作，未推进 Sprint 文件；该诊断操作不属于上述 Chat 轮次，不计作归档成功或恢复证据。

尝试将隔离 worker 一并部署为只读容器时，启动方案需要挂载宿主 Docker socket 与 Codex 授权文件。自动审批以广泛容器控制和凭据暴露风险拒绝了该动作；没有启动该 worker，也没有改动正式服务。须在明确批准且经安全边界复核后，才能重建完整隔离部署并重新采集真实产品正向轮次。当前 AC-014/015 与 BUG-0063 归档准入维持阻断。
