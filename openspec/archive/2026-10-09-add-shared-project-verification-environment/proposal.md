# 平台提供跨空间项目验证环境变更提案

## 背景

BUG-0030 的实现缺少与当前代码匹配的项目依赖和真实浏览器，导致合成回归通过后仍无法完成页面验收。Chat 执行器只保证通用工具链，其他空间和项目会重复遇到环境缺口。需要平台提供可声明、可预检、隔离且可复用的项目验证能力。

## 变更内容

- 新增项目验证声明与环境身份，区分基础执行器工具、Node 项目依赖和 Firefox/Chromium 浏览器就绪状态。
- 新增受控依赖和浏览器制品准备、离线复用及版本失效规则；验证任务在隔离工作副本运行。
- 新增授权的预检、任务执行和结果查询能力，产出真实浏览器证据与脱敏诊断。
- 以 BUG-0030 和第二个独立 Web 项目验证通用性；合成 DOM 与真实浏览器结果分别呈现。

## 能力影响

### 新增能力

- `project-verification-environment`：跨空间项目验证声明、受控制品、环境预检、真实浏览器任务与证据治理。

### 修改能力

无既有生效规格需要改变；现有 Chat 执行器工具链和测试治理语义保持不变。

## 影响范围

预计涉及后端平台任务、授权 API、执行容器/部署配置、Node 锁文件依赖与浏览器制品、请求日志和 Task Trace、测试与部署文档。首期不新增专属项目管理 UI、数据库迁移或对象存储协议；设计与实施发现范围变化时回填 Change 并同步 OpenAPI、Orval、文档及测试。
