# 平台提供跨空间项目验证环境技术设计

## 背景与现状

Chat executor 通过受控 Docker 运行 Agent，镜像预检只覆盖通用工具；项目 `node_modules`、Playwright 浏览器和系统库不在保证范围。BUG-0030 已出现后端与合成 DOM 回归通过、真实浏览器缺失的交付阻塞。REQ-0044 已评审并纳入 sprint-009，与 REQ-0042 的基础 Agent 执行环境治理独立。

## 目标与非目标

目标：跨空间项目可声明 Node/Firefox/Chromium 验证环境，在任务运行前得到明确就绪状态，并取得真实浏览器证据；制品可受控复用，工作区与结果严格隔离。

非目标：在 Chat 基础执行器镜像中预装所有项目依赖；开放任意宿主命令、公网或 Docker socket；首期支持 Python、移动端或专属 UI；仅凭合成 DOM 测试认定真实浏览器验收。

## 设计决策

### D1 独立验证任务与制品

平台新增验证任务服务和受控 runner 镜像，沿用服务端可信空间/项目绑定和工作副本。API 只接受声明 ID、预定义验证目标和幂等请求 ID；具体命令来自授权仓库声明且通过允许列表与参数模式校验。控制端调度隔离容器，容器内不挂 Docker socket、平台业务库或 Agent 凭证。基础 Chat 执行镜像保持通用工具链。相较每项目手工安装，此方案可复用；相较膨胀 Chat 镜像，验证任务具有独立依赖、资源和网络权限。

### D2 环境身份与准备阶段

环境身份由锁文件摘要、Node 与包管理器版本、Playwright 包版本、目标 OS/架构、验证镜像摘要组成。依赖准备在独立容器与受控制品源完成，校验完整性后发布不可变只读制品；浏览器与系统库随受版本约束的 runner 镜像提供，启动探针校验。运行容器只消费已校验制品，不在线安装。不同 OS/架构和版本不共享 `node_modules`；失效时重新准备或返回 unavailable。共享只限不可写、无凭证的制品层。

### D3 预检、运行与证据状态

先核验授权与项目绑定，再检查声明、锁文件、制品、浏览器启动、目标服务可达。ready、preparable、unavailable 均有稳定原因码；缺制品和受控网络可用时进入准备任务，准备失败不启动验证。验证任务的状态为 queued、preparing、running、passed、failed、blocked、cancelled、timed_out。环境 blocked 与测试 failed 分开；验收方只将真实浏览器 passed 且所需证据完整的任务计为已验证。

### D4 空间隔离与网络

每个验证任务从授权仓库制作独立工作副本和私有目录；同仓库双空间不共享可写层。运行容器只可访问被授权的预览服务与内部控制端点，CPU、内存、进程、磁盘、时间和并发有限额；准备容器与运行容器网络策略分离。请求不能指定宿主路径、端口、镜像或任意命令。所有结果读取重新校验空间/项目授权；撤权后不能读旧截图。

### D5 证据与观测

受保护结果包含浏览器与版本、环境身份、视口、步骤/断言摘要、截图、computed style 摘要、开始/结束时间和失败类别。保存合成与真实浏览器证据类别，避免混淆。`product_data_collection_observability.status: applicable`；`affected_layers: [api, request_logs, task_traces, task_trace_spans]`；`reason: 验证任务跨 API、制品准备和长时浏览器执行`；`validation: 跨空间身份关联、失败类别、授权读取与脱敏检查`。首期无专属 Web 操作，usage_events 与客户端封装新增采集为 N/A；若后续引入 UI 再重新评估。日志不包含完整命令输出、页面正文、凭证或本机绝对路径。

## 数据与 API

建议引入验证声明、环境制品与任务元数据，使用既有 SQLite/MySQL 兼容迁移模式；截图和详细结果使用平台受保护证据存储，元数据仅保存不透明引用、摘要、保留截止时间。API 至少提供环境预检、创建验证任务、读取状态/证据和取消任务，均以服务端授权绑定而非浏览器提供的路径为准。OpenAPI、Orval、`docs/03-api-index.md`、`docs/04-database-design.md` 与相应测试在实施时同步。制品来源及镜像摘要须可审计，数据库不保存实际依赖树或项目源码。

## 风险与缓解

- 制品投毒或跨项目缓存串用：摘要校验、不可变版本键、只读共享、工作区私有化。
- 浏览器启动依赖漂移：runner 镜像构建与启动均探针；Playwright 与浏览器版本锁定，部署前双架构验证。
- 项目测试命令越权：服务端白名单、独立容器、只读基础挂载、资源和网络限制、拒绝跨空间请求。
- 截图泄漏页面数据：授权读取、短保留期、截图与公开日志分离，不将正文纳入 Task Trace。
- sprint-009 容量缓冲仅 7/30 人天：先交付预检与制品准备，再交付隔离浏览器执行与双项目验收；若真实运行条件不足，不把脚本存在视为完成。

## 部署与回滚

构建固定摘要的验证 runner 与制品准备镜像；部署前离线探针验证 Node、包管理器、Firefox、Chromium 与系统库。先开启内部预检，再允许授权任务；回滚时停止新任务，保留已完成证据和旧制品引用，恢复前一已验证镜像；不删除活跃任务或受保护证据。生产 Compose/环境示例、容量与清理说明同步更新。

## 待实施核对

确认现有仓库绑定与工作副本 API、私有数据目录和对象存储抽象；选择元数据迁移的最小表结构；为 BUG-0030 与第二项目定义合成、安全且可重复的真实浏览器用例。若选择现有 API 或受保护证据层时发现接口不适配，先更新本设计再实施。
