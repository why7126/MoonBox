# Git 远程同步技能设计

## 现状与目标

`/git-check` 可检测 staged 和 tracked 文件，但不负责确定交付范围或执行提交。新技能编排已有检查器与 Git 命令，在每个会改变仓库状态的阶段保留可复核的输入、输出和停止条件。

## 关键决策

1. 默认按本次交付范围选择路径和 hunks。工作区有多条链路时，不能用 `git add .`、`git add -A` 或自动提交既有暂存内容。先展示候选与排除清单，范围不明时采用引导式选项确认。
2. 忽略规则只解决未跟踪文件。已跟踪但不应入库的文件需先明确历史泄漏风险，再通过 `git rm --cached` 移出索引；不删除本地文件，不静默改写历史。
3. 提交前检查 staged 文件清单、diff、`git diff --cached --check` 和 `/git-check`。安全错误阻断；warning 应记录审查结论。提交信息从可验证的交付事实生成，不根据文件名臆造需求或修复结果。
4. 仅当 `releases/vX.Y.Z/release.json` 等正式发布证据和发布门禁确认版本时，在目标提交上创建缺失的 `vX.Y.Z` tag；既有同名 tag 指向其他提交时阻断，不移动或覆盖。
5. 推送前 fetch 并检查与上游的拓扑。非快进时先区分远端新增提交与本地提交，再按项目 Git 策略整合和重验；冲突不能安全判定时保留冲突状态并请求具体决策。禁止 force push、自动覆盖远端 tag 和未经证实的冲突解决。

## 风险与处理

- 多条交付链路混合：默认拆分或明确选择一次提交的范围。
- 敏感数据已进入历史：停止推送并给出历史清理和凭证轮换建议，不以 `.gitignore` 伪装为修复。
- 推送后标签与提交不一致：先推分支并确认远端提交，再推指定 tag，最后核验远端引用；失败时报告精确状态，不盲目重试。
