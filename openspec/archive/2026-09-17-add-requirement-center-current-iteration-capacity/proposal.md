## 背景与动机

需求中心已经是 REQ、BUG、Change 和 Sprint 状态的主入口，但当前用户只能看到对象数量与阶段分布，无法直接判断当前迭代容量是否接近或超过规划容量。REQ-0031 已明确提出“当前迭代容量（2个当前迭代），已使用容量/总容量”，需要把 Sprint 容量压力前置到需求中心。

## 变更内容

- 在需求中心上下文聚合中新增当前迭代容量摘要，包含 Sprint ID、已使用容量、总容量、容量单位、容量来源、容量状态和安全提示。
- 在前台需求中心统计/筛选附近展示当前迭代容量，支持 1 个或 2 个当前迭代并存。
- 容量计算以 Sprint Scope、`scope_estimates[]` 和 `capacity_person_days` 为事实源，不用卡片数量或前端临时状态推断。
- 增加容量异常降级：默认容量提示、接近上限、已超量、待核实、刷新失败保留旧数据和权限过滤。
- 同步 Web 行为事件、请求日志、OpenAPI/客户端类型、后端/前端测试和 1440px UI 验收要求。
- 不新增 Sprint 容量编辑、自动排期、资源预测、DB 表、对象存储、部署拓扑或后台异步任务。

## 能力影响

### 新增能力

无。

### 修改能力

- `web-catalog-requirement-center-real-data`: 扩展需求中心上下文聚合，返回当前迭代容量摘要并保证权限、事实源和观测边界。
- `web-catalog-requirement-center`: 扩展前台需求中心页面，在现有统计/筛选区域展示当前迭代容量和状态。

## 影响范围

- 后端：需求中心上下文聚合服务、Sprint scope 与容量字段读取、权限过滤、错误脱敏和请求日志摘要。
- Web：需求中心统计区域、刷新失败保留、容量状态样式、深浅主题、窄屏布局和测试 fixture。
- API / 客户端：如新增字段，需要同步 OpenAPI 来源、Orval 客户端类型和 API 文档。
- 观测：复用 `usage_events` 与 `request_logs`；普通查询聚合不新增 Task Trace，除非后续实现改为批量或异步任务。
- 测试：后端聚合与权限测试、前端状态组合测试、TypeScript 校验、1440px/窄屏视觉验收。
