# REQ-0050 第八轮隔离产品逐项补证

本轮使用当前源码及重新构建的 Web 页面、一次性 SQLite 产品服务和独立的临时对象存储。所有对象、账号和图片均为无敏感内容的隔离样本。浏览器请求未拦截，正式项目未写入。`product-guards/` 的文件变更仅用于制造隔离反例，检查后恢复原样。

| 范围 | 实际观察 | 证据 |
|---|---|---|
| 规则冲突与只读权限 | 当前对象存在历史同条文修改时返回差异；改为无同条文修改且验收另有阻断时，真实 REQ 页面不出现“查看修改”，独立 Change 差异 API 返回 404。查看者能阅读差异但准备归档返回 403，未登录返回 401。旧确认入口返回 409；确认记录、事件和归档轮次均未增加。 | `product-api/access-and-retired-decision.json`、`no-conflict/`、`product-guards/no-write.json` |
| 发送前安全反例 | 当前冲突、删除原场景、预检后修改交付内容均在发送前 409；这些结果分别受到当前冲突或验收指纹变化影响。历史文件篡改样本也返回 409，但与既有冲突共存，不能据此单独签认历史篡改的归因。 | `product-guards/result.json` |
| 审阅抽屉与视觉 | 修正旧内容残留后，1440×900 和 390×844 深浅主题均无横向溢出；长文、无匹配和浏览器断网时分别展示可滚动内容、明确空态和连接错误，失败时不继续显示旧规则。 | `real-review/`、`states/` |
| 附件与草稿 | 无敏感测试图片确实上传到隔离对象存储，内容哈希与本地测试图片一致。归档被拒、打开和关闭审阅抽屉后，草稿与附件仍在，焦点返回入口；只读数据库确认没有创建 Chat 轮次。 | `attachment/` |
| 直接归档尝试 | 对独立 Change 调用产品共同归档入口一次，返回 409，活动目录仍在，规格未合并。诊断指向隔离服务运行于可写源码，缺受信任的只读归档工具；不能将此尝试记为成功归档。 | `direct-archive/result.json` |
| 只读控制器复核 | 以独立容器、只读根文件系统和只读工具目录连接同一隔离样本，再调用产品共同归档入口一次；仍返回 409，未产生归档操作行、目录迁移或规格合并。API 不公开更细原因，本轮没有再次执行。 | `direct-archive-trusted/result.json` |

据此，AC-L01、AC-L03、AC-L09 与 AC-L10 的本版完整样本已签认；其他项保持部分样本。AC-L03 仅证明无需额外人员确认且原权限仍生效，直接归档尝试没有成功，成功与并发仍由 AC-L07 单独验收。尤其没有同轮成功的真实产品归档、完整跨入口并发、独立归因的历史篡改，以及实际旧版进行中操作的恢复。不能将发送前拒绝、模拟执行器完成或已有 BUG-0063 归档代替这些场景。
