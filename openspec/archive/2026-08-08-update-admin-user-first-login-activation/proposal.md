## 背景与动机

后台用户管理已支持创建、冻结和解冻，但当前“待激活”用户必须被管理员解冻为“正常”后才能登录，导致“解冻”被误用为“激活”。同时，待激活用户被冻结再解冻后若直接变为正常，会绕过用户本人首次登录激活流程。

## 变更内容

- 允许“待激活”的后台管理员使用有效临时密码完成首次登录，并在登录成功后自动转为“正常”。
- 冻结用户时记录冻结前状态，至少覆盖“待激活”和“正常”。
- 解冻用户时恢复冻结前状态；待激活用户被冻结后解冻仍为“待激活”，正常用户被冻结后解冻恢复“正常”。
- 已冻结、已删除、非后台管理员用户不得通过首次登录激活进入管理后台。
- 用户管理列表、状态筛选、解冻确认弹窗、临时密码说明、审计记录、API、数据库和测试同步体现新的状态语义。
- 原型作为设计输入，后续实现必须完成 UI Skeleton、1440px 视觉验收和 REQ 最终一致性回填。

## 能力范围

### 新增能力

- 无。

### 修改能力

- `web-admin-user-management`: 修订用户状态治理、创建用户临时密码说明、列表状态展示、解冻确认弹窗和审计追溯规则。
- `web-admin-auth-system`: 修订后台登录认证规则，允许待激活后台管理员首次登录自动激活，并保持冻结/删除/前台用户访问边界。

## 影响范围

- Backend：用户创建默认状态、登录认证状态流转、冻结/解冻服务、会话失效、审计记录。
- Web Admin：用户列表状态标签、状态筛选、冻结/解冻行内操作、解冻确认弹窗、fixed toast、临时密码说明。
- Database：新增或等价支持冻结前状态持久化字段，例如 `status_before_freeze`。
- API：用户列表/详情响应、冻结/解冻接口、后台登录接口、OpenAPI 与错误语义。
- Security：登录失败与审计不得泄露密码、token、冻结前状态内部字段或账号枚举信息。
- Tests：后端 pytest、前端 Vitest/Testing Library、1440px 视觉或浏览器验收。
