# 跨入口后继证明与安全恢复设计

## 背景与现状

旧原执行只有9/12及opsx.progress，最终sync_incomplete。CLI补齐后12/12 ready，19项治理投影累计变化包括6个文档和13份摘要；不代表全仓只有19处变化。reconcile_external保留needs_review直接返回，recover有清单路径要求完全相等；reader用旧阶段覆盖。历史基线只有启动正文与同步哈希，无法完整恢复同步时正文。证据详见BUG根因文档。

## 目标与边界

面向所有受支持直接治理命令，建立后继交付关系和可解释安全恢复，不按BUG-0055特判。保留专用review/archive协议、权限、绑定、唯一性、容量、真实冲突和验收有效性门禁。不扩大模型调用授权，不重放旧命令或重写原轮成功。此 Change 已进入实施，未完成部署验收。

## 证明与同步采集

以版本化结构化结果表达event、对象、Change、scope/binding、执行/校验模式、同步成功及输出版本；由实际标准同步结果产生证明，命令文本只提供定位线索。严格区分start/progress与完成，内部错误不能被后续shell成功覆盖。解析分号、换行、引号、等号参数、复合shell及引用文本；不能确定时保留缺证，不猜成功。旧schema按原语义读取，禁止把历史dry-run记录升级成真实成功。

## 后继核验数据与流程

推荐复用现有私有证明存储新增版本化后继记录，不覆写原steps；记录原操作/保护版本、后继交付身份与事件、核验时间、分类后的输入/输出摘要、证据引用和结果。是否新增DB索引由实现前访问模式评估决定；若需要迁移先同步设计/数据库文档并验证SQLite与MySQL，禁止临时裸改生产表。

1. 授权并读取原操作、当前guard和对象/Change唯一身份，确认原执行已终止且无新执行占用。
2. 读取CLI后继的正式完成事实及当前交付证据，不能仅依赖trace标签、任务全勾选或ready；核对代码/交付输入、逐AC证据与当前动作契约。
3. 区分派生输出、合法后继交付、无关并发、相关冲突和历史缺证。派生输出核验归属及指纹；设计/任务变化触发受影响验证；共享全局约束仍验证。历史partial保持原标签。
4. 生成独立可追溯证明，复读指纹/绑定/权限，以原guard版本及operation条件原子确认；新执行或相关变化获胜时拒绝旧核验。
5. 后继核验记录幂等，失败不部分放行；中断后重读并续接核验，不重放业务命令。原执行状态与后继核验结论分开。
6. 产品和CLI调用相同当前准入判定；产品实际发送再次校验版本/快照。归档仍通过标准脚本和专用恢复日志完成。

## 展示与接口

响应区分历史执行结果、当前交付阶段、当前动作准入、核验时间、差异类别与恢复能力；卡片不把旧阶段当当前交付。缺证、真实冲突、运行中、权限/绑定变化、版本被替代分别返回可定位原因，沿现有错误码目录分配不杜撰冲突编号。核验入口无权时不展示可执行能力，服务端再次授权。

沿用卡片状态详情及运行状态入口，实施前建立selector/action映射和状态矩阵；具体动作族为查看执行、查看差异、受控核验、归档发送及其现有确认交互。1440×900与390×844验证成功、冲突、核验中/失效、刷新后状态及computed style；如新增modal先补完整动作矩阵。接口/OpenAPI及生成客户端同步，禁止只改展示放开按钮。

## 验证编排与现场

先验证环境、同步辅助依赖、数据身份、授权、部署版本、产品登录及验收入口；稳定修改后集中验证，按指纹增量复验，正常样本串行，竞争样本显式注入。首次成功、失败拒绝、历史恢复、合成与真实观察分别取证。

隔离REQ/BUG样本验证产品受阻→CLI续接→产品核验→实际发送归档→业务终态；等价CLI对象进行同输入准入对照。测试中核验标准归档目录、Issue阶段、规格合并次数与刷新状态，不仅HTTP入队或按钮可点。

BUG-0055保留sprint-011；部署后读最新状态与旧记录完整性，按新协议恢复并核验实际动作/归档终态。若现场已被合法推进则验证幂等终态，不按旧快照回滚。实际正式归档遵守届时有效授权；无授权不把隔离成功冒充正式恢复完成。

## 风险与取舍

忽略所有Markdown或清空guard会放过真实冲突，拒绝采用。仅重复原证明校验无法承接合法后继。后继证明增加记录与竞争复杂度，以不可变历史、原子版本、幂等键和拒绝默认控制。历史行级归因不能补造，机制验证和历史归因分开报告。

## 部署与回滚

后端、worker、治理控制器及Web版本一致后执行全链路。新schema向后可读，未知版本安全拒绝。回滚代码保留记录和业务状态，部分归档只走专用恢复，不能重复合并或直接恢复数据库快照。

## 实施契约补充（2026-10-21）

后继恢复当前支持 `opsx-apply`、`opsx-modify`。其他直接命令继续使用已有精确完成证明；评审和归档仍走专用恢复，不自动套用交付验收。原 steps 不改写，`final_verification.successor` schema v1 保存原操作/保护版本、当前验收 run 与逐文件差异；历史归因为 partial。没有新增数据库表或字段，沿用 guard 条件更新和私有 journal 原子写入。

| 动作 | 有效完成事件 | 后继证据 | 拒绝条件 |
| --- | --- | --- | --- |
| req/bug 文档命令、Sprint、转 Change | 同名点分事件 | 原精确证明 | start/progress、探测模式、对象不符 |
| opsx-apply / opsx-modify | 对应完成事件或 opsx.accept | 标准 opsx.accept 收据、有效计划与逐 AC 指纹、同任务范围 | 缺证、真实输入冲突、未覆盖变化、过期权限/版本 |
| review / archive | 专用协议 | 原有专用恢复证明 | 通用核验不得旁路 |

标准同步追加 `MOONBOX_WORKFLOW_RESULT` JSON 行。外层 shell 退出 0 不代替该行的 write/ok/对象条件；带 dry-run/check 的复合命令保守视为探测。CLI 正式 opsx.accept 写入 Change `.workflow-receipts/` 的不可覆盖 JSON 收据，绑定计划和完整报告哈希。新失败报告不复用旧成功收据。读取不执行仓库脚本，仍独立验证当前验收指纹；收据本身不授予权限。

后继合法变化必须被当前计划完整输入或已核验 artifact 覆盖；trace/tasks 仅接受当前完成事实和原任务文本范围，摘要仅接受当前验收 run。无关对象变化由对象投影排除，共享规则/正式规格/本对象 Sprint 语义变化继续拒绝。发送阶段继续使用既有当前准入和快照围栏。

| 入口/动作 | selector | 状态与证据计划 |
| --- | --- | --- |
| 卡片状态详情 → 查看执行 | 现有卡片 summary、查看执行按钮 | 当前阶段保留；保护独立禁用动作；1440/390 与刷新 |
| 运行详情 → 核验当前成果 | direct-completion-detail / direct-completion-verify | 可核验、核验中、成功、差异冲突；核验接口回归和产品截图 |
| 归档发送 | Chat 输入框与发送按钮 | 完整 prepare→send→终态；不以按钮 enabled 代替验收 |

没有新增 modal、API 字段或端点；错误原因沿现有字符串 reason_code 传递，OpenAPI/生成客户端结构无需改变。样式沿用组件，仅新增具体原因文案。证据区分接口合成、隔离真实模型、正式历史恢复和 CLI。

重复验收会追加旧 run/checkpoint 摘要。实现将新增摘要按对应 manifest 的 schema、Change、run 身份和 AC 集合核对归属；旧失败摘要不成为当前验收权威，当前 ready 仍独立验证。已存在历史摘要不允许因“派生输出”而任意改写。该规则避免合法重复前检使后继证明再次自失效。
