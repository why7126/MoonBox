# 需求中心完成门禁与会话连续性修复提案

## 背景

来源 [BUG-0044-requirement-stage-premature-transition-session-split](../../../issues/bugs/review/BUG-0044-requirement-stage-premature-transition-session-split/bug.md)，已评审并纳入 sprint-010，严重度 high，估算 XL／8 人天。历史证据显示前轮尚未结束，文档先变更使下一动作开放，忙碌会话被排除后新建会话，导致同对象治理轮次重叠。根因确认限已记录案例与共用机制，不代表全入口已真实验收。

## 变更内容

- 统一完成型阶段迁移、动作准入与业务验证结果；启动开发/返修及时显示研发中。
- 后端以项目和规范化主对象为键控制治理发送互斥，覆盖双标签页、跨会话及直接 API。
- 忙碌时查看可访问的原执行，空闲后续用原会话，保留草稿；失败或未知状态先核验已有成果。
- 明确外部 CLI 收敛、权限隔离、只读入口与未接入命令边界，建立逐入口和逐 AC 的证据矩阵。

## 能力影响

### 新增能力

无独立新能力。

### 修改能力

- `web-catalog-requirement-center-real-data`：修订九阶段投影与完成门禁，增加执行期间只读保障。
- `web-catalog-chat-workbench`：修订对象会话复用及忙碌、归档和删除分支。
- `local-project-governance-loop`：修订未处理成果策略，增加对象执行互斥、完成核验和恢复契约。

## 影响范围

涉及 requirement_center 阶段聚合、governance preparation、Chat 发送与 worker 终态、Web 需求中心和 Agent 助手。实施需同步 API/OpenAPI/生成客户端、SQLite/MySQL 持久状态、权限与 UI 契约及测试。管理后台、对象存储、部署拓扑不变；不修改“部分输出”文案，不包含 BUG-0028 修复，不合并或删除历史会话。

## 回滚方案

部署前保留治理文件及执行记录；暂停新的治理发送，核对运行中/待核验记录后回退应用版本。新增持久表采用增量迁移并保留数据，不通过删表、清空活动轮次或回滚有效治理成果恢复服务。旧版本无法理解未决记录时继续限制写入并人工核验，不直接恢复并发放行。本轮仅生成文档，不执行部署或回滚。
