# 需求中心完成门禁与会话连续性修复设计

## 背景与现状

根因证据见 [root-cause.md](../../../issues/bugs/review/BUG-0044-requirement-stage-premature-transition-session-split/root-cause.md) 的 E1—E6。阶段读取 `_issue_status` / `_map_stage` 与会话 `_latest_object_conversation` 分离；后者过滤 active_turn_id，worker 终态才清除该字段。历史新会话创建早于前轮结束6秒。已有测试明确期望跳过活动会话，需要改变策略及回归断言。

## 目标与边界

统一完成门禁、对象互斥、可访问会话续用和可恢复执行事实。治理文件仍是成果事实源，执行记录决定这些成果何时成为可操作阶段。独立 CLI 不依赖产品 Chat，但不承诺互斥未接入产品的外部进程。只读浏览不获取写入锁。BUG 来源含父需求 prototype：实施前只读取相关卡片/动作片段，建立增量 UI Contract 和 Skeleton 首轮确认，不重新设计整页。

## 修复方案

### 持久执行事实与原子发送

新增项目对象执行守卫记录，唯一键为授权项目身份（space_id、repository_id）与规范化对象类型/完整ID，保存 version、operation_id、turn_id、执行状态、执行前已确认阶段、候选成果指纹、验证结果与时间。守卫为业务准入事实，不依赖可降级的观测日志。通过条件更新或唯一约束原子抢占，事务内绑定轮次并持久化待调度状态，提交后执行；调度失败保留可核验失败状态。SQLite/MySQL 同时覆盖唯一性、事务竞争、迁移及恢复。

准备会话不长期占用写锁，真正发送前再次验证对象权限、绑定版本、动作可用性并抢占。幂等键按用户、项目、对象、动作及请求内容摘要隔离；同键同内容重放原结果，同键异内容受控拒绝。不同动作竞争同一对象守卫。旧回调必须匹配 operation_id/version，不能释放新轮次。Worker 心跳或租约只用于诊断失联，超时本身不授权重发；未知执行进入待核验，恢复确认旧执行结束后才释放。

### 阶段与完成契约

| 事件 | 投影与准入 |
|---|---|
| 准备完成、尚未发送 | 保持阶段，展示建议命令；不自动发送 |
| 一般治理执行中 | 保留执行前已确认阶段，显示执行中并阻止后续写动作 |
| 开发/返修实际启动 | 及时显示研发中，保留首次 apply completed_at |
| 轮次成功、业务校验与同步都通过 | 基于同一成果指纹提交已确认阶段，并开放允许的后续动作 |
| 成功但校验/同步失败 | 保留未确认阶段，进入结果待核对 |
| 失败、停止、未知、重启 | 保留成果与执行记录，核验执行终态及成果后决定恢复 |

完成验证不得采信助手自然语言。按命令校验预期成果、Issue/Change/Sprint 引用、相关文档门禁及 Workflow Sync 结果，绑定本轮输入和成果指纹；校验期间文件变化则重新核验。默认成功必须同时满足终态成功、业务验证和同步通过。失败但已有有效成果可经独立恢复核验形成 recovered_valid 结果，保留原 failed/stopped 事实，不伪造成成功轮次。仅文件存在或 tasks 全勾选不足以放行。

没有关联产品执行的外部文件更新，经同等级治理验证后收敛；同对象存在未决产品执行时先核验冲突，不能借外部同步绕过守卫。存量无执行记录的合法对象通过一次可信验证初始化，不推造历史启动/完成时间。

### 会话与权限选择

优先返回本人同项目同主对象正在执行的可访问会话，状态为 busy，可查看但不可再发治理命令；其他用户占用时仅返回对象忙碌摘要，不返回会话 ID、标题或内容。空闲后沿用原会话；多历史会话继续按 turn、消息、updated_at、稳定创建事实排序。归档/删除会话不复用，但其未决执行仍阻止新写入；明确不可用原因、核验终态后才允许创建。

原会话存在未处理隔离成果时返回 needs_review，保留成果和草稿，不静默换会话；处理或验证该成果后刷新基准，只有明确选择另建且无执行冲突才创建兼容会话。对象别名必须解析到唯一规范身份，不能按标题互斥。Change 来源 Issue 能确定时绑定同一主对象；多来源 Change 按规范顺序获取相关对象守卫，避免绕过与死锁。

### API 与界面

对象准备响应保留兼容字段，增加 execution_state、can_send、reason_code 及授权后可用的查看执行目标；忙碌查询正常返回受控状态，实际重复发送返回文档化409，权限失败沿用403/不可见策略。客户端不根据 reused_conversation 猜测可发送状态。API 字段与错误码在实施时同步项目规范、OpenAPI 和生成客户端。

需求中心与 Agent 助手共用状态组件：执行中、结果待核对、成功可继续；查看执行跳转已有会话，不弹出自动发送。草稿按用户/项目/对象隔离保存，切换与刷新后不串用。动作和 modal 组件按动作族统一处理；只读文档、进度、验收详情继续可用。实施前建立 selector、按钮→modal→状态→证据矩阵，新增视觉结构先确认 Skeleton。

### 入口适用矩阵

REQ/BUG 的分析、生成、完善、评审、迭代、Opsx、开发、归档分别列为独立真实验收行，并覆盖卡片及助手入口。已接入的只读分析仍关联当前对象，但不获得写入权限；若分析命令会写文件则采用治理写入门禁。直接 Chat 的已识别治理命令走相同发送守卫；无法识别主对象或未接入的命令明确拒绝自动治理写入，不宣称自由文本任意工具调用已被对象锁覆盖。只读按钮单独验证，未接入入口记 N/A 并说明原因，不能冒充通过。

## 测试策略

按 acceptance.md 的 AC-001—AC-012 映射实施任务及证据。先串行运行对象并发/恢复测试，再运行独立前后端回归。隔离样本受控延迟复现文件先写、轮次慢收尾；不在 BUG-0028 重跑治理写入。1440px 覆盖执行中、完成可继续、失败/未知与查看执行，保留 selector/computed style；合成 API/并发测试与真实产品轮次分开。未取得权限或环境时记录具体缺口，不外推验收通过。

## 数据采集与链路观测

```yaml
product_data_collection_observability:
  status: applicable
  affected_layers: [usage_events, request_logs, task_traces, task_trace_spans]
  reason: 对象准备、治理发送、核验和阶段生效跨越界面、API及异步任务
  validation: 已验证行为关联、可信request_id、对象与轮次关联、复用/忙碌/拒绝原因、恢复节点、脱敏和日志降级；直接API允许无行为事件，证据见evidence/acceptance/signoff.md
```

沿用观测保留周期：请求及任务明细90天、行为180天；不改变既有观测表schema。新增业务守卫不能随观测日志清理：未决记录保留至核验完成，终态守卫保留最新已确认投影与必要指纹，旧操作诊断按既有策略清理。日志禁存原始 Prompt、凭证、个人信息及文件正文，客户端链路ID不作授权依据。OpenAPI/Orval、Web透传与DB迁移适用；对象存储、管理后台和部署拓扑 N/A，因本修复不改这些入口和组件。

## 风险与回滚方案

双进程竞争、发送后崩溃及陈旧回调通过持久守卫与版本围栏控制；恢复保守可能暂时阻塞对象，提供查看与受控核验，不自动重复执行。先兼容部署新增表和读取器，再接入发送与投影；回滚先停止新写入并排空/核验未决记录，保留新增表及有效成果，详见 proposal。UI 原型确认和运行环境为实施门禁，当前文档就绪不代表这些门禁已通过。
