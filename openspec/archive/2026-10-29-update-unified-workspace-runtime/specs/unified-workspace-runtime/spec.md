# 统一主源码目录与交付链路工作区及模块化执行架构增量规格

## ADDED Requirements

### Requirement: 仓库与唯一主工作区

系统 SHALL 满足以下约束：每仓库登记一个完整主源码目录并建立主工作区身份，目录包括 .git、src 及治理资料。空间管理权限、仓库管理 Git 身份与主线、工作区管理执行目录。首期同一实际仓库不重复绑定多个空间，路径别名、已有 linked worktree 和同仓库元数据需归一识别；远程 URL 相同不单独证明本地实例相同。前端只传业务标识，后端解析目录。

#### Scenario: 仓库与唯一主工作区的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 同一实际仓库以原路径、符号路径别名或其 linked worktree 重复登记，均解析到同一仓库身份并拒绝重复主目录；远程 URL 相同的不同本地实例不误合并。

### Requirement: 交付链路唯一活动开发工作树

系统 SHALL 满足以下约束：REQ/BUG 及其关联子 Change 归一到同一交付链路，最多一个活动开发 worktree，子 Change 串行复用。无 Issue 来源的独立 Change 以自身为链路。并发创建通过唯一约束和幂等操作返回同一结果；开发、检查和返修复用，不因消息、会话、重试新建目录。普通讨论不创建。临时集成/恢复工作树另记用途，不提供绕过上限的开发入口。

#### Scenario: 交付链路唯一活动开发工作树的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 同一 REQ 的两个子 Change 并发申请，仅创建一个活动开发树；第二个 Change 排队，验收返修仍使用原树；另一 REQ 可获独立树。

### Requirement: 基线与创建流程

系统 SHALL 满足以下约束：默认选择主工作区；隔离或并行任务按需显式选择独立工作树。创建前校验既有评审、Sprint、Change 和对象授权门禁，解析任务所需的确定提交。主目录未提交治理修改与 Git 提交版本分别展示；必要资料未进入基线则阻断并说明缺口，不静默丢弃、不顺带提交无关修改。使用真正 Git worktree，不用导出后重新初始化的仓库冒充。记录起始提交和专属分支/检出位置。

#### Scenario: 基线与创建流程的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 主目录有未提交的任务必要治理材料时创建被阻断，显示缺失材料且不自动提交；材料进入指定提交后创建真实 Git worktree，记录正确基线且不带无关脏文件。

### Requirement: 会话与轮次绑定

系统 SHALL 满足以下约束：一个会话绑定一个工作区，多会话可共享；执行轮次固定仓库、工作区、交付链路和输入版本。活动轮次期间不切换目录；历史会话恢复时校验真实目录、仓库身份和权限，缺失或不匹配时显式阻断，不回退到主目录。跨工作区续接使用可追溯的新会话/操作，不把旧执行历史改写成新目录事实。

#### Scenario: 会话与轮次绑定的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 同工作区两会话历史均指向原身份；活动轮次切换被拒绝；删除或替换底层目录后恢复失败且不回落主目录。

### Requirement: 统一执行与分层互斥

系统 SHALL 满足以下约束：主目录与 worktree 共用 moonbox-core 和执行适配。对象级保护防止重复推进，工作区级只允许一个写任务，不同链路按可用资源并行；公共治理、共享 Git 管理与主线集成统一协调。外部编辑不可假定受锁约束，采集与写入前复核版本。不能通过移除旧锁直接宣称支持并行。

#### Scenario: 统一执行与分层互斥的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 同一工作区两个写任务只能一个执行；不同链路可按容量并行；外部编辑后旧版本写入被拒绝或重新预检，公共治理更新串行且不会丢失。

### Requirement: 治理事实和写入分工

系统 SHALL 满足以下约束：主目录负责 Issue 编号、评审、Sprint 纳入、Change 创建、公共注册表/Sprint 汇总以及正式归档；任务工作树修改对应实现、测试、任务记录、相关文档与验收材料。任务范围内命令需通过统一执行上下文遵守该分工，不能因原脚本默认写注册表而修改不属任务的共享事实。正式规格仅在归档合并生效。

#### Scenario: 治理事实和写入分工的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 任务树可修改本 Change 任务和实现；直接重写公共注册表、Sprint 汇总及已生效规格被拒绝；主线受控流程可更新对应正式事实。

### Requirement: 看板与版本投影

系统 SHALL 满足以下约束：主看板从指定主目录读取完整一致治理快照，再叠加数据库运行信息。分别显示治理阶段、执行状态、集成状态；工作树完成不自动变成正式交付。工作区详情展示其基准与局部状态，读取失败保留最近完整版本并标明未更新。任务与证据按工作区归属，不能混用其他分支结果。

#### Scenario: 看板与版本投影的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 任务树完成而尚未合入时主看板不显示正式交付；主目录治理读取失败保留上次完整快照并显示未更新；其他工作区证据不能混用。

### Requirement: 模块命名与依赖边界

系统 SHALL 满足以下约束：模块统一采用 moonbox- 前缀，见模块表。moonbox-ui/moonbox-exec 经受控接口进入 moonbox-core；核心协调执行、工作树及历史组件；存储和 Git 操作不从 Web 直接调用。保留既有认证、业务规则与对外兼容契约。以模块边界和复用验证验收，不以移动目录数量作为完成依据。

#### Scenario: 模块命名与依赖边界的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** Web 与非交互入口对同一身份和输入执行相同鉴权与核心策略；依赖检查证明 Git/内容存储通过受控接口访问；所有模块名使用 moonbox-，无 TUI 交付要求。

### Requirement: 运行版本和资源隔离

系统 SHALL 满足以下约束：执行记录固定实际镜像不可变标识和工具链版本；新版本对新任务生效，活动轮次不静默换环境，恢复需验证兼容。升级失败可回到已知可用版本且保留原记录，不冒充旧轮次运行于新版本。空间运行状态、凭证、缓存授权以及工作区文件分离；不同测试环境分别分配数据库、端口、网络和容器，复用 REQ-0048 编排接口。

#### Scenario: 运行版本和资源隔离的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 启动时保存镜像 digest 和工具版本；更新默认镜像不改变活动轮次；不兼容恢复拒绝；两个空间的凭证、缓存、端口、数据库和容器资源不交叉。

### Requirement: Git 共享数据与沙箱

系统 SHALL 满足以下约束：worktree 不是安全隔离。可信管理组件处理创建、分支/共享元数据管理、集成和移除；执行器仅获适用的目录及 Git 能力，不为 .git 指针可达性开放整个主目录、所有工作树或凭证。路径越界、链接、权限撤销与非法绑定均失败关闭。

#### Scenario: Git 共享数据与沙箱的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 构造越界链接、伪造 .git 指针、跨空间工作区标识与非法绑定，读取/执行均拒绝；正常 Git 工作树操作可通过受控管理接口完成。

### Requirement: 生命周期、清理与诊断

系统 SHALL 满足以下约束：区分准备中、可用、准备失败、清理中、已移除等生命周期，使用占用和执行记录表达忙闲而非混为任务成功。创建/清理中断可核对并续接。主目录不可普通删除；活动任务、未提交/未合入成果、恢复依赖未处理不得删除工作树。诊断展示安全标识、失败阶段、镜像版本和可执行下一步，不暴露私有路径或密钥。

#### Scenario: 生命周期、清理与诊断的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** 模拟创建/移除中断，重复请求核对现场后续接；主目录、正在写入、存在未提交/未合入成果或恢复引用的目录不得普通删除；错误提示不泄漏路径。

### Requirement: 兼容迁移与关联交付

系统 SHALL 满足以下约束：先登记现有 source 为主工作区并迁移会话/基线关系，再开放新 worktree。旧 copy 标记为历史副本，保留会话、差异、未应用成果和恢复入口，不能只改类型；迁移按版本标识、清单校验及可重入操作进行，失败保留旧数据。新建 copy 退出但旧成果未核对前不删除。主目录路径可单独验收，独立工作树正式开放需与 REQ-0054/0055 的保护和交付门禁集成。

#### Scenario: 兼容迁移与关联交付的执行与边界

- **WHEN** 对应业务操作在正常、冲突或权限变化条件下触发
- **THEN** source 登记后旧会话和轮次可追溯；copy 标为历史副本并保留未应用成果；迁移中断重试不重复登记、不丢正文；0042/0054/0055 集成门禁未齐时不开放独立树正式交付。

### Requirement: 原型与真实验收证据

系统 SHALL 将原型作为设计输入，最终交付以设计、验收清单、1440px及关键交互视觉证据、computed style、Mock/API边界和REQ最终一致性共同判断。

#### Scenario: 静态原型不能代表实现完成

- **WHEN** 只有原型或合成接口测试通过
- **THEN** 真实视觉、权限及运行AC保持未验收，不能标记整体交付完成
