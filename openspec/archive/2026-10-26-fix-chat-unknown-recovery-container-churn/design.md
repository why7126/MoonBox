# Chat 未知轮次有界恢复设计

## 背景与现状

证据 E1—E8 见 BUG root-cause.md：空闲循环扫描所有 unknown，reconcile_unknown 返回 False 后没有更新调度状态，容器工厂每次执行预检及读取。全文部署指纹不同，关键函数已核对；不能把旧轮次视为已完成。方案仅修复重复创建机制。

## 修复方案

### 持久化状态与预算

建立以 turn_id 唯一关联的恢复记录，包含 state（waiting、leased、paused、resolved）、attempt_count、first_attempt_at、next_retry_at、last_result、lease_token、lease_expires_at、generation、resume_request_id 和时间戳。使用 UTC 数据库时间，建立 state/next_retry_at 索引；历史 unknown 惰性登记，首次领取开始预算，不篡改业务状态和历史时间。

默认每代最多6次，首次可立即执行，失败后依次等待30、60、120、240、300秒；等待附加0—10%正向抖动，总等待上限330秒。每代从首次领取起最长30分钟，次数或时长先到即暂停。非法、零或无限参数启动时拒绝；可配置范围次数1—10、基础等待10—60秒、等待上限60—300秒（不含抖动）、总预算5—60分钟。到期扫描只更新暂停，不创建容器。无变化记录也消耗一次检查预算，不能无限跳过预算。

### 原子领取与公平调度

先领取正常任务，再处理至多1条到期恢复；恢复在独立有界执行槽中运行，主调度不等待 Docker。默认恢复槽1个，单次包含预检与读取最长60秒，租约120秒（含超时后的进程及容器清理余量），所有子进程超时强制关闭并确认回收。租约到期不返还已消费次数，重启不重置预算。条件更新同时校验 generation、state、到期时间与租约；提交权威终态前再次校验 token 和原 active_turn/executor 身份，旧持有者不能覆盖新结果。失租后取消读取并回收其容器；新持有者须确认同 turn 旧恢复容器已退出才启动，无法确认则暂停并报告，避免物理双实例。

使用 next_retry_at、turn_id 稳定排序避免偏爱同一轮次。正常任务在资源可用的隔离调度测试中5秒内被领取；恢复持续排队不阻塞正常任务，正常任务持续繁忙时允许恢复延后但仍执行预算过期判定。

### 结果分类与状态真实性

读取仍只查询原 thread/turn，禁止重发提示词。completed/failed/interrupted 才走既有终态映射、事件和账务收敛；no_terminal、record_missing、rpc_rejected、timeout、workspace_identity、security_rejected、internal_error 分开记录。安全或身份拒绝立即暂停，其他非终态按预算退避；未知异常也落调度结果，不能裸异常绕开预算。恢复 paused 不清除 active_turn、不释放写入保护、不生成业务完成证据。

### 无变化检查和预检缓存

记录执行日志的非敏感身份指纹；本地日志与执行状态库元数据、预检身份指纹同时无变化时最多跳过相邻一次昂贵读取，下一次强制权威读取，避免日志与状态库更新时序造成永久漏读，但仍消耗检查预算并退避；指纹不可取得时按有界读取处理，不因缺少指纹永远跳过。每次恢复都核验可信工作区和授权快照。

只缓存成功的工具链/沙箱预检，进程内缓存有效期5分钟；键包含解析后的镜像内容ID、策略版本、工作区规范路径及目录身份的摘要、挂载/网络/只读配置、认证配置版本摘要。可变镜像标签每次解析，无法确认身份则不命中。认证文件刷新在缓存之外执行；凭据变化立即失效，秘密不进入日志。工作区替换、权限撤销、策略变化、到期或预检失败均失效；缓存不替代每次实际执行的沙箱限制、工作区和权限检查。仅隔离读取恢复使用此优化，普通业务执行保留现有保障。

### 暂停续接

初版提供后端运维命令，默认只读展示；修改操作要求明确 turn、预期 generation、唯一 request_id、原因与操作者审计身份。复用部署运维权限，只有已授权主机操作者能执行，不对 Web 用户新增接口。续接只对 paused、原身份仍匹配且无有效租约的记录创建下一代预算，旧代不可变摘要保留；同 request_id 幂等，不同请求需匹配当前代。定时扫描、浏览器轮询和 worker 重启均无权重置预算。本版不自动因新证据开新代，新证据由操作者核对后显式续接。

### 数据库与迁移

增量建表和索引，不回写历史业务终态；遵循现有迁移版本管理。SQLite 用条件更新实现竞争检测，MySQL 同样条件更新并检查影响行数，不依赖 SQLite 专有 SQL。事务不跨 Docker 调用。失租旧任务在清理前也验证围栏；最后一次尝试中断且预算耗尽时只领取清理任务，不创建新读取容器。已授权历史删除及备份删除重放同步移除恢复账本，兼容没有新表的旧备份。唯一 turn_id、时间/空值、CAS、租约和幂等键在两库验证；generation 历史摘要可独立记录，避免泄露正文。同步 docs/04-database-design.md 和 compatibility/database/；上线前 MySQL drift/smoke、备份与回滚复核。

- reason: 后台恢复需关联尝试、暂停原因、耗时、缓存命中与实际容器创建/回收数。
- validation: AC-07脱敏、观测故障降级和双库迁移回归；目前尚未实施。

request_logs 为 N/A：没有 HTTP 入口；usage_events 为 N/A：不伪造后台用户行为。运维续接单独审计，禁止记录凭据、提示词、原始路径和完整外部响应。观测写入失败不阻断恢复状态提交，输出有界脱敏降级日志。

## 测试策略

AC-01/02 用可控时钟与执行器覆盖永久失败、退避和权威终态。AC-03/04 覆盖双库重启、过期租约、失租取消、并发CAS及正常领取5秒预算。AC-05 验证所有缓存失效键与失败拒绝。AC-06 验证运维权限、幂等与状态保护。AC-07 覆盖分类及观测降级。AC-08 在登记的独立 Docker 环境验证成功、失败、取消和中断清理，暂停后真实观察至少330秒无该轮次新增容器；保存实际镜像与代码指纹。合成测试与真实观察分开记录，不碰生产旧轮次、共享卷和宿主数据。

## 风险与回滚方案

有限预算可能暂停仍可恢复的轮次，保留运维续接与原因诊断。缓存过宽会削弱安全，采用短时进程缓存和完整身份失效，失败默认重新检查。阻塞 Docker 调用须有实际超时回收测试，不以线程 future 超时替代进程关闭。通过仅关闭自动恢复的配置降级，正常任务继续；不得回退后重新激活无界扫描。新增表保留以便恢复与审计，不自动删除数据。

## 未决边界

原始历史执行异常和当时具体RPC失败仍未知，无需为修复本调度缺陷重放业务。当前参数是待实施验证的设计值，不代表已测性能；若实现证据要求调整，先同步本设计和验收基线。
