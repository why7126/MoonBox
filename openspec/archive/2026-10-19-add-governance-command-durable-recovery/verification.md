# 治理持久恢复实施验证

## 交付范围与实现

首期仅 req-review、bug-review。新增 governance_operations 与 governance_recovery_attempts；操作与原 turn 分离，检查点单调推进，原终态保持。准备记录与候选绑定版本在模型前核对；运行角色心跳按 schema/action 交集判定。已应用成果不重新生成，恢复使用原 application/journal 和项目写入锁。

详情 GET 无写入；恢复 POST 需要原会话访问、当前对象写权限、版本、幂等键和明确确认。领取持久 CAS、fencing token 和 lease，自动预算全操作三次（2/10/30 秒）；手动一次不重置自动预算。执行前与逐文件提交重查授权和绑定。过期不领取；活跃/未知执行及未完成事务保护，管理员明确续保或一致性复核，不能绕过原 writer。到期不自动删除共享成果或创建永久备份。

恢复面板使用原有 Button、ChatDialog 和主题 token。详情、六阶段、原终态、期限、确认、证据和重新生成草稿独立显示；轮询仅 GET，乱序响应不能覆盖新状态。草稿不会自动发送。公共输出展示延续 REQ-0046。
