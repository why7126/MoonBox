# 本地数据挂载与自动快照轮转设计

## 背景与现状

本地数据库连接串以 `/app/data/sqlite/moonbox.db` 为目标，现有 Compose 挂载可能让其实际落在 `data/runtime/backend/sqlite/moonbox.db`。两处文件均可能存在，需按内容验证。Chat 平台执行状态库、业务库快照与独立删除日志是不同数据域；快照启动和约 24 小时周期创建，当前缺少数量上限。REQ-0043 的 AC-001 至 AC-019 是本设计验收来源。

## 目标

- 本地所有 SQLite 组合解析到宿主机 `data/sqlite/moonbox.db`；运行状态和备份仍按用途分目录。
- 以安全库存与人工确认处理旧库差异，保留可执行回滚路径。
- 为自动快照实现默认 2、正整数上限和 0 关闭自动创建，并保护删除日志、手动副本和治理引用。
- 以脱敏摘要记录迁移、创建、校验、跳过、过期与失败结果。

## 非目标

不合并 Chat/Codex 状态 SQLite 与业务库，不按空间分库，不调整生产 MySQL 存储，不新增备份 UI、下载 API 或在线自动恢复。

## 设计方案

### D1 挂载与启动门禁

根 Compose、本地六模式 Compose 和 Chat/Governance overlay 统一将宿主机 `data/` 挂载为容器 `/app/data`，或采用等价且经验证不会分叉的子目录挂载。检查实际解析后的 bind source、容器目标和 `DATABASE_URL`，SQLite 模式若仍指向 legacy runtime backend 路径则阻断并提示迁移；不得自动建空库掩盖旧库。MySQL 模式保留生产连接串校验；不因本地路径异常退回 SQLite。工作区 runtime 必须位于独立的 `data/runtime/` 用途目录，避免 source 工作区挂载重叠。

### D2 迁移与库存

先以只读模式盘点两个业务库、自动/手动快照和治理 manifest 引用，记录相对路径、数量、摘要和占用。停服后分别保全源库和目标库；执行 `PRAGMA integrity_check`、schema 版本、关键表行数及必要的内容摘要比较。两库不同或检查失败时停止自动选择并输出差异清单，由运维确认可信来源和回滚目标；不得覆盖任一原文件。切换挂载后验证 API、Chat Worker、关键业务数据与重启，再按清单经受控入口清理 legacy 文件。迁移前恢复点须保全，清理动作单独记录结果。

### D3 配置与一致性

`MOONBOX_CHAT_LOCAL_SNAPSHOT_LIMIT` 缺失时为 `2`；仅接受 `0` 或无符号十进制正整数，拒绝空值、负数、小数及其他字符串。API 与 Worker 从同一显式 env 配置解析并暴露一致性指纹给既有就绪检查；非法值在启动阶段给出脱敏配置错误。`0` 停止启动和周期自动快照，不触发对既有库存的立即清理，删除日志仍独立持久化。

### D4 自动快照轮转事务边界

保留启动与约 24 小时周期。新快照创建后先完成 SQLite 完整性、摘要和账本登记校验，再以账本中的来源类型、创建顺序和治理 manifest 引用计算未受保护自动快照。仅通过既有受控 expire 操作逐份清理超额副本，并同步更新文件与账本。手动副本不计入上限；被 manifest 引用的自动副本是受保护例外。来源不明的旧副本先保留并列入库存核对，不按文件名或 mtime 推断可删。失败时保留旧有效恢复点、登记一致性和逐项失败结果；不得因上限强删最后可用恢复点。

### D5 删除与恢复

独立删除日志既不受快照上限影响，也不随轮转清空。离线恢复历史快照时重放删除意图，验证已删除会话不复活。成套备份 manifest 所引用快照保持可查找、可校验，其生命周期仍由显式运维流程管理。

## 数据与 API

本次不新增 HTTP API、业务表结构、索引或 schema 迁移。快照账本如需记录来源类型和引用保护，应兼容既有条目：未知来源只读保留并进入盘点，不以缺省值误判为自动副本。SQLite 快照完整性与恢复演练须有回归；生产 MySQL 连接和启动门禁须回归。无 API contract 变化，OpenAPI、Orval、API 索引更新为 N/A；若实施中增加 API，必须补齐契约、客户端生成和测试。

## 风险

- 两处业务库内容分歧 → 停服保全与差异报告，人工选定来源前不切换。
- 快照创建成功但登记或过期失败 → 先验证登记，再逐份受控过期；失败保留有效旧副本并报告库存偏差。
- 旧快照来源不明 → 不纳入可删集合，待库存核对和迁移决策。
- `0` 被误解为清除备份 → 配置说明和回归明确仅停止自动创建。
- 目录调整影响 Worker 或 source 工作区 → 检查实际挂载与重启、执行及离线恢复路径。

## 迁移与回滚方案

按“只读库存 → 停服 → 双库分别保全 → 完整性/差异校验 → 人工确认来源 → 切换挂载 → API/Worker/重启验证 → 受控清理”执行。任何前置检查失败停留在原状态；切换后失败则停服恢复原挂载和已保全数据库，再验证关键表及 Chat 状态。历史快照初次轮转前生成引用清单，保留迁移前恢复点，逐份过期而非批量删除。生产 MySQL 不执行本地 SQLite 迁移。

## 验证策略

覆盖 Compose 配置解析矩阵、旧/新库内容相同与不同、损坏库、非法配置、默认/正整数/0、API/Worker 配置不一致、启动与周期轮转、手动及治理引用保护、故障注入、删除意图回放、SQLite/MySQL 启动回归、Git ignore 和文档一致性。合成回归与真实本地部署、重启及离线恢复证据分别记录。
