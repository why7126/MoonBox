# 本地数据挂载与自动快照轮转提案

## 背景

本地业务 SQLite 的配置路径与实际 Compose 挂载可能分别指向 `data/sqlite/` 和 `data/runtime/backend/`，两处已有文件不能凭名称判定相同。Chat 自动快照目前缺少数量上限，长期运行会持续占用磁盘。REQ-0043 已评审并纳入 sprint-009，需要在保全旧数据和恢复点的前提下统一路径与轮转语义。

## 变更内容

- 统一根 Compose、本地 Compose、Chat/Governance overlay、辅助脚本与环境示例的本地 SQLite 挂载；启动前识别路径分叉，生产 MySQL 门禁保持有效。
- 提供旧业务库和历史快照的只读盘点、停服保全、差异校验、受控切换与回滚流程；差异未决时拒绝自动覆盖。
- 增加 `MOONBOX_CHAT_LOCAL_SNAPSHOT_LIMIT`，默认 `2`，非负十进制整数；`0` 停止自动快照但保留独立删除日志、历史副本和手动备份。
- 新快照验证并登记后按创建顺序经受控接口轮转未受保护自动副本；治理成套备份引用、手动副本及最后有效恢复点受到保护。
- 补齐目录权限、Git ignore、部署与数据库文档、故障注入和恢复验收。

## 能力影响

### 新增能力

- `local-snapshot-rotation`：本地自动快照的配置、来源识别、引用保护、轮转、删除意图保留和恢复校验。

### 修改能力

- `deployment-governance`：本地数据目录治理补充实际挂载一致性、路径分叉阻断和旧库安全迁移条件。

## 影响范围

涉及本地 Compose/overlay、启动脚本、Chat API 与 Worker 配置、快照和备份账本、SQLite 迁移工具、部署示例、数据库与部署文档及相关测试。当前不新增产品 UI 或 HTTP API，不变更业务表结构、生产 MySQL 数据位置、Codex 执行器状态库或手动备份入口。
