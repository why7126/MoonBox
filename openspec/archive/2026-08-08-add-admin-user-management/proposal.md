## 背景与动机

MoonBox 管理后台需要从单一入口能力扩展为可治理的用户账号生命周期系统，支撑后台管理员对平台用户进行查询、创建、编辑、冻结、解冻、删除、重置密码和安全追溯。

当前平台已有 Web、管理后台、REST API、数据库和对象存储治理基础，但缺少正式规格来约束用户管理页面、用户状态、超级管理员保护、头像上传、敏感操作确认和审计记录。

## 变更内容

- 新增管理后台用户管理页面，位于 `SYSTEM` 或等价系统管理导航分组。
- 新增用户列表、搜索筛选、分页、行内操作和固定操作列能力。
- 新增后台创建/编辑用户弹窗，角色范围仅为“后台管理员”和“前台用户”。
- 新增用户状态治理：冻结、解冻和逻辑删除；冻结后目标用户有效会话必须在 10 秒内失效。
- 新增后台重置密码能力，并要求二次确认、原因填写、防重复提交和敏感结果保护。
- 新增系统内置唯一超级管理员保护，列表展示但不可编辑、重置密码、冻结、解冻或删除。
- 新增头像上传与即时回显要求，覆盖本地 Docker `:3000` 上传读取边界。
- 新增用户管理写操作审计追溯要求。

## 能力范围

### 新增能力

- `web-admin-user-management`: 管理后台用户账号生命周期治理，覆盖列表、筛选、创建、编辑、状态变更、密码重置、超级管理员保护、头像上传、审计和 UI 横切验收。

### 修改能力

- 无。

## 影响范围

```yaml
impact:
  backend: true
  web: true
  miniapp: false
  admin: true
  database: true
  storage: true
  api: true
capabilities:
  new:
    - web-admin-user-management
  modified: []
```

- Web 管理后台：新增用户管理页面、列表、筛选、弹窗、状态操作、toast 和头像回显。
- REST API：新增或扩展后台用户管理、头像上传、冻结/解冻/删除、重置密码接口。
- 数据库：需要用户角色、状态、空间数聚合、审计字段和逻辑删除表达。
- 对象存储：头像上传、读取和本地 Docker 访问边界。
- 测试：后端 pytest、API 集成测试、前端 Vitest/Testing Library 和 UI/E2E 验收。
