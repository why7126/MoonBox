# Chat 流式正文完整预览修复提案

## 背景

来源 [BUG-0067](../../../issues/bugs/review/BUG-0067-chat-stream-preview-premature-truncation/bug.md)，已评审且纳入 sprint-014，严重度 medium，沿用3人天估算。原样本294片段仅1126字节，预览在21片段截断，产生误导性缺失提示。根因证据已确认。

## 变更内容

- 用有界正文预算与分页读取替代固定21片段的内容完整性判定。
- 区分正常生成、展示预算限制、读取窗口限制和真实历史缺口；预览受限时提供完整内容读取入口。
- 保留最终答案身份与版本选择、旧格式兼容、权限与资源保护，补充后端、前端及真实浏览器回归。

## 能力影响

### 新增能力

无独立新增能力。

### 修改能力

- `chat-scalable-storage`：细化“持续保存与有界读取”的短正文预览、提示和分页契约。

## 影响范围

后端 assistant_output、result_reader 与 Chat API schema；Web 正文展示、状态提示和完整内容入口；OpenAPI、客户端及API索引。无计划数据库迁移、对象存储或部署拓扑变化。轮次收尾状态问题不在范围，不修改正式spec直到归档。

## 回滚方案

回滚到兼容当前分片和最终答案身份的上一版本；保留已提交结果和原执行状态，不删除片段、不回放业务命令。旧客户端继续使用 output_truncated；新增原因字段可忽略。回滚会恢复预览缺陷，应明确提示限制。
