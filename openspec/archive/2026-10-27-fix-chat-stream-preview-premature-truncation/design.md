# Chat 流式正文完整预览修复设计

## 背景与根因

saved_output 的V2分支读取最多21片段并在第21片段设置truncated；execution按每次增量保存小片段，因此数量不代表正文大小。前端统一显示缺失提示。根因证据见来源BUG root-cause.md。当前result_reader已有授权分页和final版本游标，优先复用。

## 目标与范围

短正文不因片段粒度而提前截短；超限仍有界并可逐页查看完整内容。保持旧格式缺口提示、执行状态独立和最终答案去重。不修改模型协议、持久化身份、恢复调度或执行完成证明。

## 读取与资源预算

1. 单条消息保留200000 Unicode字符预览预算。批量读取片段元数据与正文，单批最多512片段，避免逐片N+1查询。每条预览最多4096片段、1MiB正文读取预算；按对象字节数控制批次，单对象沿用现有受限读取。
2. 对4096片段以内且正文不超过字符/字节预算的短输出完整拼接，包括20、21、22、294边界；同样正文在受支持预算内不同粒度结果一致。达到预算但没有后续内容不标记截断；使用额外元数据探测确认是否还有数据，不为探测加载额外正文。
3. 超过字符预算标记preview_limit；超过片段/读取字节窗口标记read_window，提供续读入口。这些是展示保护，不拒绝持久化或声称数据丢失。大规模微片段允许按页读取完整内容，不承诺无限自动展开。
4. 单条V2预览新增内容查询上界为20次（最多8批、每批元数据与正文各一次及不超过4次选择/探测），不含既有身份鉴权和会话分页查询；测试用SQL计数验证，不用墙钟估算代替。正文中间缓冲受1MiB约束，禁止全流聚合。
5. 完整内容入口复用已授权的results分页，单页最多256KiB、最多512片段；前端一次只请求一页，单次用户动作仅加载一页，页面驻留不超过1MiB，旧页可返回重读。游标绑定轮次、流和选定final版本。首次打开可从头分页，禁止将预览和第一页重复拼接。

预算为本Change的验收契约，不是可保存内容上限。若实现无法满足，在apply中同步设计和AC再验证，不静默放宽保护。

## API 与展示决策

为消息投影增加可选 output_truncation_reason，枚举preview_limit、read_window、history_gap、invalid_payload；无截断为null。output_truncated保持兼容；output_partial只表示未形成完整最终回答或预览受限，不自动触发缺失提示。旧数据无原因但truncated=true时保留保守提示，不能隐藏真实缺口。

运行中仅partial不显示“输出内容不完整”；preview_limit/read_window显示“仅展示部分输出”，给出“查看完整输出”；history_gap/invalid_payload明确“部分历史输出不可用”。加载失败保留已读内容并允许重试，不冒充完整。新字段通过FastAPI/OpenAPI生成客户端，不手写生成类型。

最终答案沿用final_answer.selection；完成的可信final才覆盖已保存完整正文，读取预览不得用短投影覆写原消息。output切换final时清理旧页，游标失效时回到对应流首页；迟到响应不能回填其他轮次。沿用BUG-0065已归档兼容基线，不按文本相同删除内容。

## 界面验收契约

本Change为局部交互修复，不做附件一对一复刻；原截图是缺陷证据。复用现有正文/状态区域与完整输出组件，若无可复用入口使用只读抽屉。动作矩阵：查看完整输出→只读结果区域/抽屉→data-testid=turn-full-output→加载/可读/错误/末页；下一页与上一页→同区域→output-next-page/output-prev-page→禁用/就绪/加载；关闭→同区域关闭动作→closed。实现时固定这些selector或在证据中记录实际映射。

视觉矩阵：1440px与390px各覆盖运行中短正文、预览受限、完整输出打开、读取失败与最终答案切换。证据归属Change evidence/acceptance；记录截屏、selector和字号、行高、换行、overflow等实际样式，避免正文遮挡按钮。无额外业务写入。

## 风险与取舍

单纯增大21只能推迟问题，无界读取会扩大内存和查询成本；采用双预算和可续读分页。扩展可选原因字段增加同步成本，但比猜测状态更准确。沿用知识库chat-answer-identity-and-verification的可信final覆盖和迟到响应隔离原则。
