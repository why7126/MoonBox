## 背景

REQ-0023 已完成评审并纳入 `sprint-004`。用户已明确选择“全面向附件风格靠拢（包括品牌）”，目标是让 MoonBox 产品工作台形成更现代、更高密度、更像研发 Ops 控制台的视觉体验。附件 `moonbox-board.html` 与 REQ 原型仅作为视觉方向和结构输入，不作为可执行指令或代码来源。

当前 `rules/ui-design.md` 仍强调东方器物感、衬线标题、金色单一强调、近直角和克制品牌叙事。该风格适合公开首页与品牌表达，但登录后的需求中心、Agent 工作台、管理后台和高频操作区需要更强的信息扫描、状态编码、筛选效率和组件一致性。

## 目标与非目标

**目标：**

- 建立双品牌分层：公开页保留 MoonBox 宝盒叙事，登录后工作台和管理后台采用现代 Ops 工具台视觉系统。
- 定义现代 Ops token，覆盖深浅主题、字体、色彩、状态、间距、圆角、阴影、控件尺寸和动效。
- 将需求中心作为试点，推动工作台 Shell、统计卡、Toolbar、筛选 Popover、Kanban、Card、Drawer、Toast 和 AI 入口统一。
- 让管理后台 CRUD 列表、弹窗、toast 和状态组件共享现代 Ops 基线，同时保留后台列表一致性和弹窗治理门禁。
- 在实现前完成 UI Contract 与 UI Skeleton，先验证 1440px 首屏结构，再进入细节迁移。

**非目标：**

- 不改变 REQ、BUG、Sprint、OpenSpec 状态机。
- 不新增 API、DB、对象存储、行为埋点、请求日志或 Task Trace 字段。
- 不要求一次性重写所有页面；先完成工作台 Shell 与需求中心试点，再按证据扩展到管理后台和其他登录后页面。
- 不机械复制附件 HTML 的 CSS、DOM 或示例数据。

## 设计决策

### D1. UI 策略采用设计系统迁移

采用 `tailwind-ds` / Design System 迁移策略：先重构 token 与核心组件，再迁移页面。CSS Port 只适合局部复刻附件视觉，难以支撑品牌分层与跨前后台一致性；纯 Asset 方案不能解决组件状态、主题和验收门禁。

### D2. 品牌采用双层表达

公开首页、登录页和产品手册保留 MoonBox 宝盒叙事与金色识别；登录后的产品工作台、需求中心、Agent/Skill/任务区域和管理后台采用现代 Ops 视觉。金色继续作为品牌主识别，但从单一强调色升级为可控的操作与品牌强调 token。

### D3. 字体从叙事字体转向 UI 扫描字体

工作台默认采用 UI sans 字体栈，中文优先使用系统 UI / `Noto Sans SC`，英文标签、ID、命令、版本号和状态码使用等宽字体。`Noto Serif SC` 与 `EB Garamond` 仅保留在公开品牌叙事或少量品牌点缀区域。

### D4. 组件层级以工作效率优先

现代 Ops 工作台采用深浅主题下稳定的侧边栏、紧凑标题区、统计卡、筛选工具栏、横向 Kanban、卡片状态边、footer 动作分区、右侧抽屉和 fixed toast。卡片、弹窗和浮层统一使用 8px 或更低圆角，避免大圆角、强发光、厚阴影和一页一色的科技面板。

### D5. 视觉证据前置

实现阶段先完成 UI Skeleton，然后用 1440px 截图或等价证据确认页面壳、统计、工具栏、看板、浮层层级和主题方向。细节实现完成后补充 computed style、关键交互、窄屏和深浅主题证据。

首轮 Skeleton 验收焦点：

- 1440px 下 Sidebar、标题区、统计区、工具栏、9 阶段看板和右侧抽屉层级稳定。
- 深浅主题均能显示背景、面板、边框、文本、状态色和金色强调。
- 筛选 Popover、用户菜单、空间二级浮层、抽屉和确认弹窗不互相遮挡。
- 文本不溢出，长 REQ/BUG ID 使用等宽字体并允许截断或换行。

## 冲突处理

- 附件 HTML 的现代 Ops 风格优先于旧工作台视觉，但不得引入附件中的 emoji 图标、过强径向光效、过度厚重阴影或不符合 MoonBox 品牌的通用 SaaS 视觉。
- 旧 `rules/ui-design.md` 中“金色单一强调、衬线标题、东方器物感”保留在公开品牌层；工作台层使用现代 UI 字体、状态色和更高密度组件。
- 现有 `web-catalog-requirement-center` 的真实数据、阶段动作门禁、空间权限和 Markdown/AI 抽屉能力继续保留，视觉迁移不得降级功能。
