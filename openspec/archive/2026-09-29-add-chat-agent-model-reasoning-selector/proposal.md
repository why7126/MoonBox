## 背景与动机

Chat 工作台已经支持个人 Codex 会话、真实执行、会话历史、轨迹和 Diff，但输入区仍缺少发送前可见和可控的执行配置。REQ-0035 已完成评审并纳入 `sprint-006`，需要把 Agent、模型和推理配置选择转为 OpenSpec Change，确保它进入发送 API、轮次事实源和执行观测，而不是停留在前端装饰。

## 变更内容

- 在 Chat 工作台输入区新增 Agent、模型和推理配置选择入口；首版 Agent 只有 Codex，状态必须清晰。
- 由服务端能力配置驱动可用模型、推理配置、默认值、禁用原因和降级策略，前端不得硬编码不可验证列表。
- 发送消息时携带当前配置，后端重新校验用户、空间、会话、Agent、模型和推理配置权限。
- 轮次事实源记录请求配置、实际生效配置和降级原因摘要；历史轮次展示实际生效配置，不被当前选择覆盖。
- 覆盖配置加载失败、不可用选项、运行中禁用、已归档只读、长模型名、窄屏和浮层退出等 UI 状态。
- 同步 API、DB、OpenAPI、客户端类型、行为事件、请求日志、Task Trace、流程节点、测试和文档边界。
- 将 `prototype/web/` 产出的 UI Contract、UI Skeleton、1440px 视觉验收、computed style、Mock/API 边界和 REQ 最终一致性纳入实现门禁。

## 能力范围

### 新增能力

- 无。

### 修改能力

- `web-catalog-chat-workbench`: 扩展 Chat 工作台输入区执行配置、配置能力发现、发送参数、历史回显、状态约束和原型驱动 UI 验收。
- `codex-session-execution`: 扩展 Codex 会话执行轮次的请求配置、实际生效配置、降级原因、运行互斥和脱敏观测追溯。

## 影响范围

- Web 前台：Chat 工作台 Composer、配置栏、模型/推理菜单、轮次详情、运行中/归档/错误态和响应式布局。
- API：配置能力查询、Chat 发送请求/响应字段、历史轮次读取字段、受控错误码、OpenAPI 和客户端类型。
- 数据库：轮次请求配置、实际配置、降级原因或等价 JSON 字段；需要 SQLite/MySQL 兼容迁移和文档同步。
- 观测：usage_events、request_logs、task_traces、task_trace_spans 记录脱敏配置标识、实际生效配置摘要、降级节点和错误码。
- 测试与文档：后端接口测试、前端组件/交互测试、OpenAPI/Orval 校验、DB 兼容测试、UI 1440px/窄屏视觉证据、产品数据采集与链路观测说明。
