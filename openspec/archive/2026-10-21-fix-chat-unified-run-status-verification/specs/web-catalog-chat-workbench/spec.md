# 每轮统一状态与输出反馈增量规格

## ADDED Requirements

### Requirement: 每轮可信状态统一投影
系统 SHALL 为每轮提供唯一主状态入口，分别保存执行、业务证明、正文完整性与读取状态，遵守REQ-0046 FR-008优先级，不从助手措辞推断成功。

#### Scenario: 模型结束而业务未完成
- **WHEN** 模型已结束但后端处于校验、应用或回读
- **THEN** 展示实际业务阶段；待定不伪装活动进度，普通聊天不展示业务校验通过，工具次数不使用已读文案

#### Scenario: 失败和正文缺口
- **WHEN** 执行失败、停止、未知或存在正文缺口
- **THEN** 保留原终态并独立去重提示缺口，无正文不声称保留输出，正常流式不增加缺最终答复警告，校验拒绝不被正文成功措辞覆盖

#### Scenario: 读取失败与历史完成
- **WHEN** 已有可信完成快照但更新失败或占用事实矛盾
- **THEN** 保留历史完成并标记更新失败或待确认，不用陈旧权限放行写动作，不把本次完成解释为REQ交付或可归档

### Requirement: 轮次身份与统一详情
系统 SHALL 使用conversation_id、turn_id及可信operation_id定位详情和恢复尝试，保留历史失败与原文，不用对象最新成果补齐缺失关联。

#### Scenario: 多轮与迟到响应
- **WHEN** 切换会话、历史分页、重连或迟到旧响应到达
- **THEN** 只更新匹配身份及有效版本，旧确认失效，不覆盖其他轮次，不删除正常正文和输入区

#### Scenario: 局部原型验收
- **WHEN** 状态区域实现待验收
- **THEN** prototype仅为设计输入，需Change设计、REQ验收、Skeleton确认、双视口截图、computed style、Mock/API声明及REQ最终一致性证据共同签认


### Requirement: 跨入口当前动作一致性

系统 SHALL 以同一结构化验收事实判定产品与CLI归档准入，并保留历史完成证明。合法后续阶段须有可信关联和当前证据，未知占用、真实冲突及证据过期不得放行。卡片仅显示一次阻塞摘要，历史核验细节默认折叠。

#### Scenario: 后续合法交付承接历史评审

- **WHEN** REQ或BUG已有可信评审成果且后续Change完成有效验收
- **THEN** 产品与CLI按当前归档动作作出一致判断，不因旧评审摘要变化永久阻断
- **AND** 历史操作与原终态保持不变，后续实质变更由当前证据覆盖
