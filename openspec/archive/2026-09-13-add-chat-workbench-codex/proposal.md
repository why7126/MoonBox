## 背景与动机

MoonBox 的 Chat 导航尚未接通独立页面，既有 AI 抽屉返回固定反馈，无法承载真实 Codex 持续执行。REQ-0025 已评审并纳入 sprint-004，需要形成个人会话、业务上下文、真实执行和代码变更查看闭环。

## 变更内容

- 新增个人私有 Chat 工作台、会话历史与关联、执行轮次和真实 Diff。
- 在服务端预配置仓库中复用每会话工作区，固定单一 Codex 接入路线，支持恢复、中止确认及显式重试。
- 平台统一认证和额度管理；历史保留至主动删除并设置容量上限，工作区代码和审计独立管理。
- 承接已确认的 Ops 风格、附件交互布局和 UI Skeleton/视觉验收门禁。
- 不新增 TASK 引擎、Agent 树、个人认证界面、上传、默认 Git 提交/合并/推送或部署授权。

## 能力范围

### 新增能力

- `web-catalog-chat-workbench`: 个人会话、业务关联、Ops 交互、真实执行呈现与历史管理。
- `codex-session-execution`: 服务端执行、隔离、持久化恢复、中止、额度容量、可信变更与观测。

### 修改能力

无。既有需求中心全局 AI 抽屉及阶段反馈契约保留，新增可携带对象进入独立 Chat 的入口，不将原有抽屉直接替换为新页面。

## 影响范围

涉及 src/web 的路由/页面/请求封装、src/backend 的会话 API/数据模型/服务及独立执行 worker，SQLite/MySQL 迁移、OpenAPI/客户端生成、部署与安全文档。新增运行时版本与资源配置，在实现阶段验证。首版不使用附件对象存储链路，不新增管理端页面。

需求估算沿用 XXL=13 人天，不因拆成两个规格重复计量；Sprint 合计28/30人天，修复缓冲仅2人天，接入不确定性见 design.md 风险及评审RC-001至RC-004。
