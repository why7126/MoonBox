# Issue 原型引用检查设计

## 背景与目标
复用 promote-issue-stage.py 的单一物理移动入口，使直接调用和归档包装入口都接受相同检查。
## 设计决策
- 共享检查模块仅扫描当前 Issue 文本、关联 Change 和所属 Sprint 文本；通过 trace 关联及精确 Issue ID 定位，不扫描全仓历史正文。
- 支持 Markdown 行内/引用式链接及明确 prototype 路径，HTML href/src/srcset、CSS url/import 的静态本地资源。查询串与片段剥离后验证文件目标；不执行 JS、不联网、不校验锚点语义。动态及远程引用给出非阻断提示。
- Markdown 明确历史标题（历史记录、变更记录、迁移记录、历史验收）内引用只作历史提示；代码围栏为示例提示。普通正文链接按有效引用检查，不凭“旧路径”字样豁免。
- 以源目录到目标目录映射模拟迁移：原位置可访问而新位置不可访问为迁移断链；当前已缺失为既有缺失。目标提前写为新路径且模拟后有效则允许。
- 原型资源递归检查限仓库内、去重、跳过符号链接，不读取仓库外内容。可访问符号链接目标或无法确定的根路径语义不给出虚假通过。
- 所有阻断先于 trace 写入与移动；批量处理隔离当前 Issue。成功移动后复核，失败保留目录和诊断、不回滚未知并发写入、不列为成功。重复调用已在目标目录的 Issue 仍复核。
- 预览和 check 不写文件；不自动替换历史路径。归档 wrapper 在状态修复前先预检，避免引用阻断时提前写子文档。
## 风险与取舍
支持明确的静态语法，动态 JS、外部 URL、HTML base 语义单独提示；不是完整浏览器渲染或全仓链接审计。历史标题仅按约定明确匹配，避免隐藏当前链接。
## 验证策略
隔离目录测试正常/断链/缺失/历史/外部资源、编码路径、关联引用、dry-run 零写入、后检故障与重试及 wrapper 门禁顺序。真实项目只运行只读检查，不迁移用户 Issue。
