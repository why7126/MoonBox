## 背景

需求中心治理对象增多后，现有枚举筛选如果只能单选或缺少下拉内搜索，会迫使用户反复切换条件，降低规划、评审、迭代和验收时的扫描效率。

REQ-0033 已进入 `sprint-006`，本变更把筛选下拉升级为支持复选、多选、搜索和稳定排序的工作型控件，同时保持 9 阶段看板、真实数据事实源、授权边界和统计口径不变。

## 变更内容

- 增强需求中心工具栏中适合枚举选择的筛选维度，支持复选、多选、单维 OR 与跨维 AND 组合语义。
- 在多选下拉内增加搜索输入，支持按展示名称过滤，包含稳定 ID 的选项同时支持 ID 匹配。
- 增加选中摘要、单维清空、全局清空、无结果空态和候选项内部滚动，避免长文本挤压工具栏。
- 按业务语义稳定排序筛选项：阶段按 9 阶段顺序、优先级按 P0-P3、Sprint 按当前/最近优先、负责人按当前用户或名称降级排序、类型按业务顺序。
- 保持手动刷新、主题切换、文档抽屉开关和下拉搜索过程中的筛选状态。
- 保持当前需求中心事实源、权限模型、阶段动作、卡片字段和服务端授权边界；首版不引入服务端分页、高级查询语言或个人筛选模板。

## 能力影响

### 新增能力

- 无。

### 修改能力

- `web-catalog-requirement-center`: 强化前台需求中心筛选与搜索体验，增加枚举筛选多选、下拉内搜索、选中摘要、清空、排序和原型驱动 UI 验收要求。
- `web-catalog-requirement-center-real-data`: 强化真实统计、筛选和搜索契约，要求多选条件、权限过滤、统计区、看板卡片和 9 阶段列保持一致。

## 影响范围

- 前端：需求中心筛选工具栏、多选下拉控件、筛选状态组合、统计与空态联动、深浅主题与响应式验收。
- API：首版不要求新增或修改 API 字段；若实现发现现有上下文缺少候选项或 ID 字段，需在实现阶段升级本 Change 的观测与 API 文档/类型同步范围。
- 数据库：无新增表、迁移、索引或保留周期变化。
- 安全：候选项、数量、搜索提示和错误态只能基于当前用户有权访问的需求中心上下文。
- 观测：首版不新增行为事件、请求日志字段或 Task Trace；若实现增加筛选行为事件、URL 持久化或请求封装变化，需改为适用并补充验证。
