## MODIFIED Requirements

### Requirement: 前台需求中心筛选与搜索

系统 MUST 支持用户按对象类型、关键字、负责人、分级和 Sprint 聚焦需求中心看板范围，并为适合枚举选择的筛选维度提供复选、多选、下拉内搜索、稳定排序、选中摘要和清空能力。

#### Scenario: 用户按对象类型筛选

- **WHEN** 用户点击全部、需求或 Bug 筛选控件
- **THEN** 看板必须只展示匹配对象类型的卡片
- **AND** 统计区必须与当前筛选范围一致

#### Scenario: 用户搜索治理对象

- **WHEN** 用户输入 ID、标题、文档名或负责人关键字
- **THEN** 看板必须展示匹配的 Requirement 或 Bug
- **AND** 不匹配的卡片不得出现在当前结果范围内

#### Scenario: 用户按负责人、分级或 Sprint 筛选

- **WHEN** 用户选择负责人、分级或 Sprint 筛选项
- **THEN** 看板卡片范围必须按筛选条件刷新
- **AND** 筛选不得破坏 9 阶段列头与横向滚动行为
- **AND** 分级筛选必须在同一控件内分组展示需求优先级和 BUG 严重性，需求按 P 值匹配，BUG 按严重性匹配

#### Scenario: 用户多选枚举筛选项

- **WHEN** 用户在 Sprint、分级、负责人、阶段或其他适合枚举选择的筛选维度中选择多个选项
- **THEN** 同一筛选维度内必须按命中任一选项的 OR 语义过滤卡片
- **AND** 不同筛选维度之间必须按 AND 语义组合
- **AND** 全局关键词搜索必须继续与筛选维度按 AND 语义组合
- **AND** 统计区、阶段数量、看板卡片和筛选无结果态必须基于同一过滤结果刷新

#### Scenario: 用户在下拉内搜索候选项

- **WHEN** 用户打开多选筛选下拉并输入候选项搜索关键词
- **THEN** 下拉列表必须即时过滤当前维度候选项
- **AND** 搜索至少匹配用户可见名称
- **AND** Sprint、Requirement、Bug、Change 或其他包含稳定 ID 的候选项必须同时支持 ID 匹配
- **AND** 搜索无结果时必须展示轻量空态并保留已选项状态
- **AND** 清空候选项搜索后必须恢复完整候选项排序

#### Scenario: 多选下拉展示复选框与摘要

- **WHEN** 用户打开多选筛选下拉
- **THEN** 每个候选项必须用复选框表达 checked、unchecked 或 disabled 状态
- **AND** 用户点击候选项文本或复选框均必须切换选中状态
- **AND** 触发器未选择时必须展示默认占位
- **AND** 少量选择时触发器可以展示选项名
- **AND** 较多选择或窄屏空间不足时触发器必须展示数量摘要
- **AND** Sprint 维度选中集合等于默认 Sprint 范围时，外层筛选数量可以保持 0，Sprint 触发器必须展示“默认 Sprint 范围”或等价默认态文案，用户手动改变 Sprint 选择后才展示选项名或已选数量
- **AND** 同一筛选浮层内各筛选触发器必须使用统一 label 列宽，使 Sprint、分级、负责人、阶段的摘要文案从同一水平位置开始
- **AND** 长文本不得挤压工具栏刷新、搜索或其他筛选控件

#### Scenario: 用户清空筛选条件

- **WHEN** 用户点击单个维度清空入口
- **THEN** 系统必须只清空该维度的已选筛选项并同步刷新统计和看板
- **WHEN** 用户点击单个维度全选入口
- **THEN** 系统必须选中该维度当前可见且可选的候选项；候选搜索生效时，全选范围必须限制为当前搜索结果
- **AND** Sprint 维度全选必须包含“未纳入 Sprint”合成候选项，以覆盖无明确 Sprint 归属的卡片
- **WHEN** 用户点击全局清空筛选入口
- **THEN** 系统必须清空全部筛选维度和关键词搜索并恢复默认结果范围

#### Scenario: 筛选候选项稳定排序

- **WHEN** 系统展示筛选候选项
- **THEN** 筛选容器内的多选维度必须按 Sprint、分级、负责人、阶段顺序展示
- **AND** Sprint 候选项状态必须仅展示为“进行中”或“已归档”，“当前迭代”必须作为同行辅助标签展示
- **AND** Sprint 候选项必须提供“未纳入 Sprint”合成候选项；选中后必须匹配无明确 Sprint 归属的卡片，清空 Sprint 维度仍表示不按 Sprint 过滤
- **AND** Sprint 必须按当前迭代或最近迭代优先，其后按编号或更新时间倒序展示
- **AND** 阶段或状态必须按需求中心业务阶段顺序展示
- **AND** 需求优先级必须按 P0、P1、P2、P3 顺序展示，P 值与说明必须同一行展示
- **AND** BUG 严重性必须按 blocker、critical、high、medium、low 顺序展示，并与需求优先级在分级控件内分组区分
- **AND** 负责人必须优先展示当前用户或最近参与者，其后按展示名或 ID 稳定排序
- **AND** 类型必须按全部、需求、缺陷、独立 Change 或现有业务顺序展示
- **AND** 证据不足时必须降级为稳定名称或 ID 排序，不得依赖不稳定运行时对象顺序

#### Scenario: 用户手动刷新 9 阶段看板

- **WHEN** 用户点击需求中心工具栏中的刷新图标按钮
- **THEN** 系统必须重新读取需求中心上下文并更新统计区和 9 阶段看板
- **AND** 系统必须保留当前搜索、对象类型、负责人、分级和 Sprint 筛选条件
- **AND** 刷新过程中刷新按钮必须展示 loading 语义并避免重复点击
- **AND** 刷新失败时不得清空当前看板，必须保留最近一次成功加载的数据并给出轻量失败提示
- **AND** 主题切换、打开或关闭文档抽屉、在下拉内搜索候选项时也不得丢失已选筛选条件
- **AND** 用户点击非筛选区域时，已打开的筛选浮层必须关闭

### Requirement: 原型驱动 UI 验收

系统 MUST 将 REQ-0023 的产品原型和附件视觉方向作为设计输入，并在实现、验收和归档阶段保持文档一致。

#### Scenario: OpenSpec 设计承接原型契约

- **WHEN** 需求中心 UI 型需求进入 OpenSpec Change
- **THEN** Change design.md 必须写明 Prototype Source、Conflict Resolution、UI Contract 和 UI Skeleton
- **AND** UI Contract 必须声明事实源优先级、品牌分层、Token、组件、交互状态、权限规则、Mock/API 边界和 computed style 验收点
- **AND** UI Skeleton 必须覆盖页面结构、区域边界、组件层级、状态容器、数据依赖、可测选择器和 1440px 验收焦点
- **AND** 对于 REQ-0033，UI Skeleton 必须覆盖工具栏、多选下拉、搜索输入、复选框候选项、无结果空态、单维清空、全局清空、权限态、选中摘要和窄屏摘要

#### Scenario: 视觉验收覆盖现代 Ops 关键状态

- **WHEN** 需求中心 UI 变更进入实现验收
- **THEN** 系统必须保留 1440px 桌面视口视觉证据
- **AND** 视觉证据必须覆盖默认首屏、侧边栏展开/收起、用户菜单、筛选 Popover、看板横向滚动、空列、错误态、卡片 hover、右侧抽屉、AI 入口、深浅主题和窄屏状态
- **AND** 对于 REQ-0033，视觉证据还必须覆盖多选摘要、下拉内搜索、搜索无结果、候选项内部滚动、全选入口、清空入口、刷新保留筛选和文本溢出检查
- **AND** 验收材料必须记录关键筛选控件的 computed style 证据，包括触发器尺寸、Popover 宽高、复选框尺寸、focus ring、边框、背景、文字颜色和滚动容器高度
- **AND** OpenSpec 归档前必须确认 requirement.md、acceptance.md、trace.md、Change design.md、实现证据和验收结论一致
