# 聊天历史读取生命周期约束

## ADDED Requirements

### Requirement: 历史状态与详情读取解耦

系统 MUST 优先展示可信轮次摘要，终态展示不得依赖完整事件回放；详情隐藏时停止详情专属取数。

#### Scenario: 打开已完成历史且详情收起
- **WHEN** 用户打开已完成历史会话并保持详情收起
- **THEN** 摘要在事件详情返回前可显示，且没有详情专属事件、Diff、context周期读取

### Requirement: 相同资源共享读取且隔离权限

系统 MUST 合并同授权上下文内相同轮次资源和游标的并发请求，权限失效时清除结果，不跨用户共享。

#### Scenario: 多组件并发订阅同轮事件
- **WHEN** 状态、页脚和详情请求同键事件页
- **THEN** 最多一个在途请求，结果被共享，单个订阅者取消不影响其他订阅者

#### Scenario: 权限失效或会话切换
- **WHEN** 返回401、403、404或认证身份改变
- **THEN** 未授权结果不可继续展示，旧请求不污染新会话，未知状态不得投影为完成

### Requirement: 分页与状态更新完整可靠

系统 MUST 正确合并分页与末尾用量，保留活跃状态更新及可信成果核验，不因缓存解除写入保护。

#### Scenario: 长事件历史与活跃轮次并存
- **WHEN** 事件超过400条且另有活跃轮次
- **THEN** 按需详情无漏页或重复，页脚用量完整，活跃轮次继续更新直至终态

### Requirement: 恢复查询不重叠

系统 MUST 对同一恢复操作限制单请求在途并合并刷新触发，保留可见性、终态和预算控制。

#### Scenario: 响应超过轮询间隔
- **WHEN** 恢复接口响应超过3秒且发生刷新触发
- **THEN** 同操作最多一个在途请求，有效结果最终显示，不因持续丢弃旧响应长期停留加载


### Requirement: 完整授权摘要接口

系统 MUST 提供兼容的轮次 summary 只读接口，在复用原轮次授权边界的前提下返回完整工具次数、最新事件序号与末尾用量；禁止返回原始事件正文，禁止用0替代缺失用量。

#### Scenario: 用量位于第四百条之后
- **WHEN** 已结束轮次的最新用量事件位于事件首页之外
- **THEN** 摘要仍返回最新用量和完整工具次数，客户端无需重放事件首页；非所有者或失效空间请求被拒绝，响应不进入HTTP缓存
