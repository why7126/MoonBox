# 修复 Chat 中纯治理 Change 归档授权与命令工具路径

## 背景

关联缺陷 `BUG-0034-chat-standalone-archive-scope-tool-path` 已确认：产品内归档纯治理 Change 时误用普通治理权限，命令沙箱又因 PATH 缺失找不到内置工具。已完成的目标 Change 只能转到宿主环境归档，产品内闭环仍失效。

## 变更内容

- 对已 applied 且纳入 Sprint 的纯治理 Change 主对象，在完整归档命令和成员权限匹配时授予最小归档 profile。
- 在执行器私有命令环境中固定 PATH，使模型命令能够解析镜像内已经预检的工具。
- 以隔离沙箱覆盖允许与拒绝路径，区分合成验证和真实产品观察。

## 能力影响

### 修改能力

- `local-project-governance-loop`：补充纯治理 Change 的受控归档授权与沙箱工具可用性。

## 影响范围

涉及 Chat 后端权限策略、执行容器配置、测试和本地部署说明。现有 API、数据库结构、Web 交互与客户端生成不变。权限写入边界会按条件增加，但普通治理命令不扩权。

## 回滚方案

如授权回归失败，恢复原策略与执行器配置并重建 Worker；纯治理 Change 暂用已验证的宿主标准归档脚本。保留现有 Change 和 Issue 事实源，不回滚数据库或已完成归档。
