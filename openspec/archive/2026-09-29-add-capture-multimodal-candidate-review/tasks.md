# Capture 实施与验收任务

范围依据为 REQ-0029 的 36 条 AC；实施进行中，勾选仅代表对应局部验证通过。任务 1 是 UI 细节实现的前置，任务 2→3→4→5 是服务端主链，6 依赖1至5，7在相关实现后取证，8在7通过后收尾。仅本 Change 范围实施，用户工作区其他变更保留。

## 1. 原型与 UI Skeleton 先行

- [x] 1.1 复核 design 的冲突裁决、HTML反向工程、selector映射、动作与modal矩阵、computed style清单，按当前组件入口回填实际文件与状态（AC-PROTOTYPE-001）。
- [x] 1.2 实现限定 Capture 的工作区骨架、材料/候选/结果/错误状态容器和稳定 selector，使用标明合成数据的隔离 fixture，生产入口不暴露模拟成功。
- [x] 1.3 完成1440px深浅主题首轮Skeleton截图、宽度/字体/单一MD编辑器/头脚滚动样式采样与确认记录；用户已确认正式方向为“单一 MD 编辑器 + 内嵌图片/文本文件材料块”（AC-PROTOTYPE-002）。

## 2. 草稿数据与权限契约

- [x] 2.1 新增草稿、版本、材料、确认和映射的数据模型、索引与增量迁移，覆盖SQLite/MySQL时间/JSON/唯一约束/CAS及重复迁移验证。
- [x] 2.2 实现本人授权项目的草稿创建/分页/读取/CAS保存、删除与确认竞争、绑定版本检查，验证多窗口、越权和迟到响应隔离（AC-008/009/018）。
- [x] 2.3 实现能力返回、Unicode码点/图片/候选限制、事务配额计数和稳定DTO/错误原因；同步具体OpenAPI契约（AC-002/019）。
- [x] 2.4 实现草稿主动删除、未关联上传24小时清理、共享/正式引用保护和备份恢复前删除标记重放，保留非终态材料（AC-017/019）。

## 3. 图文材料与受限 AI 整理

- [x] 3.1 实现私有图片上传、签名/解码/动画/像素校验、即时预览与内容代理，复用标准Bucket前缀及每次授权，覆盖撤权、超限与部分上传失败。
- [x] 3.2 接入经核验的多模态执行适配，建立只读上下文和材料副本、工具白名单/写权限隔离与清理；证明模型可读图片且无法调用正式写入（AC-001/003、AC-XCUT-003/006）。
- [x] 3.3 提取 /capture 整理规则与版本摘要，实现异步整理、结构化结果校验、待澄清及错误反馈；迟到/重新整理不覆盖人工版本。
- [x] 3.4 实现稳定候选内部ID与版本、类型切换分级校验、合并拆分来源边和删除集合，验证图片关系及超限拒绝（AC-004至007）。
