# web-admin-user-management Specification Delta

## MODIFIED Requirements

### Requirement: 用户创建与编辑
系统 SHALL 支持后台管理员通过弹窗创建用户，并编辑用户头像、昵称和角色。

#### Scenario: 创建用户
- **WHEN** 后台管理员提交包含用户名、头像、昵称和角色的创建表单
- **THEN** 系统校验用户名全局唯一、4-32 位、仅允许字母和数字且必须以字母开头，并在成功后创建待激活用户
- **AND** 用户名为空、长度不足、非字母开头或包含非法字符时，系统 SHALL 展示明确错误提示并阻断提交
- **AND** 系统生成一次性临时密码、写入后端 `password_hash`，并通过临时密码弹窗仅在本次创建结果中展示一次
- **AND** 临时密码弹窗 MUST 明确该密码用于用户本人首次登录激活，不表示账号已经处于正常状态

#### Scenario: 编辑用户
- **WHEN** 后台管理员编辑已有用户
- **THEN** 系统将用户名只读展示，并仅允许修改头像、昵称和角色
- **AND** 编辑提交 SHALL 只校验可编辑字段，不得因只读用户名不符合新增用户正则而禁用保存或静默阻断提交
- **AND** 若编辑保存失败，系统 SHALL 展示明确错误提示或失败反馈

#### Scenario: 防重复提交
- **WHEN** 后台管理员重复触发创建或编辑提交
- **THEN** 系统 SHALL 防止产生重复用户或重复写操作

### Requirement: 用户管理 UI 横切一致性
系统 SHALL 遵循 MoonBox 管理后台 UI 规则和用户管理横切验收要求，并将用户管理页作为后台 CRUD 列表页模板化适配的首个验收样板。

#### Scenario: 状态操作确认
- **WHEN** 后台管理员触发冻结、解冻、删除或重置密码
- **THEN** 系统使用设计系统确认弹窗，且不得调用 `window.confirm`
- **AND** 确认弹窗 SHALL 在“操作原因”标签展示红色 `*` 必填标识，且 `*` MUST 紧跟字段名同一行展示
- **AND** 操作原因为空、仅包含空白字符或少于 4 个字符时，系统 SHALL 在确认弹窗中展示明确错误提示
- **AND** 操作原因校验失败时，系统 SHALL 不调用对应用户操作 API

#### Scenario: Toast 不位移
- **WHEN** 用户管理页面展示成功或失败反馈
- **THEN** 系统使用 fixed toast，且不得引发布局位移或挤压列表、分页、弹窗内容

#### Scenario: 弹窗宽度与滚动
- **WHEN** 新增或编辑用户弹窗在桌面或低视口打开
- **THEN** computed width 与设计预期一致，弹窗 body 可滚动，底部操作按钮可访问

#### Scenario: 用户管理页模板化适配
- **WHEN** 用户管理页迁移到后台 CRUD 列表页模板或等价组合模式
- **THEN** 用户管理页 SHALL 保持用户列表、筛选、分页、创建、编辑、冻结、解冻、逻辑删除、重置密码、头像上传、临时密码展示和超级管理员保护能力无可感知回退
- **AND** 页面 SHALL 只保留用户管理业务字段、接口调用和业务规则
- **AND** 可复用的页面骨架、筛选、表格、分页、弹窗和 toast 行为 SHALL 收敛到模板或通用组件
