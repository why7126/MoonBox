# 提案

## 背景

`BUG-0010-admin-user-actions-validation-no-feedback` 已确认用户管理页存在两类前端校验反馈缺陷：

- 编辑已有用户时，保存逻辑仍受新增用户名正则影响；编辑态用户名不可编辑且错误提示不展示，可能导致保存静默失败。
- 重置密码、冻结、解冻、删除确认弹窗在操作原因为空时仅禁用「确认」按钮，不展示错误提示，管理员感知为点击无响应。

该问题影响后台用户管理核心流程，属于 P1/high 修复。

## 变更内容

- 调整用户编辑弹窗校验：新增用户继续校验用户名；编辑用户仅校验可编辑字段，不能因只读用户名阻断保存。
- 调整确认弹窗操作原因校验：空值、空白值或不足 4 个字符时展示可见错误，且不调用后端操作 API。
- 保持后端 `reason` 最少 4 字符的审计约束不变。
- 补充前端回归测试，覆盖编辑态异常用户名、空原因、短原因和合法原因成功路径。

## 非目标

- 不修改用户管理 API 契约。
- 不修改数据库结构。
- 不调整用户状态机、密码重置生成规则或审计字段。
- 不处理 `BUG-0011` 的列表枚举标签和时间字段展示问题。

## 回滚方案

如修复引发用户管理页提交异常，可回滚本 Change 对用户管理页前端校验和测试的修改；后端 API、数据库和 OpenAPI 不涉及变更，无需迁移回滚。
