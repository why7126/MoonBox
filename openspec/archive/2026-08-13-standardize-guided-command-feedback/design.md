## 设计目标

统一所有高频命令在“需要用户反馈”时的交互形态，降低开放式追问比例，同时保留用户自由补充的空间。

## 交互契约

命令在需要用户选择、确认、补充或处理阻塞时，MUST 优先输出一组原生交互卡片。原生交互卡片 SHOULD 支持可点击选项、推荐项高亮、跳过或关闭入口，以及可补充说明入口。

当客户端或工具层不支持原生交互卡片时，MUST 先声明降级原因，再降级为文本决策卡：

```text
降级说明：当前客户端或工具层不支持原生交互卡片，以下使用文本结构化选项。

需要你确认：
1. <决策点>
   - A. <选项>（推荐）：<推荐理由>
   - B. <选项>：<适用条件>
   - 可补充说明：<用户可自由补充的内容>
```

## 规则

- 每轮只聚焦 1-3 个关键决策。
- 每个决策点提供 2-4 个互斥选项。
- 至少一个选项标注“推荐”，并说明推荐理由。
- 默认包含“可补充说明”，除非问题是明确的二元确认。
- 用户选择后，后续回复只追问剩余阻塞点，不重复询问已确认事项。
- 不把引导式反馈用于无需用户反馈的成功路径；成功路径仍保持紧凑。
- 不用长篇开放式追问替代结构化选项；确实无法穷举选项时，先给推荐默认路径和补充说明入口。

## 边界

- 本规范只约束 Agent 命令的用户反馈输出，不改变业务产品界面。
- 本规范不要求所有客户端立即接入真实 UI 控件；支持原生交互卡片的客户端 MUST 优先使用交互卡片。
- `request_user_input` 等交互工具不可用时，命令必须先声明具体降级原因，再按文本决策卡输出。

## 校验策略

`scripts/validate-agent-context-budget.py` 增加目标命令 Skill 的契约检查，确保 `explore`、`capture`、`req-*`、`bug-*`、`sprint-*`、`opsx-*`、`release-*`、`git-*` 命令包含“原生交互卡片优先、声明降级原因、文本结构化选项降级”的引导式反馈约束。
