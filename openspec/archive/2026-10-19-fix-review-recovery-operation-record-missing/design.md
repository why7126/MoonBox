# 评审恢复记录完整性修复设计

## 背景与现状

部署 backend/worker 的旧 DIRECT_ACTIONS 不含 req-review，prepare 静默返回；completion_block_reason 见目录即读取 operation，因此 baseline-only 触发 direct_command_recovery_blocked。实际部署函数隔离复现与原轮次一致，详见 BUG root-cause.md E5—E8。工作区名单已扩展，实施前核对既有 diff，复用而不重复覆盖。

## 修复方案

### 动作与记录契约

以统一动作分类作为准备及收尾的输入。对 req-review、bug-review 以及现有 req/bug-generate、req/bug-complete、req/bug-opsx、sprint-propose、opsx-apply/modify/archive 建立适用矩阵；不同动作仍保留既有业务核验，不用扩大名单替代业务完成门禁。普通对话及未接入动作明确 N/A，不因目录残留进入错误检查。

准备只有在 baseline 与 operation 的动作、对象、轮次、项目绑定及基线身份可核对时成功；在启动执行器前验证完整性，写入失败明确返回失败。沿用现有原子单文件写入与锁，在两文件间中断时通过预检检测，不能声称两文件已有原子事务。收尾复用同一契约，不能仅以目录存在判断动作适用性，也不能缺记录直接放行。

### 兼容与恢复决策

| 状态 | 处置 |
|---|---|
| 完整且身份一致 | 继续既有候选及应用校验 |
| 新准备写入中断 | 启动前失败，保留已有记录与成果，明确阶段 |
| 旧 baseline-only | 识别历史兼容状态，只有原身份、权限、基线及应用账本可证明时沿既有恢复链核验；证据不足明确阻断 |
| 记录丢失、损坏或归属冲突 | 保留现场并给出具体诊断，禁止补空 operation 或伪造原身份 |
| 已应用但响应丢失 | 回读原应用结果，不重复迁移或创建评审记录 |
| 后续轮次、版本、权限或绑定变化 | 拒绝陈旧恢复，不覆盖新成果 |

不建设新通用恢复调度器，不把失败轮次改为成功。历史成果在现有能力不足时允许明确阻断并保留证据；不能因此宣称支持自动恢复。REQ-0047 承接通用持久化与续接增量。

### 完成与错误传播

沿用 BUG-0044 对象守卫、权威终态、成果指纹及同步证明。成功依据为后端校验、应用、同步与事实源回读，而非助手措辞。保留原始错误码和失败阶段，避免统一映射 executor_unavailable；若公开错误契约变化，同步 API 文档、OpenAPI、Orval 与接口测试。展示维持 REQ-0046 边界，无恢复能力不呈现入口。

## 测试策略

AC 映射见 verification.md。先在临时隔离目录调用真实模块复现旧缺陷，再验证修复；故障注入覆盖两次写入间中断、损坏、重复恢复、并发、权限及绑定变化。真实隔离产品入口分别验证 req-review 与 bug-review，从轮次到候选、应用、目录、索引、看板回读。不得用真实用户数据制造损坏。

## 部署与回滚

实施时记录 backend、worker、controller 的实际制品版本和相关模块摘要；核对运行进程加载版本而非仅新解释器文件。按受控本地验证流程检查活动任务再更新验证环境，生产部署需独立授权。仅工作区回归不满足 AC-008。保留旧记录，回滚不得删除成果或撤销合法应用；旧版本无法安全识别记录则阻断新执行。

## 数据采集与链路观测

product_data_collection_observability: applicable；affected_layers: api、request_logs、task_traces、task_trace_spans、治理候选/应用、Web 结果。

reason: 评审准备与收尾错误需要贯穿轮次、候选、应用与页面，防止恢复诊断丢失。

validation: 关联脱敏操作、轮次、候选和应用身份，覆盖准备、执行、应用与回读各阶段及原始错误；直接 API 与端侧已有链路 ID 透传均需核对。不得保存完整 Prompt、凭证或个人标识。usage_events 不新增计费事件；DB schema、保留周期、对象存储默认不变；无新公开字段则 OpenAPI/Orval 生成 N/A，有变化则同步生成。无 UI 布局改版，仍需真实页面状态证据。安全边界沿用权限、绑定和冲突检查，不放宽。

## 风险

旧版历史记录可能不足以安全恢复，明确阻断是合法结果；不静默重跑模型。已有工作区改动较多，实施前聚焦审查相关 diff 并保留无关工作。Sprint 剩余缓冲 7 人天，发现超出局部修复范围时重新估算，不将通用恢复需求混入本 Change。
