# 设计：验收返修台账分层

## 文档职责

| 文件 | 职责 |
|---|---|
| `tasks.md` | 计划任务与执行勾选；返修阶段只新增可关闭的返修任务项和台账链接 |
| `acceptance-fixes.md` | 完整验收返修台账、偏差证据、附件截图逐项视觉对照表、REQ 子文档一致性扫尾检查、文档未更新项原因 |
| `trace.md` | Change 执行事实、返修摘要、证据入口、验证结果和归档前可审计链路 |
| linked Issue `acceptance.md` | 面向验收的状态、待人工验收结论、证据列表和失败项 |
| linked Issue `trace.md` | 生命周期事件投影，由 Workflow Sync 维护 |
| Sprint 四件套 | 范围级验收入口和发布摘要，不复制完整返修台账 |

## 台账内容

`acceptance-fixes.md` 推荐包含：

- 返修批次：时间、反馈来源、范围判断、状态。
- 偏差证据：期望、实际、复现条件、证据来源、证据状态。
- 处理记录：改动摘要、影响边界、未改文档或系统边界原因。
- 附件截图逐项视觉对照表：仅在 UI/视觉反馈存在时使用。
- 验证证据：测试命令、截图、computed style、OpenSpec 校验。
- REQ/BUG 子文档一致性扫尾检查。

## 兼容策略

- 既有 Change 中已经写入 `tasks.md` 的返修记录不强制迁移。
- 新的 `/opsx-modify` 输出应优先使用 `acceptance-fixes.md`。
- 归档复核必须同时接受旧结构和新结构，但当新结构存在时以新结构为完整台账事实源。

## 风险与取舍

- 优点：`tasks.md` 恢复为任务清单，完整返修事实有独立台账，归档前审计更清楚。
- 风险：新增一个文档入口后，命令需要明确同步链接，避免台账与 trace 摘要漂移。
- 控制：`tasks.md` 必须保留台账链接，`trace.md` 必须保留证据入口，`opsx-archive` 必须读取台账。
