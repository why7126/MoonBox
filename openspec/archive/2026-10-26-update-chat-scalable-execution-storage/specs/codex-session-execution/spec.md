# Chat 执行配额与持续保存规格变更

## MODIFIED Requirements

### Requirement: 平台额度与结果空间
系统 MUST 使用服务端认证与用户空间可信计量；本次单机部署仍使用部署者 Codex 认证，费用及上游额度由该账号承担，不向前端或仓库脚本暴露凭证。用户／空间月度Token及累计Chat存储缺省无限，支持显式有限运营策略且升级保留；不设单轮Token预算，不以结果累计字节设固定业务上限。解析、队列与容器仅保留部署级资源保护。

#### Scenario: 未配置限额
- **WHEN** 月度Token或累计Chat存储运营配置未提供
- **THEN** 默认为无限并记录用量，必要认证、仓库或存储配置缺失仍返回未就绪，非法配额报错而非无限

#### Scenario: 显式不设运营上限
- **WHEN** 用户／空间策略为unlimited
- **THEN** 不按相应运营总量阻断；既有有效并发策略、同会话互斥及未知态继续生效，部署处理能力不足时受控排队

#### Scenario: 终态已确认但用量尚未核实
- **WHEN** 收到可信终态而无可信Token用量
- **THEN** 幂等释放该轮并发占用，Token保持未知，实际已提交存储按账本计量，迟到结算不重复释放或累计；未知执行仍占用互斥

#### Scenario: 结果超过预留
- **WHEN** 累计结果超过旧单轮预留或固定快照总量
- **THEN** 不据此中止，按有界批次继续保存；只有显式有效存储运营配额或真实资源保护触发才安全停止并保留已提交结果

#### Scenario: 升级有限策略与废弃预算
- **WHEN** 升级含已有有限月度或存储配置及旧单轮预算
- **THEN** 保留有限运营策略，旧单轮字段仅兼容诊断不限制新轮次，排空或核验旧活动轮次后切换

### Requirement: 事件持久化与可信差异
系统 MUST 保留事件归属、原标识和本地序列，持续分块提交并去重，使用可信前后快照区分本轮和累计Diff；禁止以内存全量汇总作为持久化前提。只有提交完成的段可报告已保存。

#### Scenario: 两轮修改同文件
- **WHEN** 第二轮调整第一轮已修改文件
- **THEN** 本轮差异只反映第二轮且保留累计基准，全文与差异可按需读取

#### Scenario: 事件重放
- **WHEN** 终态后收到重复或较早事件
- **THEN** 依据可信来源标识与偏移去重，不重复消息或把终态回退；缺乏重放依据时标明未知缺口

#### Scenario: 保存中断
- **WHEN** worker在块写入或段提交时退出
- **THEN** 重启仅公开已提交段，校验未发布块并显示未确认尾段，重复恢复不重复计量
