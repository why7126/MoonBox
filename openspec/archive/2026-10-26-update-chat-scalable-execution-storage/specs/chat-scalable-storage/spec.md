# Chat 大规模快照与分块存储规格

## ADDED Requirements

### Requirement: 不设固定规模门槛的可信快照
系统 MUST 分批扫描受信文件并建立版本化快照，不按文件数或总字节拒绝；路径、Git忽略、符号链接、硬链接、特殊文件与撤权边界保持。

#### Scenario: 大规模仓库
- **WHEN** 至少12000文件和600MiB样本在资源充足环境执行
- **THEN** 能建立完整基线并开始执行，该样本不是新上限

#### Scenario: 增量与属性变化
- **WHEN** 文件新增、修改、删除、重命名或权限变化
- **THEN** 增量索引与独立全量对照一致，仅可靠内容证据允许复用

#### Scenario: 中断或并发漂移
- **WHEN** 扫描退出或发现并发修改
- **THEN** 保留上一有效版本，未完成版本不可成为可信基线，恢复重新校验检查点

### Requirement: 持续保存与有界读取
系统 MUST 将事件、回复、快照正文与差异保存为可验证的分块或索引，保存量与展示窗口分离；队列满执行背压或安全停止，不静默丢弃。

#### Scenario: 长输出和重连
- **WHEN** 输出至少32MiB且浏览器断开重连
- **THEN** 已提交段可按可信游标顺序回读且摘要一致，不重复展示，不受旧16MiB总量门槛限制

#### Scenario: 大文本与二进制
- **WHEN** 文本超过64KiB或合计4MiB，或内容为二进制
- **THEN** 全文可按需保存读取，二进制采用适合的内容引用；未加载、计算中、缺失和历史不可用分别表达

#### Scenario: 工作内存约束
- **WHEN** 固定处理窗口下总输出扩大四倍
- **THEN** 满足设计预先冻结的RSS和时延预算，不按总内容聚合，保留测量和环境证据

### Requirement: 部署资源保护与原轮次恢复
系统 MUST 保留有限协议解析、队列、CPU、内存及进程保护；区分运营配额、磁盘、保存、容器、协议和上游错误，保留阶段及已保存范围；部署保护不进入运营配置。

#### Scenario: 保护触发
- **WHEN** 合法超保护帧、畸形消息、存储失败或容器异常发生
- **THEN** 返回稳定分类与安全处理路径，已提交结果不丢失，同机服务健康按设计基线验证

#### Scenario: 准备失败续接
- **WHEN** 证实原轮次尚未开始且资源已恢复
- **THEN** 以原turn_id的新attempt幂等续接准备，保留历史失败，实际执行与回读独立验证

#### Scenario: 运行终态未知
- **WHEN** 不能证实原执行结束
- **THEN** 先核验原进程与成果，保持互斥及人工处理路径，不直接重发；已终止后的显式重试仍按既有新轮次关联契约执行

### Requirement: 迁移删除与可信计量
系统 MUST 支持版本化双读、分批迁移与校验，保留旧有效数据；删除意图覆盖所有新增引用及恢复；Token未知不记零，存储按唯一已提交对象与账本计量。

#### Scenario: 历史缺失与迁移退出
- **WHEN** 旧快照无全文或迁移被中断
- **THEN** 明示legacy_unavailable，保留旧读取并可恢复迁移；回滚只到支持现有数据的兼容版本，不删除新数据

#### Scenario: 删除后备份恢复
- **WHEN** 已删除会话经迁移或备份恢复重新出现引用
- **THEN** 读取前重放删除意图且拒绝内容可见，受保护审计副本继续独立管理

#### Scenario: 重复引用与迟到用量
- **WHEN** 同会话复用对象或重复收到Token结算
- **THEN** 物理正文按会话内唯一对象计量，迟到用量仅幂等补差，未知保留null；SQLite/MySQL结果一致

### Requirement: 脱敏执行观测
系统 MUST 关联行为、请求、轮次与任务阶段，仅采集计数、字节、耗时、错误类别和标识；正文与观测分离授权。

#### Scenario: 直接调用和采集失败
- **WHEN** 直接API执行或观测存储失败
- **THEN** 不伪造用户行为，观测可降级且不阻断业务；业务结果保存失败仍走安全停止／核验
