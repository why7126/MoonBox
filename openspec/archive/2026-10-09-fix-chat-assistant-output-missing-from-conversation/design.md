# Chat 助手输出正文可读性修复设计

## 背景与现状

静态检查 execution.py：run_claim 将增量写入 execution.output，并累积 reply；正常收尾在快照和容量检查后写入 assistant 消息。启动后的异常可能进入 unknown。reconcile_unknown 读取权威终态并恢复工具事件，当前未见助手正文补写。这是候选故障机制，不能证明历史两轮实际执行路径。消息分页或 Web 展示遗漏仍需排除。

## 根因与授权边界

生成时 root_cause_status 为 hypothesis，按当轮用户指示豁免生成门禁；实施前 BUG E10–E12 已将当前机制确认为 confirmed，根因门禁通过。后续实施用隔离合成轮次验证当前代码机制；任何测试结果均不反推已删除的历史轮次。生成阶段不执行产品修复或历史数据回填。

## 修复方案

1. 建立按 conversation、turn、executor turn 和 message/item 标识关联的正文选择规则。已有持久化最终答案优先；缺失时仅投影同轮次已保存的 assistant 输出。工具输出不能作为助手正文。
2. 优先让执行写入与恢复共用幂等正文落库逻辑；使用现有事务、generation 和 worker fencing，避免旧 worker 覆盖新一代或重复恢复产生多条助手消息。先核对现有约束；若必须加唯一约束，先检查历史重复并制定 SQLite/MySQL 兼容迁移。
3. 对 unknown 或收尾未完成的读取提供有界降级：服务端在权限检查后按稳定序号读取同轮次输出，按 item 边界去重归并，并标注部分输出来源。不要在 GET 中写库，不将降级结果重复计入持久化消息总数；分页采用轮次稳定锚点，已存在正文不再重复投影。
4. 明确增量与完成快照互斥的归并规则：同 item 的最终快照替代其增量，不二次追加。缺失 item 标识的历史数据只按可信 turn 和 sequence 有界归并；无法证明完整时展示部分内容。事件缺口、容量裁剪和截断显式标识，不从日志恢复未授权原文。
5. 最终答案与过程消息区分。权威 final_answer 可替代对应部分正文；仅有 commentary 或增量时保留部分输出语义。显示正文不改变 stopped、failed、unknown，不解锁未知轮次的重复发送。
6. API 如需增加正文来源、部分标识或截断字段，采用可选兼容字段并同步 schema、OpenAPI 和客户端。Web 复用现有安全 Markdown 与消息组件，不新增动作按钮或 modal；必要样式调整按现有 UI 合同核查，保持窄屏和轨迹入口。

## 验证策略

覆盖 BUG acceptance.md AC-001至AC-009：停止、未知、恢复为三类终态、重复事件与并发恢复、正常完成、无输出、历史分页、替代证据边界、权限脱敏。重点注入输出事件提交后断连、消息事务回滚、快照或容量失败，核对事件已保存时正文可读；使用正常停止作对照。断言消息数量、稳定身份、正文选择和终态不被误报。

合成后端测试、API 分页集成测试、前端状态测试与真实浏览器观察分别留证。浏览器覆盖刷新、重进、对话/轨迹切换及1440px和窄屏；不使用真实归档命令复现。

## 产品数据采集与链路观测

product_data_collection_observability：applicable。
affected_layers：chat_messages、execution_events、request_logs、task_traces、task_trace_spans。
reason：正文补存和事件投影跨越消息持久化、执行事件、API与Web展示。validation：后端关联、幂等、权限和DOM状态验证通过；真实浏览器验收待环境补齐，详见 verification.md。观测只保存脱敏标识、计数、长度、错误类别和状态，不新增正文、Prompt、工具结果或凭证到日志。
usage_events 新增采集为 N/A：不新增用户动作入口；客户端链路 ID 协议、对象存储与保留周期变更为 N/A：当前设计不调整这些边界。实施范围变化时重新声明。

## 风险与回滚方案

事件序号缺口、多个 item、重复快照和读写竞态可能造成内容重复或错误拼接；用稳定身份、有界读取和原子幂等测试控制。读取降级不能无界扫描会话，测试查询数量与事件窗口。回退实现保留既有数据；不删除补写正文，不回滚真实业务执行结果。

## 待实施时确定

核对事件分页协议、消息唯一键和现有 UI 状态字段后决定最小接口/索引变更；在 tasks 中记录选择及证据。本次方案不将这些设计决策写作已实现事实。

## 实施契约补充

当前机制已由 BUG root-cause.md E10–E12 确认；历史 T1/T2 仍不可判定。本次不新增表或字段，正文幂等使用确定性消息主键和已锁定的 turn；执行异常、正常收尾和恢复共用写入 helper。消息 API 的虚拟行参与 SQL 分页，落库前后使用相同 ID 和 turn 创建时间，GET 不写库。每轮最多检查1000条事件和200000字符，超界或序号缺口显示部分/截断；最终答案以有界脱敏的权威 final_answer 事件为依据。

### UI 状态与视觉契约

此为正文可读性修复，不进行参考稿复刻，无新布局、动作按钮或 modal。沿用 `/chat` 既有 `.chat-assistant-col`、`.chat-message-bubble` 和安全 Markdown；新增 `[data-testid=chat-partial-output]` 文本提示，未知/失败/停止状态仍由 TurnActivity 展示。已有正文时不重复显示活动区增量。1440px与窄屏核对正文宽度、换行和状态提示；使用合成 API 的组件测试只证明前端状态，真实后端行为由隔离 API 测试单独验证。当前 Change 无 prototype 资产，Skeleton 重建不适用。
