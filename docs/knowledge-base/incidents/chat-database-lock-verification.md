# Chat 数据库锁竞争与核验事务隔离经验

SQLite零行UPDATE也会开启写事务。先写terminal再扫描文件的读取路径可以拖住共享库，不能把随后报错的鉴权线程当作持锁者。现场线程栈、内核锁与部署版本需对齐，再用独立数据库验证；采样不等于完整事务时长，当前线程不能追溯当作历史故障线程。

修复采用无写事务的核验计划与短事务围栏应用，保留权限、项目代次、完整guard原值及终态校验；锁重试只覆盖已回滚且无业务副作用的短数据库事务。提交未知先读权威事实，不重放apply或模型。生产运行时版本与隔离源码验证分别记录。

测试复用边界：双库并发与注入证明事务机制；真实执行器样本证明当前源码端到端保存；浏览器合成身份样本证明显示与自动核验。都不将原BUG-0056轮次改为成功。外部编辑器与治理写入仍须遵守既有快照/并发校验，不能宣称数据库锁阻止任意文件修改。
