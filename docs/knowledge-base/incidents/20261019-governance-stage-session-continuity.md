# 治理阶段慢收尾与对象会话连续性

历史案例中，治理文件先推进阶段，下一动作在前轮结束前开放；会话选择排除活动会话，导致同对象新建会话。根因证据位于 BUG-0044 的 root-cause.md，运行数据仅保留脱敏时间关系。

## 防止复发

- 文件存在、消息中的完成表述、任务全勾和轮次成功均不能单独作为交付完成依据。业务核验、同步证明和稳定成果指纹共同决定完成型阶段迁移。
- 对象守卫在发送事务中抢占；准备会话不提前占锁。唯一键覆盖授权项目和规范化对象，版本与轮次身份防止陈旧回调释放新执行。
- 忙碌会话作为查看原执行的入口；不通过另建会话绕过执行互斥。其他用户只能看到忙碌摘要。
- 失败、停止和未知保留原终态及成果；只有权威终态与成果核验满足条件才能恢复。心跳超时不是重发许可。
- 开发/返修启动及时显示研发中，与完成型迁移分开；只读文档和进度仍可访问。

## 本次接续验证

原产品执行经用户授权停止后，本机会话接管，未并发修改同一工作区。测试恢复使用本机隔离依赖；临时目录使用真实路径，保留符号链接拒绝策略。

SQLite对象守卫、准入、会话复用、权限、阶段和生命周期回归通过；MySQL独立临时容器验证竞争与恢复，不连接现有业务库。具体计数和证据见 Change 的 verification.md。合成回归不等于逐入口真实产品验收。

UI骨架已获用户确认；实际1440px状态、只读抽屉、原会话与草稿取证完成。真实REQ生成成功及BUG慢收尾/负向结果分别记录，不把每个入口的HTTP验证说成独立模型完成。最终就绪以Change机器验收清单为准。

源模式应用必须保存与成果指纹绑定的同步证明；旧成功结果只能回读精确成果并重新运行只读同步检查后补证。completed但无写入不等于业务完成；可信终态和精确基线一致可恢复同阶段重试。failed/stopped合法成果保留并核验，unknown不解锁。历史归档目录是终态事实，不能强求所有旧trace含新execution字段并伪造时间。
