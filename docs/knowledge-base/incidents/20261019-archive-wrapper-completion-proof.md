# 归档包装脚本完成证明与状态收敛

BUG-0049：顶层命令识别不能代表包装脚本内部同步。正式文件已归档时，门禁仍可能缺少可核验的完成证明；单纯扩充脚本名白名单不能解决真实性问题。

修复由 archive_proof 读取原私有基线、校验项目绑定与执行身份、比对归档 delta 及合并后的 Requirement 全量集合，检查归档位置和 Issue/Sprint关联，再在项目锁内运行固定源码工具的只读 Workflow Sync check并复读快照。只保存新的 archive_verification，不把历史 false 改成 true。原执行门禁由operation/version保护。

仅完成轮次允许自动重核验；失败、停止、未知不在本次恢复范围。目标capability发生后续合法变更也可能导致旧结果无法证明，保持待核对并给出原因；RENAMED delta暂不自动确认。无delta的文档类Change仍校验核心归档文件和工作流。

真实观察：BUG-0048由验收中恢复已完成；未重跑归档。独立首次归档样本BUG-0050结果以本Change最终证据为准，不能用旧轮次恢复冒充。

验收期间父任务与样本并发治理写入导致注册表回指review；门禁正确拒绝。正式样本执行必须暂停其他治理写入，串行核验后再恢复父任务，不能用恢复样本冒充无干扰首次成功。BUG-0051经用户补充授权独立执行。

## 只读检查的派生时间兼容

archive_workflow_check.py 强制只读，只忽略目标已归档 Change 在 Sprint 展示行的时间戳差异，状态、路径和其他内容继续严格比较。避免 accepted_at 更新顺序形成假阳性；不修改治理源文件。运行子进程显式绑定已部署 backend 的模块路径。BUG-0051以原归档轮次复核通过，未重放。
