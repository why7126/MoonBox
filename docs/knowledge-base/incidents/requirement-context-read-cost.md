# 需求中心快照读取性能与安全复用

## 已验证机制

同一请求的注册表身份索引与归档目录索引可消除逐卡重复解析和扫描；106身份与171目录对照需同时覆盖短ID歧义、活动优先、重复归档、删除、版本隔离和越界路径。标题只在不可变请求上下文复用，不缓存授权或可变响应。

首遍缓存字节只是候选，第二遍完整读取后逐字节比较。即使文件系统没有推进mtime/ctime，第二遍差异也会使尝试失效，后续回退双遍完整读取。用目录描述符、O_NOFOLLOW、文件类型/链接数/大小及读取前后fstat保留原安全边界。缓存预算需计入字典、路径和元数据对象，不能只算正文。

## 测量边界

局部索引微基准、ASGI HTTP和真实浏览器分别记录。正常HTTP需补齐核对、投影、提交、序列化调度及请求审计；父子阶段不能相加。冷样本清理应用缓存不等于清理操作系统页缓存。旧基准夹具会随业务模型字段和模块相对导入变化失效，须先跑成功探针再做长测。

## 当前限制

本次按固定输入完成时延和30分钟资源验证；功能回归、配对HTTP和真实浏览器分别签认，首次空库初始化单列。长请求下RSS应独立定时采样，不能等请求结束才采集；先按目标并发预热。尾部不稳定时固定扩大样本数并保留既有慢样本，不按结果挑选批次。源规模增长超过固定上限时，应由用户明确选择上限内扩容/超限拒绝或另行评审上限；本轮用户选择保留安全上限。证据与当前结果见[Change验证记录](../../../openspec/archive/2026-10-30-fix-requirement-center-context-load-latency/verification.md)。

## 首页摘要与证据核验分离

sprint-015 后应先确认首页的真实依赖集合，而不是把源码目录、开发 worktree 或恢复点的数量直接当作根因。摘要可以排除文档/规则正文及深层验收证据，但必须保留该集合的安全读取、字节新鲜度与当前权限；完整检查继续使用完整快照，摘要“待检查”不能变成通过或写资格。

不可变快照内复用纯文件关联索引能进一步降低暖读成本；卡片、用户可见性、执行状态和验收判断应逐请求生成。只有版本相同才能复用，不能仅靠 TTL、mtime 或 watcher 判断。停止全量轮询后，活动进度可用有界轻量状态读取，仍需处理项目切换、权限撤销、隐藏页和过期响应。

验收应分别保留固定版本的自然/受控负载窗口，以及并发文档变化导致重建的样本。正式页面首卡、HTTP、排队/等待/传输和服务端独占/嵌套阶段分别对账；服务健康、镜像哈希一致和单次快速响应仅为前提。2026-10-29 的正式 120 样本满足门槛，但压力刷新 P95 接近边界，八组持续资源测试中的文档失败重试也须保留，不能推导任意过载条件下均满足目标。当前最终资源结论以关联 Change 验证记录为准。


## 最终归档证据边界（2026-10-30）

最终120请求复验与后台审计关联通过；自然/额外2CPU打开HTTP P95分别0.307/0.384秒，首卡0.573/0.715秒，刷新0.389/1.199秒。此前失败与阶段通过窗口保留，不能由最终通过推断任意负载达标。资源与配对证据按明确源指纹边界复用，未宣称全部在最终审计版本重跑；详见[归档验证](../../../openspec/archive/2026-10-30-fix-requirement-center-context-load-latency/verification.md)与[Sprint复盘](../retrospectives/sprint-014-retrospective.md)。
