# 会话准备延迟的证据边界与安全优化

本轮确认的是重复完整快照读取位于会话导航关键路径；不反推历史21.27秒请求的精确耗时比例或数据库等待。当前机制可以闭合，历史未知继续明确保留。依据：[修复验证记录](../../../openspec/changes/fix-object-session-preparation-latency/verification.md)。

## 可复用经验

1. 浏览器等待服务响应只能定位等待区间。升级到同请求响应ID、阶段区间及审计关联后，才分析准备阶段；嵌套阶段以区间并集扣除，避免重复计算。
2. 优化完整读取次数时，授权/绑定/epoch、实际文件字节与源投影一致性都要重新证明。同路径别名用目录描述符确认物理身份，不能只用路径字符串；不能跨reconcile事务沿用可信快照。
3. 暖态、冷态和并发分别固定数据、实际候选代码、资源及采样规则。独立进程冷缓存不等于OS冷缓存；中间慢样本和失败必须保留。CPU预算决定并行上限。
4. 并发性能改善可能暴露原有SQLite读后写升级竞争。使用真实双连接同步屏障重现，再把短写入保护限制在明确写入口；不把文件扫描搬进写事务，不将SQLite分支测试冒充MySQL实机结果。
5. 真实浏览器测试要区分路由到达、历史呈现和可交互。离页取消与组件卸载证据不同；没有实际导航的点击、故障未命中的成功请求不能当成取消/失败通过。
6. 临时加载候选与诊断只服务取证。恢复原件、健康、临时文件和数据库清理均有摘要证明；验收通过不表示已经发布。
