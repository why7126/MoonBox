# Chat 未知轮次重复创建容器的恢复调度经验

BUG-0064的运行证据显示：容器自动销毁正常，旧unknown轮次仍被每轮扫描重新读取，预检与读取各自创建容器。因此仅清理容器不能解除触发条件。原执行最初进入unknown的具体异常仍未知，不应以资源治理猜测业务终态。

恢复动作需要持久预算、到期时间、并发租约与独立暂停态；次数在领取时消费，异常退出也不返还，重启不重置。租约终态提交使用同事务围栏，旧持有者清理只限定自身代次，避免误删新代资源。正常任务和恢复槽隔离，恢复等待不占用正常调度。

成功预检复用必须绑定镜像内容、工作区身份、策略和认证版本，仍保留实际权限检查。无变化提示只能减少相邻一次读取，不能永久遮蔽权威终态。真实Docker验证与合成时钟测试分别记录；清理结论必须由登记资源的零残留检查证明。

具体实现、失败修复和验证结果以[Change追溯](../../../openspec/archive/2026-10-26-fix-chat-unknown-recovery-container-churn/trace.md)为准；归档验收与下述运行实例部署分别记录。

兼容边界：按本次范围保留的旧 API 服务尚未包含恢复账本清理逻辑；带恢复记录且未来已解除活动锁的会话，在旧 API 上删除历史可能受外键约束阻止。当前 unknown 会话原本就被活动锁禁止删除。后续完整发布需同步已归档修复中的 API 清理代码；本次不重建 API 服务。出现运行问题时优先关闭新 worker 自动恢复，保留账本与业务数据，不直接启动会无界重试的旧 worker，不通过将 unknown 人工改成成功来止血。

`product_data_collection_observability`: 适用；`affected_layers`: worker、恢复账本、既有 Task Trace。`validation`: 只采集恢复状态、次数、到期时间、健康状态和 Docker 生命周期计数，不采集会话正文、提示词或凭据。API 字段、UI、客户端生成及对象存储未变；数据库仅新增已验收的恢复表。
