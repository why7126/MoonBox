# 迭代归档接入 Sprint 对象会话与命令预填

## 背景

需求中心当前迭代容量区域已有归档入口。前序探索通过浏览器观察到，可见对象均已完成时，入口仍因验收报告 sign-off 缺失禁用；源码显示当前确认按钮仅提示手动执行命令。该观察不代替 Sprint 完整范围的完成判定。需求中心 REQ、BUG、CHANGE 卡片已有对象会话准备、复用与 Chat 跳转链路，可作为本需求的交互基线。

本需求作为 REQ-0037 的后续增强，关联 REQ-0039，将 SPRINT 接入同类对象会话能力，并把“进入归档会话”的条件与“归档执行成功”的条件分开。原需求的已归档交付事实保持不变。

## 目标用户与目标

- 项目负责人：从已完成范围的 Sprint 直接发起收尾，减少手动寻找会话与输入命令。
- 产品、开发和测试协作者：保留同一 Sprint 的讨论与执行上下文，清楚知道尚未发送、执行中、归档受阻或归档成功。
- 治理维护者：保留权限、验收签署和同步门禁，避免入口状态提前阻止用户进入收尾流程。

成功表现为用户一次点击进入正确 Sprint 会话，获得准确待发送命令；最终状态来自实际归档结果。

## 范围

### 包含

当前迭代归档按钮的准入计算与反馈、SPRINT 对象身份解析、可用会话复用或创建、Chat 导航、命令预填、草稿保护、执行中保护、幂等、防跨项目串会话、执行期门禁和归档后的状态刷新。

### 不包含

不建设新的 Sprint 管理页，不扩展其他 Sprint 命令入口，不批量改造 REQ/BUG/CHANGE 卡片，不自动发送或执行命令，不跳过签署，不自动认可验收，不改变既有 Sprint 生命周期，不在本阶段实现业务代码或创建 OpenSpec Change。

## 功能要求

### FR-001 按完整范围判断入口资格

服务端基于当前项目的 Sprint 事实源解析全部 REQ、BUG、Change 及其关联交付状态；使用与需求中心“已完成”一致的权威映射，不简单以任务勾选率、前端列位置或单个 applied 状态作为完成证明。关联 Change 不能因隐藏为非独立卡片而漏检。

有至少一个范围对象、全部对象完成且 Sprint 尚未归档时，允许发起归档会话。搜索、类型筛选、分页和当前可见卡片数量不改变判定。容量为零或容量未知不单独否决已确定完整且完成的范围。空 Sprint 禁用并提示“迭代暂无对象”；范围或对象状态无法确认时禁用并提示待核实，不能将未知当作完成。仍有未完成对象时说明未完成数量，并在已有权限内提供可定位信息。

### FR-002 分离入口检查与最终归档门禁

入口检查范围完成、Sprint 存在且未归档、项目权限和可用事实源。验收报告签署、归档文档完整性及最终 Workflow Sync 结果不作为进入会话的完成条件。

点击按钮和导航均不修改 Sprint 归档状态。命令发送后重新检查最新范围和权限，并执行现有归档流程的签署、文档一致性、Change 闭环、同步和恢复门禁。签署缺失时提供检查结果与后续操作，不伪造签署、不报告归档成功。入口通过不构成最终归档通过证明。

### FR-003 直接进入 Chat 工作台

点击归档按钮后准备对象会话并直接进入 Chat 工作台，正常路径不再经过当前“进入归档确认流程”弹窗或仅显示手动执行提示。准备中按钮显示加载态并阻止重复点击。

进入后显示可识别的 Sprint ID 与当前项目上下文。若请求期间切换项目，旧请求结果不能将用户带回错误项目或注入错误命令。准备失败保留原页面，展示可重试反馈；不降级为无关联空会话。

### FR-004 SPRINT 对象身份与会话复用

对象类型为 SPRINT，对象 ID 为实际规范 Sprint 编号。身份至少包含空间、仓库/项目、对象类型及对象 ID，并受当前用户的会话访问策略约束。不能把 Sprint 作为 CHANGE 处理，也不能仅按会话标题搜索匹配。

优先复用该对象最近的未归档、未删除且当前用户可用的会话；多会话排序沿用对象会话服务：执行保护先行，普通候选按最近 turn 更新时间、最近消息更新时间（均有值优先）、会话 updated_at、created_at、ID 降序，具体见 business-flow.md。不恢复已删除或已归档会话。没有可用会话时创建并建立对象关联。没有权限访问某个会话时不泄漏其内容，是否可创建自身会话遵循既有对象权限策略。

### FR-005 精确预填且不自动发送

会话就绪后，输入框填入斜杠命令、单个空格和当前 Sprint 完整 ID。例如目标为 sprint-011 时，文本为 `/sprint-archive sprint-011`。不附加隐藏执行指令，不残留模板参数。

预填不自动点击发送，不创建消息、执行 turn 或归档任务。用户可以编辑、删除或主动发送。已有输入与目标命令完全相同时不重复插入；输入为空时直接填入。

已有不同非空草稿时，默认保留草稿，在 Chat 内提供“填入归档命令”与“保留当前草稿”选择。用户选择填入后才替换，选择保留则撤销本次待预填意图。该例外不影响进入正确会话，也不以新建会话绕过草稿保护。待预填意图按目标会话隔离且只消费一次，刷新或返回不反复覆盖输入。

### FR-006 执行状态保护与幂等

复用既有对象执行保护：SPRINT 正在执行、结果待核对或存在阻止继续操作的状态时，进入对应可见执行会话并说明原因，不替换草稿、不新建会话规避保护、不自动重发归档命令。状态收敛后用户可重新从入口准备命令。

同一用户同一对象的重复点击、并发请求及失败重试不能产生多个等价新会话。新建和关联需要作为完整准备结果返回，关联失败不得报告就绪。归档发送后的重复执行防护复用现有治理命令机制。

### FR-007 权限、状态变化与失败反馈

前后端均遵守对象与项目权限；服务端独立校验，不能依赖按钮禁用保护。无权用户看不到其他用户会话内容，也不能创建越权执行入口。

读取后范围发生变化、对象重新进入研发中、Sprint 已被他人归档、会话不可访问或请求失败时，重新读取相关状态并给出明确反馈，不沿用旧就绪缓存强行启动。已归档 Sprint 不继续展示可执行归档入口；查看历史会话沿用既有能力。

### FR-008 结果刷新与追溯

用户发送后通过 Chat 展示真实执行状态及门禁失败信息。仅在既有归档流程确认成功后更新 Sprint 当前态。回到需求中心时重新读取当前迭代列表、容量和 Sprint 统计；刷新失败给出重试提示，不将失败伪装为已同步。

归档执行失败、等待签署或只完成会话准备时，Sprint 保持真实未归档状态。已成功归档的 Sprint 按既有规则退出当前迭代区域，历史交付对象与会话仍可追溯。

## UI 约束与参考契约

保真模式为局部一致：附件截图用于确认容量条右侧归档图标的位置和既有视觉语言，不要求整页像素复刻。用户确认的直接进入 Chat 行为优先于旧归档确认弹窗。截图中的容量、数量和 Sprint 编号是示例数据，不作为固定渲染值。

| 组件/动作 | 参考锚点与目标定位 | 状态与交互 | 后续验收证据 |
|---|---|---|---|
| 归档按钮 | 容量条右侧图标；`current-iteration-archive-action` | 可用、禁用、加载、键盘 focus；正常路径 modal 为 N/A | 1440px 与窄视口截图、DOM 状态、computed style |
| 入口原因提示 | `current-iteration-archive-summary` | 展示未完成或未知原因；不用 sign-off 阻止进入 | 可访问名称、提示文案、截图 |
| Chat 命令输入 | 既有 Chat 输入组件；产品 selector 为 [data-testid=chat-prompt] | 空输入、已有相同命令、不同草稿、执行保护 | 输入值、未产生消息/turn 的请求与产品证据 |
| 草稿冲突选择 | Chat 现有交互组件族；已实现 selector 见 prototype/web/context.md | 保留为默认，用户明确选择才替换 | 两个分支的交互与截图证据 |

保持现有容量、指标、筛选及看板布局，复用设计 token 和按钮样式。采样按钮尺寸、padding、图标大小、颜色、边框、focus 样式及窄视口溢出，不在本阶段虚构像素值或视觉通过结论。req-complete 已在 prototype/web/context.md 补齐 selector、UI Reference Replication Contract、状态与动作矩阵，并提供交互原型；真实骨架确认与分阶段验收证据留待实现。

## 验收方向

| 编号 | 条件 | 预期 |
|---|---|---|
| SC-001 | 全范围完成但尚未签署 | 可以进入 Chat；发送后检查签署，不能提前归档 |
| SC-002 | 未完成对象被筛选隐藏 | 仍禁用入口，并说明未完成 |
| SC-003 | 空范围或状态未知 | 禁用并区分原因；容量未知但范围可确认且全部完成可进入 |
| SC-004 | 有会话、多个会话、无会话 | 分别复用、按统一规则选择、新建关联；不串项目 |
| SC-005 | 输入为空或已为目标命令 | 精确预填且只出现一次，不发送、不产生 turn |
| SC-006 | 存在不同草稿 | 默认保留；主动选择后填入；刷新不重复覆盖 |
| SC-007 | 连点、重试、对象执行中 | 不重复新建或执行；进入正确执行会话并保护输入 |
| SC-008 | 无权限、切换项目或状态过期 | 服务端拒绝或重新校验，旧响应不污染新项目 |
| SC-009 | 归档成功、受阻或失败 | Chat 与需求中心反映真实结果，无提前成功展示 |
| SC-010 | 1440px、窄视口及键盘操作 | 图标位置一致，状态可识别，提示可访问，输入不溢出 |

以上 SC 编号仅标识 PRD 摘要场景；正式 AC 编号统一见 acceptance.md。以上为 PRD 验收方向，未执行验收；正式清单见 acceptance.md，尚未执行产品验收。

## 影响面与观测

- Web：需求中心归档入口、Chat 导航与草稿接收；保留原有对象卡片行为并做回归。
- API：对象会话准备与 Sprint 准入需要支持 SPRINT/sprint-archive；若契约改变，同步 OpenAPI、API 索引和生成客户端。
- 数据库：先核查既有对象关联是否支持 SPRINT，尚未确定需要迁移；若需调整，覆盖 SQLite/MySQL 与数据库设计文档。
- 安全：沿用权限、会话所有权、项目隔离和执行保护；不新增跨用户共享权限。
- 观测：按 `docs/standards/product-data-collection-observability.md` 区分入口点击、会话复用/创建、预填与用户发送后的执行；请求、会话、Sprint、任务上下文可关联，预填不能记为归档执行成功。
- 行为事件和请求日志失败不得阻断主业务；不得记录完整草稿、Prompt、凭证或本机路径。验证失败路径可排障且脱敏。
- 对象存储、部署拓扑、管理后台和移动端为 N/A：本需求不新增这些端或资源操作；复用既有运行环境。
