# 迭代归档会话入口用户故事

## 用户故事与验收映射

| 编号 | 角色与目标 | 验收要点 | 功能/验收关联 |
|---|---|---|---|
| US-001 | 项目负责人希望全部对象完成后从容量条发起收尾 | 全范围判断；签署未完成仍能进入会话；空范围及未知状态有原因 | FR-001/002；AC-001～004 |
| US-002 | 协作者希望回到同一 Sprint 的讨论上下文 | 复用最近可用会话；无可用会话才创建；同编号跨项目不混用 | FR-003/004；AC-005～008 |
| US-003 | 操作者希望发送前检查命令且保留自己的草稿 | 精确预填、可编辑、不自动发送；不同草稿默认保留 | FR-005；AC-009～012 |
| US-004 | 正在执行任务的用户希望避免重复提交 | 忙碌或待核对进入现有执行；连点/重试不重复新建；不覆盖输入 | FR-006；AC-013/014 |
| US-005 | 项目负责人希望只看到真实归档结果 | 发送时重新检查，签署缺失不给成功，成功后刷新事实源 | FR-007/008；AC-015～019 |
| US-006 | 键盘及窄屏用户希望准确识别按钮状态 | 可访问名称、focus、禁用原因、响应式与局部视觉一致 | UI 契约；AC-PROTOTYPE-001～006 |

## 非目标与权限

本次只增强已有归档入口。不会赋予跨用户会话访问权，不自动签署或发送，不为忙碌对象新建会话规避执行保护。
