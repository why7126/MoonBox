# 迭代归档会话入口业务流程

## 主流程

```text
读取项目与 Sprint 全部范围事实
  → 未归档 + 非空 + 全对象已完成 + 有权限
  → 点击容量条归档按钮（加载/去重）
  → 服务端重新检查身份、范围、权限、执行状态
  → 忙碌/待核对：定位既有执行会话，仅查看，不预填
  → 可交互：选取可用 Sprint 对象会话；没有则创建并关联
  → 检查当前项目仍与发起时相同
  → 进入 Chat
  → 空输入：填入目标命令；相同命令：保持一次
  → 不同草稿：保留原输入，提供保留/填入选择
  → 等待用户主动发送
  → 重新核对范围、权限、签署、归档文档及同步门禁
  → 成功：根据最终事实刷新当前迭代及统计
  → 受阻/失败：展示真实结果，保留历史，不提前更新归档状态
```

## 会话选择与对象身份

身份为当前授权用户作用域内的空间、仓库、SPRINT 类型和规范 Sprint ID。主关联指向该 Sprint，不能按标题推断。排除已删除、已归档和不可访问会话。

执行保护先于普通候选排序。可继续的多个候选沿用既有服务排序：最近 turn 更新时间降序（有值优先）、最近消息更新时间降序（有值优先）、会话 updated_at、created_at、ID 降序。执行中的会话由既有保护机制优先定位，不借“最新”选择其他会话绕过。

## 异常与恢复

| 情况 | 处置 | 状态边界 |
|---|---|---|
| 未完成、空范围、状态未知 | 禁用并区分原因 | 无会话创建及归档写入 |
| 容量零或未知但完整范围确认已完成 | 不用容量否决入口 | 范围本身仍须可确认 |
| 会话准备失败/关联失败 | 留在原页，可重试 | 不打开孤立空会话 |
| 并发点击或重试 | 同一准备操作返回同一结果 | 不重复建会话或 turn |
| 准备中切换项目 | 忽略旧导航及旧预填 | 不污染新项目 |
| 无权限、Sprint 已归档或范围变化 | 服务端拒绝或重新读取并反馈 | 不复用旧就绪结论 |
| 非空草稿 | Chat 内 inline 提示；默认保留 | 明确选择后才替换纯文本；保留附件和其他输入上下文 |
| 刷新或重新挂载 | 一次性消费预填意图 | 不重填、不重发 |
| 归档失败或中断 | 依据原执行恢复机制处理 | 不重放已成功副作用，不重写原失败历史 |

## 与父需求的差异

REQ-0037 的容量区域位置与图标保留；入口条件改为范围完成，不由容量与 sign-off 联合阻塞；原归档确认提示替换为直接 Chat 导航。最终签署和归档校验继续保留。

REQ-0039 的会话复用语义扩展到 SPRINT。此入口只准备会话和草稿，不因引用生成类候选规则而提前创建 candidate 或 turn。
