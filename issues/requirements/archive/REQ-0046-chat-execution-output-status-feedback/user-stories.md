# Chat 执行状态反馈用户故事

## US-001 识别正常执行

作为普通聊天用户，我希望执行状态只表达一次，持续输出保持可读，避免把正常流式过程当成异常。

关联要求：FR-002、FR-003。验收：AC-001、AC-002。

## US-002 理解异常结果

作为治理命令使用者，我希望明确区分失败、停止、停止请求中及结果未知，避免重复写入。

关联要求：FR-004、FR-005。验收：AC-003、AC-004、AC-005。

## US-003 辨认正文完整性

作为历史消息阅读者，我希望知道正文是否缺失或没有最终答复，而不混同执行结果。

关联要求：FR-001、FR-006。验收：AC-006、AC-007。

## US-004 识别业务拒绝

作为产品成员，我希望校验拒绝优先于助手的成功措辞，普通聊天不展示虚假的校验通过。

关联要求：FR-007、FR-008。验收：AC-008、AC-009。

## US-005 查看正确轨迹

作为排障人员，我希望进入当前消息对应轮次的轨迹，无权限或不可用时得到解释。

关联要求：FR-009。验收：AC-010。

## US-006 跨刷新保持理解一致

作为用户，我希望刷新、重连、历史分页及切换会话后状态不错位、不退回陈旧结果。

关联要求：FR-010。验收：AC-011、AC-012。

## 边界

故事覆盖反馈、查看及既有恢复动作的统一入口，不新增恢复权限、执行策略、会话合并或成果回滚。

## US-007 在本轮识别业务进度

作为治理命令用户，我希望模型结束后继续在同一状态行看到校验、应用、确认，只有本次操作满足门禁才显示完成，不把任务交付与轮次结束混淆。验收：AC-015、AC-016、AC-020；关联 FR-008、FR-011。

## US-008 从原操作安全恢复

作为用户，我希望在失败或停止的原轮次查看成果、核对原因、确认继续剩余步骤；恢复完成后保留原终态，新生成不覆盖原操作与草稿。验收：AC-017—AC-019、AC-021；关联 FR-009、FR-012。

## US-009 阅读多轮历史

作为历史阅读者，我希望每轮只关联自己的成果与恢复尝试，旧轮次不因最新操作成功而变成完成，完成后恢复预算不占用正文空间。验收：AC-015、AC-020、AC-022；关联 FR-010、FR-011。

## US-010 已评审但执行结果待核对

作为需求负责人，我希望卡片保留可信已评审阶段，并解释为何暂不能加入迭代，能安全核验或查看原执行，而不用重复评审。关联 FR-013/014；验收 AC-023—026。后端完成证明与执行保护解除由关联 BUG 实现。


## 跨入口一致性返修约定

卡片只呈现一次当前动作的阻塞摘要，历史成果、核验时间、重新核验、差异和原执行收进默认折叠的“状态详情”。运行详情仍归属于原Chat轮次。归档准入采用当前Change的结构化验收证据和明确人工签认，与CLI共用只读判定；进度统计按AC身份去重，自动通过不等于用户人工签认。旧评审历史保留，经过验证的后续合法流转可承接旧保护，真实冲突、未知占用、权限变化、缺失或过期证据仍阻断。覆盖REQ与BUG，不能按具体编号特判。

后续补充评审仍为 approved 且对象身份一致时，只有完整评审文件被当前有效验收证据覆盖，才能承接旧评审保护；结论拒绝、未覆盖或过期仍阻断。关联解析统一支持 related_change、related_changes 与 openspec_changes 的字符串/对象形式。

## 验收后归档衔接补充

再次验收产生的报告与 trace 运行正文属于派生输出，不得使归档恢复记录自失效；交付输入、链路身份、真实证据完整性及并发变化仍受门禁保护。验收收尾后必须通过产品与 CLI 共用的正式准入，验收 passed 不等于归档 ready。错误须区分交付输入变化、旧记录过期、规格基线缺证、身份冲突和记录损坏。

关联链路先归档后，验收证据按唯一已完成归档身份定位，继续核对原内容哈希；活动目录仍存在、归档身份歧义、未完成或证据被篡改时仍阻断。
