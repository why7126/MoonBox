# Chat 执行状态与输出完整性反馈流程

## 主流程

```text
打开会话 / 接收新消息
  → 绑定消息所属轮次
  → 读取可信执行状态 + 正文完整性 + 适用的业务校验结果
  → 正常运行：状态行展示一次，正文持续可读
  → 终态/异常：按 FR-008 合并反馈
  → 存在正文缺口：补充独立缺口说明
  → 用户查看轨迹：进入对应轮次，只读查看
  → 新的可信事实到达：更新已解决的提示，保留未解决事实
```

## 状态分支与顺序

按 requirement.md FR-008 的六步优先级生成唯一主状态；分别保留执行、业务、正文和读取事实。普通聊天无业务阶段；治理执行结束但业务尚未完成时显示可信阶段或待确认，不宣告任务完成。后续业务确认更新结构化状态，助手原文不修改。

## 动作及异常路径

```text
消息 → conversation_id + turn_id → 可信 operation_id
  → 本轮状态行 → 本轮执行详情（阶段 / 原执行 / 轨迹 / 证据）
  → 后端允许 resume → 确认对象、阶段、版本 → 提交幂等请求
      → 等待核验 → 校验 / 应用 / 回读 → 已完成 · 经恢复完成
      → 失败 / 过期 / 冲突 → 保留成果与原终态，刷新合法动作
  → 后端允许 regenerate → 非空草稿确认 → 填入草稿 → 用户另行发送
  → 读取错误 → 保留上次确认并标记更新失败 → 只读刷新
```

展开、查看证据、刷新均不写业务数据。版本变化使原确认失效；重复提交不重复应用。原运行未知且占用未核验时不开放续接/重试。缺失操作关联不拿最新 candidate 补齐。不同轮次、操作、会话的状态与弹窗隔离，切换时关闭旧确认；读取响应按身份和版本收敛，迟到旧响应不得覆盖新事实。

正常完成默认折叠，异常说明和必要动作在本轮可见；移除独立恢复面板时保留整个 ConversationMessages 与输入区。动作、关闭、键盘和外部点击行为详见 prototype/web/context.md。

## 相对父需求的变化

REQ-0025 提供对话、事件、执行与会话基础。本需求增加统一反馈呈现规则，不修改执行状态机、权限或会话策略。BUG-0030 的过程留存能力保留；BUG-0044 的对象互斥和阶段门禁独立交付。

## 数据与验证边界

产品使用真实轮次/消息/校验数据；prototype/web/prototype.html 仅是局部模拟状态样本，不调用 API，不作为运行态证据。状态组合组件测试与真实浏览器执行观察分别验收。

## 生命周期与核验流程

可信生命周期 → 卡片所属列；操作核验异常 → 同卡片异常提示；准入判断 → 后续动作可用性。三者分别表达。

用户重新核验 → 检查后端能力 → 防重复提交 → 核对既有证明/占用/版本 → 刷新共享操作结果 → 更新 Chat 与卡片。失败保留历史事实，说明具体原因；相关变化可查看只读差异，执行异常可定位原轮次。该流程不重跑评审、模型或应用；无能力时只展示真实原因与已有查看入口。


## 跨入口一致性返修约定

卡片只呈现一次当前动作的阻塞摘要，历史成果、核验时间、重新核验、差异和原执行收进默认折叠的“状态详情”。运行详情仍归属于原Chat轮次。归档准入采用当前Change的结构化验收证据和明确人工签认，与CLI共用只读判定；进度统计按AC身份去重，自动通过不等于用户人工签认。旧评审历史保留，经过验证的后续合法流转可承接旧保护，真实冲突、未知占用、权限变化、缺失或过期证据仍阻断。覆盖REQ与BUG，不能按具体编号特判。

后续补充评审仍为 approved 且对象身份一致时，只有完整评审文件被当前有效验收证据覆盖，才能承接旧评审保护；结论拒绝、未覆盖或过期仍阻断。关联解析统一支持 related_change、related_changes 与 openspec_changes 的字符串/对象形式。

## 验收后归档衔接补充

再次验收产生的报告与 trace 运行正文属于派生输出，不得使归档恢复记录自失效；交付输入、链路身份、真实证据完整性及并发变化仍受门禁保护。验收收尾后必须通过产品与 CLI 共用的正式准入，验收 passed 不等于归档 ready。错误须区分交付输入变化、旧记录过期、规格基线缺证、身份冲突和记录损坏。

关联链路先归档后，验收证据按唯一已完成归档身份定位，继续核对原内容哈希；活动目录仍存在、归档身份歧义、未完成或证据被篡改时仍阻断。
