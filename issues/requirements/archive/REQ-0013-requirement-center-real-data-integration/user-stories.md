# 用户故事

## US-001 查看真实治理对象

作为产品负责人，我希望需求中心展示真实 REQ 与 BUG，而不是静态示例数据，以便根据当前项目事实源判断哪些对象需要生成、评审、纳入 Sprint、开发或验收。

验收要点：
- 看板对象来自后端 BFF 聚合接口。
- 页面不再使用生产运行时 Mock 数据。
- 对象数量、标题、阶段、Sprint、Change 和更新时间与治理事实源一致。

## US-002 识别跨事实源状态

作为项目负责人，我希望系统把 Issue registry、trace、Sprint 和 OpenSpec Change 状态映射到同一 9 阶段看板，以便快速识别真实研发进度和状态漂移。

验收要点：
- 状态映射覆盖 9 个阶段。
- 事实源冲突时卡片展示阻塞或漂移提示。
- registry 摘要与 trace 冲突时，以 trace 为优先事实源。

## US-003 使用真实筛选与统计

作为协作者，我希望按对象类型、负责人、优先级、Sprint 和关键字筛选真实数据，以便快速定位当前关注的需求、缺陷或阻塞项。

验收要点：
- 统计与当前筛选结果一致。
- 搜索支持 ID、标题、阶段产物、负责人或来源。
- 筛选无结果时保留 9 阶段列并展示空态。

## US-004 基于空间权限浏览

作为空间成员，我希望只看到自己有权限访问的空间和治理对象，以便在不同项目空间之间切换时不会误看或误操作不属于当前空间的数据。

验收要点：
- 空间列表来自接口返回的可访问空间。
- 本地保存空间无效时自动回退到可访问空间。
- 空间设置、进入后台、创建或加入空间等入口由真实权限控制。

## US-005 处理加载和错误

作为前台用户，我希望需求中心在真实数据请求过程中有明确加载态，在失败或无权限时有可恢复反馈，以便知道页面是否正在加载、是否需要重试或切换空间。

验收要点：
- 请求期间不闪现 Mock 数据。
- 接口失败支持重试。
- 权限不足、当前空间无对象、筛选无结果分别展示可理解状态。

## US-006 安全读取治理事实源

作为安全审计者，我希望后端聚合接口只返回白名单字段，不暴露本地路径、密钥、原始日志或 Markdown 全文，以便真实数据接入不会扩大治理资产泄露面。

验收要点：
- API 响应不包含本机绝对路径、系统用户名、token、`.env` 内容或堆栈。
- 错误响应使用受控错误码和安全文案。
- 测试覆盖脱敏和异常场景。
