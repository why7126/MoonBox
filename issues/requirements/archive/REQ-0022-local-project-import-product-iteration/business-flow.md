# 本地项目绑定与成果应用业务流程

## 正常链路

```text
成员进入需求中心
  -> 服务端按空间和仓库授权解析项目
  -> 读取稳定治理快照 -> 展示卡片 / 文档 / 刷新按钮同步提示（不展示独立连接栏）
  -> 卡片进入本人关联 Chat（只带入意图，不发送）
  -> 用户发送 -> 校验治理动作、原仓库与副本基准
  -> 独立副本执行 -> 生成待应用成果和完整差异
  -> 用户审阅并确认 -> 服务端取得项目写入互斥
  -> 重验授权、基准、成果和允许文件集合
  -> 应用与一致性校验 -> 持久化真实结果 -> 释放互斥
  -> 刷新需求中心与文档 -> 正式事实更新
```

## 自动更新支路

```text
本地文件稳定落盘 / 页面重新可见 / 应用完成
  -> 请求当前项目快照
  -> 项目身份和请求版本仍匹配？
     否：丢弃迟到响应
     是：完整解析成功？
         否：保留最后成功快照，提示同步失败或稍后重试
         是：更新卡片；有未保存草稿则只提示文档存在新版本
```

## 状态与异常分支

| 触发 | 产品状态和处置 | 禁止行为 |
|---|---|---|
| 未绑定、无权限、目录不可读 | 无连接或无权限；明确原因 | 回退全局目录、显示别的空间内容 |
| 源文件未提交且副本不一致 | 基准不一致；先准备可信基准，已有成果保留 | 静默用旧副本执行 |
| Chat 执行失败或停止 | 沿用真实终态，保留可审阅差异；首版只允许确认成功的治理成果进入应用 | 失败一轮直接当成可应用完整成果 |
| 源文件在执行后改变 | 冲突；整批不写，重新基于最新源内容处理 | 自动强制覆盖 |
| 应用时已有写入 | 等待或提示繁忙，服务端协调 | 只靠按钮 disabled 互斥 |
| 重复应用同一成果 | 返回同一次操作结果 | 重复写入或重复推进生命周期 |
| 应用中断 | 待核对；恢复事务/操作记录并校验文件 | 状态未知时立即重试 |
| 部分写入失败 | 恢复完整一致结果或保留明确恢复阻塞；看板不读取半成品 | 对用户报告整批成功 |
| 权限撤销 | 后续请求拒绝，清除无权内容；写入前再次检查 | 用历史会话所有权绕过权限 |
| 仅刷新失败 | 已应用结果仍保留，提示看板同步失败 | 将已应用降为未应用并再次写入 |

## 数据和一致性边界

- 正式源、执行副本、历史快照分别保存身份与版本；基准比较包含文件内容和存在性，覆盖新增、删除、迁移及未提交文件。
- 用户一次确认的成果集合固定，不能在后台混入之后生成的差异。应用前如成果已变，原确认失效。
- 批量应用恢复不覆盖他人的后续变化；读快照与受控写入协调，外部文件变动需稳定读取与重试。
- 第一次验收采用 captured → draft 的 req-generate 链路，联动 requirement、trace、registry、CHANGELOG；不自动创建其他需求或推进 Sprint。
- 5 秒目标从最后一个相关文件完成稳定写入且可形成完整快照开始计时，不从模型说“完成”开始。

## 与原始需求及关联需求的关系

无父 REQ。原 capture 的完整导入与迭代平台缩小为预配置单项目、单治理动作闭环。REQ-0025 提供个人会话与隔离执行；本需求增加成果受控应用。REQ-0024 的人工编辑权限保持有效，合法系统治理动作与人工全文编辑分开授权。

## 实施前需落实的设计项

基准准备方式、事务或日志恢复方案、应用操作持久化、只读挂载下的受控写通道在 OpenSpec 设计中确定。设计要能满足上述产品结果；不能将这些问题转为“用户自行同步文件”而宣称完整闭环已交付。

## 实施一致性记录（2026-09-11）

实际链路为授权项目目录 → scoped 稳定快照 → 新个人会话与建议草稿（不发送）→ 手动发送 → 平台容器执行器 → 严格四文件校验 → 完整 Diff → 维护确认 → 202 持久队列 → 可信控制器写入 → 轮询真实终态。文档保存和 tasks 勾选同样携带 expected_version 并进入队列。

## 看板事实源分流

registry对象清单 → Issue trace优先于registry摘要 → 终态直接已完成；非终态再读取活动/归档Change，验收态进入验收中。Sprint在活动与归档目录核对；文档验收使用真实文件集合。归档历史漂移作为诊断信息，不能制造当前执行阻塞。


## 首屏加载返修

进入页面 → 原位骨架（数据未知，不是0或空） → 授权项目与快照读取 → 成功替换为卡片/真实空态；失败保留重试入口。后台刷新保留原数据，仅刷新按钮busy。

## trace 单入口规则

所有REQ/BUG卡片在所有阶段仅保留一个trace.md入口，读取所属Issue目录的trace.md，标签和标题使用普通文件名；缺失时提示不可用，不回退Change trace。Change trace仍参与内部阶段判断，其他文档入口不变。


### 卡片进度阅读流程

点击研发/测试/人工验收 → 解析当前卡片关联 tasks.md → 按项目作用域读取 → 展示完整文档 → 定位章节或任务。关联缺失、文件缺失、定位目标缺失分别提示；用户仍可关闭阅读器，缺章节时可继续浏览全文。


### 迭代规划文档阅读

卡片 sprint.md 属于关联 Sprint，通过现有 Issue 文档读取接口按当前授权项目解析。展示、读取和缺失校验共用解析：按关联 ID 查活动目录，仅活动目录不存在时查同 ID 归档目录；活动目录缺文件不读取归档旧副本，不回退 Issue、Change 或其他 Sprint。文件缺失时保留明确提示；读取保持只读，trace.md 仍仅属于当前 REQ/BUG。


### 主动作阻塞与消息避让返修

卡片主动作统一使用接口disabled_reason、Issue阻塞和前置文档缺失判断，阻塞提示、按钮原生禁用、title原因与执行前守卫一致；文档仍可阅读，补齐后刷新恢复按钮。Tips位于Agent助手上方并保留安全间距，提高层级；窄屏限制宽度、长词换行，超长消息在受限高度内滚动，不遮挡助手。


### 主文档持续展示返修

REQ的requirement.md、BUG的bug.md一旦在所属Issue中生成，即在全部阶段卡片持续显示并固定文档列表首位，包括迭代规划、开发、验收和已完成。读取始终来自所属REQ/BUG当前目录，兼容Issue归档迁移；不读取Change同名文档。未生成不伪造入口，文件删除后按最新快照移除，已打开入口读取缺失明确提示。仅调整展示与排序，保留既有阶段编辑和只读权限。


### Sprint 文档持续展示

sprint.md在关联Sprint文档出现后于所有阶段卡片持续展示，包括准备开发态、研发中、验收中和已完成；requirement.md/bug.md仍保持首位。复用关联Sprint读取、只读能力、活动/归档解析及缺失不回退。只扩大展示白名单，不将sprint.md新增为其他阶段的必需文档，不改变阻塞与权限判断。


### 卡片文档分组与排序

常驻区按所属requirement.md/bug.md、关联sprint.md、所属trace.md固定排序；阶段区按当前任务优先排序。准备开发态proposal/spec/design/tasks；研发和验收tasks/spec/design/proposal；已完成archive/tasks/spec/design/proposal；已评审review优先，其他沿阶段阅读顺序。两个分组之间仅保留4px间距，无分隔线与额外内边距，组内自然换行，单组无空白占位；来源、权限及原必需文档校验不变。


### 文档读取与刷新性能

单次Change文档请求复用同一授权稳定快照的临时目录，避免授权和正文读取重复物化；不引入跨请求缓存，保留项目授权、写入恢复、epoch及绑定版本检查。相同项目的context刷新复用进行中请求，初始加载完成后开始轮询；切换项目及卸载取消旧请求。文档内容/草稿/版本冲突处理与原型布局不变。分段日志仅含服务端request_id、操作名、成功状态及各阶段毫秒耗时，不含文档内容或本机路径。


### 卡片更新时间格式

所有阶段REQ/BUG卡片统一显示“更新 YY/MM/DD HH:mm”，保留真实日期及源时间时分，各字段补零；缺失、无效或仅有日期/时分时显示“更新时间未知”，不补造日期和时间。footer必要时换行，时间自身不拆分，避免窄屏挤压动作。


### 所属需求原型常驻入口

所属REQ的prototype.html及prototype目录内HTML存在时，在主文档后常驻展示；多端以相对路径区分，兼容活动/归档目录。发现与读取共用安全解析，缺失无占位、不回退其他Issue/Change、不扩大必需文档校验。维持项目授权、只读预览和4px紧凑分组。


原型入口标签仅显示区分多端所需相对路径（如web/prototype.html、admin/prototype.html），移除“原型 · ”前缀；常驻位置、排序、URL与预览权限不变。
