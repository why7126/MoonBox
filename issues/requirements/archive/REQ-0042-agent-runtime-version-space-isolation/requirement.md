# 统一主源码目录与交付链路工作区及模块化执行架构

## 1. 背景与问题

现有 Chat 工作区身份与会话目录、source/copy 模式耦合。源码目录、治理投影与副本之间的版本关系增加执行和成果回写复杂度。用户确认以唯一主源码目录为默认执行入口，按交付链路使用 Git worktree 隔离并行任务，同时保留原需求的不可变环境版本、多空间隔离和诊断能力。此处依据此前静态代码分析，不声明当前线上已完成改造。

## 2. 目标用户与业务目标

空间成员和开发者需要清楚知道任务在哪个目录执行；团队希望不同交付链路并行且不混入修改；维护者需要可靠的绑定、版本、诊断和迁移。目标是统一执行身份与事实源，保持单目录路径简单，并为独立 worktree 提供完整生命周期。

## 3. 范围与非目标

纳入仓库与主工作区登记、交付链路工作树、会话绑定、模块职责、调度与锁、主看板事实投影、不可变运行版本、受控清理和旧数据兼容。恢复点保留/恢复由 REQ-0054 承接，人工确认合入由 REQ-0055 承接。

不纳入新终端 TUI、七个独立微服务、Rust 重写、远程多机调度、任意容器托管、自动推送/发布或重建 REQ-0048 的隔离验收环境供应。

## 4. 功能要求

### FR-001 仓库与唯一主工作区

每仓库登记一个完整主源码目录并建立主工作区身份，目录包括 .git、src 及治理资料。空间管理权限、仓库管理 Git 身份与主线、工作区管理执行目录。首期同一实际仓库不重复绑定多个空间，路径别名、已有 linked worktree 和同仓库元数据需归一识别；远程 URL 相同不单独证明本地实例相同。前端只传业务标识，后端解析目录。

### FR-002 交付链路唯一活动开发工作树

REQ/BUG 及其关联子 Change 归一到同一交付链路，最多一个活动开发 worktree，子 Change 串行复用。无 Issue 来源的独立 Change 以自身为链路。并发创建通过唯一约束和幂等操作返回同一结果；开发、检查和返修复用，不因消息、会话、重试新建目录。普通讨论不创建。临时集成/恢复工作树另记用途，不提供绕过上限的开发入口。

### FR-003 基线与创建流程

默认选择主工作区；隔离或并行任务按需显式选择独立工作树。创建前校验既有评审、Sprint、Change 和对象授权门禁，解析任务所需的确定提交。主目录未提交治理修改与 Git 提交版本分别展示；必要资料未进入基线则阻断并说明缺口，不静默丢弃、不顺带提交无关修改。使用真正 Git worktree，不用导出后重新初始化的仓库冒充。记录起始提交和专属分支/检出位置。

### FR-004 会话与轮次绑定

一个会话绑定一个工作区，多会话可共享；执行轮次固定仓库、工作区、交付链路和输入版本。活动轮次期间不切换目录；历史会话恢复时校验真实目录、仓库身份和权限，缺失或不匹配时显式阻断，不回退到主目录。跨工作区续接使用可追溯的新会话/操作，不把旧执行历史改写成新目录事实。

### FR-005 统一执行与分层互斥

主目录与 worktree 共用 moonbox-core 和执行适配。对象级保护防止重复推进，工作区级只允许一个写任务，不同链路按可用资源并行；公共治理、共享 Git 管理与主线集成统一协调。外部编辑不可假定受锁约束，采集与写入前复核版本。不能通过移除旧锁直接宣称支持并行。

### FR-006 治理事实和写入分工

主目录负责 Issue 编号、评审、Sprint 纳入、Change 创建、公共注册表/Sprint 汇总以及正式归档；任务工作树修改对应实现、测试、任务记录、相关文档与验收材料。任务范围内命令需通过统一执行上下文遵守该分工，不能因原脚本默认写注册表而修改不属任务的共享事实。正式规格仅在归档合并生效。

### FR-007 看板与版本投影

主看板从指定主目录读取完整一致治理快照，再叠加数据库运行信息。分别显示治理阶段、执行状态、集成状态；工作树完成不自动变成正式交付。工作区详情展示其基准与局部状态，读取失败保留最近完整版本并标明未更新。任务与证据按工作区归属，不能混用其他分支结果。

### FR-008 模块命名与依赖边界

模块统一采用 moonbox- 前缀，见模块表。moonbox-ui/moonbox-exec 经受控接口进入 moonbox-core；核心协调执行、工作树及历史组件；存储和 Git 操作不从 Web 直接调用。保留既有认证、业务规则与对外兼容契约。以模块边界和复用验证验收，不以移动目录数量作为完成依据。

### FR-009 运行版本和资源隔离

执行记录固定实际镜像不可变标识和工具链版本；新版本对新任务生效，活动轮次不静默换环境，恢复需验证兼容。升级失败可回到已知可用版本且保留原记录，不冒充旧轮次运行于新版本。空间运行状态、凭证、缓存授权以及工作区文件分离；不同测试环境分别分配数据库、端口、网络和容器，复用 REQ-0048 编排接口。

### FR-010 Git 共享数据与沙箱

worktree 不是安全隔离。可信管理组件处理创建、分支/共享元数据管理、集成和移除；执行器仅获适用的目录及 Git 能力，不为 .git 指针可达性开放整个主目录、所有工作树或凭证。路径越界、链接、权限撤销与非法绑定均失败关闭。

### FR-011 生命周期、清理与诊断

区分准备中、可用、准备失败、清理中、已移除等生命周期，使用占用和执行记录表达忙闲而非混为任务成功。创建/清理中断可核对并续接。主目录不可普通删除；活动任务、未提交/未合入成果、恢复依赖未处理不得删除工作树。诊断展示安全标识、失败阶段、镜像版本和可执行下一步，不暴露私有路径或密钥。

### FR-012 兼容迁移与关联交付

先登记现有 source 为主工作区并迁移会话/基线关系，再开放新 worktree。旧 copy 标记为历史副本，保留会话、差异、未应用成果和恢复入口，不能只改类型；迁移按版本标识、清单校验及可重入操作进行，失败保留旧数据。新建 copy 退出但旧成果未核对前不删除。主目录路径可单独验收，独立工作树正式开放需与 REQ-0054/0055 的保护和交付门禁集成。

### 模块名称与职责表

| 模块名称 | 首期职责与边界 |
|---|---|
| moonbox-ui | 现有 Web 交互、工作区选择、执行与交付状态；不直接执行 Git 或操作物理路径 |
| moonbox-tui | 预留终端交互模块命名与适配边界；首期不交付可用终端界面，不要求空壳目录 |
| moonbox-exec | 非交互任务入口，复用核心鉴权、编排和恢复规则 |
| moonbox-app-server | 客户端接口、身份认证、请求校验、能力与业务结果输出 |
| moonbox-core | 交付链路识别、执行编排、状态协调、工作区选择及策略决策 |
| moonbox-exec-server | 受控命令、进程、沙箱和文件采集，不持有无限 Git 管理权 |
| moonbox-rollout | 对话与执行历史、恢复点索引、内容与证据引用，保持权限和删除语义 |
| moonbox-worktree | 主目录登记、受管理 Git worktree 创建、绑定、检查、恢复目标与清理 |

以上为逻辑模块名称，全部使用 moonbox- 前缀。首期不要求独立进程、独立服务、语言迁移或一次性物理目录重排；具体包路径在 Change 设计明确且业务代码保持 src 边界。治理和受控合入是 MoonBox 业务能力，不因模块拆分另建重复工作流引擎。

## 5. UI 约束

复用 Web 空间、Chat 与需求中心。工作区选择展示主目录或任务工作区、所属链路、版本、可用性和权限原因，不显示内部路径。创建、复用、冲突、失联和清理使用统一动作状态；隐藏不可执行入口不能替代服务端拒绝。验收/合入状态分别由关联需求提供。交互原型与拆解见 prototype/web/，动作及验收约束见 business-flow.md 与 acceptance.md，首期不增加终端界面。

## 6. 数据、安全与部署影响

涉及 Web、API、数据库、Agent 执行与安全边界；实施时同步 OpenAPI、Orval 客户端、数据库设计、SQLite/MySQL 兼容迁移、部署挂载与权限规则和测试。只迁移本需求关联数据，不修写无关历史事实。路径、密钥、完整 Prompt 和文件正文不进入通用观测日志。业务证据按授权存储，路径不作为客户端权限依据。

## 10. 细化方案与实现风险

### 镜像兼容与迁移矩阵

| 条件 | 行为 |
|---|---|
| digest、工具协议与工作区策略均一致 | 原任务可在核对后续接 |
| 仅默认镜像更新、原 digest 仍可用 | 老任务继续固定原版本，新任务使用新版本 |
| 原镜像不可获取或协议不兼容 | 阻断续接并保留成果；显式新任务选择兼容环境，不改写历史 |
| 升级失败 | 回退默认版本供新任务使用，已启动任务逐项核对，不伪装回退执行事实 |

迁移顺序：备份绑定和内容引用 -> 识别物理仓库 -> 登记主工作区 -> 将旧会话映射到原目录身份 -> 校验历史与恢复引用 -> source 使用统一执行入口 -> copy 保留 legacy 身份和成果 -> 三需求集成通过后关闭新 copy 入口并开放独立开发树。每步保存迁移版本和结果；失败不删除旧副本，不将未提交文件自动混入主线。真实支持的镜像 digest/工具版本及数据库迁移脚本由 Change 设计列出，未测组合默认拒绝恢复。

具体接口、数据库字段、物理模块路径与部署并发参数在正式评审和 Sprint 纳入后的 Change 设计确定；不阻碍需求文档评审。
