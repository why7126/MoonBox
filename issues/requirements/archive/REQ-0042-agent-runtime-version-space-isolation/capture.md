# 统一主源码目录与交付链路工作区及模块化执行架构

## 一句话

统一 Agent 运行环境的不可变镜像版本，以空间级运行目录隔离执行数据，明确同一仓库在多空间中的绑定策略，并提供环境诊断摘要与多空间回归。

## 原始描述

用户提出：“Agent 运行环境版本治理与多空间隔离：统一不可变镜像版本、空间级运行目录、同仓库绑定策略、环境诊断摘要及多空间回归”。

## 分类与拆分

- 类型：REQ；这是运行环境与空间隔离能力的交付需求。
- 保持单条：镜像版本、运行目录、仓库绑定、诊断与回归共同构成多空间 Agent 执行闭环，可在后续 PRD 中分解验收场景。
- 初判优先级：P1；运行环境一致性与多空间隔离影响 Agent 执行可靠性，待评审确认。
- 相关需求：`REQ-0040-space-agent-model-reasoning-config` 关注空间可用 Agent、模型与思考程度，本需求关注执行环境、仓库与运行数据隔离，交付和验收闭环独立。

## 初步范围

- 为 Agent 运行环境定义统一、可追溯的不可变镜像版本及升级或回退边界。
- 每个空间使用独立运行目录，隔离工作区、缓存及运行产物，并明确清理生命周期。
- 明确同一仓库被多个空间绑定时的身份、工作副本、读写与并发策略。
- 提供可脱敏的环境诊断摘要，便于确认镜像版本、空间运行目录状态、仓库绑定和执行前置条件。
- 覆盖至少两个空间、同仓库绑定、版本切换与隔离边界的回归场景。

## 历史待澄清（当前结论见下文）

- [ ] 镜像版本的发布、锁定、升级和回退粒度是全局、空间还是执行会话。
- [ ] 同仓库多空间绑定是允许独立工作副本、限制单空间绑定，还是提供可配置策略。
- [ ] 空间目录中哪些内容需要持久化，空间删除或解绑后如何清理。
- [ ] 环境诊断摘要面向管理员、空间成员还是执行日志，以及允许展示哪些脱敏字段。

## 建议验收要点

1. 同一指定版本的 Agent 运行环境可按不可变镜像标识启动，执行记录可追溯实际版本。
2. 不同空间的运行目录及产物互不越界；同空间重复执行遵守明确的复用和清理规则。
3. 同一仓库跨空间绑定时，读写、并发与权限行为符合已确认策略，不会串用另一空间的运行状态。
4. 诊断摘要能定位版本、目录和绑定异常，同时不泄漏密钥、完整本机路径或敏感上下文。
5. 多空间回归覆盖正常执行、同仓库冲突、版本变更、失败恢复与隔离边界。

## 已确认架构

1. 每仓库一个主源码目录，包含 .git、src、issues、iterations、openspec、docs、rules 等完整项目文件。不同项目分别绑定仓库。主目录也登记为工作区；默认执行使用它，隔离、并行或独立审阅时按需创建 Git worktree。
2. worktree 共享 Git 身份与历史，拥有独立文件目录；替代新任务的导出文件并重新初始化 Git 的 copy 模式。主目录之外保存受管理 worktree，运行数据、凭证、备份与源码分离。不同容器挂载路径不得形成另一份独立治理事实副本。
3. 空间管理权限，仓库管理主线，工作区管理实际执行目录；会话绑定工作区，多轮执行记录精确工作区身份及版本。禁止前端任意指定物理路径。第一阶段同一实际仓库不重复绑定到多个空间。
4. 一个 REQ/BUG 交付链路最多一个活动开发 worktree，子 Change 串行复用；无 REQ/BUG 来源的独立 Change 最多一个。开发、验收与返修复用原工作区。不同交付链路才并行；普通讨论不创建工作树。临时恢复与集成工作树单独分类登记，不作为第二个开发工作树。
5. 按 Codex 职责划分 moonbox-ui/moonbox-tui、moonbox-exec、moonbox-app-server、moonbox-core、moonbox-exec-server、moonbox-rollout、moonbox-worktree：交互、非交互入口、服务接口、核心编排、命令及沙箱执行、历史与恢复引用、工作区生命周期。首期保留 Web，不新增可用终端 TUI；不要求七个独立服务或更换语言。沿用 React/FastAPI/数据库/容器基础。
6. 主目录和 worktree 共用执行器。对象级保护防止重复推进；工作区级写任务串行；不同工作区按部署资源并行；共享 Git 管理、公共治理更新及主线集成统一协调。外部编辑器不受平台锁完全约束，须检测变化。测试数据库、端口、网络和容器另行隔离，worktree 不是安全沙箱。
7. 主看板以主目录治理文件为正式事实源，叠加数据库执行进度，分别展示治理阶段、执行状态、集成状态。工作树局部完成不代表正式交付，工作区详情标注其版本。
8. 主目录负责 Issue 编号、评审、Sprint 纳入、Change 创建、公共注册表与 Sprint 汇总、正式归档。任务工作树负责对应实现、测试、任务记录、相关文档和验收材料；正式规格仅通过归档合并生效。
9. 主目录当前治理内容与 worktree 起始 Git 提交分别记录。创建前准备确定的任务资料基线；不假定未提交文件自动带入，也不顺带提交无关修改。
10. 受信任组件管理共享 Git 元数据和创建/移除，执行器仅访问授权范围，不为 Git 可用性挂载整个主仓库或凭证。记录不可变执行镜像、工作区、实际输入版本和诊断摘要。

## 迁移与非目标

先登记主工作区和迁移会话身份，再接入工作区级恢复、Git worktree、并行调度及成果集成。旧 copy 会话不直接改名为 worktree；保留未应用成果和历史，核对后迁移。清理前核对活动任务、未提交/未合入成果和恢复引用，禁止强制删除主目录或未知成果。

不在本需求重复实现恢复点轮转与冲突恢复、成果合入审批与幂等执行；分别由关联需求承接。REQ-0048-chat-isolated-acceptance-orchestration 已负责隔离验收环境供应，本需求仅约定工作区和环境身份接入，不重新建设其供应系统。首期不做远端多主机调度、自动推送发布或任意容器托管。

## 新增验收要点

- 同一仓库唯一主工作区，跨空间不通过路径别名绕过身份与锁；主工作区执行路径兼容原行为。
- 同一 REQ/BUG 多 Change 不重复创建工作区；返修与会话重建继续定位原目录；不同链路文件互不污染。
- moonbox-ui/moonbox-exec 调用同一核心执行与权限逻辑，各模块依赖边界明确，Web 原流程可回归。
- 工作区局部状态不覆盖主线事实，公共注册表与汇总写入串行，任务输入版本可追溯。
- 非法目录、共享 Git 元数据越权、已撤销权限被拒绝；运行资源与源码隔离。
- 旧会话与未应用副本成果可查，清理不破坏有效证据；双库迁移和 OpenAPI/客户端同步按实际实现验证。
