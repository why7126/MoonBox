# 规则修改说明与安全归档业务流程

## 主流程

```text
对象归档预检发现规则修改
 → 阻断项显示“查看修改”
 → 展示原规则、修改后、理由、仍禁止的情况和受影响验收
 → 系统复用现行验收与归档门禁
 → 受影响场景的逐项验收证据完成且有效
 → 结构化验收已就绪时直接沿用该结果；旧交付没有结构化计划时核对可追溯验证记录
 → 用户重新检查归档
 → 用户另行发起原归档命令
 → 写入前复核当前验收证据、项目权限、历史链与并发状态
 → 记录归档事实；中断时沿原操作恢复
```

查看、重新检查、实际归档是三个独立动作。没有“确认本次修改”、拒绝或撤销按钮；无相关修改的对象沿原归档流程。

## 阻断与恢复

| 场景 | 页面提示及处理 | 保留事实 |
|---|---|---|
| 原条文、差异或影响范围不完整 | 指出缺少的材料，不能放行 | 旧规则与诊断 |
| 删除、重命名、弱化旧保护或其他不明改动 | 指出不允许的修改，继续阻断 | 原拒绝理由 |
| 验收证据缺失、失败、过期或当前用户无归档权限 | 分项提示缺口，不能归档 | 草稿、附件和现有验收结果 |
| 检查后内容、证据、权限或历史变化 | 旧预检失效，重新核对差异及受影响验收 | 原检查记录，不覆盖 |
| 写入竞争或结果不明 | 回读原操作，不能沿用旧检查结果 | 检查点及已写入部分 |
| 中断后恢复 | 只完成原操作剩余步骤；无法证实时阻断 | 原归档身份和历史证据 |
| 已完成 | 返回原结果，不重复合并、迁移或发送命令 | 原 journal、manifest 和证明 |

## 旧方案切换

新版验收通过前原门禁继续有效。切换时，页面确认动作与新确认写入口同步退场；已完成旧证明仍按原版本只读验证。仅确有进行中的旧产品操作才按原检查点恢复，不自动转成新版结果。BUG-0063 已归档，只作历史读取样本；不制造其产品旧操作。

## 观测边界

页面查看、请求结果和归档记录使用脱敏关联标识；CLI 不伪造界面事件。普通遥测故障不能决定准入。归档恢复记录步骤摘要，不保存完整聊天、凭据或附件内容。
