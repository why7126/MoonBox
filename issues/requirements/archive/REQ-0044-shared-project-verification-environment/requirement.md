# 平台提供跨空间项目验证环境

## 1. 背景

BUG-0030 的修复已有后端和合成 DOM 回归，但真实浏览器验收受浏览器可执行文件缺失、项目依赖与运行架构不匹配、受限环境无法在线补装影响。现有 Chat 执行器只承诺通用工具链，不承诺项目 `node_modules`、测试依赖或浏览器。后续其他空间和项目会遇到相同交付阻塞，因此需要平台级、可声明、可隔离、可复用的验证环境。

## 2. 目标用户与目标

- 项目维护者和 Agent：提交可验证的项目与任务，得到明确的环境就绪结果和真实浏览器证据。
- 平台运维者：受控管理依赖与浏览器制品，诊断失败并限制空间间资源与数据交叉。

目标是将“执行器工具可用”和“项目验收环境可用”分别判定，使 Web 项目能在无需每次临时联网安装的条件下重复完成真实浏览器验收。

## 3. 范围与边界

### 纳入首期

- Node 项目：以仓库内锁文件和声明的包管理器、Node 版本、目标 OS/架构生成环境身份；支持平台受控的依赖准备与离线复用。
- Firefox 与 Chromium：使用匹配的 Playwright 包和浏览器版本，预检浏览器文件、系统库及启动能力。
- 平台任务：按授权的空间与项目发起预检、准备、运行、结果查询；同仓库跨空间仍采用独立工作副本及私有任务目录。
- 证据：记录浏览器、版本、运行环境、视口、验证命令、截图和脱敏通过/失败摘要；支持 BUG-0030 作为首个验收样本，并用第二项目验证通用性。
- 生命周期：制品版本、复用、失效、空间任务清理、超时、并发和配额有明确策略。

### 不纳入首期

- Python、移动端 SDK、桌面端、WebKit 及任意用户上传的运行镜像。
- 在 Chat 执行器基础镜像中打包所有项目依赖或浏览器。
- 默认开放验证任务对公网、宿主 Docker socket、其他空间目录或真实认证文件的访问。
- 因验证环境就绪而自动把 BUG/Change 标记为验收通过；验收仍依据具体测试结果和真实观察。

## 4. 功能要求

### FR-001 项目验证声明

平台读取授权项目的验证声明和锁文件，识别包管理器、Node/Playwright 版本、Firefox/Chromium、验证命令及视口。声明中的命令必须经平台允许范围校验；不得将浏览器请求提供的任意宿主命令或路径直接执行。声明缺失、锁文件冲突或目标架构不支持时给出可行动的稳定错误类别。

### FR-002 环境身份与制品准备

依赖制品键至少包含锁文件摘要、包管理器与 Node 版本、OS/架构及平台镜像版本；浏览器制品键包含 Playwright 与浏览器版本、OS/架构。准备过程在受控网络或内部制品源完成，运行任务优先使用已校验制品；缓存命中不得绕过内容校验。Darwin 制品不得复用到 Linux ARM64。制品按引用与保留策略清理，不删除活跃任务所依赖的版本。

### FR-003 就绪预检与诊断

正式验证前分别检查基础执行工具、项目依赖、浏览器二进制、系统库、浏览器实际启动和目标服务可达性。结果区分 ready、preparable、unavailable，并返回缺失类别、环境身份及推荐处置；无法准备时不得启动并宣称验收完成。诊断不能包含凭证、页面正文、完整本机路径或连接串。

### FR-004 跨空间验证任务

只有已授权空间与项目成员可触发和查看任务。平台以独立工作副本、任务目录和资源限制执行；不同空间不得复用可写工作区、会话状态、截图或认证。允许按身份共享只读且已校验的依赖和浏览器制品。任务具有排队、准备、运行、完成、失败、取消与超时状态，重复请求具备幂等语义。

### FR-005 浏览器证据与可复核结果

任务可在 1440px 与窄屏运行 Firefox/Chromium 验证，并输出受权限保护的截图、视口、浏览器版本、测试步骤、断言、computed style 摘要及失败类别。保留合成 DOM 测试与真实浏览器观察的证据类别差异；页面刷新、重进、轨迹切换等交互必须由真实浏览器执行才计入真实验收。未通过的项不得从测试文件存在或脚本语法通过推断通过。

### FR-006 安全、观测与运维

准备网络与运行网络分离；运行任务只访问授权预览服务及必要受控端点，按任务限制 CPU、内存、进程、磁盘、时间和并发。请求日志与 Task Trace 只保存空间/项目不透明标识、环境版本、状态、耗时、计数和稳定错误码；截图访问须授权，生命周期到期后受控清理。部署文档须给出制品升级、回退、容量和无网失败处理。

观测设计与验收遵循 `docs/standards/product-data-collection-observability.md`；若 Change 最终引入 DB、对象存储或 Web 请求入口，必须重新声明受影响层级和验证摘要。

## 5. 产品入口与 UI 约束

首期通过平台授权 API 和 Agent 工作流触发验证；结果可写入 Change 验证材料并由现有治理入口引用，不新增专属项目管理页面。后续如需可视化配置和任务列表，应单独设计角色、状态、交互及视觉验收。本期 API 调用方不能通过自由文本扩大验证命令、工作区或网络权限。

## 6. 验收口径

1. 两个空间、两个项目及同仓库双空间绑定场景均可独立运行；私有工作区、凭证、结果不串用。
2. 同版本环境可复用已校验制品；锁文件、Playwright、Node、OS/架构变化会产生不同环境身份并重新预检。
3. 缺浏览器、系统库、离线依赖或目标服务时给出明确诊断，任务不进入虚假的完成态。
4. Firefox 与 Chromium 能真实启动并执行 1440px 和窄屏用例，证据含截图和 computed style 摘要。
5. BUG-0030 的真实浏览器验收可完成；另一个独立项目成功运行，证明平台能力不依赖该 BUG 的仓库结构。
6. 撤权、跨空间读取、恶意路径/命令、任务超时与制品回退均有安全和恢复测试，观测数据已脱敏。

## 7. 关联与状态

REQ-0042 管理 Agent 执行环境版本与多空间运行隔离，本需求管理项目验证依赖与浏览器任务。两者共享版本和隔离原则，但各自评审、排期、Change 和验收。BUG-0030 是首个使用样本，原 Change 的实现和验收状态不因本需求记录而自动改变。
