# 平台提供跨空间项目验证环境

## 一句话

由 MoonBox 平台为不同空间和项目按声明准备可复核的验证环境，首期支持 Node 锁文件依赖及 Firefox、Chromium 浏览器验收。

## 原始描述

BUG-0030 的实现已有合成回归，但项目依赖与浏览器缺失使真实页面验收无法完成。用户要求从产品和平台视角补齐，让后续其他空间、项目也能使用；在 `/explore` 后选择平台验证环境方案，并明确新建关联 REQ，独立评审、排期和验收。

## 初步范围

- 项目声明包管理器、锁文件、目标 OS/架构、所需浏览器、验证命令；平台在执行前给出就绪、可准备或缺失的诊断。
- 平台按锁文件、运行时、OS/架构准备依赖制品，不跨架构复用 `node_modules`；浏览器与 Playwright 版本匹配，并验证系统依赖。
- 为每个空间和项目提供隔离的临时浏览器验证任务；支持 Firefox、Chromium、1440px 与窄屏、截图及可复核的结果摘要。
- 验证环境的制品可按版本复用，项目工作区、凭证、验收结果和生命周期隔离；不把浏览器与任意项目依赖塞入 Chat 基础执行镜像。
- 首期聚焦 Web/Node 项目；Python、移动端 SDK 和其他运行时作为后续扩展。

## 相似需求与拆分结论

| 候选 | 相似点 | 处理 |
|---|---|---|
| REQ-0042-agent-runtime-version-space-isolation | 执行镜像版本、多空间隔离、环境诊断 | 用户明确选择新增关联 REQ；本项聚焦项目验收依赖与真实浏览器任务，有独立交付闭环，沿用其隔离和版本原则 |
| REQ-0025-chat-workbench | 已提供 Chat Agent 执行入口 | 不重复建设聊天或基础执行器 |

保持单条需求：依赖准备、浏览器供给、隔离预检及证据输出共同构成可运行的跨项目验证闭环。BUG-0030 是首个验收样本，不作为平台能力唯一适用对象。

## 建议验收要点

1. 两个不同空间的项目可分别声明、准备并运行浏览器验证，结果不串用。
2. 相同锁文件和平台版本可复用制品；锁文件、Playwright 版本或 OS/架构变化时正确失效或隔离缓存。
3. 缺少浏览器、系统依赖或离线包时在任务前返回明确缺口，不开始声称“已验收”。
4. 验证任务产出浏览器、版本、视口、截图和通过/失败摘要；敏感路径、凭证、页面正文不得进入公共诊断或观测事件。
5. BUG-0030 可在该环境完成刷新重进、轨迹切换、1440px 与窄屏真实浏览器验收；另一个项目使用同能力完成独立验证。
