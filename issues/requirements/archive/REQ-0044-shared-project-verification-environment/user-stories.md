# 平台提供跨空间项目验证环境用户故事

| 编号 | 角色与故事 | 验收要点 |
|---|---|---|
| US-001 | 作为项目维护者，我希望提交验证声明后先知道环境是否就绪，避免测试运行中才发现依赖缺失。 | 锁文件、架构、浏览器、系统库和目标服务分别报告；缺口有稳定类别。 |
| US-002 | 作为 Agent，我希望为当前授权项目申请隔离浏览器任务并取得证据，以便完成 Change 验收。 | 只能操作当前授权空间/项目；结果包含浏览器版本、视口、截图、断言及证据类别。 |
| US-003 | 作为多空间管理员，我希望同一仓库在不同空间验证互不串用工作区、凭证和结果。 | 双空间绑定和并发运行时私有状态隔离，只读制品可按版本复用。 |
| US-004 | 作为平台运维者，我希望按版本准备、复用和清理依赖及浏览器制品。 | 版本键与摘要可追溯，跨架构不复用，活跃引用不被清理，失败可回退。 |
| US-005 | 作为评审者，我希望区分合成测试和真实浏览器证据，避免把脚本存在误当成视觉验收完成。 | 1440px、窄屏、刷新和视图切换需真实浏览器结果；缺项保持 pending。 |

本需求关联 REQ-0042 的运行环境版本与空间隔离原则，验证任务能力独立交付。首期不新增专属 UI。
