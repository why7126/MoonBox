# 统一 data 目录边界与本地数据挂载及快照轮转

## 一句话

统一本地业务 SQLite 的数据目录和 Compose 挂载，保留按用途隔离的执行状态与备份目录，并为本地自动快照设置可配置的数量上限。

## 原始描述

用户发现 `data/sqlite/moonbox.db` 与 `data/runtime/backend/sqlite/moonbox.db` 并存，且 `chat-platform/runtime` 内有多个 SQLite 文件。经连续 `/explore`，用户选择继续按用途分目录；要求将本地快照数量上限做成环境变量，默认保留 2 份，并允许配置为不做自动备份。本次要求正式记录配置语义、旧快照迁移清理和验收条件。

## 分类、拆分与相似检查

- 类型为 REQ：涉及数据目录、部署挂载与快照保留策略的预期能力调整，尚不将历史数据库文件差异直接判为已确认缺陷。
- 保持一条：业务库路径、挂载和本地快照轮转共同构成本地数据持久化与恢复交付闭环。
- `REQ-0025-chat-workbench` 已交付聊天与 Codex 执行能力；本需求关注其后续数据持久化和备份治理，验收闭环独立，作为相关需求记录。
- `REQ-0042-agent-runtime-version-space-isolation` 关注执行环境版本和多空间隔离，不覆盖业务库挂载与备份轮转。
- 初判优先级 P1：当前双路径和快照无上限影响恢复判断及磁盘容量，待评审确认。

## 初步范围

1. `data/sqlite/moonbox.db` 为本地业务 SQLite 唯一 canonical 路径；梳理根 Compose、本地 Compose、Chat overlay、环境示例、脚本与文档中的容器映射。生产 MySQL 路径保持独立。
2. `data/runtime/` 继续承载 Chat 执行器状态、治理控制状态与按用途隔离的备份，不以文件扩展名强行归并；明确目录、权限、Git ignore 和挂载边界。
3. 新增本地自动快照数量上限环境变量（建议 `MOONBOX_CHAT_LOCAL_SNAPSHOT_LIMIT`）：未设置默认 `2`，正整数表示自动快照保留上限，`0` 表示不再创建自动快照。非法值应明确拒绝，不静默回退。该值不关闭独立删除日志。
4. 新快照通过完整性及登记校验后再轮转；保护被治理成套备份引用的快照与独立删除日志。配置改为 `0` 时不立即清空历史快照。
5. 为旧业务库路径和既有快照制定停服、备份、完整性及关键表对比、迁移、回滚和受控清理步骤；不得按文件名或修改时间直接批量删除，也不得覆盖可能包含不同数据的两份业务库。
6. 同步 `.env.example`、本地部署示例、数据管理与数据库/部署文档，并覆盖默认、正整数、`0`、非法值、启动重启、快照轮转、引用保护及迁移回归。

## 待澄清

- [ ] 快照上限是所有登记副本的绝对上限，还是仅自动快照上限；已被成套备份引用的副本建议作为受保护例外。
- [ ] 从历史无限保留切换到上限 2 时，旧快照清理采用一次性受控迁移还是首次成功创建后的分批轮转；需要确认迁移前的恢复点和空间余量。
- [ ] 配置为 `0` 时是否允许运维显式手动创建快照；当前建议仅关闭自动创建。

## 建议验收要点

1. 本地服务和脚本均连接 `data/sqlite/moonbox.db`，旧路径不再产生新的业务库；现有不同数据的库不会被静默覆盖。
2. Chat 执行状态、备份快照和删除日志保持各自目录及访问边界，业务库切换后 Chat 启动、执行、删除与离线恢复路径可用。
3. 默认配置在启动与周期创建后最多保留 2 份未受保护的自动快照；可配置正整数；`0` 不创建自动快照且删除日志仍工作。
4. 轮转只通过备份账本的受控过期入口删除已登记副本；成套备份引用的快照及删除日志不被误删，失败时保留可用恢复点并报告异常。
5. 既有快照迁移或清理有清单、完整性验证、回滚记录和磁盘占用前后对比；生产 MySQL 配置不受本地 SQLite 目录调整影响。

## 探索结论

用户已确认按用途分目录、默认 2 份自动本地快照及允许关闭自动快照；本次仅采集需求，未实施迁移、删除文件或修改运行配置。
