# 统一 data 目录边界与本地数据挂载及快照轮转用户故事

## US-001 本地开发识别唯一业务库

作为本地开发或运维人员，我希望根 Compose、本地 Compose 和 Chat/Governance overlay 最终连接同一宿主机业务库，以便启动、排障和备份时不会误用不同数据。

验收要点：所有 SQLite 启动路径指向 `data/sqlite/moonbox.db`；旧挂载不再创建业务库；生产 MySQL 不回退到本地 SQLite。关联 FR-001、AC-001 至 AC-003。

## US-002 运维安全处理旧库

作为运维人员，我希望迁移前看到新旧两份数据库的完整性、schema 和关键表差异，只有确认来源后才切换，以便不覆盖可能不同的数据。

验收要点：停服、分别备份、差异报告、切换验证与回滚步骤可执行；差异未决时停止自动迁移。关联 FR-006、AC-004 至 AC-006。

## US-003 运维配置自动快照数量

作为运维人员，我希望通过一个环境变量设置自动快照上限，默认仅保留 2 份，并可设置为 `0` 关闭自动创建，以便控制磁盘增长。

验收要点：默认、正整数、`0`、非法值与 API/Worker 配置一致性均可验证；`0` 不清空已有快照或独立删除日志。关联 FR-003、FR-004、AC-007 至 AC-010。

## US-004 平台安全轮转与恢复

作为 Chat 平台使用者，我希望轮转不会误删治理成套备份引用或删除日志，以便恢复时保留可用恢复点且已删除内容不会复活。

验收要点：新副本校验成功后受控过期旧自动快照；引用保护、手动副本隔离、失败保留与删除回放均有回归证据。关联 FR-004、FR-005、AC-011 至 AC-015。

## US-005 维护人员定位数据目录与异常

作为维护人员，我希望目录归属、权限、忽略规则和脱敏错误摘要一致，以便确认容量、配置和恢复问题而不泄漏敏感信息。

验收要点：目录与挂载文档一致；磁盘占用报告、错误摘要、任务链路适用性和 Git 边界得到验证。关联 FR-002、FR-007、AC-016 至 AC-019。
