# 统一 data 目录边界与本地数据挂载及快照轮转业务流程

## 本地启动流程

```text
读取部署模式与环境变量
  → MySQL 生产模式：按既有 MySQL 门禁启动
  → SQLite 本地模式：校验业务库路径与宿主机挂载
      → 路径分叉或配置非法：阻止启动，输出脱敏诊断
      → 一致：连接 data/sqlite/moonbox.db，启动 API 与 Chat Worker
  → 解析自动快照上限
      → 0：保留独立删除日志，不创建自动快照
      → 正整数：启动时创建并验证快照，再进入轮转
```

## 自动快照轮转流程

```text
启动或约 24 小时周期到达
  → 读取一致的快照上限
  → 0：跳过自动创建，保留历史库存
  → 正整数：创建新快照 → 完整性、摘要、账本登记校验
      → 校验失败：保留旧恢复点，报告错误
      → 校验成功：标记自动来源 → 查找未受保护自动副本
          → 保护被治理成套备份引用及手动副本
          → 按创建顺序通过受控 expire 清理超额自动副本
          → 更新库存和磁盘占用摘要
```

## 历史数据迁移流程

```text
列出新旧业务库和快照库存
  → 停服并分别备份两库
  → SQLite 完整性、schema 版本、关键表行数对比
      → 数据差异未确认：暂停；保存差异与回滚材料
      → 确认来源：切换挂载与连接，启动并验证 API/Worker/重启
  → 旧路径与旧快照按清单受控清理
  → 记录数量、摘要、磁盘占用及回滚结果
```

## 删除与恢复流程

```text
用户删除会话
  → 独立删除日志先记录意图
  → 主库清理、执行线程清理及备份库存核对
  → 离线恢复历史快照时重放删除意图
  → 已删除会话不得因旧快照恢复而复活
```

## 与已交付需求的差异

`REQ-0025-chat-workbench` 建立 Chat 执行与本地独立备份，原策略为不自动过期。本需求只调整本地业务库实际挂载和自动快照轮转；会话权限、用户交互及在线恢复能力不变。`REQ-0042-agent-runtime-version-space-isolation` 的空间隔离不在本流程中实施。
