# 管理后台 CRUD 列表页组件化与模板体系

## 背景

MoonBox 管理后台已通过用户管理页沉淀出一套面向后台运营场景的列表页体验，包括较高信息密度、筛选查询、数据表格、分页、行级操作、确认弹窗、表单弹窗、toast 反馈以及加载和空状态。随着后续后台页面增加，如果继续复制单个页面的大段 JSX/CSS 与交互逻辑，容易造成视觉不一致、行为漂移和重复开发成本。

本需求聚焦管理后台 CRUD 列表页模板体系，目标是在首期建立可复用的页面组件、组合模式和约束规则，让后续后台列表型页面能够与用户管理页保持一致，并以更低成本交付新增、编辑、删除、启停、筛选和分页等通用管理能力。

## 目标用户

- 后台功能开发者：需要基于统一模板快速创建 CRUD 列表页，减少重复实现和样式漂移。
- 产品与设计协作者：需要用统一后台页面模式描述列表页、筛选项、状态操作和弹窗交互。
- 管理后台使用者：需要在不同后台页面中获得一致的布局密度、操作位置、反馈文案和状态表现。
- 维护与测试人员：需要通过稳定组件边界和模板约定降低回归测试成本。

## 范围

### 包含

- 首期覆盖管理后台 CRUD 列表页，不覆盖非列表型后台页面。
- 建立后台列表页模板结构，至少覆盖页面标题区、主操作区、筛选区、列表表格区、分页区和反馈状态区。
- 抽取或规范后台列表页通用组件，至少覆盖筛选栏、数据表格、分页、确认弹窗、表单弹窗、toast 反馈、空状态和加载状态。
- 明确列表页常见 CRUD 交互规则，包括新增、编辑、删除、启用、禁用、重置或等价状态操作。
- 以已归档的用户管理页作为首期视觉密度、布局和交互基准。
- 支持将现有用户管理页回迁或适配到模板体系，作为首个模板验收页面。
- 提供后续后台列表页复用模板的约束，减少复制页面级大段 JSX/CSS 的实现方式。

### 不包含

- 不覆盖管理后台登录认证体系、权限模型、角色配置或会话管理。
- 不覆盖复杂仪表盘、统计分析页、详情页、树形配置页、流程编排页或非 CRUD 列表型运营工具。
- 不建设完整 Design System 或跨端组件库。
- 不覆盖普通 Web 前台、移动端、小程序或桌面端页面。
- 不要求引入新的前端 UI 框架或替换现有技术栈。
- 不定义具体业务实体的数据模型、API 字段或数据库表结构；具体页面的业务字段由后续需求或 OpenSpec Change 定义。

## 功能要求

### FR-001 后台 CRUD 列表页模板结构

系统 MUST 提供管理后台 CRUD 列表页模板结构，用于承载后续列表型后台页面。

模板 SHOULD 至少包含页面标题区、主操作区、筛选区、表格区、分页区、加载状态、空状态、错误状态和操作反馈区域。

模板 MUST 适配后台重复使用场景，避免将说明性营销内容、过大的装饰布局或与后台任务无关的视觉元素作为默认组成部分。

### FR-002 通用列表页组件边界

系统 MUST 抽取或规范后台 CRUD 列表页常用组件边界，避免每个页面重复实现相同的筛选、表格、分页、弹窗和 toast 逻辑。

首期组件范围 SHOULD 覆盖筛选栏、数据表格、分页、确认弹窗、表单弹窗、toast 反馈、空状态和加载状态。若后台 Shell 或页头已有稳定实现，模板 MUST 与其保持兼容，不得引入冲突布局。

通用组件 MUST 支持页面传入业务字段、操作按钮、状态标签、筛选项和表单内容，不得固化为用户管理页专用实现。

### FR-003 用户管理页模板化适配

系统 SHOULD 将现有用户管理页作为首个模板化适配页面，用于验证模板能承载真实后台 CRUD 列表场景。

适配后，用户管理页的核心能力、视觉密度、筛选行为、表格列展示、分页行为、弹窗操作和 toast 反馈不得出现可感知回退。

用户管理页中可复用的结构和行为 SHOULD 收敛到模板或通用组件中；页面仅保留与用户管理业务实体强相关的字段、接口调用和业务规则。

### FR-004 CRUD 操作交互一致性

模板 MUST 为新增、编辑、删除、启用、禁用、重置或等价状态操作提供一致的入口位置、按钮层级、确认策略和反馈方式。

破坏性操作 MUST 使用确认弹窗或等价确认机制，并在成功或失败后给出受控反馈。非破坏性操作 SHOULD 保持轻量反馈，不应打断用户连续处理列表数据。

操作完成后，列表数据、分页状态和筛选条件的刷新策略 MUST 明确，避免出现操作成功但页面仍显示旧状态的情况。

### FR-005 筛选、表格与分页规范

模板 MUST 支持后台列表页常见筛选能力，包括关键词、状态、时间或页面自定义筛选项。筛选提交、重置和加载反馈 MUST 保持一致。

表格组件 MUST 支持稳定的列定义、行级操作、状态展示和空数据展示。列宽、操作区和状态标签 SHOULD 避免因内容变化造成布局明显跳动。

分页组件 MUST 支持当前页、每页数量、总量展示或等价能力，并与筛选条件联动。筛选条件变化后，分页 SHOULD 回到第一页或采用明确规则。

### FR-006 状态、错误与反馈体验

模板 MUST 为加载中、空数据、接口错误、操作成功、操作失败和权限不足等状态提供统一呈现方式。

错误反馈 MUST 使用受控文案，不应暴露内部接口路径、堆栈、数据库错误或敏感字段。

toast、弹窗和页面内状态提示 SHOULD 保持一致的视觉层级，避免遮挡主要操作或造成重复提示。

### FR-007 模板复用约束

后续新增后台 CRUD 列表页 SHOULD 优先通过模板和通用组件创建。

当页面需要偏离模板时，开发者 SHOULD 明确偏离原因，并保持基础布局、反馈状态和交互规则与后台整体体验一致。

模板体系 MUST 避免复制用户管理页大段 JSX/CSS 作为新页面起点；确需复用历史实现时，应逐步回收为通用组件或页面组合模式。

## UI 约束

- 后台 CRUD 列表页应保持用户管理页已验证的后台视觉密度和操作节奏。
- 页面主操作、筛选区、表格操作和分页应位置稳定，便于重复处理数据。
- 表格、筛选、弹窗和 toast 的视觉样式应与现有管理后台一致，不引入新的强装饰风格。
- 破坏性操作应有明确视觉区分和确认反馈。
- 加载、空状态和错误状态不得造成页面大幅跳动或主要操作不可恢复。
- 模板应优先服务桌面后台管理场景，同时保证常见窄屏下不发生文本重叠或控件遮挡。

## 关联需求

- REQ-0004-admin-user-management：用户管理页作为首期后台 CRUD 列表页模板的视觉、交互和真实场景基准。
- REQ-0005-admin-auth-system：后台认证系统为后续管理页面提供真实访问边界；本需求不重复定义认证能力。
