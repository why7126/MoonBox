# 用户故事

## US-001 基于模板创建后台 CRUD 列表页

作为后台功能开发者，我希望使用统一的 CRUD 列表页模板创建新页面，以便减少重复 JSX/CSS 和交互逻辑实现。

验收要点：

- 模板提供页面标题区、主操作区、筛选区、表格区、分页区和反馈状态区。
- 页面可配置业务字段、筛选项、表格列、状态标签、行级操作和主操作。
- 新页面不得以复制用户管理页大段页面代码作为默认创建方式。
- 模板默认符合 MoonBox 管理后台近直角、细线、克制金色强调和信息密度规则。

## US-002 复用一致的筛选、表格和分页体验

作为管理后台使用者，我希望不同后台列表页的筛选、表格和分页行为一致，以便在重复处理数据时不需要重新学习页面。

验收要点：

- 筛选提交、重置、加载和空状态与当前筛选条件一致。
- 分页 DOM 与用户管理页基准一致，总数位于左侧，翻页、页码和每页数量控制位于右侧。
- 表格列、行级操作和状态标签在内容变化时保持稳定，不出现明显布局跳动。
- 筛选条件变化后，分页按明确规则回到第一页或保持可解释状态。

## US-003 复用一致的 CRUD 操作反馈

作为后台管理员，我希望新增、编辑、删除、启用、禁用和重置等操作有一致的入口、确认和反馈，以便降低误操作风险。

验收要点：

- 破坏性或状态变更操作使用设计系统确认弹窗。
- 管理后台状态变更不得调用 `window.confirm`。
- 操作成功或失败使用 fixed toast 反馈，不挤压列表、分页或弹窗内容。
- 操作完成后列表数据、筛选条件和分页状态按模板规则刷新。

## US-004 通过用户管理页验证模板可用性

作为产品与测试人员，我希望现有用户管理页能够适配到模板体系，以便用真实页面验证模板不是空泛抽象。

验收要点：

- 用户管理页适配后核心能力、视觉密度、筛选行为、表格展示、分页、弹窗和 toast 反馈无可感知回退。
- 用户管理页只保留业务字段、接口调用和业务规则等页面专属内容。
- 可复用结构和行为收敛到模板或通用组件。
- 适配结果可作为后续后台 CRUD 列表页的参考样板。

## US-005 治理弹窗宽度与低视口滚动

作为维护与测试人员，我希望新增、编辑和确认弹窗遵守统一宽度与滚动规则，以便避免 CSS 级联导致弹窗尺寸异常或操作不可达。

验收要点：

- 模板实现不得让通用 `modal-card` 与专属宽度类并存。
- 新增/编辑弹窗在浏览器 computed style 中验收最终宽度。
- 低视口下弹窗 body 可滚动，底部主操作和取消操作可访问。
- 弹窗遮罩不吞掉内部滚动，也不导致页面主体误滚动。
