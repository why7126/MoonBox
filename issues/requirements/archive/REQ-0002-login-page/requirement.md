# Web 端登录页

## 背景

MoonBox 需要在官网访问路径中提供清晰、可信的登录入口，让目标用户从首页进入产品身份认证场景。现有设计文档同时覆盖首页与登录页，本需求仅抽取登录页相关内容，并围绕 Web 端登录页的品牌呈现、页面状态、表单信息架构与前端交互边界进行整理。

本阶段登录页以原型和前端体验闭环为主，不连接后端认证服务。

## 目标用户

- 已获得 MoonBox 访问资格，需要进入产品空间的 AI 创业者、小型软件团队成员和 AI 原生企业团队成员。
- 从官网首页 CTA 或登录入口进入 MoonBox 的访客。
- 需要在进入产品前确认品牌可信度和登录上下文的潜在用户。

## 范围

### 包含

- Web 端登录页页面结构与视觉呈现。
- 首页进入登录页后的页面状态管理。
- 登录页返回首页的入口和行为。
- MoonBox 品牌 Logo 在登录卡片中的展示。
- 用户名、密码、记住我和登录按钮组成的登录表单。
- 用户名与密码必填校验。
- 登录页背景复用首页产品视觉，并使用遮罩保证表单可读性。

### 不包含

- 后端登录接口、Token 签发、会话刷新和权限校验。
- 忘记密码、注册、申请体验、第三方登录、邮箱验证码、手机号验证码。
- 登录成功后的真实业务跳转和工作台加载。
- 首页首屏内容、首页 Logo 替换、首页右侧产品视觉替换等首页独立需求。
- 管理后台、微信小程序、移动端或桌面端登录页。

## 功能要求

### FR-001 登录页入口与页面状态

- 首页的登录相关入口或 CTA 应能进入同一登录页。
- 进入登录页后，应呈现独立的登录页面状态，避免与首页内容混排。
- 如使用 URL Hash 或等价前端状态标识登录页，返回首页时应清除登录页状态。

### FR-002 返回首页

- 登录页左上角应展示“返回首页”入口。
- 点击“返回首页”后，应恢复首页视图。
- 返回后不应保留登录页表单、遮罩或登录状态标识。

### FR-003 登录页品牌呈现

- 登录卡片顶部应展示 MoonBox 产品 Logo。
- Logo 展示应与首页品牌资产保持一致，避免出现旧 Logo、占位图或文本替代。
- 登录页整体视觉应保持 MoonBox 品牌一致性，突出专业、可信和 AI 原生软件工厂的产品气质。

### FR-004 登录页背景与可读性

- 登录页背景应复用首页产品视觉，形成从首页到登录页的品牌连续性。
- 背景上应增加深色遮罩或等价视觉处理，确保登录表单、按钮和辅助文本在常见桌面与移动视口下清晰可读。
- 背景不应遮挡、干扰或弱化登录表单的主要操作路径。

### FR-005 用户名密码登录表单

- 登录表单应包含用户名输入框、密码输入框、记住我控件和登录按钮。
- 用户名与密码均为必填项。
- 密码输入框应使用密码类型展示，默认隐藏明文。
- 提交时如用户名或密码为空，应在前端给出明确的字段级或表单级提示。
- 当前原型提交不连接后端；表单提交不应产生真实认证请求。

### FR-006 登录页信息收敛

- 登录页不展示“忘记密码”。
- 登录页不展示“申请体验”。
- 登录页不展示第三方登录、注册入口或其他未纳入本需求的认证方式。
- 登录页文案应聚焦已有账号登录，不引导用户进入未定义流程。

## UI 约束

- 登录页应适配桌面与移动视口，登录卡片在小屏下不得溢出屏幕或遮挡关键背景状态。
- 登录卡片、输入框、按钮、复选框等元素应复用项目设计系统与现有 Web 端样式规范。
- 表单区域需要有足够对比度，按钮主操作状态明确。
- “返回首页”应作为轻量导航入口，视觉层级低于登录按钮但保持可发现。
- 不应新增与当前品牌不一致的装饰性视觉元素。
