# Chat 无默认运营配额与大规模工作区持续执行

## 一句话

Chat 默认不设运营额度，取消工作区固定规模门槛，通过增量快照、结果持续落盘与按需加载支持项目增长，并保留部署级资源保护和可恢复执行。

## 原始描述

用户／空间 Token 和 Chat 存储默认不限额，保留未来运营配置能力；单轮 Token 不设平台预算。工作区文件数、文件总大小和执行结果不设固定业务总量上限，采用分批、增量、持续落盘和按需加载。协议解析与执行容器保留部署级资源保护，不进入运营配置。资源不足时展示明确原因，保留已完成结果，并提供恢复路径。

## 已确认范围与边界

- 用户／空间月度 Token 与累计 Chat 存储默认不限额，继续真实计量；未来运营配置能力保留，本期不开发后台配置界面。
- 单轮 Token 不设置平台预算，未来也不作为运营配置；保留手动停止、权限校验及上游账号约束。
- 工作区文件数、文件总大小和结果累计大小不设固定业务总量上限；采用分批扫描、增量快照、持续落盘及按需读取。
- 文本保存、内存缓冲与页面展示分离，不以无限内存换取无限结果；大文本及差异按需加载。
- 协议解析与容器保留部署级资源保护，不进入运营配置，不取消隔离、授权及同会话互斥。
- 资源不足明确反馈实际原因，保留已持久化的过程和成果，提供可验证恢复路径；不承诺超出物理资源仍可完成。

## 背景与探索结论

同会话只读排查发现，Chat 在模型启动前的 workspace_prepare 阶段触发 WorkspaceError。运行中 worker 的快照函数复现一万文件上限，当前采样为 12585 个文件；临时仅将只读调用参数改为 20000 后成功。样本为调查时点事实，不作为长期固定规模。当前快照另有 512 MiB 总大小边界，单轮处理缓冲为 16 MiB。

代码依据：src/backend/app/chat/workspace.py、execution.py、settings.py、app_server.py。现有处理依赖内存累计回复、完整快照及差异拼接，不能仅删除检查或配置 unlimited；本期需要调整处理链路。

## 判重与归属

- REQ-0025-chat-workbench：已归档基础能力，作为父需求；本次是用户确认的独立后续交付，不重写历史交付事实。
- REQ-0043-unify-data-mount-and-snapshot-rotation：备份目录与轮转，区别于本次每轮工作区快照。
- REQ-0046-chat-execution-output-status-feedback：展示反馈；本次需要资源原因与已持久化结果的真实底层支撑。
- REQ-0047-governance-command-durable-recovery：治理操作恢复；本次执行资源恢复应复用其语义，避免重复恢复入口。
- 保持一条需求：均围绕 Chat 大规模执行与结果保存的一条验收链路，运营后台不单独纳入本期。

## 优先级初判

P1：当前仓库规模已造成执行前阻断，且项目历史增长会持续触发固定门槛；尚不属于全平台紧急故障。

## 建议验收方向

- 超过一万个文件及 512 MiB 的受控仓库可执行，取消旧固定业务门槛。
- 长结果超过旧 16 MiB 总处理门槛仍可持续保存和分段读取，内存占用有界。
- 大文本与差异按需读取，快照增量处理不遗漏新增、修改、删除及重命名。
- 磁盘不足、内存压力、连接中断、worker 重启时保留已提交结果，错误真实可见，恢复无重复执行或重复结算。
- 默认无限仍真实计量，不影响上游额度、权限隔离和同会话互斥；已有有限配置兼容与迁移在设计中明确。
- 按 docs/standards/product-data-collection-observability.md 验证阶段关联、错误摘要和脱敏。
