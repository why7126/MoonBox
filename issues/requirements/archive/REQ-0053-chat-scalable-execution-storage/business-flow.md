# Chat 无默认运营配额与大规模工作区持续执行业务流程

## 正常链路

```text
用户发送 → 授权／同会话互斥／有效运营策略检查
  → 实际资源预检 → 加载有效基线 → 分批扫描与增量校验
  → 原子发布可信快照 → 启动执行器
  → 按轮次序列持续保存事件及回复 → 前台按需加载
  → 核对执行终态 → 校验结果完整性／工作区差异
  → 幂等结算 → 展示执行与成果各自事实
```

“原子发布”指完整性校验后的基线可见性，不预设整个扫描必须单事务。首次扫描可全量，后续只复用经验证未变内容。工作区发生并发修改时重采或保持不完整状态。

## 异常与恢复

| 发生阶段 | 当次处理 | 可恢复入口 | 禁止行为 |
|---|---|---|---|
| 准备前／扫描中资源不足 | 标明尚未执行，保留有效基线与检查点 | 资源恢复后重新检查并续接准备 | 将半成品作为完整基线 |
| 运行中保存失败 | 标明已保存范围和缺口，实施背压或安全停止 | 原轮次核验后续接或明确重试 | 静默丢弃、提前宣布成功 |
| 浏览器断开 | 后台独立运行，保留游标 | 重连从可信游标读回 | 把断网当执行失败 |
| worker 退出／终态未知 | 原历史保持未知，阻止重复有副作用执行 | 核验原轮次与成果，无法证实则人工处理 | 自动重新发送原命令 |
| 迁移失败 | 保留旧有效版本，记录进度 | 恢复迁移或按计划回滚 | 删除旧数据后才校验 |

## 动作准入与数据事实

读取已保存内容始终受会话所有者、空间和对象授权约束。恢复前重新核对资源、权限、轮次状态及原操作；重复恢复请求只产生一次有效恢复，不重复应用文件或结算。当前可操作状态不回写历史 failed／stopped 为 completed。

恢复动作成功只证明该动作完成；必须分别验证实际续接、最终结果与真实读取。无法取得可信终态时仅显示“待核验”，不给可直接重发的快捷按钮。

## 与父需求的差异

REQ-0025 的授权、同会话互斥、上游执行和计量继续复用；本期替换固定规模阻断、全量重复扫描及内存集中汇总路径。REQ-0043 的业务库备份轮转不属于工作区增量快照，不调整其保留策略。REQ-0047 的治理恢复语义作为依据，不能建第二套互相矛盾的终态。

## 用户／系统边界

后台运营设置不在范围内。技术保护由部署层负责，前台只解释原因与处理路径，不提供内存、CPU、进程等参数编辑。资源不足时不得自行删除用户成果或历史证据腾空间。

## 实现一致性核对（2026-10-26）

保存失败后先读取已提交内容，再核验原轮次。只有持久证据确认未发送启动请求且当前权限/环境/运营额度通过时，原轮次追加准备尝试并排队；其他情况保留原状态和结果。文件查看先选本轮/累计，再分页比较内容块或读取执行前/后正文。 验证结论以 Change 当前 acceptance-plan 和证据清单为准。
