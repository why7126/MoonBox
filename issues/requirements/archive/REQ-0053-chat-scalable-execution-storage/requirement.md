# Chat 无默认运营配额与大规模工作区持续执行

## 1. 背景与问题

项目持续积累源码、治理文档与验收证据，Chat 当前执行链路在模型启动前创建全量工作区快照，并在运行后计算差异。既有一万个文件、512 MiB 快照总大小及 16 MiB 单轮处理缓冲，可能将正常增长的项目或长任务挡在执行入口或中途停止。

同会话只读调查中，目标仓库样本包含 12585 个文件，运行中 worker 的快照函数返回“工作区文件数量超过快照边界”；仅在对照调用中将文件数参数改为 20000 后成功。该数量是调查时点样本，不代表当前实时文件数，也不作为新上限。用户已确认：默认不设运营额度，取消固定业务总量门槛，采用分批、增量、持续落盘和按需加载，同时保留部署级保护。

当前配置、代码与历史决策依据见 capture.md。现有代码把回复、快照和差异部分聚合在内存中，本需求不是简单删掉检查或把阈值换成更大的整数。

## 2. 目标用户与业务目标

- AI 创业者与研发团队：同一项目增长后仍可持续执行，不因历史证据变多而被固定文件数门槛阻断。
- 长任务使用者：过程输出及时保存，刷新或重连后可以继续查看，故障后知道成果保存到了哪里及如何恢复。
- 部署维护者：根据实际主机资源控制执行负载，保护同机 API、数据库与其他任务，不需通过运营后台调整技术参数。

目标：取消固定业务规模门槛，同时使内存占用可控、结果完整性可核验、资源异常可解释且可恢复。“不限额”表示平台不设置固定业务总量上限，不承诺无限硬件、无限上游额度或任意任务必然完成。

## 3. 范围与非目标

纳入 Chat 发送与入队、工作区准备、快照与差异、执行事件与回复保存、历史按需读取、资源不足反馈及恢复、计量兼容、历史数据兼容和部署说明。

不纳入：后台运营配额界面、收费套餐和账单系统、变更上游账号额度或模型上下文、无限内存与无限进程、取消沙箱与审批权限、多机调度平台、重做备份轮转与异机灾备。现有治理命令恢复能力复用，不另建平行恢复系统。

## 4. 功能要求

### FR-001 默认配额与无限语义

新部署中用户／空间月度 Token、用户／空间累计 Chat 存储默认无限，继续记录可信实际用量。未来允许运营配置的范围仅保留上述两类资源的扩展契约，本期不提供配置页面。不使用超大整数模拟无限，不把显式非法配置静默解释为无限；必要权限、仓库绑定及存储配置缺失仍明确报错。

### FR-002 单轮 Token 与既有配置兼容

单轮 Token 不设平台预算，未来不作为运营配置；手动停止、权限变化、上游错误及资源保护仍有效。升级不得暗中撤销已有显式用户／空间有限配额；迁移报告需说明其保留或转换方式。旧单轮预算、固定快照门槛和结果总量字段应明确废弃、兼容读取或迁移行为，不得升级后继续隐藏地阻断新策略。未知 Token 用量保持未知并等待可信结算，不能以零替代；重试与迟到结算幂等。

### FR-003 工作区规模与读取边界

不以文件数、文件总大小达到固定值作为业务拒绝条件。文件范围沿用受信仓库与授权边界，Git 忽略、安全路径、链接和特殊文件处理不得因取消规模门槛而放宽。不为规避规模问题删除历史验收证据，也不静默排除应被追踪的业务文件。实际资源不足必须依据资源证据报告，而非伪装为固定配额不足。

### FR-004 分批与增量快照

首次扫描可以分批全量建立可信基线，后续复用已验证的未变化内容并更新变化项。覆盖新增、修改、删除、重命名、权限相关属性及允许的链接元数据。仅凭不可靠缓存不得宣布内容相同；采集时遇到并发修改需检测并重采或标记不完整。快照仅在完成完整性校验后作为可信比较基线，未完成快照不能覆盖最后有效基线。扫描进度与检查点可恢复，不能因中断重复提交或误报无差异。

### FR-005 结果持续持久化

执行事件、过程回复及最终成果按可恢复的序列持续写入持久存储，不依赖一次性内存聚合全部结果；累计输出不因旧 16 MiB 门槛停止。保留轮次归属、顺序、去重与完整性标记，区分已接收、已持久化、未确认及缺失内容。刷新、重连和 worker 重启后可读取已提交结果。存储背压应通过有界队列、受控降速或安全停止处理，具体实现由 Change 确定；禁止无限排队或静默丢弃。

### FR-006 文本与差异按需加载

完整保存与页面展示分离；取消以旧单文件文本大小或文本累计展示预算作为完整内容保存的业务上限。大文本可分块保存和读取，二进制保持适用的元数据与内容引用策略，不强制转换成文本。文件列表、事件、回复和差异使用分页、分段或等价机制；限制单次读取与渲染量不等于限制总保存量。暂未加载、计算中、存储缺失与历史不可用必须区分，不得把展示截断说成完整成果。

### FR-007 协议与容器部署级保护

协议格式校验、解析资源、输入输出队列、容器 CPU／内存／进程等保护继续保留，归属部署与运行保障，不进入运营配置。保护值需根据协议行为和容量验证确定，支持合法的大响应与长运行；不沿用无依据的阈值阻断正常场景，也不承诺接收任意大单帧。超出技术能力时返回可定位原因，保存可保留结果；保留路径、网络、凭证隔离及同会话互斥。

### FR-008 资源不足反馈

区分运营额度不足、实际磁盘不足、处理内存压力、执行容器资源异常、协议错误、上游错误和结果持久化失败。用户看到失败阶段、可用结果范围及下一步；技术详情提供稳定错误类别和关联标识，不暴露凭证或内部绝对路径。准备失败明确“执行尚未开始”，运行中断不伪称所有操作未发生。诊断通道本身不可用时，在恢复后补充事实，不伪造持久化成功。

### FR-009 恢复与成果保护

资源恢复后允许继续读取已保存结果、重试未完成准备或按已证实执行状态恢复。执行终态未知时先核对原轮次，不自动再执行可能已经产生副作用的命令。已有可信快照、已提交输出与已应用成果不因重试被覆盖或重复应用；不能续接时明确提供安全重试或人工核验路径。恢复请求幂等，与现有治理恢复操作保持一致。

### FR-010 历史数据与迁移

既有会话、轮次、快照和差异可继续读取；旧数据已经缺失的全文不伪造补全。存储格式或位置变化需具备版本识别、完整性校验、迁移进度和回滚方案；迁移失败保留旧有效数据。继续执行现有删除意图、授权与备份保护，不因新增存储副本使已删除内容重新可见。存储介质与数据库变更在设计阶段明确，不能假定本期无需迁移。

### FR-011 可观测性与计量

复用请求与执行链路，记录快照扫描／复用、分批持久化、资源保护、恢复核验阶段的耗时、数量、字节数、错误类别及关联轮次；不向通用日志或分析事件写入完整 Prompt、回复、文件正文、凭证或本机路径。用户与空间用量保持真实、幂等和可解释。业务结果存储与脱敏观测分开授权；观测失败不阻断业务，结果持久化失败则必须按 FR-008/009 处理。

## 5. UI 约束

复用 Chat 对话、轨迹与执行详情入口以及既有状态投影。展示准备／保存进度、历史内容按需加载状态、可查看的已保存结果、明确失败原因和恢复入口；不得新增运营参数表单。不能只显示“未收到可展示的输出”而隐去已知准备失败原因。

恢复动作使用统一动作与状态矩阵，防止重复点击；不承诺存在无法真正执行的恢复按钮。保持键盘操作、可访问性、长文本滚动和当前主题样式。局部交互原型见 prototype/web/prototype.html，拆解与动作矩阵见 context.md；1440／1024／390 视口的视觉与运行验收在实现阶段完成。页面不得暴露宿主目录、原始协议或凭证。

## 6. 验证目标与质量约束

| 验证项 | 可复核成功条件 |
|---|---|
| 默认策略 | 新部署无限语义与计量正确；显式非法配置报错，已有有限运营策略不被暗中覆盖 |
| 大仓库 | 受控环境中超过 10000 文件且超过 512 MiB 的仓库成功建立快照并执行；记录规模与环境，不将测试样本当新上限 |
| 增量正确性 | 新增、修改、删除、重命名及并发变更可检测；不变内容复用有依据，与可信全量对照一致 |
| 长输出 | 累计超过 16 MiB 的合成结果持续保存，刷新／重连后按顺序完整读取，无重复及静默丢失 |
| 大文本 | 超过旧文本保留边界的内容可保存并按需读取，页面展示限制不冒充保存失败 |
| 资源有界 | 固定处理窗口下扩大输入／输出规模，记录进程峰值内存与磁盘增长；工作内存不随全部内容线性聚合 |
| 故障恢复 | 注入磁盘不足、持久化失败、进程退出、网络中断及重复恢复，已提交数据可核验，副作用和用量不重复 |
| 历史兼容 | 旧会话可读，缺失内容如实标注，迁移中断可恢复／回滚，删除意图不失效 |
| 授权与隔离 | 跨用户／空间读取、路径逃逸、敏感数据泄漏均被阻断，同会话互斥保留 |

上述是待实现验收目标，尚无通过结论。具体容量环境、性能时间目标、内存保护值和故障矩阵在 req-complete／Change 设计前冻结并说明依据；不将模型计费调用作为所有大容量测试的必要前提。合成压力测试与真实产品观察分别报告，真实链路仍需最小端到端确认。
