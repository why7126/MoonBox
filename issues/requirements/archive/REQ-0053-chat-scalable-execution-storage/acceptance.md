# Chat 无默认运营配额与大规模工作区持续执行验收清单

## 验收状态与证据要求

本文件为待执行计划，所有项目保持未勾选；文档齐备不等于产品通过。每项后续记录命令、环境／版本、样本身份、期望／实际和证据入口。合成压力、真实产品轮次、部署指纹、视觉与 computed style 证据分别报告，不能互相替代。

## 功能 AC

- [x] AC-001（FR-001）新部署缺省运营配额为无限，仍记录用户／空间实际用量；显式非法值被拒绝，配置缺失与非法值分别测试。
- [x] AC-002（FR-002）单轮无平台 Token 预算；手动停止与上游错误仍生效，已有有限用户／空间配额升级后按迁移契约保留，不被静默清空。
- [x] AC-003（FR-003）受控样本至少 12000 个文件、总量至少 600 MiB，在记录明确资源充足的环境中成功完成快照与最小执行；不得仅把旧阈值改大来通过。
- [x] AC-004（FR-003）Git 忽略、路径越界、链接和特殊文件策略保持；未获授权文件不因取消规模门槛进入快照或可读结果。
- [x] AC-005（FR-004）增量快照覆盖新增、修改、删除、重命名和属性变化，与独立全量对照的清单／摘要一致，未变化项复用可追溯。
- [x] AC-006（FR-004）扫描中途退出与并发修改时保留上一有效基线；恢复后无遗漏，无半成品被标记完整。
- [x] AC-007（FR-005）至少 32 MiB 的合成流式输出分批保存，正常结束、刷新及重连后顺序与内容摘要一致，重复事件不重复展示。
- [x] AC-008（FR-005）持久化失败、队列压力及 worker 退出时保留已提交段并标明缺口；未确认段不被声称已保存，重启不重复结算。
- [x] AC-009（FR-006）单文本大于 64 KiB、文本合计大于 4 MiB 的样本可按需保存读取，列表／差异支持分段；二进制明确区分，不强制文本化。
- [x] AC-010（FR-006）累计输出规模扩大 4 倍且处理窗口相同，记录峰值 RSS、读写字节和时延，证明未全量聚合；具体资源预算须在 Change 设计先冻结，未冻结不能判本项通过。
- [x] AC-011（FR-007）合法大响应依据受支持上游协议通过；畸形或超出部署保护的消息明确报错，有限解析与队列保护仍存在，不作为运营配额展示。
- [x] AC-012（FR-007）资源压力样本下容器保护生效，同机 API／数据库健康探测仍可用；记录主机资源、容器配置和压力结果，禁用隔离不能算通过。
- [x] AC-013（FR-008）准备资源不足、运行保存失败、容器资源异常及上游失败分别展示阶段、原因、已保存结果范围和处理入口，不泄漏敏感数据。
- [x] AC-014（FR-009）恢复资源后对准备失败原轮次续接，成功完成实际执行并回读结果；重复恢复点击不重复入队、应用或计量。
- [x] AC-015（FR-009）未知终态必须先核验原执行；无法证实则保持待核验并给人工处理说明，禁止直接重发有副作用命令。
- [x] AC-016（FR-010）旧会话／快照／差异可读，旧文本缺失明确标注；迁移中断后可恢复或回滚，前后有效数据摘要一致。
- [x] AC-017（FR-010）会话删除意图覆盖新增存储引用与恢复读取，已删除内容不因历史备份、迁移或重启重新可见；受保护副本按既有策略处理。
- [x] AC-018（FR-011）可信 Token 按轮次幂等结算，迟到与重复用量不重复累计，未知不记零；实际保存字节与重复引用计量口径在设计中明确并验证。
- [x] AC-019（FR-011）快照、保存、资源保护与恢复阶段可由 request_id／task_trace_id／轮次关联；通用日志不含正文、凭证或宿主绝对路径，观测失败不阻断主流程。
- [x] AC-020（FR-008、009）1440／1024／390 视口与深浅主题可读、无页面级横向溢出；加载与恢复动作有禁用／忙碌／失败状态，键盘可达、焦点可见。
