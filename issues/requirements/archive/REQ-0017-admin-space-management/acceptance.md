# 验收标准

## 功能 AC

- [ ] AC-001 空间列表支持按空间名称、唯一标识、负责人搜索，并支持状态、创建来源、有效期、用量状态筛选；筛选变更后列表、分页和空态与当前条件一致。
- [ ] AC-002 空间列表展示空间名称/编码、负责人、成员数、产品数、AI 用量、有效期、状态、创建来源、更新时间和操作列，并按 `allowedActions` 渲染查看、编辑、冻结、恢复、更多等状态化操作；长期有效空间的有效期列展示“长期有效”。
- [ ] AC-003 创建空间必须校验名称、唯一标识、负责人、成员配额、存储配额、AI 配额和有效期；负责人从用户管理列表的状态正常用户中选择，不暴露负责人 ID；创建成功后原子创建同名产品并建立不可解绑的一对一绑定。
- [ ] AC-004 空间唯一标识创建后不可修改；正常、冻结、回收中空间均参与重名和唯一性校验。
- [ ] AC-005 空间申请审批展示待审批数量；申请审批 Tab 使用后台统一紧凑审批表格展示空间名称/编码、申请人、负责人、资源申请、有效期、申请时间和操作，空间名称/编码两行展示，资源申请使用成员、存储和 AI Tokens 三个独立紧凑资源项展示，不使用分隔符伪元素，AI Tokens 使用中文短量级格式并不得挤压有效期或申请时间列；操作使用轻量文字操作且通过为主操作色、拒绝为危险色；申请审批列表使用真实分页接口，本轮不新增搜索/筛选交互；通过前可调整负责人、有效期和三类配额，拒绝必须填写原因，并保留历次审批记录；前台创建空间申请入口未实现前，开发/演示环境可通过后端 seed 或脚本生成待审批申请数据，演示数据必须走真实空间申请数据结构和审批链路，生产环境不自动播种，前端不得硬编码生产 Mock。
- [ ] AC-006 空间详情包含详情头、无边框文本面包屑、空间名称、状态、编码/来源、负责人摘要、负责人变更入口、状态化操作、返回空间列表入口，以及概览、成员、产品、配额与用量、操作记录 5 个分区 Tab；详情头需按原型展示空间名称与状态同行、编码/来源和负责人摘要同组、右侧实体操作按钮，删除操作使用危险色；返回空间列表入口使用无边框文字链接样式；详情页需与空间列表页复用统一后台侧边栏，并保持空间管理 active、折叠、用户菜单、个人资料、修改密码、返回前台、主题切换和退出登录入口一致；侧边栏需以视口高度稳定布局，详情主内容滚动或变长时不得撑高侧边栏，底部用户触发区需贴近视口底部且可见；负责人摘要使用后台统一头像组件展示真实头像，缺失时 fallback 首字，且负责人姓名与变更入口之间不展示额外“负责人”文案；详情页局部字体、按钮、头像、卡片和间距必须按原型紧凑尺度展示，不得使用后台页面标题级大字号或大按钮尺度；5 个分区可切换并展示对应 UI 骨架与数据；详情页编辑、调整配额、续期、移交负责人、冻结和删除入口需提交对应真实操作，成功后重新拉取当前空间详情和审计事件并同步刷新概览最近操作，删除进入回收站后退出详情回到空间列表；操作弹窗标题需展示具体操作名称；成员分区展示成员管理表格，字段为用户、角色、加入时间、状态和操作，负责人不展示在成员表格中且负责人变更仍走详情头变更流程，成员表格需在不放大字号的前提下通过适度行高、单元格垂直间距和垂直居中保证行间可读性，成员用户列复用后台统一头像组件并支持真实头像/fallback 首字，负责人和成员头像 URL 必须使用统一 `/api/v1/auth/avatar/{filename}` 路由，历史 `/api/v1/admin/users/avatar/{filename}` 需在空间读模型中规范化且不得恢复旧头像读取接口；支持从状态正常用户中添加成员、编辑成员角色和移除成员，成员角色限定为管理员、编辑者、查看者并按该顺序及加入时间倒序展示；操作记录分区接入真实分页 `/api/v1/admin/spaces/{space_id}/audit-events?page=&page_size=`，表格按时间、操作人、操作动作、变更摘要、结果、操作展示，操作动作和结果等枚举值使用轻量标签、中文文案和差异化颜色展示，操作记录分页使用轻量无边框样式且保留 hover、focus-visible 和 active 状态；行内查看打开右侧详情抽屉展示来源、对象、request_id、完整变更前后值、原因和结果，变更前和变更后存在 JSON 或原始文本内容时以 JSON code block 格式化展示，解析失败时降级显示原始文本，长内容在 code 区域内滚动且不得撑高抽屉，变更前或变更后为空、null、空字符串或“无”时使用轻量空态文本“无”，不得使用大块 JSON code block 或撑高抽屉，审批通过创建空间时新空间详情可追溯审批来源；产品分区顶部展示“绑定关系不可解除或迁移，产品名称始终与空间名称一致。”提示，下方按产品卡片列表展示，一张 Card 对应一个产品，当前阶段仅展示一个绑定产品卡片，产品 Card 不显示“绑定产品”标题，字段展示产品名称、产品 ID、绑定状态、研发状态并移除产品数字段，字段布局复用详情页统一字段网格，且不提供解绑、迁移或新增第二产品等未实现操作。
- [ ] AC-007 详情概览中“基础信息”“配额与用量”“最近操作”为同级独立模块，不得把配额与用量嵌套进基础信息或最近操作；概览布局需符合原型的基础信息左上、配额与用量左下、最近操作右侧结构，并保持左宽右窄比例；基础信息卡使用两列字段网格，字段顺序为空间名称、唯一标识、创建来源、创建时间、有效期，固定日期显示完整到期时间，长期有效显示“长期有效”，字段 label 与 value 不得表单式缩进；概览 Tab 不展示空间与产品永久绑定提示；最近操作必须基于真实审计事件最新 6 条展示，编辑、调整配额、移交负责人、续期、冻结、删除等详情操作成功后需重新拉取当前空间详情和审计事件并同步刷新概览最近操作；最近操作中的操作动作使用普通或中等字重，不得抢占卡片标题视觉层级。
- [ ] AC-008 常规编辑仅允许修改名称、简介和有效期，不包含负责人字段；负责人移交与配额调整必须使用独立高风险操作入口，负责人移交使用状态正常用户下拉选择。
- [ ] AC-009 当前一空间一产品阶段，空间名称等于产品名称、空间唯一标识等于产品 ID；产品信息由空间字段派生，产品绑定不可解绑、不可迁移，产品数固定为 1。
- [ ] AC-010 配额覆盖成员数、存储量、AI Token/模型调用量；80% 预警，100% 限制新增或继续消耗对应资源，但不得删除已有数据。
- [ ] AC-011 有效期支持固定日期和长期有效；固定日期必须使用后台统一日期时间选择控件，输入框展示 `yyyy-mm-dd hh:mm:ss`，展开后同时支持日期和时/分/秒选择，支持手动输入后格式化，默认值为当前季度最后一天 23:59:59，且必须晚于当前时间；长期有效不展示、不保存结束日期且不触发到期提醒或到期自动冻结。
- [ ] AC-012 冻结后允许查看、检索、导出及平台管理员调整必要配置，禁止成员变更、内容修改、任务执行、Agent/Skill 运行及 AI 调用。
- [ ] AC-013 删除前必须检查运行中 Agent、任务和未完成迭代；存在阻塞项时禁止删除并列出阻塞原因。
- [ ] AC-014 删除后空间、产品、成员和关联数据整体进入 30 天回收期；回收站 Tab 必须独立请求 `status=RECYCLE` 的真实分页数据，不得从默认空间列表本地过滤；回收站分页 total 使用回收站接口返回值；回收站表格展示删除时间、删除人、删除原因、剩余天数，并提供查看、恢复和彻底删除操作；回收站行内“更多”菜单必须复用普通空间列表 body 级 fixed 浮层能力，锚定当前回收站行按钮下方，不得向上漂移，确保菜单面板和菜单项文字完整可见，且不得被表格、分页、sticky 操作列或回收站容器遮罩/裁剪；当当前行无更多收敛操作时不得展示“更多”按钮或空菜单面板；删除空间成功后需刷新对应列表并确保可在回收站看到；回收期内可整体恢复。
- [ ] AC-015 提前永久删除仅超级管理员可见可用，必须输入唯一标识并填写原因，且不可撤销。
- [ ] AC-016 系统保留空间及超级管理员创建的受保护空间不允许删除。
- [ ] AC-017 所有高风险写操作必须记录操作人、时间、来源、对象、变更前后值、原因和结果，并且高风险审计记录不可删除；编辑空间、添加成员和编辑成员角色不按高风险操作强制填写操作原因，但仍需写入审计记录。
- [ ] AC-018 通知覆盖申请、配额 80%/100%、到期 30/7/1 天、冻结/恢复/续期、负责人变更、回收与永久删除。
- [ ] AC-019 后端接口必须校验权限、状态、幂等键和阻塞条件；前端不得仅凭 UI 隐藏替代服务端权限控制。

## 横切 AC（knowledge-base）

> 来源：`docs/knowledge-base/best-practices/admin-list-page-consistency.md`、`docs/knowledge-base/best-practices/admin-modal-width-css-cascade.md` — 预防 Sprint 002/003 复发类缺陷

- [ ] AC-XCUT-001 空间列表分页 DOM 必须与用户管理基准一致：总数在左侧，翻页、页码、“每页显示”文案和条数下拉在右侧。
- [ ] AC-XCUT-002 成功和失败反馈必须使用 fixed toast，不得引发布局位移，不得挤压列表、分页、弹窗或详情内容。
- [ ] AC-XCUT-003 冻结、恢复、删除、永久删除、配额调整、负责人移交等状态或高风险变更必须使用设计系统确认弹窗。
- [ ] AC-XCUT-004 管理后台状态变更不得调用 `window.confirm`。
- [ ] AC-XCUT-005 表格行内操作列在横向滚动或列较多时必须保持易访问。
- [ ] AC-XCUT-006 筛选条件变化后，列表结果、分页状态和空态提示必须与当前条件一致。
- [ ] AC-XCUT-007 弹窗实现不得让通用 `modal-card` 与专属宽度类并存，避免通用样式覆盖创建、编辑、审批等业务弹窗宽度。
- [ ] AC-XCUT-008 弹窗实现必须在浏览器 computed style 中验收宽度，确认最终宽度与原型或设计预期一致。
- [ ] AC-XCUT-009 低视口下弹窗 body 必须可滚动，底部主操作和取消操作必须可访问。
- [ ] AC-XCUT-010 弹窗遮罩不得吞掉内部滚动，也不得导致页面主体误滚动。
- [ ] AC-XCUT-011 必填字段、错误提示和底部操作区不得互相遮挡；必填项 `*` 必须为红色，新增/编辑空间弹窗标题不得展示装饰图标。
- [ ] AC-XCUT-012 新增空间弹窗字段顺序必须为：空间名称/空间编码、负责人/成员上限、存储空间/AI Tokens、有效期类型/到期时间、描述整行；编辑弹窗不包含负责人和配额字段，描述仍独占一整行。
- [ ] AC-XCUT-013 后台管理下拉框必须统一使用共享 `AdminSelect` 或等价组件，覆盖用户管理、空间管理和后台分页条数；展开列表必须位于触发器下方，不覆盖原下拉组件，并支持键盘选择和点击外部关闭。
- [ ] AC-XCUT-014 空间列表必须对齐原型首屏结构：展示 4 张统计卡、下划线主页签、空间名称/编码、负责人、成员数、产品数、AI 用量、有效期、状态、创建来源、更新时间、操作列，成员数和产品数列按短数值内容收窄，AI 用量列按内容适度收敛但仍保留两行进度条表达且不挤压操作列；AI 用量按原型两行展示：上行展示进度条，下行仅展示百分比数值，并通过进度条和百分比颜色表达正常、预警和超限；创建来源用轻量标签，更新时间格式为 `yyyy-mm-dd hh:mm:ss`；除空间名称/编码列和 AI 用量列外表头和内容不换行；低频或高风险操作收敛到“更多”，且更多菜单必须以不受表格 overflow 或 sticky 操作列裁剪的浮层方式展示，并支持点击外部和 Escape 关闭，定位锚定当前行“更多”按钮，显示在按钮正下方并从按钮左边缘展开，面板与按钮之间保留小间隙且不得重叠，不得横向漂移到筛选栏或表格中部，菜单面板不透明、紧凑，背景与边框颜色适配暗色/浅色主题并与对应页面背景有清晰区分，菜单项内容靠左对齐且普通项高对比可读，普通项与危险项均需有清晰 hover/focus-visible 状态；空间名称为无边框文字链接，操作列宽度参照用户管理列表，1440px 桌面视口下操作列必须可见且不拥挤，行内操作与状态展示应对齐用户管理列表的无边框文字链接和低视觉重量风格，状态需用不同语义图标或颜色区分正常、冻结、回收站。
- [ ] AC-XCUT-015 空间管理高风险操作原因必须参照 BUG-0010 的后台确认弹窗校验模式：字段显示红色必填标记和输入提示；空原因或不足 4 字点击确认时展示可见错误、设置 `aria-invalid` 或等价可访问性反馈，不得静默无响应，不得发起写请求；有效原因才允许提交。
- [ ] AC-XCUT-016 添加成员和编辑成员弹窗字段必须纵向布局；用户和角色下拉展开列表不得被弹窗滚动容器裁剪或遮罩，需以宽度匹配触发器的不透明浮层展示；移除成员弹窗操作原因必填标签必须保持单行紧凑显示，红色星号不得单独换行。
- [ ] AC-XCUT-017 管理后台亮主题金色主按钮文字必须使用主题适配深棕或深文本色，字重为中等，不得使用突兀纯黑；暗主题主按钮需保持可读，hover 和 focus-visible 需保持足够对比。
