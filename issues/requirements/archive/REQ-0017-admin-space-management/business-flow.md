# 业务流程

## 总体流程

```text
进入后台空间管理
  |
  +-- 空间列表：搜索/筛选/分页/状态化操作
  |     |
  |     +-- 创建空间
  |     |     -> 校验名称与唯一标识
  |     |     -> 选择负责人、成员、配额、有效期
  |     |     -> 原子创建空间 + 同名产品
  |     |     -> 写入审计并刷新列表
  |     |
  |     +-- 查看详情
  |           -> 概览 / 成员 / 产品 / 配额与用量 / 操作记录
  |
  +-- 申请审批
  |     -> 查看申请详情
  |     -> 核定负责人、有效期、配额
  |     -> 通过：创建空间 + 同名产品 + 通知
  |     -> 拒绝：填写原因 + 通知 + 保留记录
  |
  +-- 回收站
        -> 查看回收期空间
        -> 恢复：整体恢复空间、产品、成员和关联数据
        -> 永久删除：超级管理员二次确认 + 输入唯一标识 + 填写原因
```

## 空间生命周期

```text
申请中
  | 审批通过
  v
正常 ACTIVE
  | 手动冻结 / 到期自动冻结
  v
冻结 FROZEN
  | 续期或风险解除后恢复
  v
正常 ACTIVE
  | 删除前阻塞检查通过
  v
回收中 RECYCLE
  | 30 天内恢复
  v
正常 ACTIVE

回收中 RECYCLE
  | 超级管理员提前永久删除或回收期结束清理
  v
永久删除 PURGED
```

## 配额与有效期流程

```text
查看配额与用量
  |
  +-- 用量 < 80%：正常展示
  +-- 80% <= 用量 < 100%：预警展示并通知负责人
  +-- 用量 >= 100%：禁止新增或继续消耗对应资源

调整配额 / 续期
  -> 填写变更值与原因
  -> 服务端校验权限、状态、幂等键
  -> 保存变更并写入审计
  -> 通知空间负责人
```

## 与现有需求的差异

- 区别于 `REQ-0004-admin-user-management`：本需求治理空间、产品绑定、空间成员和资源配额，不治理平台用户账号本身。
- 区别于前台空间申请能力：本需求仅覆盖后台运营侧申请审批与空间治理，不设计用户侧申请入口。
- 区别于纯产品管理：本需求要求一空间一产品强绑定，产品名称随空间名称同步，不提供产品迁移或解绑。

## 数据与权限边界

- 空间、产品绑定、成员、配额、申请、审计记录均由后端事实源驱动。
- 前端可根据 `allowedActions` 展示操作入口，但服务端必须再次校验权限、状态和阻塞条件。
- 高风险动作包括冻结、恢复、删除、永久删除、负责人移交、配额调整和有效期调整，均需要原因、幂等保护和审计写入。
