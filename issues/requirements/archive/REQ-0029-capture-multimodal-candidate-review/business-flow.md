# 业务流程

## 主链路

```text
选择授权项目 → 新建/恢复本人草稿 → 文字与图片校验/上传
  → 服务端自动保存 → AI 只整理候选 → 服务端结构校验
  → 用户编辑/改类型/合并/拆分/删除 → 自动保存新版本
  → 确认全部保留候选 → 校验项目/权限/当前版本
  → 固定确认快照与任务 → 锁内分配最终 REQ/BUG 编号
  → 保存恢复计划 → 批量写 capture/trace/registry/index
  → 整批一致性校验 → 解除读取屏障 → 真实看板刷新 → 来源回查
```

## 状态与异常

| 当前阶段 | 事件 | 结果与恢复 | 编号/正式写入 |
|---|---|---|---|
| 输入/上传 | 空材料、超限、上传失败 | 保留已有输入；移除失败项或重试；未可用材料不送模型 | 无 |
| 草稿编辑 | 自动保存失败 | 保留本地当前编辑，禁止确认，重试保存 | 无 |
| 整理 | 模型失败、图片不可读、结果非法 | 明确失败原因，返回草稿重试；原材料和人工版本保留 | 无 |
| 候选审阅 | 编辑、改类型 | 同一内部 ID，新版本；目标类型分级重新建议 | 无 |
| 候选审阅 | 合并/拆分 | 新内部 ID，父候选来源边保留；旧候选标为已替代，不参与确认 | 无 |
| 候选审阅 | 删除全部 | 空态，可回到输入；确认禁用 | 无 |
| 确认 | 版本或项目绑定变化 | 冲突，保留编辑并重新审阅；不能确认旧快照 | 无 |
| 已受理 | 重复点击或更换请求键 | 同批同版本返回原任务；不重新编号 | 仅原任务可分配 |
| 创建中 | 网络断开/刷新 | 重新读取原任务，不新建草稿或确认任务 | 复用原映射 |
| 创建中 | 进程中断/部分写入 | 整批处于恢复中，按已知前后镜像向前续作；看板不公开半成品 | 复用原映射 |
| 恢复中 | 外部修改/权限撤销 | 保留恢复证据并报告需处理；不删锁、不强改成功、不覆盖外部修改 | 不分配新映射 |
| 创建成功 | 再次提交同一确认 | 返回原完整结果 | 无新写入 |
| 未确认草稿 | 主动删除 | 确认影响范围；无任务占用、无正式引用才释放资源，保留删除标记 | 无 |
```

## 身份与保存规则

- 批次身份、候选内部身份、候选版本、确认任务与正式 Issue ID 分离。显示序号可以变化，不用于图片关联。
- 保存使用版本检查，1 秒停止输入/最长 5 秒触发；服务端确认保存才显示“已保存”。多窗口冲突不覆盖已有版本。
- 关闭不等于删除；同用户同项目从恢复草稿入口继续。原型仅模拟本地保存，产品使用服务端保存。
- 编辑与改类型保持候选 ID；合并新条目引用全部父来源，拆分子条目按对应证据关联原图，不机械复制无关图片。
- 确认生成不可变快照；任务处理中不再编辑该快照，关闭后仍可恢复查看任务。
- 50 个草稿/1 GiB 草稿材料、10 张图/每图 10 MiB/合计 50 MiB、2000 万像素及 20000 码点文字是首版限制，服务端统一返回。
- 未确认材料保留至主动删除；正式来源与成功确认映射随 Issue 保留。未关联上传 24 小时清理；未终态恢复证据不自动清理。

## 与关联需求差异

无父需求。本需求扩展 Capture 入口的未编号审阅闭环；REQ-0022 的候选是已有 REQ 的文档生成成果，REQ-0028 的附件属于 Chat 输入。共用附件与受控写入基础，不共享错误的候选身份或改变其他需求范围。

## 副作用与观测

AI 整理阶段只有草稿写入权限。确认后仅写采集产物，不自动生成 PRD/bug.md、评审或进入 Sprint。业务原始材料独立于脱敏请求日志和任务节点；用户行为→请求→整理/确认任务可关联，直接 API 不伪造页面事件。
