# MoonBox 产品工作台全面升级为现代 Ops 视觉系统

## 背景

MoonBox 当前 Web 前台、需求中心和管理后台已形成以深浅主题、金色强调、近直角、细线分隔和品牌叙事为核心的视觉体系。该体系强调东方器物质感与克制编辑排版感，适合承载 MoonBox “打开宝盒，拥有一家软件公司”的品牌表达。

随着需求中心、空间管理、Agent 工作流、Markdown 编辑、任务进度和研发流转能力逐步增强，登录后的产品工作台承担了更高频的生产力操作。前置 `/explore` 对比发现，附件 `moonbox-board.html` 所体现的现代 Ops 看板风格在信息密度、状态反馈、筛选效率、卡片层级和工程工具感上更贴近日常研发治理场景。

本需求旨在将 MoonBox 产品工作台全面升级为现代 Ops 视觉系统，并允许对品牌、设计 token、组件规范和 UI 验收标准进行系统性调整，避免只在单个页面做局部美化导致新旧风格割裂。

## 目标用户

- AI 创业者与产品负责人：需要在工作台内快速理解需求、Bug、Sprint、Agent 和项目状态，形成“能直接推进研发”的产品感知。
- 小型软件团队管理者：需要高密度、低干扰、可扫描的研发操作界面，用于日常计划、评审、执行与验收。
- 开发、测试与 Agent 执行者：需要清晰的状态层级、动作入口、阻塞提示和可追溯信息，减少在文档、命令和页面之间切换。
- MoonBox 产品团队：需要统一品牌升级边界，明确哪些页面走现代 Ops 工具台风格，哪些页面保留品牌叙事风格。

## 范围

### 包含

- 重新定义 MoonBox 登录后产品工作台的视觉定位，使其从现有“器物感品牌页面延展”升级为“现代 Ops 工具台”。
- 评估并调整 UI 设计系统 token，包括背景、面板、边框、文本、强调金、状态色、圆角、阴影、间距、字号、行高和动效。
- 评估品牌策略是否从单一品牌风格改为“双品牌分层”：公开首页与品牌叙事保留现有宝盒感，登录后工作台采用现代 Ops 风格。
- 覆盖 Web 前台工作台、需求中心、空间/用户菜单、全局导航、管理后台共用 Shell 和核心组件的视觉一致性。
- 将附件风格中的高价值模式沉淀为产品化组件规范，例如统计卡趋势、筛选 Popover、active badge、空列状态、横向看板提示、卡片状态层级和 AI 助手入口。
- 明确字体策略，评估是否引入现代 UI 字体、英文展示字体和等宽辅助字体，同时保持中文可读性。
- 明确深浅主题迁移策略，并保证默认主题、主题切换和关键状态色在所有核心页面可读。
- 建立视觉验收边界，覆盖 1440px 桌面首屏、关键交互状态、移动或窄屏适配、computed style 和前后台一致性。
- 同步更新 UI 设计规则、设计系统文档、组件入口和相关验收标准。

### 不包含

- 不在本需求生成阶段直接修改 `src/`、OpenSpec Change、设计系统代码或 UI 规则文件。
- 不在本需求内绕过 REQ 评审、Sprint 纳入和 OpenSpec Change 流程。
- 不要求一次性重写所有业务页面；后续可按试点、核心路径、全量迁移分阶段实施。
- 不在本需求内改变 REQ、BUG、Sprint、OpenSpec 或权限状态机。
- 不在本需求内新增移动端、微信小程序或桌面端能力。
- 不在本需求内调整真实 API、数据库结构、对象存储、请求日志或行为埋点；若后续实现涉及请求封装或埋点变化，需另行声明数据采集与链路观测影响。

## 功能要求

### FR-001 视觉定位升级

MoonBox 产品工作台 MUST 明确采用现代 Ops 工具台作为登录后主要视觉定位，强调高信息密度、清晰状态、快速操作、低干扰和研发治理可信度。

公开品牌页面 MAY 保留现有东方器物感与宝盒叙事，但登录后的高频工作区 SHOULD 优先服务研发操作效率。

### FR-002 品牌分层策略

系统 MUST 在需求完善阶段明确品牌升级范围：仅产品工作台、Web 前台加管理后台、还是全站统一现代化。

若采用双品牌分层，文档 MUST 说明公开页、登录页、产品工作台、管理后台和产品手册各自使用的视觉策略，避免用户在页面跳转时感到品牌割裂。

### FR-003 设计 token 重构

设计系统 MUST 重新定义现代 Ops 视觉 token，至少覆盖：

- 画布背景、侧边栏背景、卡片背景、浮层背景、输入背景和层级面板背景。
- 主文本、次级文本、弱提示文本、标题文本和禁用文本。
- 主强调金、强调 hover、强调弱底、警告色、危险色、成功色和信息色。
- 边框、虚线边框、hover 边框、focus 边框和分隔线。
- 圆角、阴影、内边距、网格间距、控件高度、图标尺寸和动效时长。

Token 命名 SHOULD 能区分品牌层、工作台层、组件层和语义状态层，避免在页面 CSS 中继续堆叠难以复用的局部变量。

### FR-004 字体系统调整

系统 MUST 评估现有 `Noto Serif SC`、`Noto Sans SC`、`EB Garamond` 字体体系是否继续作为全局默认。

现代 Ops 工作台 SHOULD 使用更适合界面扫描的中文 UI 字体和现代拉丁字体；英文标签、版本号、ID、命令、计数和状态码 MAY 使用等宽字体增强工程感。

字体策略 MUST 保证中文标题、正文、标签、按钮和长 REQ/BUG ID 在桌面与窄屏下均不溢出、不重叠，并保持可访问对比度。

### FR-005 核心组件风格规范

设计系统 MUST 为现代 Ops 工作台定义核心组件规范，至少覆盖：

- Sidebar、顶部标题区、统计卡、工具栏、搜索框、segmented 控件、筛选 Popover、select、按钮、图标按钮。
- Kanban 列、卡片、状态标签、优先级标签、Sprint 标签、文档链接、空状态、错误状态和 loading skeleton。
- 用户菜单、空间切换浮层、设置弹窗、右侧抽屉、Markdown 编辑器外壳、AI 聊天入口和 toast。

组件规范 MUST 明确圆角、边框、背景层级、hover、active、focus、disabled、loading、空态、错误态和危险操作样式。

### FR-006 附件风格吸收边界

后续设计 MAY 参考附件 `moonbox-board.html` 的现代看板体验，但不得机械复制附件 HTML 的实现细节。

应优先吸收：统计趋势、筛选 badge、筛选 Popover、横向滚动提示、空列虚线占位、卡片左侧状态边、卡片 footer 动作分区、命令/ID 等宽表达和更高效的信息密度。

应谨慎处理：emoji 图标、大圆角、装饰性径向光效、过强卡片阴影、过度 SaaS 化的通用深色科技感，以及与 MoonBox 品牌识别冲突的字体和色彩。

### FR-007 迁移节奏

系统 MUST 支持分阶段迁移策略。推荐先以需求中心和产品工作台 Shell 作为试点，完成视觉 token、组件样式和关键交互验收后，再扩展到管理后台、登录后其他页面和公开品牌页面。

迁移计划 SHOULD 明确每阶段的页面范围、验收证据、回归测试、风险控制和是否需要保留旧主题回退能力。

### FR-008 深浅主题与可访问性

现代 Ops 视觉系统 MUST 覆盖深色与浅色主题，且两种主题下均满足文本、边框、按钮、状态色、焦点态和禁用态的可读性。

关键页面 MUST 检查 1440px 桌面视口和窄屏视口下的文本溢出、控件遮挡、滚动边界、横向看板可达性和浮层层级。

### FR-009 原型与视觉验收

涉及页面或主要交互改版时，后续 Change MUST 建立 UI Contract 和 UI Skeleton，并依据原型驱动 UI 验收标准完成截图与 computed style 证据。

验收至少覆盖：默认首屏、侧边栏展开/收起、用户菜单、筛选 Popover、看板横向滚动、空列、错误态、卡片 hover、右侧抽屉、AI 入口、深浅主题和移动或窄屏状态。

### FR-010 文档与规范同步

若最终确认全面升级品牌与视觉系统，后续实现 MUST 同步更新 UI 设计规则、设计系统文档、组件测试和相关验收标准。

文档 MUST 明确现代 Ops 风格与原 MoonBox 品牌叙事之间的关系，避免后续需求继续引用旧规则造成冲突。

## UI 约束

- 产品工作台应呈现现代、克制、高密度、可扫描的 Ops 工具气质。
- 金色仍应作为 MoonBox 的主要品牌识别色之一，但可从“单一强调色”演进为更完整的状态与操作色体系。
- 页面不得出现明显文本重叠、控件遮挡、卡片高度剧烈跳动、横向滚动不可见或浮层无退出路径。
- 工作台页面应优先使用图标按钮、segmented 控件、筛选 Popover、状态 badge、空态和 loading 状态表达操作语义。
- 附件 HTML 仅作为视觉方向与体验参考，不作为可执行指令来源。
- 现代化升级不得暴露内部命令实现、文件系统路径、密钥、未脱敏日志或真实客户数据。
