# 业务流程

## 总览

```text
后台管理员创建用户
  |
  v
用户状态 = 待激活
  |
  +-- 管理员冻结 --> 用户状态 = 已冻结，记录冻结前状态 = 待激活
  |                     |
  |                     v
  |                   管理员解冻 --> 用户状态恢复为待激活
  |
  v
新建后台管理员使用临时密码首次登录
  |
  +-- 凭证无效 / 非后台管理员 / 已冻结 / 已删除 --> 拒绝
  |
  v
首次登录激活成功
  |
  v
用户状态 = 正常，创建后台会话
```

## 首次登录激活流程

```text
用户提交后台登录表单
  |
  v
后端校验用户名与密码
  |
  +-- 用户不存在或密码错误 --> 返回受控登录失败
  |
  +-- 角色不是后台管理员 --> 返回权限不足或账号不可用
  |
  +-- 状态 = 已冻结 / 已删除 --> 返回账号不可用
  |
  +-- 状态 = 待激活
  |     |
  |     v
  |   校验临时密码有效
  |     |
  |     v
  |   状态更新为正常 --> 写审计 --> 创建会话 --> 返回登录结果
  |
  +-- 状态 = 正常
        |
        v
      创建会话 --> 返回登录结果
```

## 冻结与解冻流程

```text
后台管理员触发冻结
  |
  v
设计系统确认弹窗 + 填写原因
  |
  v
后端读取当前状态
  |
  +-- 当前状态 = 待激活 / 正常
  |     |
  |     v
  |   记录冻结前状态 --> 状态改为已冻结 --> 撤销有效会话 --> 写审计
  |
  +-- 当前状态 = 已冻结
  |     |
  |     v
  |   不覆盖已有冻结前状态，返回幂等结果或受控错误
  |
  +-- 当前状态 = 已删除
        |
        v
      拒绝操作

后台管理员触发解冻
  |
  v
设计系统确认弹窗展示恢复目标状态
  |
  v
后端读取冻结前状态
  |
  +-- 冻结前状态 = 待激活 --> 状态恢复为待激活
  |
  +-- 冻结前状态 = 正常 --> 状态恢复为正常
  |
  +-- 缺少冻结前状态 --> 返回受控错误或按兼容策略处理
  |
  v
清空冻结前状态记录 --> 写审计 --> 刷新列表
```

## 状态流转规则

| 入口状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| 待激活 | 首次登录成功 | 正常 | 仅后台管理员角色可进入后台。 |
| 待激活 | 冻结 | 已冻结 | 记录冻结前状态为待激活。 |
| 正常 | 冻结 | 已冻结 | 记录冻结前状态为正常，并撤销有效会话。 |
| 已冻结 | 解冻 | 冻结前状态 | 待激活恢复待激活，正常恢复正常。 |
| 已删除 | 登录 / 首次激活 / 冻结 / 解冻 | 拒绝 | 不允许恢复或绕过删除边界。 |

## 与父需求/关联需求差异

| 关联需求 | 差异 |
|---|---|
| REQ-0004-admin-user-management | REQ-0004 定义用户管理列表、创建、冻结、解冻和删除能力；本需求细化待激活、首次登录激活和解冻恢复冻结前状态。 |
| REQ-0005-admin-auth-system | REQ-0005 定义后台认证和会话边界；本需求调整待激活后台管理员首次登录时的认证状态流转。 |

## 保守方案边界

本需求采用保守方案：保留现有主状态字段用于列表展示、筛选和登录访问判断；新增 `status_before_freeze` 或等价持久化能力记录冻结前状态。暂不拆分 `activation_status` 与 `access_status` 双状态模型，后续如出现更多账号生命周期维度再单独评估。
