# 原型说明

## 目标

本原型用于说明后台用户列表中“待激活 / 已冻结 / 正常”状态的操作语义，以及解冻确认弹窗如何展示“解冻后恢复到冻结前状态”。

## 覆盖场景

- 待激活后台管理员：可冻结，不能由管理员解冻为正常；用户本人首次登录成功后才转为正常。
- 待激活用户被冻结：列表展示为已冻结，解冻确认提示“恢复为待激活”。
- 正常用户被冻结：列表展示为已冻结，解冻确认提示“恢复为正常”。
- 临时密码说明：新建用户成功后的敏感结果文案应表达“用于首次登录激活”。

## 不覆盖

- 不实现真实 API 调用。
- 不实现完整后台登录页或首次登录改密流程。
- 不展示已删除用户恢复能力。
- 不覆盖上传链路。

## 视觉约束

- 延续 MoonBox 管理后台近直角、细线、克制金色强调和高信息密度。
- 弹窗和 toast 用于表达交互位置与文案，不作为最终设计稿。
- 后续实现必须使用浏览器 computed style 验收弹窗宽度和低视口滚动。

## 页面清单

| 页面/状态 | 原型文件 | 说明 |
|---|---|---|
| 用户管理列表 | `prototype.html` | 展示待激活、已冻结、正常三类账号状态及筛选入口。 |
| 解冻确认弹窗 | `prototype.html` | 展示“解冻后恢复为待激活”的确认文案和原因输入。 |
| fixed toast | `prototype.html` | 展示解冻成功后固定位置反馈，不挤压列表或弹窗。 |

## 组件层级

- `AdminUserStatusPage`：承载页头、筛选栏、表格、分页、确认弹窗和 toast。
- `AdminUserFilterBar`：包含搜索、角色筛选、状态筛选。
- `AdminUserStatusTable`：展示用户行、状态标签、冻结前状态和行内操作。
- `UserStatusBadge`：展示待激活、正常、已冻结状态。
- `UnfreezeConfirmModal`：展示恢复目标状态、操作原因和确认按钮。
- `AdminFixedToast`：展示成功或失败反馈。

## 状态矩阵

| 当前状态 | 冻结前状态 | 可见操作 | 弹窗/反馈重点 |
|---|---|---|---|
| 待激活 | 无 | 编辑、重置密码、冻结 | 不展示“激活”或“解冻即正常”。 |
| 已冻结 | 待激活 | 编辑、重置密码、解冻 | 解冻后恢复为待激活。 |
| 已冻结 | 正常 | 编辑、重置密码、解冻 | 解冻后恢复为正常。 |
| 正常 | 无 | 编辑、重置密码、冻结 | 冻结后撤销会话。 |
| 已删除 | 任意 | 不可操作 | 不展示恢复入口。 |

## 交互触发

- 点击“冻结”：打开状态变更确认弹窗，要求填写原因。
- 点击“解冻”：打开解冻确认弹窗，并展示恢复目标状态。
- 确认解冻成功：关闭弹窗，刷新列表状态，展示 fixed toast。
- 修改状态筛选：刷新列表、分页和空态提示，保持与当前筛选一致。
- 待激活用户首次登录：不在本页面完成，由后台登录流程触发状态自动转正常。

## 数据依赖

- 用户列表 API 需要返回用户主状态 `status`。
- 已冻结用户需要可推导或返回冻结前状态，用于展示解冻恢复目标。
- 解冻确认弹窗需要目标用户 ID、用户名、当前状态、冻结前状态和操作原因。
- 登录激活流程需要后端在临时密码校验成功后更新状态并返回会话。

## 响应式断点

- 1440px：主验收视口，表格、筛选栏、弹窗和 fixed toast 不遮挡。
- 1280px：后台列表保持可读，行内操作列可访问。
- 低视口高度：确认弹窗 body 可滚动，底部取消和确认按钮可访问。
- 移动端：本需求不新增移动端后台能力；如复用响应式布局，不得出现文字重叠或横向不可控溢出。

## 1440px 验收焦点

- 筛选栏三列布局稳定，不因状态文案变化挤压搜索框。
- 表格状态标签、冻结前状态和行内操作不重叠。
- 解冻确认弹窗最终 computed width 与设计预期一致。
- 弹窗中“解冻后恢复为待激活/正常”提示可见且不与原因输入遮挡。
- fixed toast 位于视口固定位置，不引发布局位移。
- 页面无 `window.confirm` 交互痕迹。
