# 验收清单

## 功能 AC

- [ ] AC-001 后台管理员创建用户成功后，新用户主状态为“待激活”，并可在用户列表按“待激活”筛选到该用户。
- [ ] AC-002 创建用户返回的一次性临时密码仅在创建结果弹窗中展示一次，文案明确该密码用于首次登录激活。
- [ ] AC-003 待激活且角色为“后台管理员”的用户使用有效临时密码登录后台时，系统允许完成首次登录激活。
- [ ] AC-004 首次登录激活成功后，目标用户状态自动更新为“正常”，并返回 access token、过期时间和当前用户摘要。
- [ ] AC-005 状态为“正常”且角色为“后台管理员”的用户可按既有后台认证规则正常登录。
- [ ] AC-006 角色为“前台用户”的账号不得通过待激活首次登录流程进入管理后台，即使密码正确也必须被拒绝。
- [ ] AC-007 状态为“已冻结”的用户不得登录后台，不得完成首次登录激活，也不得通过已有会话访问 `/api/v1/admin/**`。
- [ ] AC-008 状态为“已删除”的用户不得登录、首次激活、冻结、解冻或恢复为“待激活/正常”。
- [ ] AC-009 冻结“待激活”用户时，系统记录冻结前状态为“待激活”，并将主状态设置为“已冻结”。
- [ ] AC-010 冻结“正常”用户时，系统记录冻结前状态为“正常”，撤销目标用户有效会话，并将主状态设置为“已冻结”。
- [ ] AC-011 已冻结用户解冻时，系统根据冻结前状态恢复主状态；冻结前为“待激活”则恢复为“待激活”，冻结前为“正常”则恢复为“正常”。
- [ ] AC-012 解冻成功后，系统清空或重置冻结前状态记录，避免后续状态操作读取过期数据。
- [ ] AC-013 冻结已冻结用户不得覆盖原冻结前状态；系统应返回幂等结果或受控错误。
- [ ] AC-014 首次登录激活、冻结、解冻和删除操作记录审计信息；冻结审计包含冻结前状态，解冻审计包含恢复后的状态。
- [ ] AC-015 审计、日志、错误反馈和前端持久化不得保存明文临时密码、access token、会话 ID 明文或内部冻结前状态字段细节。
- [ ] AC-016 用户列表默认和“全部状态”仍不展示已删除用户；状态筛选仍仅提供“全部状态”“待激活”“正常”“已冻结”。
- [ ] AC-017 后端数据库、Schema、API 响应、OpenAPI 文档和测试需要同步覆盖冻结前状态记录或等价持久化能力。
- [ ] AC-018 旧有“管理员调用解冻接口激活新建后台管理员后再登录”的测试路径必须调整，不得继续固化“解冻 = 激活”的旧语义。

## UI 与测试 AC

- [ ] AC-019 用户列表中的“待激活”“正常”“已冻结”“已删除”状态标签在深浅主题下清晰可辨。
- [ ] AC-020 对待激活用户，行内操作可提供“冻结”，但不得通过“解冻”或其他文案暗示管理员已替用户完成首次激活。
- [ ] AC-021 对已冻结用户，解冻确认弹窗展示解冻后的恢复目标状态，例如“解冻后恢复为待激活”或“解冻后恢复为正常”。
- [ ] AC-022 登录失败、账号不可用和权限不足文案使用受控表达，不泄露账号是否存在、冻结前状态字段、密码哈希或内部鉴权细节。
- [ ] AC-023 后端集成测试覆盖待激活首次登录成功后自动转正常、待激活冻结后解冻仍待激活、正常冻结后解冻恢复正常、前台用户拒绝后台登录、已删除用户不可恢复。
- [ ] AC-024 前端测试或浏览器验证覆盖用户列表状态筛选、状态标签展示、冻结/解冻确认弹窗恢复状态提示和 fixed toast 反馈。
- [ ] AC-025 后续 OpenSpec design.md 必须引用 `trace.md` 的 `knowledge_base_refs`，并说明横切 AC 如何落到状态操作、弹窗和列表验证。

## 横切 AC（knowledge-base）

> 来源：`docs/knowledge-base/best-practices/admin-list-page-consistency.md`、`docs/knowledge-base/best-practices/admin-modal-width-css-cascade.md` — 预防 Sprint 002/003 复发类缺陷

- [ ] AC-XCUT-001 用户列表分页 DOM 必须与当前用户管理页基准一致：总数位于左侧，翻页、页码、“每页显示”文案和条数下拉位于右侧。
- [ ] AC-XCUT-002 首次激活、冻结、解冻、登录失败等成功和失败反馈必须使用 fixed toast 或等价固定反馈，不引发布局位移，不挤压列表、分页、弹窗或抽屉内容。
- [ ] AC-XCUT-003 冻结、解冻、删除、重置密码等状态变更必须使用设计系统确认弹窗。
- [ ] AC-XCUT-004 管理后台状态变更不得调用 `window.confirm`。
- [ ] AC-XCUT-005 表格行内操作列在横向滚动或列较多时必须保持易访问。
- [ ] AC-XCUT-006 状态筛选条件变化后，列表结果、分页状态和空态提示必须与当前条件一致。
- [ ] AC-XCUT-007 TSX 或模板实现中不得让通用 `modal-card` 与专属宽度类并存，避免通用样式覆盖业务弹窗宽度。
- [ ] AC-XCUT-008 冻结、解冻、删除、重置密码和临时密码结果弹窗必须在浏览器 computed style 中验收最终宽度，确认最终宽度与设计预期一致。
- [ ] AC-XCUT-009 低视口下弹窗 body 必须可滚动，底部主操作和取消操作必须可访问。
- [ ] AC-XCUT-010 弹窗背景遮罩不得吞掉内部滚动，也不得导致页面主体误滚动。
- [ ] AC-XCUT-011 必填字段、错误提示、恢复状态提示和底部操作区不得互相遮挡。
