# 需求中心文档抽屉简化原型拆解

## 页面清单

- 需求中心主页面：卡片区、筛选区、阶段区沿用现有实现。
- 右侧文档抽屉：本需求唯一直接改动区域。
- 抽屉外 Change 文档入口：复用卡片、详情或既有文档分组；不在抽屉内重建 Change 属性模块；合并展示时按文件名和语义去重。

## 关键区域

```text
需求中心页面
  ├─ 卡片与文档入口
  └─ 右侧文档抽屉
       ├─ 抽屉标题区
       ├─ 文档属性区
       └─ 正文阅读区
```

## 组件层级

| 层级 | 组件/区域 | 说明 |
|---|---|---|
| 1 | 文档抽屉容器 | 承载标题、属性、正文、加载和错误状态 |
| 2 | 标题区 | 显示文档名、所属对象、关闭/展开动作 |
| 2 | 文档属性区 | 唯一保留的属性模块，支持展开/收起 |
| 2 | 正文阅读区 | Markdown 内容阅读与滚动 |
| 外部 | Change 文档入口 | 抽屉外以直接紧凑文档入口或短标签承接多 Change 可达性 |

## 状态矩阵

| 状态 | 期望表现 |
|---|---|
| 加载中 | 显示既有加载态，不显示 Change 属性模块骨架 |
| 加载失败 | 显示错误态，不显示 Change 属性模块 |
| REQ 文档 | 文档属性 + 正文 |
| BUG 文档 | 文档属性 + 正文 |
| 独立 Change 文档 | 文档属性 + 正文 |
| 单 Change 关联 | 抽屉内不展示追溯模块，抽屉外紧凑入口仍可达 |
| 多 Change 关联 | 抽屉内不展示追溯模块，抽屉外通过直接紧凑文档入口逐个可达，同名文档按文件名和语义去重，Change trace 用 `Change 1`、`Change 2` 短前缀区分 |
| 无文档属性 | 不保留 Change 属性模块或空白占位 |

## 交互触发

- 点击文档按钮：打开当前文档抽屉。
- 点击文档属性展开/收起：仅影响文档属性区。
- 点击关闭或外部关闭动作：关闭抽屉，保留既有脏数据保护。
- 选择抽屉外紧凑 Change 文档入口：直接点击 `Change 1 Change trace.md` 等短文档入口打开目标 Change 文档；同名 `proposal.md`、`spec.md`、`design.md`、`tasks.md`、`sprint.md` 只展示一次，不默认首项。

## 数据依赖

- 当前文档内容和文档属性：复用现有文档读取接口与缓存。
- Change 关联数据：保留供抽屉外入口使用，不在抽屉属性模块展示。
- 权限与只读状态：复用现有空间、项目和对象授权。

## 响应式断点

- 1440px：主验收视口，验证右侧抽屉的顶部结构、文档属性、正文起始位置和滚动。
- 窄视口：验证抽屉宽度、文本换行、关闭动作、文档属性折叠和正文阅读。

## 1440px 验收焦点

- “Change 追溯属性”模块完全不存在。
- 文档属性区顶部间距自然，没有上一模块残留。
- 正文首屏可读面积增加或至少不低于删除前。
- 深浅主题边框、背景、文字色、金色强调符合现有 token。
- 长标题、长 Change ID 和长正文不撑破抽屉。
