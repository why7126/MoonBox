# 用户故事

## US-001 产品负责人默认聚焦当前迭代

作为产品负责人，我希望进入需求中心后默认看到当前迭代相关卡片和未纳入 Sprint 的待规划卡片，以便快速判断当前 Sprint 的推进状态并处理规划前对象。

验收要点：

- 首次进入需求中心时，默认卡片集合来自当前迭代范围和未纳入 Sprint 范围。
- 默认范围同时覆盖 REQ、BUG 和独立 Change。
- 页面通过既有 Sprint 多选表达当前 Sprint 和“未纳入 Sprint”已选中，而不是误导用户认为系统只有这些卡片。

## US-002 项目负责人查看非当前范围

作为项目负责人，我希望在默认聚焦当前迭代和未纳入 Sprint 的同时，仍能显式切换到全部、历史或归档范围，以便追溯历史和调整规划池对象。

验收要点：

- 用户能从既有 Sprint 多选查看非当前范围、清空 Sprint 查看全部或取消“未纳入 Sprint”收窄到当前 Sprint。
- 查看非当前范围时，搜索、对象类型、负责人、优先级、归档可见性和文档阅读能力保持可用。
- 用户重置筛选或回到默认视图时，恢复当前 Sprint + 未纳入 Sprint 范围。

## US-003 多当前迭代时不任意选择

作为项目负责人，我希望当系统存在多个当前迭代候选时，默认展示全部当前迭代相关卡片和未纳入 Sprint 卡片，并在 Sprint 多选中明确多个选中项，以免系统无依据地只选择其中一个 Sprint。

验收要点：

- 多个 planning 或 in_progress Sprint 同时存在时，默认范围包含这些当前迭代的卡片和未纳入 Sprint 卡片。
- 页面提供进一步选择单个 Sprint 的显式操作。
- 系统不得仅按编号最大、更新时间最新或读取顺序静默选择一个 Sprint。

## US-004 协作者在刷新和切换上下文后保持一致

作为开发或测试协作者，我希望刷新、切换空间或切换项目后，需求中心仍能稳定遵守默认当前 Sprint + 未纳入 Sprint 范围，以便不会因为迟到响应或接口失败看到错误卡片集合。

验收要点：

- 手动刷新保留用户显式选择的范围。
- 空间或项目切换后，默认范围重新按新上下文的当前 Sprint 和未纳入 Sprint 计算。
- 接口失败或 Sprint 事实源解析失败时，不静默回退到全量卡片并伪装为当前迭代结果。
