# 工作区恢复点复用保留与冲突恢复

## 1. 背景与问题

多轮对话和多个会话共享工作区后，每条消息机械生成永久全量快照会增加扫描与存储成本；仅依赖 Git 又无法保护未提交成果。用户确认每轮保留历史、写入有可信基线、内容变化才生成版本，并以保护引用和有限中间版本实现恢复。复用已归档 REQ-0053 的分批内容存储能力，不重做其规模化执行。

## 2. 目标用户与业务目标

开发者需要在失败或返修后找回未提交成果且不覆盖后续人工编辑；维护者需要控制快照增长并识别可恢复范围。目标是在主目录和任务 worktree 共用机制，减少重复版本，保证恢复可解释、可核验。

## 3. 范围与非目标

纳入工作区级恢复点、版本复用、采集范围、保护引用、最近十个中间版本保留、差异预检、指定修改撤销、恢复到独立目录、故障续接与兼容。

不纳入数据库/外部服务回滚、精确 Git 暂存区恢复、跨空间私有内容去重、自动删除交付证据、整机灾备或新增运营存储配额。

## 4. 功能要求

### FR-001 工作区版本与记录分离

恢复点归属仓库和工作区，记录链路、关联轮次、Git HEAD、文件清单、内容引用、范围策略版本、完整性与保护状态。执行记录引用恢复点，多轮可共享版本；相同内容不等于同一权限或证据身份。上下文快照记录实际输入及截断信息，不能作为全工作区恢复点。

### FR-002 按写入阶段采集

纯只读只记录上下文/历史，转写先授权。写前验证当前状态有完整基线；等于上次可信结束版本可复用，外部修改则重采，必要采集失败不开始写。写后无变化复用，有变化才发布新版本；长任务阶段边界可加检查点。异常重启采集明确标记中断现场，不伪造正常终态。

### FR-003 范围覆盖和可恢复内容

采集覆盖实际授权可改范围，部分备份必须对应真正受限写权限。保留新增、修改、删除、文件类型和必要模式；哈希、统计和差异摘要不足以宣称可恢复。普通可恢复文件需有内容或受可靠保留的内容引用。对链接等仅元数据项明确能力不足，不跟随越界路径。凭证、Git 内部元数据、运行数据库、依赖缓存和构建产物等排除项有版本化清单，不因 gitignore 存在而认定安全。

### FR-004 完整性与增量优化

分批采集及校验后才发布完整版本；文件采集中变化需重采或保留不完整状态，不覆盖上次有效基线。内容相同复用对象，删除由清单表达。Git 状态、监听和元数据仅作候选提示，丢事件、重启或不确定时完整复核；不只凭时间戳宣称一致。扫描成本与持久字节分别计量。

### FR-005 中间恢复点轮转

每工作区默认保留最近十个未受保护的变更版本，可配置正整数；不将零解释为静默禁用保护。初始基线、验收、待合入、人工标记及故障恢复的有效引用受保护，另计。没有额外按天删除默认值，未完成版本不占用可信版本配额。内容去重不使十个版本变成十份完整仓库。

### FR-006 引用保护与回收

保护由持久化引用及所有者维护，解除须确认对应操作终结且无其他有效依赖；人工标记只能由具备相应权限的明确动作解除。回收与采集/恢复/新增引用互斥或采用等价版本保护，先删无保护过期清单、再回收零引用内容。删除工作树不能级联删除有效交付证据。轮转后保留操作历史并标记完整恢复不可用。

### FR-007 存储与备份边界

先复用现有数据库分块存储及会话内容，迁移工作区归属和授权引用，不要求同时改用对象存储。同仓库权限范围内去重，授权仍逐引用检查；历史删除意图不因共享对象重新可见。Git 对象引用需防垃圾回收失效。SQLite 自动备份默认两份是独立策略；若后续独立内容存储，需要一致备份元数据及内容，不仅备份索引。

### FR-008 三方恢复预检

撤销指定轮次修改时比较开始、结束、当前三版本：当前等于预期结束内容方可直接恢复；新增文件若后来改动不能删除，删除路径被重建不能覆盖。预检展示可恢复、冲突、不在范围的文件，记录版本和选定集合。多文件操作不宣称天然原子，逐项结果可追溯。

### FR-009 受控恢复与独立恢复目录

执行前重新鉴权、取得工作区写锁并复查预检版本；过期即拒绝，不覆盖后续修改。存在冲突优先通过 moonbox-worktree 建立恢复用途目录供检查，不作为新活动开发树。恢复须引用固定基线和内容；失效引用明确失败。第一阶段恢复文件内容与必要模式，不承诺暂存区精确还原，不回滚业务库或已生效治理动作。

### FR-010 恢复操作持久化与中断

恢复前固定操作身份、目标、范围、预期版本和已完成项，重复请求复用操作。部分成功后中断根据当前内容逐项核对，无法证明则停止相关项，不把整个操作重放覆盖文件。现有 unknown 状态保留直到核实，主动停止不自动触发模型重跑。复用 REQ-0047 恢复语义，不新建第二套平行恢复引擎。

### FR-011 容量不足与历史兼容

实际空间不足时停止新的需保护写入，保留已有版本与已保存成果并展示原因；不新增默认用户/空间配额或固定项目总规模门槛。历史快照逐版本识别、可读取、可核验后迁移；原来缺少正文的数据标记不可完整恢复，不能伪造补全。

### FR-012 模块协作与观测

moonbox-core 决定采集和恢复门禁；moonbox-exec-server 安全采集；moonbox-rollout 保存索引、内容及引用；moonbox-worktree 提供恢复目录；moonbox-app-server 输出差异、预检和操作状态；moonbox-ui 展示覆盖/冲突。日志仅记录数量、耗时、版本和脱敏身份，正文在授权内容存储中保存。

## 5. UI 约束

在既有执行详情提供恢复点列表、覆盖范围、保护原因、是否可恢复及轮次关联。撤销修改前展示三方预检与选定范围；从恢复点创建工作区展示独立目标和用途。完整恢复不可用、采集中、内容缺失与展示未加载明确区分。无权限不给可用恢复动作，重复点击返回原操作。界面使用 moonbox-ui，首期无 moonbox-tui。

## 6. 数据、安全与部署影响

涉及 Web、API、数据库、Agent 执行与安全边界；实施时同步 OpenAPI、Orval 客户端、数据库设计、SQLite/MySQL 兼容迁移、部署挂载与权限规则和测试。只迁移本需求关联数据，不修写无关历史事实。路径、密钥、完整 Prompt 和文件正文不进入通用观测日志。业务证据按授权存储，路径不作为客户端权限依据。

## 8. 验证重点与完成判断

验证证据区分静态检查、合成回归和真实执行。性能未实测前不承诺耗时或收益。此处为 PRD 验证目标，不是已完成验收；逐项验收要求已写入 acceptance.md，尚未执行产品验收。

## 10. 细化方案与实现风险

### 采集范围与容量细化

| 范围模板 | 可采集与写入边界 |
|---|---|
| 主目录治理任务 | 经授权的 Issue/Change/迭代文档；正式规格仅归档流程可写 |
| 开发工作树 | 本交付范围源码、测试、Change 任务、文档与证据；公共注册表/汇总禁止直接写 |
| 只读分析 | 无文件写权限，仅记录历史和输入上下文 |

排除凭证、真实环境配置、Git 内部、运行数据库、依赖缓存、构建产物；使用基于根目录的规范路径匹配，不跟随符号链接越界。未跟踪普通源文件在实际写范围内也纳入。超出范围的写请求需先扩展授权与恢复覆盖，不能写完后补保护。受控 Git 提交与治理写入记录独立操作事实，文件点不宣称能撤销其外部副作用。

不硬编码未实测磁盘百分比或业务配额。部署以可用字节、预计待持久化字节和运维配置的安全余量预检，写入中处理 ENOSPC；无法确认必需保护可完成则不开始新写任务。回收不能抢删保护点以腾空间。性能验证固定文件数、总量、变化率、硬件和进程限制，分别记录扫描耗时、写入字节、恢复耗时及峰值内存；复用父需求既有样本作为对照，不当作本功能已通过。

保护接口语义：标记/解除人工保护、查询保护原因、轮转和恢复共用引用版本；没有权限时拒绝，关联验收/合入/恢复操作存续时不能解除其系统保护。初始基线持续保护至工作区受控关闭且无其他依赖，验收/合入证据依赖未解除前持续保护；不新增按天自动释放策略。

具体接口、数据库字段、物理模块路径与部署并发参数在正式评审和 Sprint 纳入后的 Change 设计确定；不阻碍需求文档评审。
