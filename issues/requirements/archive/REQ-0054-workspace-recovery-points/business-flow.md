# 工作区恢复点复用保留与冲突恢复业务流程

## 主流程

```text
开始轮次 -> 判断只读/写入 -> 只读仅记历史
  -> 写入：鉴权与锁 -> 核对基线 -> 复用可信结束点或采集新基线 -> 执行
  -> 有变化才发布新结束点 -> 引用保护 -> 轮转未保护点 -> 零引用内容回收
恢复请求 -> 三方预检 -> 选范围 -> 执行前再鉴权与核版
  -> 无冲突：记录操作并逐项恢复 -> 核验结果
  -> 冲突：保留当前目录 -> 创建恢复用途目录 -> 人工检查/另行受控处理
```

### 采集范围与容量细化

| 范围模板 | 可采集与写入边界 |
|---|---|
| 主目录治理任务 | 经授权的 Issue/Change/迭代文档；正式规格仅归档流程可写 |
| 开发工作树 | 本交付范围源码、测试、Change 任务、文档与证据；公共注册表/汇总禁止直接写 |
| 只读分析 | 无文件写权限，仅记录历史和输入上下文 |

排除凭证、真实环境配置、Git 内部、运行数据库、依赖缓存、构建产物；使用基于根目录的规范路径匹配，不跟随符号链接越界。未跟踪普通源文件在实际写范围内也纳入。超出范围的写请求需先扩展授权与恢复覆盖，不能写完后补保护。受控 Git 提交与治理写入记录独立操作事实，文件点不宣称能撤销其外部副作用。

不硬编码未实测磁盘百分比或业务配额。部署以可用字节、预计待持久化字节和运维配置的安全余量预检，写入中处理 ENOSPC；无法确认必需保护可完成则不开始新写任务。回收不能抢删保护点以腾空间。性能验证固定文件数、总量、变化率、硬件和进程限制，分别记录扫描耗时、写入字节、恢复耗时及峰值内存；复用父需求既有样本作为对照，不当作本功能已通过。

保护接口语义：标记/解除人工保护、查询保护原因、轮转和恢复共用引用版本；没有权限时拒绝，关联验收/合入/恢复操作存续时不能解除其系统保护。初始基线持续保护至工作区受控关闭且无其他依赖，验收/合入证据依赖未解除前持续保护；不新增按天自动释放策略。

## 状态与异常分支

读取失败保持上次完整展示并标记过期；权限拒绝不变更业务状态；重复提交返回原操作；异步请求迟到不得覆盖另一工作区/候选；未知执行结果保留待核实，不伪造失败或成功。执行前重新确认权限与输入版本，清理不等于交付或归档。

## 动作与浮层矩阵

| 动作 | 浮层 | selector 种子（data-testid） | 状态及行为 |
|---|---|---|---|
| 查看差异 | drawer | recovery-diff | 可恢复 / 冲突 / 排除；显示前后当前版本 |
| 撤销选定修改 | confirm | recovery-restore | 预检 / 版本过期 / 恢复中 / 部分成功 / 失败 |
| 创建恢复工作区 | dialog | recovery-create | 用途说明 / 准备中 / 成功 / 权限拒绝 |
| 保护恢复点 | confirm | recovery-protect | 保护 / 解除人工保护；存在系统引用不能解除 |

每个浮层有关闭按钮和 Esc 路径；关闭只退出查看，不取消服务端已接受操作。提交中禁重复提交；提交错误保留上下文。确认类动作因文件写入/合入副作用需要明确确认；轻量工作区选择不额外确认。实现采用共享按钮/弹窗族，错误信息与主操作不重叠。

## 关联与父需求差异

本需求是 REQ-0053 的工作区级恢复细化：复用内容分块，不重做规模化执行，新增引用保护、按变化保留和三方恢复。

## 实现一致性补充（2026-10-29）

恢复操作在工作区详情中选择前后版本和文件，先做三方预检再执行；有后续人工编辑时保留文件并提示冲突，可另建恢复用途目录。默认最近十个未保护版本另加保护版本；同内容/采集范围/基线复用版本，历史轮次仍保留。旧完整正文经摘要核验后迁移；原采集范围无法证明的旧版本支持明确文件恢复，不能宣称完整项目重建。多文件操作按持久步骤续接，不恢复 Git 暂存区或业务数据库。

实施与逐项验收以 `openspec/archive/2026-10-29-add-workspace-recovery-points/` 为证据源；本补充不提前签署尚未完成的验收项。
