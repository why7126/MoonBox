# 工作区恢复点复用保留与冲突恢复

## 一句话

每轮保存执行历史，写任务具有有效恢复基线，仅在文件变化时建立内容版本，通过去重复用、关键点保护及最近十个中间版本轮转控制成本，并支持冲突感知恢复。

## 来源与已确认结论

来源为同会话架构与快照探索，用户采纳推荐内容，并明确作为已归档 REQ-0053-chat-scalable-execution-storage 的新增子需求。该父需求已实现规模化快照与持续存储，本需求新增工作区归属、保留语义与可交互恢复，不重写历史交付事实；复用 REQ-0047 的幂等恢复原则。

## 采集与版本

- 恢复点归属仓库和工作区，关联交付链路、会话、执行轮次、Git HEAD、文件清单、内容引用、采集状态和覆盖范围。多会话可引用同一工作区版本。
- 纯只读轮次记录上下文与历史，不生成全工作区文件恢复点；转写前先鉴权并准备基线。
- 写前必须具备当前状态的有效基线；若当前内容与上次结束版本完全匹配则复用，外部修改需重新采集。写前必要采集失败则不写入。
- 写后无变化复用，有变化建立清单和新增内容版本；长任务在阶段边界检查点采集。失败、中断保留已有基线，恢复后的采集不得冒充正常终态快照。
- 采集范围覆盖真正允许修改范围；允许整工作区写时不能只采集预计修改的少量文件。保存新增、修改、删除、文件类型与必要模式，哈希/差异摘要不能冒充可恢复内容。
- 同仓库权限范围内按内容去重，保留已有分批和完整性验证；先完成复用和轮转，再依据性能证据优化增量扫描，不仅凭时间戳或文件事件判定无变化。若引用 Git 对象，需可靠保留引用，避免垃圾回收后失效。
- 排除凭证、Git 内部元数据、依赖缓存、构建产物及运行数据库等非源码内容，明确排除项和不可恢复范围；忽略规则不替代敏感内容策略。

## 保留与清理

- 每工作区默认保留最近十个未受保护的变更恢复点，可配置。初始基线、验收、待合并、人工标记和故障恢复引用有效时受保护，另外计算。
- 不额外默认按天删除。先检查引用，再清单清理，最后回收无引用内容；未完成采集确认无活动和恢复依赖后才清理。
- 清理中间版本后，保留轮次历史并明确不再支持该版本完整恢复；worktree 移除不删除有效交付、验收和恢复引用。
- 容量不足停止新的需保护写入并明确原因，不静默删除恢复依据。继承父需求无默认运营额度，不新增用户/空间业务存储配额或固定项目规模门槛。
- SQLite 自动备份独立管理，默认两份配置不适用于恢复点；文件内容若采用独立存储，元数据和内容备份须有一致可恢复关系，不能只备份索引。

## 冲突恢复

- 默认提供撤销本轮指定修改、从恢复点创建新工作区两种动作。
- 比较执行前、执行后、当前三方版本；当前仍等于该轮结束版本才可直接恢复；后续人工/任务修改、被重新创建的删除路径和归属不明情况保留现场并报告冲突。
- 预检按可恢复、冲突、不在范围分类；执行时取写锁、再次核对版本与权限。冲突优先恢复到新工作区，不覆盖当前目录。
- 第一阶段恢复文件内容，不承诺精确恢复 Git 暂存区；不回滚数据库、外部服务或已生效治理操作。已合入主线的撤销走受控变更。

## 模块与验收

moonbox-core 管时机和门禁，moonbox-exec-server 安全采集，moonbox-rollout 管索引与内容引用，moonbox-worktree 提供目标目录，moonbox-app-server 提供差异和恢复接口，moonbox-ui 展示覆盖范围和冲突。

验收覆盖只读不采集、连续轮次复用、外部修改重采、无变化无新内容、多会话共享、十版本轮转与保护引用、删除和重建冲突、采集/恢复中断幂等续接、容量不足保留成果、跨空间拒绝访问、工作树清理后的可追溯性。分别测量扫描时间与存储增长，不把内容去重声称为扫描成本消失。

## 非目标与待细化

不替代数据库/外部服务备份，不重建父需求的全套规模化内容存储，不提供跨空间私有内容去重。内容存储后端、保护解除条件、部署容量阈值、索引兼容及大文件边界在 PRD 细化；不预设额外自动删除期限。

## 优先级依据
