# 工作区恢复点复用保留与冲突恢复用户故事

## US-001 历史与恢复分离

作为空间成员，我希望系统支持历史与恢复分离，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-001；验收：AC-001。
- 验收要点：连续只读轮次保留历史但不新增文件恢复点；多个轮次可引用同一完整版本；上下文摘要和缺正文旧记录不可显示为完整可恢复。

## US-002 按变化采集

作为空间成员，我希望系统支持按变化采集，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-002；验收：AC-002。
- 验收要点：连续写轮次复用可信前轮结束版本；无文件变化不新增版本；外部改动后重新采集；写前采集失败时模型/命令尚未开始修改文件。

## US-003 采集覆盖

作为空间成员，我希望系统支持采集覆盖，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-003；验收：AC-003。
- 验收要点：在授权范围内分别新增、修改、删除普通文件并改执行位，恢复得到正确内容与模式；排除项不采正文；链接不跟随越界；备份范围缩小同步限制执行器写范围。

## US-004 采集中变动

作为空间成员，我希望系统支持采集中变动，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-004；验收：AC-004。
- 验收要点：采集中修改文件或中断内容写入，不发布虚假完整版本，原有效基线仍可用；重启丢监听后完整复核；相同内容复用对象、删除记录仍可解释。

## US-005 十版本轮转

作为空间成员，我希望系统支持十版本轮转，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-005；验收：AC-005。
- 验收要点：创建十二个未保护变更点及三个保护点，最后保留最近十个未保护点与三个保护点；无变更轮次不挤出版本；配置零或负数拒绝；不按天自动删除。

## US-006 保护与回收竞争

作为空间成员，我希望系统支持保护与回收竞争，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-006；验收：AC-006。
- 验收要点：新增引用与 GC 同时发生时有引用内容不被回收；解除一个保护后其他保护仍有效；人工保护仅经授权明确解除；删除工作树后仍可读交付证据。

## US-007 内容授权及备份

作为空间成员，我希望系统支持内容授权及备份，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-007；验收：AC-007。
- 验收要点：同仓库去重后未获引用权限者仍无法读取；已删除历史不会因共享内容复活；备份恢复同时验证索引和内容；SQLite 两份自动备份策略不被十版本策略覆盖。

## US-008 三方预检

作为空间成员，我希望系统支持三方预检，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-008；验收：AC-008。
- 验收要点：对本轮新增后被人工编辑、删除后被重建、修改后再修改三类路径均标冲突，不删除/覆盖；当前等于结束版本的路径可恢复；预检列出排除项。

## US-009 恢复执行

作为维护者，我希望系统支持恢复执行，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-009；验收：AC-009。
- 验收要点：预检后再次改文件或撤权限，执行被拒绝且无覆盖；冲突可生成恢复用途目录供检查，不计活动开发树且不能直接接新开发；Git 暂存区和业务数据库不冒充已还原。

## US-010 部分恢复中断

作为维护者，我希望系统支持部分恢复中断，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-010；验收：AC-010。
- 验收要点：在多文件恢复中间中断，重启逐项核对已完成内容后续接，不盲目重放；同幂等键返回原操作；未知执行状态不自动重新调用模型。

## US-011 磁盘及旧数据

作为维护者，我希望系统支持磁盘及旧数据，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-011；验收：AC-011。
- 验收要点：模拟空间不足，保留已有点与成果并阻断新的受保护写入；旧缺正文快照标不可完整恢复；历史完整版本校验后迁移；不额外加入用户总量门槛。

## US-012 模块和观测

作为维护者，我希望系统支持模块和观测，以便任务成果、权限和执行事实保持可解释。

- 对应：FR-012；验收：AC-012。
- 验收要点：执行采集、预检、恢复、回收成功与拒绝样本均关联仓库/工作区/轮次/操作；日志无文件正文、密钥或私有路径；采集范围和完整性状态可从 Web 查询。

## 共同边界

首期保留 Web，模块名统一 moonbox-；工作区、文件恢复、合入分别由三条关联需求承担。故事描述目标行为，不代表功能已实现。

## 实现一致性补充（2026-10-29）

恢复操作在工作区详情中选择前后版本和文件，先做三方预检再执行；有后续人工编辑时保留文件并提示冲突，可另建恢复用途目录。默认最近十个未保护版本另加保护版本；同内容/采集范围/基线复用版本，历史轮次仍保留。旧完整正文经摘要核验后迁移；原采集范围无法证明的旧版本支持明确文件恢复，不能宣称完整项目重建。多文件操作按持久步骤续接，不恢复 Git 暂存区或业务数据库。

实施与逐项验收以 `openspec/archive/2026-10-29-add-workspace-recovery-points/` 为证据源；本补充不提前签署尚未完成的验收项。
