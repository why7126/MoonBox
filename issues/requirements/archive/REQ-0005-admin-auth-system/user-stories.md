# 用户故事

## US-001 超级管理员登录后台

作为超级管理员，我希望使用初始化的用户名和密码登录管理后台，以便进入后台执行平台治理和敏感管理操作。

验收要点：

- 登录页提供用户名、密码和登录主操作。
- 用户名或密码为空时，前端给出可恢复的校验反馈。
- 用户名或密码错误时，后端返回受控错误，不泄露账号是否存在或内部认证细节。
- 登录成功后，前端获得 access token、过期时间和管理员摘要，并进入后台受保护页面。

## US-002 管理后台保护未登录访问

作为后台管理员，我希望未登录或登录态失效时不能访问后台页面和后台 API，以便后台敏感能力不会被绕过。

验收要点：

- 未登录访问后台路由时，前端进入后台登录页或等价登录入口。
- 未携带有效 access token 调用 `/api/v1/admin/**` 时，后端返回 401。
- access token 过期、无效、对应会话撤销或会话不存在时，后端返回 401。
- 已认证但无后台权限时，后端返回 403。

## US-003 超级管理员退出登录

作为超级管理员，我希望退出登录后当前凭证立即失效，以便离开后台后不会被继续复用。

验收要点：

- 后台全局区域提供可发现的退出登录入口。
- 退出登录成功后，当前服务端会话被撤销。
- 使用已退出登录的 access token 调用后台 API 时返回 401。
- 前端清理本地登录态并回到后台登录页或等价未登录状态。

## US-004 运维首次初始化超级管理员

作为运维部署人员，我希望通过环境变量首次初始化唯一超级管理员，以便新环境可以安全地获得后台初始入口。

验收要点：

- 系统首次启动或初始化时，若不存在系统内置超级管理员，则读取环境变量创建账号。
- 重复启动不得创建第二个系统内置超级管理员。
- 生产环境禁止空密码、示例密码或弱密码。
- 初始密码不得写入日志、API 响应、前端页面或审计明文。

## US-005 后台敏感操作获得真实操作者身份

作为安全审计相关角色，我希望后台管理 API 能解析真实操作者身份，以便用户管理、密码重置和状态治理等敏感操作可追溯。

验收要点：

- `/api/v1/admin/**` 不再依赖 `x-admin-role: admin` 作为正式鉴权来源。
- 后端从 access token 与服务端会话记录解析当前操作者。
- 后台 API 不信任前端传入的 `user_id`、`role`、`is_admin` 或等价身份字段。
- 账号被冻结、删除、重置密码或权限状态变化后，相关已有后台会话失效。
