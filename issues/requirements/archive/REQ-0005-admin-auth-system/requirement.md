# 管理后台登录认证系统

## 背景

MoonBox 已具备管理后台用户管理系统和后台用户数据模型，但当前后台管理 API 仍处于占位鉴权阶段。随着管理后台开始承载用户创建、冻结、删除、重置密码和头像上传等敏感操作，系统需要提供真实的后台认证边界，确保只有合法管理员能够进入后台并调用管理接口。

本需求聚焦管理后台登录认证系统，目标是为系统内置超级管理员提供账号密码登录入口，并通过 access token 与服务端会话记录建立可撤销、可过期、可校验的后台登录态。同时，本需求必须替换 `/api/v1/admin/**` 的 `x-admin-role: admin` 占位鉴权，避免仅依赖前端路由守卫形成假安全。

## 目标用户

- 超级管理员：需要使用系统初始化账号登录管理后台，并执行平台恢复、后台治理和敏感管理操作。
- 后台管理员：后续需要通过正式认证访问管理后台能力。
- 运维部署人员：需要通过环境变量完成首次超级管理员初始化，并确保生产环境不使用弱密码或示例密码。
- 安全审计相关角色：需要依赖真实操作者身份追溯后台敏感操作。

## 范围

### 包含

- 管理后台登录：支持超级管理员通过账号密码登录后台。
- 认证策略：登录成功后签发 access token，并在服务端保存会话记录。
- 会话校验：后台 API 请求必须校验 access token 对应的服务端会话是否存在、未过期、未撤销，且账号状态仍可用。
- 退出登录：支持管理员主动退出登录，并让对应服务端会话失效。
- 后台路由守卫：未登录或登录态失效时，前端后台路由应进入后台登录页或等价登录入口。
- 后台 API 鉴权：所有 `/api/v1/admin/**` 管理接口必须替换 `x-admin-role: admin` 占位鉴权，改为真实认证授权。
- 超级管理员初始化：通过环境变量首次幂等创建唯一系统内置超级管理员。
- 生产安全：生产环境禁止使用空密码、示例密码或弱密码初始化超级管理员。
- 错误处理：未认证返回 401，权限不足返回 403，登录失败、凭证过期和会话失效应给出受控反馈。

### 不包含

- 不支持普通 Web 前台用户登录体系。
- 不支持用户自主注册、忘记密码、邮箱验证、短信验证、第三方登录、OAuth、企业 SSO 或组织目录同步。
- 不支持 refresh token、长期自动续期、多端互踢或复杂设备管理。
- 不支持 MFA、细粒度权限矩阵、自定义角色配置或平台管理员授权体系扩展。
- 不支持安装向导创建超级管理员。
- 不实现独立审计日志查询页面；后台敏感操作的审计查询由后续独立需求承接。
- 不新增移动端、小程序或桌面端登录能力。

## 功能要求

### FR-001 超级管理员账号密码登录

管理后台 MUST 提供后台登录入口，支持超级管理员输入用户名和密码登录。

登录表单 MUST 对用户名和密码进行必填校验。用户名或密码错误时，系统 MUST 返回受控错误，不得泄露账号是否存在、密码哈希算法、内部用户状态或系统路径。

登录成功后，系统 MUST 返回 access token、过期时间和当前管理员摘要。管理员摘要 SHOULD 至少包含用户 ID、用户名、角色、状态和是否系统内置超级管理员。

### FR-002 access token 与服务端会话记录

系统 MUST 在登录成功后创建服务端会话记录，并将 access token 与该会话建立可校验关系。

服务端会话记录 MUST 至少支持会话 ID、用户 ID、过期时间、撤销时间、创建时间和最后使用时间等追溯字段。

access token MUST 有明确过期时间，不得无限期有效。后台 API 每次鉴权时 MUST 校验 token 对应的服务端会话存在、未过期、未撤销，且关联账号仍处于允许登录和访问后台的状态。

### FR-003 退出登录与会话失效

管理后台 MUST 提供退出登录能力。

管理员退出登录后，系统 MUST 让当前服务端会话失效。退出后使用同一个 access token 调用 `/api/v1/admin/**` MUST 返回 401。

当账号被冻结、删除、重置密码或发生影响权限的状态变化时，系统 MUST 使相关后台会话失效，避免旧凭证继续访问管理后台。

### FR-004 后台路由守卫与登录态恢复

管理后台前端 MUST 对后台路由进行登录态守卫。未登录、token 缺失、token 过期、会话撤销或后端返回 401 时，系统 SHOULD 引导用户进入后台登录页或等价登录入口。

前端路由守卫只作为体验优化。系统 MUST 以后端认证授权结果作为最终安全判断，不得只依赖前端状态阻止未授权访问。

前端不得将 access token、会话 ID 或用户摘要写入 URL、日志、错误上报、埋点或截图。

### FR-005 后台 API 正式鉴权

所有 `/api/v1/admin/**` 管理接口 MUST 默认需要认证。未列入公开端点清单的后台业务接口不得匿名访问。

系统 MUST 移除或下线 `x-admin-role: admin` 作为正式鉴权依据的行为。后端 MUST 从 access token 与服务端会话记录解析当前操作者，并基于操作者账号状态和角色判断是否允许访问。

未携带有效凭证、凭证过期、凭证无效或会话失效时，系统 MUST 返回 401。已认证但无后台权限时，系统 MUST 返回 403。

### FR-006 超级管理员首次初始化

系统 MUST 支持通过环境变量首次幂等创建唯一系统内置超级管理员。

当系统启动或初始化时，若不存在系统内置超级管理员，系统 SHOULD 读取环境变量中的超级管理员用户名和初始密码并创建账号。重复启动不得创建第二个超级管理员。

生产环境 MUST 拒绝空密码、示例密码或弱密码作为超级管理员初始密码。初始化密码不得写入日志、API 响应、前端页面或审计明文。

### FR-007 超级管理员保护与后台权限边界

系统内置超级管理员 MUST 作为最高权限账号受保护，并与管理后台用户管理系统中的超级管理员保护规则保持一致。

超级管理员可登录管理后台并访问后台管理 API。普通前台用户不得访问管理后台或调用 `/api/v1/admin/**` 管理接口。

后端不得信任前端传入的 `user_id`、`role`、`is_admin` 或等价身份字段作为权限来源。

### FR-008 认证错误反馈与安全约束

登录失败、未认证、凭证过期、会话失效、权限不足和账号不可用等场景 MUST 使用统一错误响应与受控错误码。

系统 SHOULD 对登录失败提供频率限制、延迟或锁定策略；如 MVP 暂不实现完整锁定策略，必须在后续需求或验收风险中明确记录。

认证相关日志和审计记录不得保存明文密码、access token、会话 ID 明文或其他可直接复用的敏感凭证。

## UI 约束

- 后台登录页应与管理后台视觉风格保持一致，聚焦用户名、密码和登录主操作。
- 后台登录页不展示注册、忘记密码、第三方登录、短信验证码、邮箱验证码或 SSO 入口。
- 登录失败、登录态过期和退出成功应有清晰反馈，文案不得泄露敏感内部状态。
- 后台路由守卫触发时，应保持用户能够重新登录，不应出现空白页、死循环跳转或不可恢复状态。
- 退出登录入口应在管理后台全局区域保持可发现，视觉层级低于主要业务操作。
- 桌面管理场景下，登录页和后台守卫反馈不得遮挡或破坏管理后台基础布局。
