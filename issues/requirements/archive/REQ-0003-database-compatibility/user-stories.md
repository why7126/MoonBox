# 用户故事

## US-001 本地开发使用 SQLite 快速启动

作为 MoonBox 后端工程师，我希望开发环境默认可以使用 SQLite 启动服务，以便在不依赖外部数据库服务的情况下完成日常开发、调试和基础测试。

验收要点：

- 本地环境提供 SQLite 连接配置示例。
- 本地启动不需要 MySQL 服务。
- SQLite 运行时数据库文件不进入 Git。
- SQLite 模式下基础连接、初始化和 CRUD 行为可验证。

## US-002 生产部署使用 MySQL

作为生产部署负责人，我希望生产环境必须使用 MySQL，并在配置缺失或连接失败时阻止启动，以便避免真实业务数据误写入本地或演示数据库。

验收要点：

- 生产环境数据库类型必须显式声明为 MySQL。
- 生产环境缺少 MySQL 连接串或凭据时启动失败。
- 生产环境误配 SQLite 时启动失败并输出可诊断错误。
- 文档说明生产 MySQL 的环境变量和密钥注入方式。

## US-003 后端代码保持双数据库业务语义一致

作为维护 Repository 与 ORM 模型的后端工程师，我希望数据访问层避免依赖 SQLite 或 MySQL 私有语法，以便相同业务逻辑在开发和生产环境中行为一致。

验收要点：

- ORM 模型、Repository 查询和迁移脚本经过 SQLite/MySQL 差异审计。
- 必须使用数据库特定能力时，有兼容层封装和差异说明。
- 参数化查询或 ORM 表达式覆盖主要数据访问路径。
- 约束、索引、默认值、时间字段和 JSON 字段的差异被记录。

## US-004 测试人员验证 MySQL 关键路径

作为测试人员，我希望发布前能够运行 MySQL 兼容测试，以便提前发现只在生产数据库中暴露的问题。

验收要点：

- 本地快速测试覆盖 SQLite。
- 发布前或 CI 覆盖 MySQL 连接、迁移、基础 CRUD、约束校验和事务行为。
- MySQL 测试依赖可复现，例如通过 Docker 启动。
- 测试失败能定位数据库类型、迁移版本或 Repository 场景。

## US-005 产品和技术治理追踪数据库兼容差异

作为项目维护者，我希望数据库兼容差异被沉淀到文档和兼容性目录，以便后续 OpenSpec、实现和排障时能复用同一事实源。

验收要点：

- 数据库设计文档更新开发 SQLite、生产 MySQL 策略。
- 部署文档更新 MySQL 必需配置和禁止回退规则。
- 数据库规范补充双数据库变更检查清单。
- `compatibility/database/` 或等价位置记录已知差异和处理方式。
