# 需求中心卡片常驻根因状态与开发人天标签

## 一句话

在需求中心卡片现有标签后追加 BUG 根因状态和开发人天，有数据后跨阶段持续展示，包括已完成；两者并存时根因在前。

## 原始描述与已确认交互

用户要求：“卡片常驻信息标签：在现有标签后追加可点击的 BUG 根因状态和开发人天，有数据后跨阶段持续展示，包括已完成；两者同时存在时根因在前。”

同会话 explore 已确认根因展示状态，例如“根因已确认／根因待确认”，点击查看对应根因文档，保持卡片紧凑。

## 初步范围

- 在现有等级、负责人标签之后追加新标签，顺序为等级、负责人、根因状态、开发人天。
- 根因标签仅适用于 BUG；存在有效根因信息后展示，按真实状态区分已确认与待确认，不因仅有根因文档文件就推断已确认。
- 有有效开发人天数据的卡片显示“开发 3 人天”等信息，支持小数；无数据不展示，不按优先级猜测人天。
- 两个标签同时存在时均展示，根因在前；空间不足允许换行。
- 信息不受当前流程阶段限制，研发、验收、已完成仍展示；随事实源更新。
- 根因点击复用文档查看能力及既有权限、缺失或读取失败处理，不改变 BUG 根因确认流程。

## 建议验收要点

1. 分别覆盖无数据、仅人天、仅根因、两者都有四种组合；不存在空占位标签。
2. BUG 根因状态文案与事实源一致，点击打开该 BUG 的根因文档。
3. 同时有两类信息时根因在前，两者均可见；窄卡片无溢出。
4. 阶段流转至研发、验收和已完成后标签保留，刷新后仍由真实数据恢复。
5. 人天支持小数，非 BUG 不显示根因标签；未知值不冒充零或已确认。

## 探索依据与边界

同会话已查看本地需求中心页面，并核对 `src/web/src/pages/catalog/RequirementCenterPage.tsx`：现有标签行为等级和负责人，卡片数据类型尚未声明这两个专用字段。后端已有 Sprint scope 人天汇总读取，可作为后续单卡人天数据口径调查入口。

属于同一卡片信息展示能力，一条需求即可统一交付验收。P2 为初判：改善扫描效率，不阻断现有研发流程。

## 后续细化事项

- 生成 PRD 时核对单卡人天权威来源、多 Change 聚合口径，以及零值与非法值规则；不将 Sprint 总容量误作单卡人天。
- 明确根因有效内容与状态的字段映射、缺失或不可读文档处理。

## 非目标

不新增实际工时统计，不修改根因确认门禁，不自动推进阶段，不在 capture 阶段修改业务代码。
