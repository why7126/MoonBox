# 卡片常驻信息标签用户故事

## US-001 快速评估投入

作为产品或研发负责人，我希望 REQ、BUG、独立 Change 在存在有效预估时展示开发人天，以便比较投入，而不必打开 Sprint 文档。

验收关联：AC-001、AC-002、AC-005、AC-006。零和小数可见，无值不占位，总估算与分项不重复计算。

## US-002 查看根因状态和依据

作为缺陷处理人员，我希望 BUG 展示已确认或待确认状态，并通过按钮查看该 BUG 的根因文档，避免凭流程阶段推断根因。

验收关联：AC-003、AC-004、AC-007。兼容两种现有状态字段，冲突保守展示，支持键盘与既有权限错误提示。

## US-003 跨阶段追溯

作为验收人员，我希望卡片从研发进入验收和已完成后仍保留有效标签，刷新和再次访问后也一致。

验收关联：AC-008、AC-009。归档源仍可读，源数据删除后不继续冒充当前值；切换项目不会串数据。

## US-004 紧凑扫描

作为看板使用者，我希望根因排在人天前面，窄卡片自然换行，两类信息同时可见。

验收关联：AC-001、AC-010、AC-PROTOTYPE-003。保留等级、负责人、文档和主动作现有层级。

## 2026-10-22 展示规则修订

人天按有效非负值d分档：S为0≤d≤1，M为1<d≤3，L为3<d≤5，XL为5<d≤10，XXL为d>10；显示“档位·数值人天”（如“M·3人天”），不含“开发”前缀。S青、M蓝、L紫、XL橙、XXL玫红，保留精确值和“档位 · 预估开发数值人天”提示；缺失/非法值隐藏。

新旧标签共用字体、10px字号、1.2行高、3px 8px内边距、20px圆角且无描边；根因保留状态色、点击与focus-visible提示。

分隔点展示细则：去除两侧普通空格，使用独立分隔点左右各2px固定间距；其余标签样式及根因交互保持不变。
