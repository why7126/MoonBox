# 卡片常驻信息标签业务流程

## 读取与展示流程

```text
进入需求中心 / 刷新 / 切换项目
  → 校验项目读取权限并取得一致的治理快照
  → 按完整对象身份解析有效 Sprint 归属（含 archive）
  → 匹配 Scope 估算并去重 → 合法非负数才输出人天
  → BUG 解析根因有效正文及状态 → 已确认 / 待确认 / 无标签
  → 渲染：等级、负责人、根因状态、开发人天
  → 阶段变化后重新投影，数据有效则保留
```

## 人天解析与异常分支

1. 以对象 trace 的当前有效 iteration 和 Sprint Scope 的身份关联共同确认归属；归档对象沿用归档 Sprint，不扫描其他项目找替代值。
2. `id` 等于完整 Issue ID 的记录是该对象总估算；`requirement`/`bug` 为关联键。独立 Change 使用完整 Change ID。当前写入工具一条记录可以同时带 Issue 与 Change 字段，该行只计一次。
3. 唯一合法总估算优先；重复记录仅在身份、归属和数值完全相同时去重。冲突总量不选择任意一条，返回缺失并保留诊断。
4. 没有总估算时，仅对明确关联的独立 Change 分项汇总；分项集合与对象有效关联 Change 集合一致且每项唯一有效才可汇总。无法证明完整时不展示人天。
5. 不跨多个历史 Sprint 累加。不使用优先级、story_points 或 Sprint 顶层容量替代人天。
6. 明确 0 显示，负数、空值、字符串、布尔值、非有限数不显示。读取失败与“无数据”区分，复用页面快照错误提示。

## 根因解析与点击流程

1. 在权限范围内读取该 BUG 根因文档。有效内容要求根因分析或证据章节至少有一项非空、非标题、非注释、非纯占位正文；仅 Frontmatter、根因状态章节或空表格不算有效信息。
2. 先读专用 `root_cause_status`，兼容合法枚举 `status`，两者不存在时兼容“根因状态”章节的明确声明；合法枚举为 unknown、hypothesis、probable、confirmed。
3. 多个明确根因声明不一致时显示待确认并标记需核对；非根因枚举的普通文档生命周期 status 不参与根因比较。专用字段非法时不因另一来源 confirmed 而静默确认。
4. 无有效正文不显示；有正文但未知、非法或冲突状态显示待确认；一致 confirmed 显示已确认。不改写事实源或根因确认门禁。
5. 点击根因按钮 → 文档抽屉 loading → 正文或既有错误态。关闭按钮、Esc、外部点击退出；内部操作不误关闭，返回焦点到触发按钮。
6. 文档被删除或权限撤销时禁止泄漏旧正文，不误触发其他卡片动作。开发人天无新增操作。

## 与既有能力的差异

本需求无父需求，仅关联已完成 REQ-0031 的 Sprint 容量来源与 REQ-0020 的文档抽屉。本次扩展单卡信息投影，不改变总容量算法、文档编辑权限、阶段流转或筛选。

## 状态事实边界

显示状态和治理状态独立：已完成 BUG 仍可能显示待确认，确认标签不代表修复或验收通过。持续展示以事实仍存在为条件，不是永久缓存标签。

## 2026-10-22 展示规则修订

人天按有效非负值d分档：S为0≤d≤1，M为1<d≤3，L为3<d≤5，XL为5<d≤10，XXL为d>10；显示“档位·数值人天”（如“M·3人天”），不含“开发”前缀。S青、M蓝、L紫、XL橙、XXL玫红，保留精确值和“档位 · 预估开发数值人天”提示；缺失/非法值隐藏。

新旧标签共用字体、10px字号、1.2行高、3px 8px内边距、20px圆角且无描边；根因保留状态色、点击与focus-visible提示。

分隔点展示细则：去除两侧普通空格，使用独立分隔点左右各2px固定间距；其余标签样式及根因交互保持不变。
