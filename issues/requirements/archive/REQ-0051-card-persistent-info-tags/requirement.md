# 需求中心卡片常驻根因状态与开发人天标签

## 1. 背景与价值

需求中心卡片当前在标题后展示等级与负责人。开发人天和 BUG 根因信息需要进一步查看治理文档，用户难以直接判断工作量与根因确认程度。希望把这两类已有事实放入卡片标签行，且不因对象进入研发、验收或已完成阶段而消失。

本需求承接已确认的 explore 结论：根因使用状态标签而非原因摘要，点击查看根因文档；两个标签同时存在时均展示，根因在前。优先级维持 P2，提升日常扫描与协作效率，不改变流程准入条件。

## 2. 目标用户与目标

产品与研发负责人可在看板快速识别预估开发投入；缺陷处理及验收人员可识别根因确认状态并直接查看依据。目标是复用权威数据、跨阶段一致展示，避免无值占位、错误确认与重复估算。

## 3. 范围

### 3.1 包含

- 需求中心 REQ、BUG 和独立 Change 卡片的开发人天标签；BUG 专属根因状态标签。
- 标签顺序、缺失与异常数据、刷新及已完成对象展示。
- 根因文档查看、键盘访问与既有权限和错误态。
- 卡片聚合数据补充及对应 Web 展示，复用现有数据与文档读取能力。

### 3.2 不包含

不新增人天编辑、实际工时统计、排期或预测；不修改根因判定、评审或阶段流转门禁；不增加自动确认根因动作；不扩展管理端、移动端或其他卡片页面；不改变筛选与归档对象可见性规则。

## 4. 功能要求

### FR-001 位置与排序

在现有等级、负责人标签之后追加信息，顺序固定为“等级 → 负责人 → 根因状态 → 开发人天”。某项缺失时跳过该项，其他项相对顺序不变。根因优先表示排在前面，不表示隐藏人天。空间不足自然换行，不遮挡标题、文档入口或动作区。

### FR-002 开发人天

有合法开发人天值的卡片显示“开发 N 人天”，整数不带多余小数零，小数保留有效精度。该值表示规划预估投入，辅助提示说明“预估开发人天”，不冒充实际消耗。

数据以关联 Sprint 的 `scope_estimates[].estimated_person_days` 为首版权威来源，按照完整 Issue/Change 身份匹配。当前与已归档 Sprint 都可作为有效来源，不依赖页面当前迭代筛选才能读取。

- REQ/BUG 使用对应 Issue 的估算，独立 Change 使用自身估算；不使用 Sprint 顶层总量、卡片数量或优先级替代。
- 一个 Issue 对应多个 Change 时，Issue 级总估算与 Change 分项不能重复相加；存在明确且唯一的 Issue 总估算时优先使用总估算。
- 仅有分项时，只有分项归属明确、互不重复且完整时才汇总；不完整或冲突时不输出误导性数值。跨 Sprint 历史估算不盲目累加，使用对象当前有效归属；归档对象沿用其有效归档规划。
- 显式有限非负数为合法值，零显示“开发 0 人天”。缺失、空值、布尔值、负数及非法数值不展示，不填零。
- 多来源冲突或缺少明确归属时不猜测，保留可诊断的缺失原因；具体解析与去重规则见 business-flow.md，Change 以合成与真实源格式样本验证。

### FR-003 BUG 根因状态

根因标签仅出现在 BUG 卡片。有非空、非纯模板占位的根因分析信息时展示，空文件、仅标题或待填写模板不构成有效根因信息。

状态读取该 BUG `root-cause.md`：优先专用 `root_cause_status`，兼容合法根因枚举 `status`，缺失时兼容根因状态章节。多个明确声明冲突时不确认，普通生命周期 status 不当作根因状态。解析细则见 business-flow.md。展示映射如下：

| 来源状态 | 展示 |
|---|---|
| confirmed | 根因已确认 |
| unknown、hypothesis、probable | 根因待确认 |
| 状态缺失、非法或与正文明确状态冲突 | 根因待确认，并在查看时提示需核对 |

“已确认”不能由 BUG 已评审、已完成或根因文件存在推导。标签展示不改写根因事实，不替代根因证据门禁；有效内容判定与兼容规则见 business-flow.md，并纳入 AC-003/004。

### FR-004 点击与权限

根因标签使用可聚焦按钮，鼠标点击及 Enter/Space 打开该 BUG 的根因文档，复用现有 Markdown 文档抽屉，不跳转其他对象、不触发卡片主动作或阶段流转。开发人天为只读信息标签，本版不新增点击动作。

文档不可读时遵循既有权限提示，不泄漏内容；文档删除、读取失败或状态过期时显示明确错误并支持既有重试入口，不产生无响应按钮。已完成对象可读，但文档编辑能力仍受原有阶段权限约束。

### FR-005 跨阶段与数据更新

只由数据存在性与有效性决定标签展示，不以采集、规划、评审、迭代、研发、验收、已完成等阶段作为隐藏条件。数据首次出现后，在其仍有效时持续展示；后续状态和人天更新反映最新事实。

项目切换清除前一个项目的标签数据。刷新、重新进入和归档后仍能恢复当前对象事实。源数据被明确移除时对应标签消失；短暂请求失败不得把缓存旧值当作最新事实，也不得制造零值，沿用页面既有错误与快照状态提示。

### FR-006 数据与可观测性

卡片聚合需返回可区分缺失、待确认、已确认的数据，以及有效人天和文档入口。首版不要求新业务数据库持久化字段。通过后端聚合读取权威文档，避免前端逐卡片下载完整根因文档造成请求放大。

根因点击沿用文档查看的行为事件及请求日志关联；日志不记录根因正文、敏感路径或真实业务内容。采集失败不阻断标签查看和文档读取，不为只读标签创建 Agent 任务链路。

## 5. UI 约束与状态组合

新旧标签共用字体、10px字号、1.2行高、3px 8px内边距、20px圆角且无描边；根因保留状态色、点击与focus-visible提示。根因标签保留状态文字，不仅靠颜色表达；可点击态、焦点态与只读人天标签可区分。保留原有等级与负责人视觉层级。

| 根因信息 | 人天 | BUG 展示 |
|---|---|---|
| 无 | 无 | 仅原有标签 |
| 有 | 无 | 原有标签、根因状态 |
| 无 | 有 | 原有标签、开发人天 |
| 有 | 有 | 原有标签、根因状态、开发人天 |

非 BUG 只应用人天规则。后续视觉验收覆盖 1440px 桌面、看板窄列、深浅主题、键盘焦点、长负责人换行以及已完成卡片；补充截图和关键 computed style 证据。已新增 prototype/web 局部增量原型及拆解，全部为合成 Mock；当前不声明产品视觉验收完成。

## 6. 验证方向

后续六件套和 Change 需覆盖四种数据组合、四种合法根因状态、非法状态、空或模板文档、零及小数人天、非法数值、多 Change 去重、归档 Sprint 读取、跨阶段保留、项目切换、文档读取成功/无权限/失效及键盘交互。观察真实页面和 API 投影，不以测试夹具代替实际产品验收。

分隔点展示细则：去除两侧普通空格，使用独立分隔点左右各2px固定间距；其余标签样式及根因交互保持不变。
