# 管理后台用户管理系统

## 背景

MoonBox 已具备 Web 端、管理后台、REST API、数据库与部署治理基础。随着平台进入多用户和后台运营阶段，管理人员需要在管理后台集中查看和维护用户账号，处理账号创建、资料编辑、状态治理、密码重置和角色维护等日常操作。

当前需求聚焦管理后台的用户管理系统，目标是形成可追溯、可控、可审计的账号治理入口。该需求只管理平台账号元数据和账号状态，不直接管理 Workspace 内部的需求、BUG、Spec、任务或发布内容。

## 目标用户

- 后台管理员：需要创建、查询、编辑和治理平台用户账号。
- 账号管理员：需要处理账号状态、重置密码、维护用户资料和角色。
- 超级管理员：需要保护系统内置最高权限账号，避免被误冻结、误删除或误降权。
- 安全审计相关角色：需要依赖用户管理操作记录追溯敏感变更。

## 范围

### 包含

- 用户列表：支持查看用户头像、用户名、昵称、角色、状态、空间数、创建时间和更新时间。
- 用户查询筛选：支持按关键词、角色、状态等条件检索用户。
- 用户创建：支持后台创建用户账号，并校验用户名格式和唯一性。
- 用户编辑：支持编辑用户头像、昵称和角色；用户名创建后不可修改。
- 用户状态治理：支持冻结、解冻和逻辑删除用户。
- 密码治理：支持后台重置用户密码，并记录敏感操作原因。
- 超级管理员保护：系统内置唯一超级管理员在列表展示，但禁止编辑、重置密码、冻结、解冻或删除。
- 操作安全：敏感写操作需要二次确认、原因填写、防重复提交和审计记录。

### 不包含

- 不支持用户自主注册、忘记密码、邮箱验证、短信验证、企业 SSO 或组织目录同步。
- 不支持自定义平台角色、细粒度权限矩阵配置或平台管理员授权体系扩展。
- 不支持物理删除用户账号；删除仅作为保留审计记录的逻辑删除。
- 不管理 Workspace 的停用、恢复、所有者转让、授权期限或资源配额。
- 不在管理后台管理需求、BUG、Spec、任务、发布内容或 Workspace 内部业务数据。
- 不新增移动端、小程序或桌面端用户管理能力。

## 功能要求

### FR-001 用户列表展示

管理后台 MUST 提供用户列表页，展示头像、用户名、昵称、角色、状态、空间数、创建时间、更新时间和操作列。

用户列表 MUST 支持分页。分页区域 SHOULD 在左侧展示用户总数，在右侧提供上一页、下一页、页码和每页条数切换。

### FR-002 用户搜索与筛选

用户列表 MUST 支持关键词搜索，至少覆盖用户名和昵称。

用户列表 SHOULD 支持按角色和状态筛选。角色筛选 MUST 仅包含“后台管理员”和“前台用户”。状态筛选 MUST 仅包含“全部状态”、待激活、正常和已冻结，不提供“已删除”。搜索、筛选和分页条件变化后，列表结果 MUST 与当前条件保持一致。

默认用户列表和“全部状态”结果 MUST 不展示逻辑删除用户；后端列表总数 MUST 与当前筛选结果使用相同规则计算。

### FR-003 创建用户

后台管理员 MUST 能通过弹窗创建用户。创建表单 MUST 支持用户名、头像、昵称和角色字段。

用户名 MUST 全局唯一，长度为 4-32 位，仅允许字母和数字，并且必须以字母开头。用户名创建后 MUST 不可修改。

创建成功后，新用户状态 SHOULD 为待激活，且重复提交不得产生重复用户。

### FR-004 编辑用户

后台管理员 MUST 能编辑用户头像、昵称和角色。

编辑时用户名 MUST 只读展示，不得提供修改入口。编辑提交成功后，列表与详情中的用户信息 MUST 同步刷新。

### FR-005 用户状态治理

后台管理员 MUST 能冻结、解冻和删除用户。删除 MUST 为逻辑删除，并保留审计追溯所需数据。

冻结、解冻和删除操作 MUST 进行二次确认，并要求填写操作原因。冻结成功后，目标用户的有效会话 MUST 在 10 秒内失效。

### FR-006 重置密码

后台管理员 MUST 能为普通用户重置密码。

重置密码操作 MUST 作为敏感动作处理，要求二次确认、原因填写和防重复提交。重置结果 SHOULD 明确反馈给操作者，但不得在普通列表中暴露敏感凭据。

### FR-007 角色与状态模型

用户角色 MVP MUST 仅保留“后台管理员”和“前台用户”。

用户状态 SHOULD 至少包含待激活、正常、已冻结和已删除。已删除作为逻辑删除状态保留审计追溯，不作为管理后台前端状态筛选项展示。不同状态在列表、筛选和操作可用性上 MUST 有明确表现。

### FR-008 超级管理员保护

平台 MUST 有且仅有一个系统内置超级管理员账号。该账号 SHOULD 由部署初始化流程创建，并在用户列表中展示。

系统内置超级管理员 MUST 显示“系统内置”或等价标识，并且不得提供编辑、重置密码、冻结、解冻或删除操作入口。

### FR-009 操作审计

用户管理的写操作 MUST 记录操作者、操作对象、动作、前后值、操作原因、结果、时间和请求 ID。

审计记录 SHOULD 支撑后续日志审计模块查询，但本需求不要求实现独立审计日志页面。

### FR-010 错误反馈与幂等保护

用户创建、编辑、冻结、解冻、删除和重置密码操作 MUST 具备表单校验、错误反馈和防重复提交能力。

当用户名格式错误、用户名重复、权限不足、目标用户不可操作或服务端失败时，系统 MUST 给出清晰反馈，并保持页面处于可恢复状态。

## UI 约束

- 用户管理入口应位于管理后台 `SYSTEM` 或等价系统管理导航分组下。
- 用户列表优先面向 1440px 桌面管理场景，1280px 及以上不得破版。
- 筛选区应占满可用宽度；搜索框可自适应拉伸，角色和状态筛选保持稳定宽度；状态筛选不展示“已删除”选项。
- 用户列表操作列应位于最右侧；在横向滚动或列较多时，操作入口应保持易访问。
- 创建和编辑表单中，用户名和角色为必填项，头像和昵称为非必填项。
- 时间字段展示格式统一为 `yyyy-mm-dd hh:MM:ss`。
- 系统内置超级管理员的禁用操作应从源头隐藏或置灰，并配合不可操作提示。
- 深浅主题下，状态标签、危险操作和二次确认弹窗必须保持可读、可辨识。

## 关联需求

- 暂无已确认父需求。
