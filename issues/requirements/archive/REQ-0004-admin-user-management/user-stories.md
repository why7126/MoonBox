# 用户故事

## US-001 查看和筛选用户

作为后台管理员，我希望在管理后台查看用户列表，并按用户名、昵称、角色和状态筛选，以便快速定位需要治理的账号。

验收要点：
- 用户列表展示头像、用户名、昵称、角色、状态、空间数、最近登录时间、创建时间和操作列。
- 搜索框支持用户名和昵称关键词。
- 角色筛选仅包含“后台管理员”和“前台用户”。
- 状态筛选仅包含“全部状态”、待激活、正常和已冻结，不提供“已删除”。
- 默认列表和“全部状态”不展示逻辑删除用户，筛选条件变化后自动刷新列表结果。

## US-002 创建用户

作为后台管理员，我希望通过弹窗创建用户，以便为新成员开通平台账号。

验收要点：
- 创建弹窗包含用户名、头像、昵称和角色。
- 用户名和角色为必填项；头像和昵称为非必填项。
- 用户名必须全局唯一、4-32 位、仅允许字母和数字、必须以字母开头。
- 创建成功后用户状态为待激活。
- 重复提交不会产生重复用户。

## US-003 编辑用户资料与角色

作为后台管理员，我希望编辑用户头像、昵称和角色，以便维护账号基础信息。

验收要点：
- 编辑弹窗复用创建弹窗结构。
- 编辑时用户名只读且不可修改。
- 角色范围只允许“后台管理员”和“前台用户”。
- 保存成功后列表立即回显更新后的头像、昵称和角色。

## US-004 治理用户状态

作为后台管理员，我希望冻结、解冻和删除用户，以便处理异常账号和账号生命周期。

验收要点：
- 冻结、解冻和删除必须二次确认并填写原因。
- 冻结成功后目标用户有效会话必须在 10 秒内失效。
- 删除为逻辑删除，保留审计追溯所需数据。
- 逻辑删除用户不在默认用户列表和“全部状态”中展示。

## US-005 重置用户密码

作为后台管理员，我希望重置普通用户密码，以便用户无法自行恢复时进行人工处理。

验收要点：
- 重置密码必须二次确认并填写原因。
- 临时密码或重置结果仅在响应中展示一次，不进入日志、埋点或前端持久化。
- 重置密码动作写入审计记录。

## US-006 保护系统内置超级管理员

作为超级管理员，我希望系统内置唯一超级管理员账号不被后台误操作，以便保障平台恢复能力。

验收要点：
- 唯一超级管理员在用户列表中展示，并带有“系统内置”或等价标识。
- 唯一超级管理员操作列显示不可操作状态。
- 不提供编辑、重置密码、冻结、解冻或删除入口。
