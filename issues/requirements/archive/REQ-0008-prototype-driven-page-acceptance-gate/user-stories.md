# 用户故事

## US-001 原型资产识别

作为页面开发者，我希望在开发前明确当前 Web 前台或管理后台页面是否存在 `prototype.html` 或 `prototype.png`，以便决定是否启用原型驱动验收门禁。

验收要点：

- 页面型 REQ 若存在 `prototype.html` 或 `prototype.png`，必须标记为启用门禁。
- 非 Web 端或无原型资产的需求必须说明门禁不适用原因。
- 同时存在 HTML 与 PNG 原型时，必须说明结构来源和视觉来源的优先级。

## US-002 原型拆解

作为 Agent 执行者，我希望在实现页面前拆解原型的结构、布局和关键尺寸，以便 UI Skeleton 可以按原型意图搭建，而不是先写业务逻辑再返工 UI。

验收要点：

- 拆解结果必须覆盖页面端类型、入口、主区域、组件层级、状态占位和关键交互。
- 管理后台页面必须识别 Shell、表格、分页、弹窗、toast 或其他高风险 DOM/CSS 区域。
- Web 前台页面必须识别首屏、品牌展示、主 CTA、响应式断点和视觉层级。

## US-003 UI Skeleton 先行

作为测试与验收人员，我希望页面先完成可视化 UI Skeleton，以便在真实 API 和复杂业务联调前先验收页面骨架。

验收要点：

- UI Skeleton 必须能展示主要布局区块、关键组件占位、mock 数据和基础状态。
- UI Skeleton 阶段不得把真实业务联调完成视为验收前置条件。
- UI Skeleton 通过前，不得进入真实业务逻辑联调。

## US-004 1440px 截图验收

作为产品与设计协作者，我希望看到 1440px 桌面宽度截图，以便确认实现与原型在首屏结构、密度和层级上没有明显偏差。

验收要点：

- 截图必须以 1440px 宽度生成，并覆盖页面关键区域。
- 截图验收必须记录截图路径、验收结论和未覆盖区域。
- 若页面关键内容需要滚动，必须补充滚动区域或局部截图说明。

## US-005 DOM/CSS 尺寸检查

作为维护人员，我希望关键 DOM/CSS 尺寸被检查并可追溯，以便防止表格、分页、弹窗、toast 和首屏布局在后续联调中漂移。

验收要点：

- 检查项必须覆盖当前页面适用的主容器、表格、分页、弹窗、按钮、字体、间距和滚动区域。
- 可稳定自动化的尺寸应沉淀为浏览器断言、computed style 检查或等价验证脚本。
- 业务逻辑联调后若改变已验收 UI 区域，必须重新执行受影响检查。

## US-006 带风险继续

作为产品负责人，我希望紧急场景可以显式带风险继续，以便在确有交付压力时保留决策痕迹。

验收要点：

- 门禁未通过时默认阻断业务逻辑联调。
- 如需继续，必须记录未通过项、继续原因、风险影响、补验计划和确认人。
- 带风险继续不得删除后续补验要求。
