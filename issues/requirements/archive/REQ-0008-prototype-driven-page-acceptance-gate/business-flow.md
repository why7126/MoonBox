## 门禁阶段

### 1. 识别原型资产

开发或 Agent 执行前检查需求目录中的 Web 原型资产：

- `prototype/web/prototype.html`
- `prototype/web/prototype.png`
- 等价的 Web 前台或管理后台原型路径

若需求不是 Web 前台或管理后台页面，或不存在原型资产，本门禁不阻断后续开发，但必须说明不适用原因。

### 2. 原型拆解

拆解页面结构、布局密度和关键交互边界。管理后台重点关注 Shell、列表、分页、弹窗、toast 和操作区；Web 前台重点关注首屏、品牌、CTA、响应式和视觉层级。

### 3. UI Skeleton

先实现页面静态骨架和 mock 数据展示。该阶段只验证 UI 结构与交互占位，不要求完成真实 API、权限、状态变更或持久化写入。

### 4. 截图与尺寸验收

在 1440px 桌面宽度下生成截图，并检查关键 DOM/CSS 尺寸。验收记录必须能支持后续 review、OpenSpec design 和实现任务引用。

### 5. 业务逻辑联调准入

只有 UI Skeleton、截图和尺寸检查通过后，才允许进入真实业务逻辑联调。联调后若 UI 结构或尺寸受影响，需要重新检查。

  +-- 约束 REQ-0004 用户管理页这类已有 HTML/PNG 原型页面

REQ-0008 是流程门禁型需求，不替代任何具体页面的业务需求。具体页面仍需在自己的 acceptance 中描述业务能力、API、安全和数据验收。
