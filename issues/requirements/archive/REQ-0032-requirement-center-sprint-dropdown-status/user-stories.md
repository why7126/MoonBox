# 用户故事

## US-001 查看 Sprint 筛选状态

作为产品负责人，我希望在需求中心的 Sprint 筛选下拉列表中直接看到每个 Sprint 的状态，以便区分当前迭代、规划中迭代和历史迭代，避免选错范围。

验收要点：

- 打开 Sprint 筛选时，可见 Sprint 选项包含 Sprint ID 和状态信息。
- 状态文案来自可追溯事实源，不由前端临时推断。
- 当前选中项收起后仍能表达所选 Sprint 的状态上下文。

## US-002 在多状态 Sprint 中保持选择稳定

作为研发成员，我希望在多个 Sprint 同时存在时，筛选下拉的排序、默认项和选择行为保持稳定，以便切换迭代后继续查看正确卡片和统计。

验收要点：

- 新增状态展示不改变既有筛选值、默认选择和刷新行为。
- 切换 Sprint 后，卡片列表与统计按选中 Sprint 刷新。
- 项目切换或刷新时，迟到响应不会覆盖当前项目的 Sprint 选项。

## US-003 识别异常或缺失状态

作为验收人员，我希望 Sprint 状态缺失、非法或冲突时有稳定提示，以便发现数据漂移并继续完成可读范围内的验收。

验收要点：

- 状态缺失或无法识别时展示“状态待核实”或等价文案。
- 异常选项不阻断其他 Sprint 选择。
- 异常提示不暴露内部路径、原始日志或无权对象内容。

## US-004 使用键盘和窄屏查看状态

作为只使用键盘或窄屏设备的用户，我希望 Sprint 状态展示不降低筛选控件可达性，以便在不同视口和主题下仍能完成选择。

验收要点：

- 键盘 focus、hover、选中和 disabled 状态可区分。
- 长 Sprint 名称与状态组合不溢出、不遮挡。
- 深浅主题下状态文字和标签对比度可读。
