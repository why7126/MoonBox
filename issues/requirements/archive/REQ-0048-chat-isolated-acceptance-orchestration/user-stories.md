# Chat 隔离验收环境编排用户故事

## 用户故事与追溯

### US-001 在原Chat一次发起验收

作为研发成员，我希望在原Chat一次发起验收，以便平台准备当前版本环境并回传证据，无需提供数据库连接串。

验收要点：AC-001、AC-002、AC-011。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

### US-002 声明受控模板和数据库矩阵

作为项目维护者，我希望声明受控模板和数据库矩阵，以便未绑定摘要或不支持架构被拒绝；已支持组合实测。

验收要点：AC-003、AC-010。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

### US-003 用短期不同角色访问隔离应用

作为测试成员，我希望用短期不同角色访问隔离应用，以便权限与登录态不跨任务共享，撤销/过期生效。

验收要点：AC-004。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

### US-004 在局部故障后继续可执行项

作为Agent，我希望在局部故障后继续可执行项，以便依赖失败被隔离，指纹变化只复验相关项。

验收要点：AC-005、AC-009。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

### US-005 刷新或重启后继续原操作

作为研发成员，我希望刷新或重启后继续原操作，以便保留原轮次事实，不重复迁移、初始化或工具回调。

验收要点：AC-006、AC-007。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

### US-006 控制环境费用并可靠回收

作为运维成员，我希望控制环境费用并可靠回收，以便全局/空间配额、租约和清理重试可核对。

验收要点：AC-008、AC-010。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

### US-007 查看真实证据与准确状态

作为审阅者，我希望查看真实证据与准确状态，以便证据分层、版本匹配、授权可访问，界面不误报完成。

验收要点：AC-009、AC-012。正常路径无需逐次人工配置；异常保留稳定原因与恢复入口。

## 范围约束

环境自动供应归REQ-0048；现有预检/调用接入归BUG-0045；浏览器与制品基础归REQ-0044。人工问答归BUG-0046。用户停止后不能以用户故事“自主”推断继续执行授权。全部故事待实施验证。

## 本轮续接与长期转存实施（2026-10-29）

用户可在在线证据过期后通过“长期摘要”查看已转存的逐项结果；当前失权或内容被改动时读取拒绝。系统自动续接保留原失败状态与预算，不因刷新、重启或关联轮次再次申请验收而重置次数。真实模型/产品体验签认仍待接入。


## 本机产品接入补充（2026-10-30）

用户已授权当前 MoonBox 的本机隔离产品验收，原“真实产品待接入”仅为历史检查点。当前独立源码快照、固定镜像、全新数据库、短期角色、真实模型工具结果消费/失败轮次一次续接、停止/恢复/清理失败及长期摘要已有运行证据；具体边界与结果统一见当前 Change `verification.md` 和 `evidence/implementation/product/`。不连接生产数据，不启用未实测amd64，不把合成故障回归改称真实模型样本；长期摘要不延长原始视觉证据保留期。最终20项签认由当前完整验收报告决定，未执行正式归档。
