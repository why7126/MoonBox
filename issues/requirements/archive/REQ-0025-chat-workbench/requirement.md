# Chat 工作台与 Codex 持续对话执行

## 1. 背景与来源

MoonBox 已有需求中心、空间身份与业务对象读取能力，但 Chat 工作台导航尚未接入独立页面，需求中心 AI 抽屉的发送逻辑仍返回固定文本。用户需要在 MoonBox 内持续与真实 Codex 对话，引用业务背景、执行代码修改、查看过程与实际变更，并在同一工作区继续调整。

本需求依据 `capture.md`、本次 req-explore 对话，以及用户提供的 `requirement.md`、`prototype-context.md`、`prototype.html` 三份附件整理。附件版本为 Codex 接入版 v1.3.0、视觉基线 v1.1.1；附件是产品参考材料，其中工程建议不代表已经验证或获得执行授权。附件中的人员、仓库、对象编号、回复与 Diff 样例不作为产品真实数据。

用户已确认：

1. 沿用现有金色 Ops 风格，保留附件布局与交互。
2. Codex 在 MoonBox 服务端执行，首版仅支持预先配置的仓库。
3. 会话默认个人私有，同时校验空间和业务对象权限。

本 PRD 已通过需求评审。用户进一步确认平台统一管理服务端认证并承担额度，聊天、引用快照和历史 Diff 保留至主动删除且设置容量上限。接入路线、具体阈值和验证证据按 review.md 条件通过项收敛，不宣称已完成技术验证。

## 2. 目标用户与价值

- 产品负责人：围绕 REQ、BUG、Change 与 Codex 讨论和推进研发工作，减少在文档、执行端与结果之间切换。
- 开发与项目成员：在有权访问的空间仓库中连续修改、验证、查看 Diff，并保留可追溯的执行记录。
- 平台运维人员：在服务端配置可用仓库和执行资源，管理认证、容量和隔离；本需求不新增运维管理界面。

目标是形成“输入目标 → 真实执行 → 查看结果 → 同会话继续”的闭环。MoonBox 负责身份、上下文、会话索引、接入适配和展示；Codex 负责理解输入与执行工具。不自研 Agent 循环、子 Agent 调度或另一套研发任务引擎。

## 3. 范围

### 3.1 纳入首版

- Web Chat 页面、顶部会话切换、完整历史管理、业务关联、对话输入与执行详情。
- 新建、继续、搜索、重命名、置顶、归档、恢复和受限删除会话。
- 真实 Codex 回复与执行事件、逐轮记录、文件变更及真实 Diff。
- 服务端预配置仓库、每会话独立工作区及工作分支、同会话串行执行。
- 停止确认、断连状态恢复、明确失败后的用户重试、权限和凭证隔离。
- 会话与执行记录持久化、上下文快照及脱敏链路观测。

### 3.2 不纳入首版

- 用户本机执行桥、本地项目导入、任意仓库地址导入、仓库配置管理 UI。
- 自动创建 TASK、主/子 Agent 树、强制计划审批卡、自建多阶段审批状态机。
- Agent 或模型切换 UI、任务队列管理 UI、推算进度百分比、未接入的附件上传入口。
- 自动回滚、提交、合并、推送、部署，以及对应独立管理界面。
- 共享会话、多人共同续聊、跨空间共享历史。
- 修改需求中心已有业务状态语义；不把 Codex 的执行完成映射为 REQ 验收或归档完成。

会话、轮次、事件与 Diff 共同构成一个独立交付单元，保留单条 REQ。REQ-0022 的项目导入不作为首版必需前置条件。

## 4. 主流程

```text
登录并选择有权限的空间
→ 创建或恢复个人会话
→ 绑定已配置仓库及会话工作区
→ 选择可选主对象和辅助引用
→ 发送输入，服务端校验权限并保存本轮上下文快照
→ 在正确 Codex 会话和工作目录执行
→ 展示真实回复、事件、文件变更与终态
→ 在同一会话继续输入，或归档保留
```

空间没有可用仓库或执行服务不可用时，展示明确空态或不可用原因，不回退到模拟回复。首次连接失败且没有取得 Codex 会话标识时，保留 MoonBox 会话并标记尚未建立连接。

## 5. 功能要求

### FR-001 页面与身份入口

提供独立 Chat 工作台路由，并接通现有导航；具体路由在设计阶段确定。沿用前台登录、空间切换与用户菜单。服务端校验会话所有者、有效空间成员身份和操作权限，不能只依赖前端隐藏按钮。切换空间后不展示其他空间会话、消息或 Diff。

### FR-002 会话创建与恢复

会话保存所属用户、空间、仓库、工作区与明确的 Codex 会话标识。创建 MoonBox 会话和建立 Codex 连接分别记录结果。恢复时同时校验标识、仓库和工作目录，不使用“最近一次会话”猜测目标，不因连接失败自动换用其他会话。仓库配置撤销或工作区不可恢复时阻止执行并说明原因。

### FR-003 历史管理

顶部支持按标题和关联对象编号搜索、按置顶与最近使用切换；完整历史弹窗支持全部、置顶、归档筛选。支持非空标题重命名、置顶及取消置顶。归档后只读，恢复后经权限校验可继续；运行中、停止中或状态未知的会话不得归档或删除。

删除需二次确认，同时满足运行已终止、工作区没有未处理代码变更。是否存在未处理变更以可信当前工作区状态判断，不能以“历史曾产生文件修改”永久禁止删除。删除用户会话内容不删除关联业务对象或代码，也不删除仍处于保留期内的脱敏审计。主动删除策略与工作区回收边界见 FR-013；删除执行方式在 Change 设计中明确。

### FR-004 业务对象关联与权限

主对象最多一个且可为空，类型为 REQ、BUG 或 Change；辅助引用可多个，同一对象可关联多个个人会话。对象标识采用 MoonBox 真实标识，不沿用附件样例编号。对象候选列表、引用读取、每轮发送和历史内容读取均在服务端校验权限。

改变关联仅影响之后的输入，不重写历史。对象权限被撤销时禁止继续附带其内容，并提示用户调整；不在错误、搜索结果或引用摘要中泄漏无权内容。历史快照、回复或Diff包含已撤权对象时限制对应内容访问；执行端旧历史无法可靠剔除时禁止续用并引导创建干净会话，不以本人所有权绕过撤权。

### FR-005 逐轮上下文快照

每次发送保存用户输入、对象标识、来源版本或内容摘要、实际引用内容的受控快照及 Codex 运行关联。仅有可变对象 ID 不足以复原历史上下文。快照与后续业务对象编辑解耦；存储和读取受权限、长度与保留周期约束。

业务正文和模型回复保存在受控业务存储中，不复制进通用日志或观测 metadata。快照截断应有明确提示，不能展示“已引用全部内容”而实际遗漏。

### FR-006 输入与发送

固定接入 Codex，允许自然语言输入并持续对话；不自动创建 TASK。空输入不得发送。发送后展示真实连接、启动和执行状态。同会话有未确认终止的执行时禁止新一轮提交，服务端提供互斥及请求幂等，覆盖多标签页、重复点击和网络重发。

页面刷新、关闭或切换会话不代表停止运行。支持恢复消息与执行视图；发送失败保留可恢复的输入内容。首版不展示未接通的附件或 Agent 切换按钮。

### FR-007 执行事件与真实回复

一条用户输入对应一轮执行；保存可获得的原始会话、轮次、事件标识、序号与类型，并以会话和轮次作用域去重。协议没有某字段时由适配层明确补充本地标识，不能伪称其来自执行端。

展示真实回复、命令结果、文件变更和执行终态。无对应事件能力则隐藏对应展示，不补造步骤、Agent 树、测试通过率或百分比。支持流式更新和重连后的重复事件处理；乱序事件不能把终态覆盖回执行中。Markdown、命令输出和文件内容按不可信文本安全渲染。

### FR-008 执行轮次与文件变更

右侧执行详情支持历史轮次选择、执行记录和文件变更两个页签。只显示该轮实际修改的文件；未修改时为空态。Diff 来自可信工作区对比或执行接口可验证的变更内容，明确执行前后基准。

区分本轮 Diff 与工作区累计差异。第二轮继续修改第一轮的文件时，不能把第一轮全部变化算作第二轮成果。基准不可用时明确标注不可计算，不使用示例替代。删除、新增、重命名、二进制和超大内容需有可理解的展示边界。

### FR-009 停止当前运行

停止操作先明确告知已有修改保留，并进入“停止中”；只有执行端确认运行终止后才标为“已停止”。停止超时或失联进入状态未知，不允许立即开始下一轮。

停止不回滚、不删除工作区，不承诺撤销已经发生的外部副作用。即使用户正在查看历史轮次，也保留当前运行的明确停止入口；不得误停止所选历史轮次或其他会话。停止与自然完成竞争时以可信终态为准。

### FR-010 断连与显式重试

区分明确执行失败与连接中断。连接中断先查询或恢复原运行状态，不能立即以新轮次重跑写入。服务重启后不能因内存锁丢失就允许旧运行与新运行并发。

明确失败或已停止后，由用户触发重试并创建可追溯的新轮次，关联原轮次。默认复用原输入及仍有权访问的原上下文快照，再次校验权限；若需改用最新对象内容，应显式说明或引导为新输入，不能静默替换。失败不自动重复写入。

### FR-011 工作区与服务端执行

首版仅使用运维预先配置且经空间授权的仓库。每会话分配独立工作目录和工作分支，在连续轮次间复用；恢复同时验证 Codex 标识和工作区。工作区变更保留，提交合并及清理由既有 Git 流程处理。

同会话严格串行。其他会话仅在文件、运行资源、端口、数据库、网络与凭证隔离满足要求时并发，否则按服务端容量等待，并给出真实等待状态。worktree 仅隔离代码目录，不等于完整执行隔离。执行服务生命周期不得绑定单个网页连接或 HTTP 请求生命周期。

### FR-012 权限与治理边界

默认会话个人私有；空间管理角色不因此自动获得其他成员的聊天正文或继续执行权限。空间只读用户不能执行代码写入。严格只读能力由执行端强制，不依赖“先分析，不修改”的提示词。

平台统一配置服务端凭证并承担执行额度，用户不绑定个人 Codex 账号，也不要求空间提交独立凭证。按用户和空间记录用量并设置预算、并发限制；额度不足时拒绝新执行并说明原因，具体阈值在 Change 设计中确定。平台承担费用不赋予其他成员访问个人会话的权限。

运行环境限制工作目录、网络和凭证访问。凭证不传前端、不写入日志或聊天内容；不通过开放全部权限解决适配失败。若采用的路线支持真实审批往返，按实际执行端语义展示；否则遇到超限动作明确拒绝，不制作无法传回的批准按钮。

正式功能开发继续遵守仓库的 REQ/BUG 评审、Sprint、OpenSpec 及文档权限规则。自由对话不等于开发授权；无合规 Change 的讨论允许继续，但不能因此执行正式功能写入。不得让普通网页请求把用户输入拼接成宿主机命令。

提交、合并、推送和部署不属于默认执行授权，需由执行环境约束。工作区写权限本身不代表已经具备这些操作的细粒度限制；约束的可验证实现是接入验收前置条件。

### FR-013 持久化与可恢复性

持久化会话元数据、消息、轮次、上下文快照、执行事件索引和 Diff 基准，支持刷新与服务重启后的状态恢复。保存原始事件标识和类型不代表必须原样保存敏感事件载荷；执行内容先经过权限、脱敏和长度控制。

聊天正文、引用快照和历史 Diff 保留至用户主动删除，不按 90/180 天自动到期清理。设置容量上限；达到上限时保留现有内容与查看/清理能力，暂停新增内容及新执行并提示清理。启动运行前预留该轮结果存储空间，不能因容量不足静默丢弃运行结果；具体容量与超限处置在设计中固定并验证。归档不等于删除。

工作区代码独立管理，不随会话内容删除；有未处理变更仍禁止删除会话。请求日志与执行审计沿用现行观测保留周期，不随聊天删除立即清除。备份、执行端会话副本与业务主存储需定义一致的删除范围及处理时限，不能仅移除列表即宣称全部删除。

运行状态更新、事件归属与请求幂等应能抵抗重复投递。软删除、消息保留、执行审计和工作区清理分别定义，避免删除操作意外清除代码或必要审计。SQLite 与 MySQL 路径均需验证并发与状态一致性。

## 6. 状态与异常约束

会话归档状态与执行状态分开维护，历史轮次状态不因切换页面发生变化。

| 执行状态 | 可见反馈与操作 |
|---|---|
| 空会话 | 可输入；无执行记录与变更 |
| 连接或启动中 | 显示真实状态，禁止重复提交 |
| 等待资源 | 显示等待原因，不伪造进度；不重复创建轮次 |
| 执行中 | 流式展示，可请求停止，不接受同会话新轮次 |
| 停止中 | 等待确认，不允许重新发送 |
| 已停止 | 保留内容与变更，允许继续或手动重试 |
| 已完成 | 展示实际结果，不自动提交或同步为业务验收通过 |
| 执行失败 | 展示脱敏错误和保留结果，可显式重试 |
| 状态未知 | 查询原运行，阻止新写入、归档和删除 |
| 已归档会话 | 只读查看，恢复并通过权限检查后可继续 |

删除判断、权限撤销、仓库失效、工作区丢失、连接首次失败与中止超时均需独立提示。无法确认终态时宁可维持状态未知，不根据前端计时器判定成功。

## 7. UI 约束与参考契约

### 7.1 事实源与保真模式

采用风格迁移：本次用户确认优先；业务语义以本 PRD 为准；布局和交互参考附件；视觉 Token、字体、品牌、基础组件和导航一致性遵循 `rules/ui-design.md`、共享设计 Token 及 REQ-0023。保留左侧导航、中间对话、右侧执行详情结构，不复制附件的蓝紫渐变、人员信息和演示设置。

参考 HTML 为内存模拟：消息与初始 Diff 为固定样例，新增输入仅演示状态变化。本次 req-complete 已将附件脱敏保存为 `prototype/web/prototype.html`，并在 `prototype/web/context.md` 完成拆解与参考契约；保留原稿交互用于追溯，目标 Ops 视觉尚待 Skeleton 验收。不能把模拟行为当作真实后端契约。

### 7.2 组件与动作族

| 组件或动作 | 参考 selector | 交互类型与关键状态 |
|---|---|---|

## 10. 验收方向

以下验收方向已展开为 `acceptance.md` 清单；当前产品功能验收均未执行。

1. 真实 Codex 接受输入，连续两轮使用同一会话和工作目录，刷新及切换后恢复正确历史。
2. 用户、空间和对象三层权限通过正反例验证；猜测他人会话标识无法读消息、Diff 或继续执行。
3. 主对象可空且最多一个；后续修改关联不改变前轮快照，撤权后不泄漏历史引用内容。
4. 重复发送、双标签页和重连不产生同会话并发写入，重复与乱序事件归属正确。
5. 停止显示确认过程，执行端终止后可继续；停止保留修改，断连不自动重跑。
6. 第一轮修改文件、第二轮继续调整时，分别呈现可信本轮 Diff，累计变更不冒充本轮结果。
7. 未修改、二进制、超大 Diff、无权、启动失败、工作区不可恢复等场景有真实反馈。
8. 会话历史管理闭环；运行中或有未处理变更禁止删除，清理判定不依赖历史文件计数。
9. 真实执行权限限制有效，前端无凭证与模拟结果，不支持的能力不出现虚假入口。
10. 1440px 和关键状态完成截图及样式采样，原型布局与 Ops 组件一致；正式产品移除演示控制及样例。
11. API、数据库、部署和观测同步完成，SQLite/MySQL 并发与重启恢复通过验证。

真实接入最小验证链：读取受控测试仓库代码 → 修改一个文件 → 运行验证 → 展示实际 Diff → 同会话继续调整 → 停止并确认已有修改保留。使用测试仓库，不对生产仓库做试验性写入。

## 首次使用流程验收调整（2026-09-11）

进入工作台即可编写本地草稿，首次发送自动创建个人会话再提交轮次；单仓库自动选择，多仓库在输入区选择。新建会话只打开新草稿，无前置弹窗、无空会话写入。服务未就绪仍可编辑，发送继续校验认证、仓库及执行能力。

创建和发送分别使用稳定请求标识；创建响应丢失重放得到同一会话，创建成功后发送失败复用已有会话与轮次请求，连续点击不重复提交。创建幂等按用户隔离并重验权限；参数冲突拒绝、删除记录不复活。草稿仅内存驻留并按空间/实例隔离，刷新不保证保存未发送内容。首次未关联会话仍遵循原只读策略；需要写入时按既有流程关联对象与Change。


## 顶部精简验收调整（2026-09-11）

Chat移除顶部空间工具栏和项目连接栏；会话标题行仅承接原展开/收起按钮，历史和新建动作保留。空间和主题通过共享侧边栏菜单切换。当前唯一授权仓库自动选中，首次发送创建会话；多仓库保留输入区选择，无仓库仍显示真实不可用原因，不硬编码仓库路径或绕过权限。消息区填满剩余空间、输入卡居中，切换轨迹不丢草稿。


## 会话标题与历史入口返修（2026-09-11）

已创建会话的标题及编辑图标作为重命名入口，复用既有弹窗；空草稿显示“新会话”，首次发送创建后才可改名。删除标题下拉及快速切换弹窗，其他会话统一从历史弹窗选择。移除对话/轨迹栏常驻“个人会话”标签，权限说明保留在历史弹窗：仅本人可查看，同时遵循空间、仓库与关联对象权限。保存成功同步标题及历史，空白禁用保存，失败保留编辑内容，取消不修改。后端权限校验及接口无变化。


### 输入框提示精简验收

输入框正常就绪时不显示常驻执行说明或空提示节点；仅保留服务未就绪、归档、原运行未终止、缺少仓库及发送失败提示。发送按钮在有无提示时均右对齐，权限校验与请求流程不变。
