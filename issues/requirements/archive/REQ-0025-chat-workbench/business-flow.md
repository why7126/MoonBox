# Chat 工作台业务流程

## 正常流程

```text
登录 → 本地草稿或显式选择历史会话 → 当前空间与仓库授权检查
  → 输入并发送 → 首次幂等创建会话 / 复用历史会话
  → 核验 Codex 标识和工作区及已有业务关联 → 再验权限 → 保存本轮快照与请求幂等键
  → 获取同会话执行互斥 → 启动真实运行
  → 持久化事件并流式展示 → 确认终态及本轮 Diff
  → 释放互斥 → 同会话下一轮 / 归档
```

没有仓库配置时显示不可用原因；首次连接失败保留未连接会话，不伪称恢复。资源不足进入等待状态；调度开始前重验会话及对象权限。互斥涵盖连接、等待、执行、停止中和状态未知，网页关闭不释放运行所有权。

## 停止与竞争

```text
当前运行 → 请求停止 → 停止确认弹窗
  ├─ 取消 → 继续运行
  └─ 确认 → 停止中
       ├─ 执行端确认中止 → 已停止 → 保留变更 → 可继续
       ├─ 执行端先正常完成 → 已完成 → 保留真实终态
       └─ 超时/失联 → 状态未知 → 查询原运行
```

查看历史轮次不改变当前运行目标；停止操作携带明确会话与运行标识。停止不回滚、不撤销已有外部副作用，不自动提交。

## 断连与重试

```text
断连 → 状态未知 → 查询/恢复原会话和运行
  ├─ 仍运行 → 恢复事件流，禁止重复发送
  ├─ 已完成 → 展示实际结果，不再次写入
  ├─ 已失败/已停止 → 用户显式重试
  │    → 重验权限与快照 → 创建关联原轮次的新轮次
  └─ 无法确认 → 保持未知与写入锁，提供处理原因
```

草案默认重试复用原输入和仍有权访问的原快照；要使用最新内容时显式说明并新建输入。不得因只丢失网页连接而自动重试。服务重启后的互斥与恢复由持久化事实和执行端状态共同判定。

## 历史管理与删除

```text
会话列表 → 搜索/筛选/置顶/重命名
  → 无活动或未知运行 → 归档 → 只读 → 恢复并重验权限
  → 请求删除 → 确认运行终止 + 检查当前未处理变更
       ├─ 不满足 → 说明拒绝原因，可保留会话
       └─ 满足 → 二次确认 → 删除业务会话内容
            → 按策略保留必要脱敏审计，不删除代码或业务对象
```

历史上出现过 Diff 不是永久禁止删除的依据。消息、快照、执行审计与工作区清理分开处理，聊天、快照和 Diff 保留至主动删除并受容量上限约束；审计沿用观测标准，备份和执行端副本删除时限按 review.md 条件收敛。

## 权限撤销与关联变更

列表、对象检索、每次发送、恢复和历史快照读取分别校验用户、空间与对象权限。关联编辑只影响下一轮。撤权后拒绝新的内容注入，并限制包含无权对象的旧快照；不能以“会话属于本人”为理由展示已经无权访问的内容。

## 与关联需求的差异

本需求没有父 REQ。REQ-0020 提供需求中心入口背景，本需求增加真实 Codex 会话与执行闭环；REQ-0023 提供 Ops 样式基线；REQ-0022 的本地项目导入不作为依赖；REQ-0024 的文档权限边界继续有效。

正式功能写入沿用仓库评审、Sprint 和 OpenSpec 门禁。Codex 一轮完成只表示执行结束，不自动改变需求中心业务阶段。建议需求中心携带对象进入同一 Chat 能力，具体入口范围仍由 PRD 第 11 节评审确定。

## 数据与责任

MoonBox 管理会话所有权、上下文快照、互斥、授权和展示；执行端提供真实线程/轮次/事件与中止确认；可信工作区提供 Diff 基准。业务正文进入受控业务存储，观测只记录脱敏摘要。所有流程当前为设计要求，未做真实执行验证。

## 评审确认的额度与容量流程

平台统一服务端认证并承担额度 → 按用户/空间检查预算、并发和存储容量 → 预留本轮结果空间 → 执行。额度或容量不足时拒绝新执行并提示原因，保留已有内容与清理能力；平台付费不改变会话私有权限。具体阈值与异常补偿在 Change 设计中验证。

## Change设计承接

add-chat-workbench-codex 保留需求中心旧AI抽屉，新增显式入口携带授权对象进入/chat，不自动迁移模拟消息或运行代码。撤权限制覆盖历史快照、回复、Diff及执行端旧上下文；无法可靠剔除时禁止原线程续用并引导新建干净会话。目标UI、接口及验证以该Change design和tasks承接。


实现一致性检查：本轮未改变既定业务流程与用户故事；关联仅影响后续轮次、重试复用原快照、删除保护当前代码均已承接。正式执行/副本清理仍受平台配置和验证门禁约束，当前结果见acceptance.md（2026-09-08映射）。

## 2026-09-11 验收返修：Harness 对话与轨迹

以本机 DeepSeek Harness 的对话/轨迹结构为新参考，保持 MoonBox 共享导航与空间/对象权限。对话为右侧用户气泡、无边框助手正文、紧凑自适应输入、消息复制与本轮轨迹入口；Enter发送、Shift+Enter换行、中文输入法不误发送。活动轮次显示过程摘要，失败附着轮次。消息历史加载更早页，滚动阅读不强制跳底；轨迹标签隐藏保留阅读状态。

轨迹包含按原标识配对的工具节点、搜索、内容折叠、事件概览与可调整宽度的详情。详情提供概述、参数、结果、Schema可用性及计时；窄屏上下排列。现有停止确认、原轮次重试、引用快照及Diff保留。事件每窗口最多1000条，可以读取后续窗口或从头查看；窗口边界缺少工具开始记录时不伪造开始时间。旧数据未采集字段明确显示不可用。耗时概览按对数缩放并显示说明，不冒充模型请求计时。

新增工具详情仅存于本人会话事件JSON：白名单参数、截断输出、退出码、状态、记录时间和耗时来源。先脱敏再限长；不新增表/接口/认证/部署范围。平台日志与审计不记录这些正文。明确final_answer可用时最终消息使用最终正文，其余过程留在轨迹；旧协议保持兼容。Schema、模型请求层级、缓存率、内部推理不编造，也不增加模型切换、附件、分支入口。

## 首次发送与恢复（2026-09-11）
