# 独立 Change 优先级业务流程

## 主流程

```text
读取项目及 Change → 确认来源与可见权限 → 展示优先级或缺口
  → 活动且可写：点击“设置优先级” → 卡片内编辑区
  → 选择 P0/P1/P2/P3 → 保存 → 服务端重验身份、权限、版本与活动状态
  → 原子更新事实源及必要变更记录 → 回读新版本 → 更新卡片与筛选 → 成功反馈
```

## 异常和取消

取消或 Esc 关闭编辑区，不保存；点击卡片外部不关闭，避免误丢选择。保存中防重复提交；失败保留选择与原显示值，用户可重试或取消。版本冲突只允许重载最新值后重新选择，不强制覆盖。切换项目先离开编辑态，迟到响应不得覆盖新项目对象；服务端若已成功，以再次读取真实状态为准。

## 来源转换

独立 Change 建立有效 Issue 关联后停止本入口编辑，使用父需求约定的 Issue 来源分级展示；保留 Change 原值供追溯，不写回或覆盖 Issue。关联存在但不可见时显示受限，不将其当作独立 Change。归档记录只读，无缺失字段批量填充。

## 审计与数据边界

Change trace.priority 为已确认事实源；每次有效修改记录旧值、新值、授权操作者与时间，复用既有审计设施。身份来自服务端认证，不信任客户端自报操作者。重复保存相同值不产生业务变更；审计一致性通过控制器的同一trace原子写入实现。可选行为遥测失败不影响主流程，不将必要审计当作可选遥测跳过。

## 与父需求差异

REQ-0056 决定交付阶段按 Change 成卡及来源追溯；本子需求不改变卡片数量、阶段、Sprint、任务或归档操作，仅补独立 Change 的优先级维护及展示。BUG-0070、BUG-0071 各自修复时间与检查入口，不在此流程中合并。



## 异步保存实施约定
已确认保留服务端维护窗口和异步控制器。未就绪提示暂不可保存；入队后显示保存中，完成后回读卡片。关闭编辑区不撤销已提交操作，重新读取以服务端事实为准。必要审计随trace原子提交，异步链路复用Task Trace；不新增数据库表。UI Skeleton首轮结构已获用户确认。
