# 需求中心筛选下拉框支持复选搜索多选与排序优化

## 1. 背景与价值

需求中心已承载 REQ、BUG、Sprint 与 Change 的集中浏览、筛选和阶段流转入口。随着治理对象数量增加，现有筛选下拉框如果只能单选或缺少下拉内搜索，用户需要反复打开筛选、逐项切换或依赖全局搜索才能定位目标对象，影响规划、评审、迭代和验收时的扫描效率。

本需求聚焦需求中心筛选控件体验增强：将适合枚举选择的筛选维度升级为可搜索、可复选、可多选的下拉控件，并优化选项排序，让当前迭代、常用状态和高相关项更容易找到。该需求是 REQ-0012 的局部体验增强，不改变需求中心生命周期、卡片阶段、权限模型或真实数据事实源。

## 2. 目标用户

- 产品负责人：需要快速组合多个 Sprint、需求优先级、BUG 严重性、负责人或阶段条件，查看当前规划、评审和验收对象。
- 研发与测试协作者：需要在较多卡片中快速筛选自己关注的对象，减少跨阶段查找成本。
- 空间管理员或项目负责人：需要按项目治理维度扫描异常、阻塞、待评审和迭代范围，确认范围是否完整。

## 3. 范围

### 3.1 首版包含

- 需求中心现有筛选工具栏中适合枚举选择的维度支持复选、多选、全选当前候选项和清空。
- 下拉面板内支持关键词搜索，按选项名称、ID 或稳定展示文本过滤候选项。
- 选中项使用复选框表达状态，并在触发器区域以摘要方式展示当前选择。
- 多选条件在同一筛选维度内默认使用 OR 语义，不同筛选维度之间继续使用 AND 组合。
- 筛选项排序稳定，优先展示当前相关、常用或高优先级选项，再展示普通选项。
- 保留现有搜索、类型筛选、刷新、主题、权限、空态和错误态行为。

### 3.2 首版不包含

- 不新增需求中心生命周期阶段、卡片字段或阶段动作。
- 不新增服务端分页、服务端高级查询语言或保存个人筛选模板。
- 不改变 REQ/BUG/Change 的授权边界、数据事实源、状态映射或统计口径。
- 不新增移动端、桌面端、微信小程序或管理后台同类筛选控件。
- 不在本需求内直接实现代码、OpenSpec Change 或原型文件。

## 4. 功能要求

### FR-001 多选筛选控件

需求中心的枚举类筛选维度应支持选择多个选项。适用维度首版以现有页面工具栏为准，筛选容器内按 Sprint、分级、负责人、阶段顺序展示；其中“分级”在同一控件内分组承载需求优先级和 BUG 严重性，避免将 BUG 套入需求 P 值。若某维度仍为二元开关或自由文本输入，可保留原交互。

同一维度内多选默认表示命中任一选项。例如同时选择多个 Sprint 时，卡片属于其中任一 Sprint 即可命中；同时选择多个分级时，需求卡片按 P0-P3 优先级命中，BUG 卡片按 blocker/critical/high/medium/low 严重性命中；同时选择多个阶段时，卡片处于任一已选阶段即可命中。不同筛选维度之间继续组合收敛，卡片必须同时满足各维度条件。

### FR-002 下拉内搜索

多选下拉面板应提供搜索输入，用于过滤当前维度的候选选项。搜索结果应在用户输入后即时更新，匹配范围至少包含用户可见名称；对 Sprint、REQ、BUG 或 Change 等包含稳定 ID 的选项，应同时支持 ID 匹配。

清空搜索后，候选列表恢复完整排序。搜索无结果时展示轻量空态，并保留已选项状态，不因搜索词变化丢失选择。

### FR-003 复选框与选中状态

下拉候选项使用复选框表达选中状态。用户点击候选项文本或复选框均可切换选中状态；选中、未选、禁用和 hover/focus 状态应清晰可见，并兼容深浅主题。

触发器区域应展示当前筛选摘要：未选择时显示默认占位；选择少量项时可显示选项名；选择较多项时使用数量摘要，例如“已选 4 项”。当 Sprint 维度处于默认 Sprint 范围时，外层筛选数量可保持 0，Sprint 触发器应显示“默认 Sprint 范围”或等价默认态文案；用户手动改变 Sprint 选择后，再显示选项名或“已选 N 项”。用户应能通过明确入口全选该维度当前可见候选项、清空该维度选择，也应能通过全局清空筛选恢复默认状态。Sprint 维度应提供“未纳入 Sprint”合成候选项；执行 Sprint 全选时必须包含该候选项，选中后匹配无明确 Sprint 归属的卡片；清空 Sprint 维度仍表示不按 Sprint 过滤。用户点击非筛选区域时，已打开的筛选浮层应关闭。

### FR-004 排序优化

筛选项排序应稳定且可解释。默认排序建议：

- Sprint：只展示“进行中”和“已归档”两类状态，“当前迭代”作为同行辅助标签；排序为当前迭代或最近迭代优先，其后按编号或更新时间倒序，最后提供“未纳入 Sprint”合成候选项。
- 状态或阶段：按需求中心业务阶段顺序展示，而不是纯字母排序。
- 分级：需求优先级按 P0、P1、P2、P3 顺序展示，P 值与说明在同一行；BUG 严重性按 blocker、critical、high、medium、low 顺序展示，并与需求优先级分组区分。
- 负责人：当前用户或最近参与者优先，其后按展示名排序。
- 类型：按全部、需求、缺陷、独立 Change 或现有业务顺序展示。

排序规则不得依赖不稳定的运行时对象顺序；当缺少当前迭代、负责人或更新时间证据时，应降级为稳定名称或 ID 排序。

### FR-005 筛选状态保持与刷新

用户执行手动刷新、切换主题、打开或关闭文档抽屉、搜索下拉选项时，已选筛选条件应保持不变。全局搜索、筛选下拉选择和清空筛选之间的关系应保持一致，不出现已选条件丢失、重复展示或统计与卡片不一致。

若页面已有 URL 参数、浏览器状态或本地最近筛选策略，本需求不强制新增持久化；实现阶段应明确是否复用现有策略。若暂不持久化，刷新浏览器后的恢复行为应作为非目标或后续需求说明。

### FR-006 权限、安全与异常

筛选候选项只能来自当前用户有权访问的需求中心上下文。无权限对象不得通过候选项、数量、搜索提示或错误文案泄露。数据解析失败、权限不足或候选项为空时，应使用脱敏错误态或空态，不暴露本机路径、内部堆栈、密钥、Token 或原始治理文档全文。

筛选控件不得改变后端授权判断；前端筛选只影响当前页面展示，不得作为访问控制依据。

## 5. UI 约束

- 延续需求中心 Ops 工作台视觉体系，遵守近直角、细边框、高信息密度、深浅主题可读和 MoonBox 金色强调规则。
- 多选下拉应作为工具栏控件，不改变需求中心页面壳、看板列、卡片密度和阶段结构。
- 下拉面板需支持键盘可达、焦点态、Esc 关闭、点击外部关闭和内部点击不误关闭。
- 搜索输入、复选框、选项列表、清空入口和已选摘要在 1440px 桌面视口及窄屏下不得出现文字溢出或遮挡。
- 候选项较多时，下拉列表应有最大高度与内部滚动，不推动页面布局大幅跳动。
- 选中摘要应避免挤压工具栏其他按钮；长文本应截断或转数量摘要。
