# 用户故事

## US-001 从用户菜单打开修改密码

作为后台管理员，我希望能从管理后台用户菜单进入“修改密码”，以便不离开当前后台上下文即可处理账号安全事项。

验收要点：

- 用户菜单中存在“修改密码”菜单项。
- 点击菜单项后打开修改密码 modal，而不是 toast 占位或页面跳转。
- modal 打开后焦点进入第一个密码输入项，取消后可回到后台页面。

## US-002 校验当前密码后更新新密码

作为后台管理员，我希望修改密码时必须输入当前密码和新密码，以防他人拿到当前登录态后直接篡改账号密码。

验收要点：

- 当前密码、新密码、确认新密码均为必填。
- 当前密码错误时返回受控错误，不更新密码。
- 新密码不符合安全规则或确认密码不一致时阻止提交。
- 修改目标始终为当前登录用户，不允许前端指定其他用户。

## US-003 改密成功后重新登录

作为安全审计相关角色，我希望密码修改成功后旧会话全部失效，以避免旧 token 在密码变更后继续访问后台。

验收要点：

- 密码修改成功后撤销当前用户所有后台会话。
- 前端清理本地后台登录态，并引导用户回到后台登录入口。
- 旧 access token 再访问 `/api/v1/admin/**` 返回 401。

## US-004 追溯密码变更动作

作为安全审计相关角色，我希望密码变更有审计记录，但不保存密码或 token 明文，以便兼顾追溯和凭证安全。

验收要点：

- 审计记录包含操作者、目标用户、动作、时间和安全摘要。
- 审计记录不得包含当前密码、新密码、密码哈希、access token 或会话 ID 明文。
