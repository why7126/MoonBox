# 原型拆解：后台用户菜单修改密码

## 页面清单

| 页面/状态 | 说明 |
|---|---|
| 管理后台用户管理页 | 复用现有后台壳、侧栏、用户菜单入口 |
| 用户菜单展开态 | 展示个人资料、修改密码、界面主题、退出登录 |
| 修改密码 modal 默认态 | 展示当前密码、新密码、确认新密码和底部操作 |
| 修改密码 modal 校验失败态 | 字段级或表单级错误反馈，不关闭 modal |
| 修改成功后登录入口态 | 清理本地登录态并引导用户重新登录 |

## 关键区域

```text
后台页面
  ├─ 左侧侧栏
  │   └─ 用户菜单触发器
  │       └─ “修改密码”菜单项
  └─ modal overlay
      └─ 修改密码 modal
          ├─ 标题与安全提示
          ├─ 当前密码输入
          ├─ 新密码输入
          ├─ 确认新密码输入
          ├─ 错误/成功反馈区
          └─ footer：取消 / 更新密码
```

## 组件层级

- `AdminUserMenu`：承载“修改密码”菜单项并触发 modal。
- `ChangePasswordModal`：承载表单状态、校验反馈、提交中状态和底部操作。
- `PasswordField`：可选复用密码显隐按钮，但不得泄露密码明文。
- `AdminAuthClient`：封装自助改密请求和成功后的登录态清理。
- `Toast/ErrorMessage`：展示受控反馈，禁止放入密码或 token 明文。

## 状态矩阵

| 状态 | 触发 | UI 行为 | 数据行为 |
|---|---|---|---|
| idle | 打开 modal | 三个密码字段为空，提交按钮可根据校验策略禁用或提交时校验 | 无请求 |
| invalid_local | 必填缺失或确认不一致 | 展示字段级反馈，modal 保持打开 | 无请求 |
| submitting | 点击更新密码 | 禁用提交按钮，保留取消策略由实现确认 | 调用自助改密接口 |
| failed_current_password | 当前密码错误 | 展示受控错误，字段值按安全策略保留或清空 | 不更新密码 |
| failed_policy | 新密码不合规 | 展示密码规则错误 | 不更新密码 |
| succeeded | 后端改密成功 | 清理本地登录态，进入后台登录入口 | 撤销当前用户全部会话 |

## 交互触发

- 点击用户菜单触发器：展开或收起用户菜单。
- 点击“修改密码”：关闭菜单并打开 modal。
- 点击取消或遮罩关闭：关闭 modal，不提交数据。
- 点击更新密码：执行本地校验，通过后提交接口。
- 收到 401：清理登录态并进入登录入口。
- 收到成功：清理登录态并进入登录入口。

## 数据依赖

- 当前用户身份来自本地 session + 后端 access token 解析。
- 自助改密请求需要 Authorization Header。
- 请求体包含 `current_password`、`new_password`、`confirm_password` 或等价字段；后端仍必须自行校验确认一致性或忽略确认字段后以服务端规则为准。
- 成功响应不得返回密码、密码哈希、token 或会话 ID 明文。

## 响应式断点

| 断点 | 验收重点 |
|---|---|
| 1440px desktop | 用户菜单位置、modal 宽度、字段间距、底部按钮对齐、错误文案不溢出 |
| 1024px compact desktop | modal 不超出视口，遮罩和侧栏不互相干扰 |
| 768px tablet | modal 宽度随容器收缩，footer 操作仍可点击 |
| 低视口高度 | modal body 可滚动，底部提交/取消操作可访问 |

## 1440px 验收焦点

- 用户菜单中“修改密码”与其他菜单项视觉层级一致。
- modal 使用近直角、细线、克制金色强调，符合 MoonBox 管理后台风格。
- modal 宽度经 computed style 验收，不能被通用 `modal-card` 样式覆盖。
- 当前密码、新密码、确认新密码的标签、输入框和错误反馈对齐。
- 底部“取消”和“更新密码”按钮不被错误提示或低视口滚动遮挡。
- 修改成功后页面不得停留在看似已登录的后台状态。
