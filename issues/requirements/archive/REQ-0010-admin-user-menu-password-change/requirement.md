# 后台管理用户菜单栏密码修改功能

## 背景

MoonBox 管理后台已具备真实登录认证、服务端会话校验、退出登录和管理员为后台用户重置密码等能力。当前后台用户菜单中已经存在“密码修改”入口，但仍是占位反馈，不能让当前登录管理员自助完成密码更新。

随着后台承载用户管理、品牌资产、上传和治理类敏感操作，管理员需要能够在知道当前密码的前提下主动修改自己的登录密码。该能力应复用既有后台认证边界，确保密码变更过程校验当前登录态、当前密码和新密码强度，并在变更成功后撤销旧会话，降低旧凭证继续访问后台的风险。

## 目标用户

- 超级管理员：需要在初始化密码或周期性安全要求后，自助修改自己的后台登录密码。
- 后台管理员：需要在首次激活或密码泄露风险后，自助更新自己的后台登录密码。
- 安全审计相关角色：需要确认密码变更动作有身份校验、会话失效和审计追溯。

## 范围

### 包含

- 用户菜单入口：在管理后台用户菜单中提供“修改密码”入口。
- 修改密码弹窗：点击入口后以 modal 方式展示当前密码、新密码、确认新密码和提交/取消操作。
- 当前密码校验：提交时后端必须校验当前登录用户的当前密码。
- 新密码规则：新密码必须满足后台认证安全规则，拒绝空密码、示例密码、弱密码或与确认密码不一致。
- 自助改密接口：后端提供当前登录用户自助修改密码的受保护接口。
- 会话失效策略：修改成功后撤销当前用户所有旧会话，并要求重新登录。
- 安全反馈：前端展示受控错误和成功反馈，禁止泄露密码哈希、账号内部状态、token 或会话明文。
- 测试与文档：覆盖前后端关键路径，并同步 API、错误码和安全约束文档。

### 不包含

- 不支持忘记密码、邮箱找回、短信验证码、第三方登录、OAuth、SSO 或 MFA。
- 不支持管理员为他人重置密码；该能力已由后台用户管理相关需求覆盖。
- 不支持普通 Web 前台用户修改密码。
- 不支持强制定期改密、多端设备管理、设备列表、多端互踢配置或 refresh token 策略。
- 不新增独立个人资料页面；本需求仅实现用户菜单触发的修改密码 modal。
- 不新增独立审计日志查询页面；如需可视化查询密码变更日志，由后续审计类需求承接。

## 功能要求

### FR-001 用户菜单修改密码入口

管理后台 MUST 在用户菜单中提供“修改密码”入口。入口 SHOULD 位于“个人资料”和“退出登录”之间或等价的账户安全区域，保持可发现但不抢占主要业务操作。

点击“修改密码”后，系统 MUST 打开修改密码 modal，不得仅展示 toast 占位反馈。

### FR-002 修改密码 modal 表单

修改密码 modal MUST 至少包含当前密码、新密码、确认新密码、提交和取消操作。

当前密码、新密码和确认新密码均 MUST 进行必填校验。确认新密码 MUST 与新密码一致，不一致时前端 SHOULD 在提交前给出可恢复反馈。

密码输入框 SHOULD 支持显隐切换，但不得将密码写入 URL、日志、错误上报、埋点、截图说明或其他可持久化明文位置。

### FR-003 当前密码与身份校验

自助修改密码接口 MUST 要求有效后台登录态，并通过 access token 与服务端会话解析当前操作者。

后端 MUST 校验当前密码与当前登录用户的密码哈希匹配。当前密码错误时，系统 MUST 返回受控错误，不得泄露账号是否存在、密码哈希算法、内部用户状态或系统路径。

后端不得信任前端传入的 `user_id`、`role`、`is_admin` 或等价身份字段作为修改目标；修改目标 MUST 来自服务端解析出的当前登录用户。

### FR-004 新密码安全规则

新密码 MUST 满足后台认证安全规则，至少拒绝空密码、示例密码和明显弱密码，并 SHOULD 复用或收紧超级管理员生产初始密码校验规则。

新密码 SHOULD 与当前密码不同。若新密码与当前密码一致，系统 SHOULD 返回受控错误，提示用户更换为新的密码。

系统不得在 API 响应、日志、审计明文或前端持久化状态中保存新密码明文。

### FR-005 密码更新与审计

当前密码校验通过且新密码满足规则后，后端 MUST 更新当前登录用户的密码哈希和更新时间。

系统 SHOULD 记录密码变更审计事件，审计内容只记录动作、操作者、目标用户、时间和安全摘要，不得记录当前密码、新密码、access token、会话 ID 明文或密码哈希。

### FR-006 修改成功后的会话策略

密码修改成功后，系统 MUST 撤销当前用户所有旧后台会话，包括当前会话，并要求用户重新登录。

前端收到修改成功响应后 MUST 清理本地后台登录态，并跳转或引导到管理后台登录入口。重新使用旧 access token 调用 `/api/v1/admin/**` MUST 返回 401。

### FR-007 错误反馈与恢复

当前密码错误、新密码不符合规则、确认密码不一致、未登录、登录态失效、账号不可用和服务端异常等场景 MUST 有清晰、可恢复、受控的反馈。

错误文案不得泄露内部异常堆栈、数据库字段、密码哈希算法、token、会话 ID 或用户状态细节。

### FR-008 API 与客户端约束

后端 SHOULD 在统一 `/api/v1/auth` 能力域下提供自助修改密码接口，接口必须要求有效登录态；后台入口由管理后台路由与后台接口继续执行角色二次判权。

前端 SHOULD 在现有后台认证客户端能力中封装修改密码请求，并复用统一 API 基址、Authorization Header、错误读取和登录态清理策略。

## UI 约束

- 修改密码入口使用现有用户菜单样式和图标体系，文案为“修改密码”。
- 修改密码以 modal 呈现，不新增页面跳转，不打断当前管理后台上下文。
- modal 标题、字段标签、错误文案和按钮应使用中文优先。
- modal 中的按钮视觉层级应清晰：提交为主操作，取消为次操作。
- 输入校验反馈应贴近字段或表单区域展示，不应遮挡菜单、侧栏或主内容。
- 修改成功后应给出短暂成功反馈或直接进入登录页，不应停留在看似仍已登录的后台页面。
- 桌面管理场景下，modal 宽度、字段间距和按钮尺寸应与现有后台弹窗保持一致。

## 关联需求

- REQ-0005-admin-auth-system：本需求复用后台登录认证、access token、服务端会话校验、退出登录和会话撤销能力。
- REQ-0004-admin-user-management：该需求已覆盖管理员为他人重置密码；本需求只覆盖当前登录用户自助修改自己的密码。
- REQ-0007-admin-user-first-login-activation：首次登录激活后的用户可通过本需求自助更新密码。
