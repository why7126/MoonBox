# 用户故事

## US-001 多图片描述问题

作为产品负责人，我希望在 Chat 工作台一次附上多张界面截图并补充文字说明，以便 Codex 能围绕同一轮反馈理解完整问题背景。

验收要点：

- 用户可以选择多张图片并在发送前看到稳定缩略预览。
- 用户可以移除单张图片，移除后不会影响其他图片或文字草稿。
- 图片格式、数量、体积或上传失败时给出明确错误，不假装 Codex 已读取。
- 发送后历史轮次能追溯当轮图片数量、顺序和脱敏摘要。

## US-002 使用 Skill 约束本轮上下文

作为研发成员，我希望在输入区快速引用当前仓库的 Skill，以便本轮对话遵循项目既有命令、规则或文档格式。

验收要点：

- 用户可以打开 Skill 候选并看到名称、说明和来源摘要。
- 用户只能引用当前会话绑定仓库且有权访问的 Skill。
- 选中 Skill 后以轻量 token 展示，并可在发送前移除。
- Skill 只作为本轮上下文引用，不自动执行写入型命令。

## US-003 保留 Chat 工作台轨迹与权限

作为项目成员，我希望新增图片和 Skill 后仍能查看轨迹、Diff、停止和历史，以便增强输入能力不会削弱已有执行安全。

验收要点：

- 发送中、停止中、归档、未知状态和服务未就绪时，图片和 Skill 控件遵循既有 Chat 门禁。
- 消息仍可定位本轮轨迹；图片和 Skill 作为上下文来源展示或追溯。
- 权限撤销、仓库缺失或 Skill 失效时，系统阻止继续使用并说明原因。
- 通用日志和 Task Trace 不保存完整图片、完整 Prompt、完整回复、完整 Diff 或敏感凭据。

## US-004 对话区贴近 Codex 截图基线

作为经常使用 Codex 的用户，我希望 Chat 工作台对话区更接近提供的 Codex 截图体验，以便阅读命令、结果、下一步和待处理事项更自然。

验收要点：

- 用户消息呈现为右侧紧凑气泡，助手正文以清晰分节、链接式引用和摘要列表呈现。
- 视觉迁移保留 MoonBox Ops 风格、深浅主题、共享导航和权限说明。
- 窄屏下文本、文件引用、图片预览和 Skill token 不产生横向溢出。
- 后续实现提供 1440px、窄屏、深浅主题和关键交互截图证据。

## US-005 失败恢复与重复请求

作为用户，我希望上传失败、读取 Skill 失败或网络中断后草稿仍保留，以便我能修复问题后继续发送，而不是重新组织材料。

验收要点：

- 失败不会清空文字草稿、已成功上传图片或已选 Skill。
- 用户可以针对失败图片重试或移除。
- 重复点击、请求超时或响应丢失时，服务端不会重复创建会话或重复提交同一轮材料。
- 过期图片或 Skill 版本需要用户重新确认后再发送。
