# 业务流程

## 1. 主流程

```text
进入 Chat 工作台
  -> 前端请求执行配置能力
  -> 后端按用户、空间、服务端配置和执行端能力返回 Agent / 模型 / 推理选项
  -> 输入区展示默认配置
  -> 用户可调整模型和推理配置
  -> 用户发送消息
  -> 前端携带当前配置与行为链路字段
  -> 后端重新校验配置可用性和会话权限
  -> 创建或继续执行轮次
  -> 执行端按实际生效配置运行
  -> 轮次记录写入请求配置、实际生效配置、降级原因和执行标识
  -> 页面展示回复、执行状态、文件变更和本轮配置
```

## 2. 配置加载流程

```text
Chat 页面加载
  -> GET 可用执行配置
  -> success:
       渲染 Agent、模型、推理配置和默认值
  -> partial:
       渲染可用项，禁用不可用项并展示原因
  -> failed:
       使用服务端默认配置继续或禁用发送
       展示可恢复提示
```

配置来源必须以服务端为准。前端可缓存上一次成功配置用于显示稳定性，但发送时仍以服务端校验结果为准。

## 3. 发送与降级流程

```text
用户点击发送
  -> 校验输入非空、会话可执行、配置完整
  -> POST 发送请求
  -> 后端校验配置
     -> pass: 进入执行
     -> downgraded: 使用服务端允许的替代配置，并记录原因
     -> rejected: 返回文档化错误码
  -> 前端展示实际生效配置或拒绝原因
```

降级只允许发生在服务端明确规则内。若降级会改变用户预期，应在本轮执行详情中展示实际生效值，避免用户误判。

## 4. 继续会话流程

```text
用户打开历史会话
  -> 页面加载会话最近配置或服务端默认配置
  -> 历史轮次保持各自实际生效配置
  -> 用户切换模型/推理配置
  -> 配置仅影响下一轮消息
```

若后续设计决定同一会话必须固定模型或推理配置，则切换入口应禁用或引导创建新会话，不能静默忽略用户选择。

## 5. 异常流程

| 场景 | 处理 |
|---|---|
| 配置接口失败 | 保留输入区布局；按服务端策略使用默认配置或禁用发送；允许重试 |
| 模型不可用 | 禁用该项，展示短原因；后端发送接口仍拒绝无权使用 |
| 推理配置不可用 | 禁用该项或降级到默认值；轮次记录降级原因 |
| 运行中切换配置 | 默认禁用修改；如允许预设下一轮，需清楚标注 |
| 状态未知 | 阻止新发送，不允许配置改变当前运行 |
| 历史轮次查看 | 展示实际生效配置，不使用当前选择覆盖历史 |

## 6. 与父 REQ 差异

REQ-0025 已交付 Chat 工作台、Codex 持续对话、会话/轮次、真实执行、事件、Diff、权限、停止和恢复。本需求只增强聊天输入区执行配置选择：

- 新增 Agent、模型、推理配置的能力发现、展示和选择。
- 新增发送请求与轮次事实源中的配置追溯。
- 不新增其他 Agent 接入，不改变执行隔离、会话权限或正式开发授权边界。
- 不把配置选择视为自动创建任务、自动审批或绕过 OpenSpec 的机制。

## 7. 数据与观测边界

- 行为事件记录配置选择行为和结果，不记录用户输入正文。
- 请求日志记录脱敏配置标识、状态码和错误码，不记录完整请求体。
- Task Trace 记录实际生效配置摘要、执行端降级节点和错误摘要，不记录 Prompt、回复、Diff 或凭证。
- DB 只保存轮次配置事实和必要索引；保留周期和脱敏策略沿用 Chat 工作台业务存储与观测标准。
