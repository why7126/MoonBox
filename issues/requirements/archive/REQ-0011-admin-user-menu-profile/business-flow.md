# 业务流程

## 主流程

```text
后台管理员已登录
  |
  v
打开用户菜单栏
  |
  v
点击「个人资料」
  |
  v
前端读取当前用户资料 / 使用最新会话摘要
  |
  v
展示个人资料 Modal
  |
  +--> 修改昵称
  |
  +--> 上传头像 -> 上传接口保存对象 -> 返回持久 URL -> Modal 单头像预览位即时回显
  |
  v
点击保存
  |
  v
当前用户专用接口校验登录态并更新 nickname/avatar_url
  |
  v
返回更新后的当前用户摘要
  |
  v
刷新用户菜单栏与本地会话缓存
```

## 异常流程

```text
上传失败 / 类型不支持 / 文件过大
  -> Modal 内展示错误
  -> 保留当前表单状态
  -> 允许重新选择文件

保存失败 / 昵称超长 / 登录态失效
  -> 禁止静默丢弃用户输入
  -> 展示受控错误
  -> 登录态失效时进入既有认证恢复路径
```

## 与关联需求的差异

- 与 REQ-0004 的差异：REQ-0004 是管理员维护后台用户列表和他人资料；本需求只允许当前登录用户维护自己的头像和昵称。
- 与 REQ-0005 的差异：REQ-0005 提供认证、会话和当前用户身份；本需求基于该身份更新当前用户资料。
- 与 REQ-0010 的差异：REQ-0010 处理密码修改；本需求不接收当前密码、新密码或会话失效策略。

## UI 形态变更

- 个人资料修改调整回弹窗方式。
- 用户菜单栏仍作为入口，点击后打开个人资料 Modal。
- 头像上传区参照创建用户表单：单个头像预览位、右侧格式提示和上传/更换按钮、隐藏文件 input。
- Modal 内不得同时展示身份摘要头像和上传区头像两个图标；用户名和角色摘要用文本承载。

## 数据依赖

- 当前登录用户：来自后端认证上下文。
- 当前用户摘要：至少包含 `id`、`username`、`nickname`、`avatar_url`、`role`、`status`。
- 上传结果：后端返回持久头像 URL，前端可另行维护临时预览 URL。

## 权限边界

- 当前用户资料更新接口不得接受请求体指定目标用户 ID。
- 前端展示只作为体验，后端必须以认证上下文解析当前操作者。
- 资料更新接口不得允许修改角色、状态、用户名、密码或系统管理员保护字段。
