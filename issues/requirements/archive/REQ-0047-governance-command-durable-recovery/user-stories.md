# 治理命令持久化阶段与幂等恢复闭环用户故事

| 用户故事 | 用户目标与场景 | 验收映射 |
|---|---|---|
| US-001 评审发起者 | 准备不完整或部署不兼容时立即得到原因，不浪费完整模型轮次 | AC-001、002 |
| US-002 产品成员 | 生成完成后服务中断，重新进入原会话可复用完整成果 | AC-003、004 |
| US-003 研发成员 | 应用中断或响应丢失后只完成一次迁移，不重复创建评审 | AC-005、006 |
| US-004 主动停止者 | 停止后未开始的写入不自动继续，已提交事实可确认，重新生成需明确授权 | AC-007 |
| US-005 项目维护者 | 看到耗尽预算、冲突、撤权、旧 schema 等准确原因；处理原因后受控续接 | AC-008、009、010 |
| US-006 排障人员 | 在不改写原轮次的情况下关联恢复尝试、应用、版本与错误阶段 | AC-003、013 |
| US-007 普通用户 | 页面读取失败只需刷新，按钮不会触发第二次评审 | AC-011、012 |
| US-008 数据维护者 | 活跃/半迁移成果不被普通清理破坏，过期时明确不可恢复 | AC-010、014 |
| US-009 平台维护者 | 滚动升级、重启及不同数据库部署下保持同一幂等与预算语义 | AC-002、006、015 |

## 完成判断

用户故事的“恢复成功”要求源状态、文档清单、应用与回读一致，不要求原模型轮次必须 completed。使用独立测试对象验证原 stopped/failed 与已应用结果可共存。UI 原型只展示拟议动作，不作为任何故事已实现的证据。
