# 治理命令持久化阶段与幂等恢复闭环

## 1. 背景与目标

治理命令包含生成成果、业务校验、文件应用、Workflow Sync 和事实源回读。模型结束、文件写入和用户看到正确状态不是同一完成事实。服务重启、响应丢失或版本不兼容时，需要识别已经完成的步骤，保留成果并安全续接。

REQ-0027 已提供命令产品链路与 controller；BUG-0044 已提供阶段完成门禁、对象互斥及失败成果核验。BUG-0047 已归档，补齐操作记录完整性预检、同请求重试保留与具体错误传播。这些能力作为本需求基线，不重复声明为新增交付。capture.md 的关联状态是采集时快照，当前以关联 trace 为准。

本会话隔离验证观察到：BUG 评审正常完成并应用，REQ 评审轮次 stopped 后成果经核验 applied；重启后各只有一条应用且原终态保留。该证据支持操作与执行分离，不能证明所有命令已具备统一恢复能力，也不代表原业务部署已升级。证据入口：openspec/archive/2026-10-19-fix-review-recovery-operation-record-missing/verification.md。

目标是在既有基础上统一可信阶段、成果引用与恢复决策，让用户知道已完成什么、还缺什么以及可安全执行什么；避免重复模型消耗和重复写入。P1 沿用采集优先级，依据为多阶段中断可能造成成果滞留或重复副作用；实际容量在评审后估算。

## 2. 目标用户

- 产品与研发成员：从需求中心或 Chat 发起评审，中断后复用有效成果并确认结果。
- 项目维护者：依据明确阻断原因处理版本、权限、绑定或记录完整性问题。
- 排障人员：沿同一操作查看原轮次、候选、应用、恢复尝试和事实源版本，不依赖模型措辞判断成功。

## 3. 范围与非目标

首期完整覆盖 req-review / bug-review 的准备、成果校验、应用、回读及恢复，包含服务重启、响应丢失、并发和权限变化。为其他已接入治理命令建立逐动作能力矩阵，明确已支持、仅观测、不支持的恢复步骤，不自动扩展其副作用执行权限。

不重建现有 controller、对象锁或候选写入器；不重开已归档 BUG。统一提示文案和布局由 REQ-0046 承接，本需求提供可信事实及恢复动作契约。普通聊天、同轮人工问答续接、自动重新运行模型、生产发布、跨系统不可逆操作和无限重试不在范围内。停止模型不等于撤销已经提交的文件；本需求不新增隐式回滚。

## 4. 功能要求

### FR-001 独立操作身份

业务操作拥有稳定身份，关联对象、命令、项目绑定、发起身份、原基线以及模型轮次、候选和应用。恢复尝试关联原操作，不伪造新成功轮次。同一幂等键与相同输入返回原操作；同键不同输入明确冲突。用户有意重新生成时建立新操作并保留来源关系，不复用旧成果身份。

### FR-002 三类状态分别保存

分别维护执行尝试终态、业务操作阶段和展示读取状态。执行 completed 不直接意味着业务完成；failed/stopped 后仍可存在已核验合法成果。业务恢复成功不改写原轮次。前端读取失败不改变后端完成事实，未知执行仍须确认执行器已停止及围栏安全后才允许写入恢复。

### FR-003 可信阶段与检查点

业务阶段依次为准备、生成成果、校验、应用、回读确认、完成；阻断、等待处理与重试等待作为可解释结果保留。每次阶段推进保存操作版本、成果引用及指纹、源版本、已完成步骤、时间、原始错误和可执行下一步。阶段事实由后端验证形成，不能依靠助手文本或仅凭日志行推断。

复用现有 writer 的逐文件、同步和核验记录；不另建相互矛盾的事实源。记录与文件或数据库的提交窗口需可识别：崩溃后通过回读确定已提交内容，无法证明时阻断，不宣称跨存储天然原子或全局恰好一次。

### FR-004 启动能力与版本预检

复用 BUG-0047 的基线、操作记录及身份校验，补充 backend、worker、controller 的记录 schema 与动作能力兼容核验。区分部署不兼容、服务未就绪、原记录损坏和当前权限不足。未满足契约不启动完整模型轮次，返回安全原因及处理路径，不泄露内部配置。滚动升级或降级遇到不支持的记录时只读保留，不擅自转换或补空记录。

### FR-005 恢复资格判定

每次恢复重新检查当前身份权限、项目绑定、操作归属、源版本、成果指纹、既有应用、对象互斥及执行器占用。能力结果包含可否恢复、允许动作、阻断原因和结果版本。读取时可恢复不代表执行时仍可恢复；提交动作再次核验，防止时间窗口冲突。无证据或权限不足不暴露可写恢复入口。

### FR-006 按阶段续接

| 现场 | 恢复行为 |
|---|---|
| 尚无完整成果 | 保留部分输出；说明需要重新生成，不自动重跑模型 |
| 成果完整、尚未校验或应用 | 重验成果与基线，只执行剩余合法步骤 |
| 文件应用或同步中断 | 依据原日志和当前文件回读恢复，冲突时停止并保留现场 |
| 已应用但响应丢失 | 回读原唯一应用及结果版本，不重复迁移或创建 review.md |
| 已回读完成但页面未同步 | 重新获取完成结果，不执行治理写入 |
| 无法证明记录或成果归属 | 保留证据并返回明确阻断与人工处理建议 |

不得因重试覆盖较新成果，或把旧应用关联到新轮次。历史 baseline-only 等记录只在原身份、基线和既有应用证据充分时使用已有核验链；无法安全恢复是合法阻断结果。

### FR-007 重试预算与主动停止

自动重试仅适用于已授权、可幂等的后端剩余步骤。记录可重试原因、次数、退避时间、最近失败与上限；进程重启不能重置预算。冲突、撤权、绑定变化、非法成果和不支持的 schema 不自动重试；超过预算进入明确阻断状态。首期上限、退避及手动续接约束见第 10 节。

用户主动停止后不自动恢复模型生成。已提交步骤仍保留；对停止后尚未提交的写入阶段，恢复策略和授权语义须明确，默认不扩大原授权。安全回读和确认既有应用可以继续，不能把“停止”解释为隐式撤销或再次执行许可。

### FR-008 恢复结果与入口契约

复用原对象会话及任务关联，提供查看证据、重新核验、续接剩余步骤、明确重新生成或人工处理的能力声明。刷新状态与恢复写入在接口语义上分开；调用方不能通过改参数绕过动作权限。成功结果包含操作、应用和事实源版本，重复请求返回一致结果；失败保留原始原因及发生阶段。

本需求定义动作可执行性和结果数据；REQ-0046 负责统一提示与展示。若既有界面没有对应动作，需求完善时补齐最小入口交互契约及原型，不能先出现无后端能力的按钮。

### FR-009 完成门禁

只有业务校验、合法应用、Workflow Sync 与事实源回读均通过，才确认业务完成。回读应核对 approved/review、registry/index、原有子文档完整性及唯一应用；页面延迟不撤销已确认结果。重启或恢复不能跳过任一必要门禁，模型成功措辞不能覆盖业务拒绝。

### FR-010 跨命令适用与兼容

交付动作矩阵，逐项声明记录 schema、阶段覆盖、可恢复步骤、是否允许自动重试和证据来源。首期对 req/bug-review 完整验收；generate、complete、opsx、Sprint 及归档沿用既有能力，不因共享记录模块就宣称已支持统一自动恢复。普通对话和只读命令无业务写入恢复时明确不适用，不误阻断。

## 5. UI 约束

需求中心与 Chat 使用相同后端业务事实，区分原执行已停止、成果已核验和状态正在读取。恢复动作仅对当前对象、操作版本和有权限用户有效；请求中防重复提交，失败后展示可执行的下一步。状态不只依赖颜色，支持键盘操作。

不进行附件截图复刻或全站布局改版。后续 req-complete 明确动作至弹窗/确认、selector、状态及证据矩阵；若有 UI 实现，采集 1440px 与关键窄视口、刷新重连、阻断及恢复成功证据，并声明真实 API 与 Mock 边界。本轮不生成原型，也不把既有截图作为新功能交付证明。

## 7. 验证要求

在各阶段提交前后注入中断，分别记录合成回归与真实隔离产品观察。至少验证：准备不完整不启动模型；生成后重启能复用完整成果；应用中断安全续接；响应丢失只返回一次应用；并发或权限/绑定变化拒绝恢复；版本不兼容明确阻断；重启不重置预算；主动停止不自动重跑；页面读取失败只刷新结果。

REQ 与 BUG 两类评审均须完成端到端验证，核对目录完整迁移、文档指纹、唯一应用、索引、原会话和刷新重连后的看板。验收同时检查成果未丢失、副作用未重复、原轮次终态未改写；不能用测试总通过替代真实轮次和运行版本证据。正式 AC 编号及证据矩阵由 req-complete 补齐。

## 10. 首期策略定稿

本节为已评审的首期产品约定；不修改现有运行配置，不代表功能已经实现。

### 重试预算

瞬时存储不可用、短暂连接失败、可证明未提交的超时允许自动重试；版本冲突、权限/绑定变化、记录损坏、校验拒绝、未知执行器占用及 schema 不兼容均不允许。超时但提交结果不明时先只读回读，不直接重写。

每个操作最多 3 次自动重试（不含首次执行），退避依次为 2、10、30 秒，作用于整个操作而非每个阶段独立重置。尝试计数与 next_retry_at 在领取前持久化，重启不清零；单个操作同一时间最多一个恢复执行者，锁竞争不消耗重试次数。连续服务不可用仅更新诊断，超出预算进入待人工处理。

用户“重新核验”只读且不消耗写入重试预算；预算耗尽后，只有阻断原因已消除且后端重新判定可恢复，才提供一次明确确认的手动续接。每次确认最多执行一次剩余事务尝试，不重置自动预算，记录单独手动计数。重复点击同一请求不新增尝试；不自动循环生成新操作。

### 停止与授权

主动停止使生成终止，并撤销尚未领取的自动续接；停止状态未确认、执行器租约或围栏尚未安全释放前不能接管写入。未开始应用的成果进入待用户确认，用户明确“继续剩余步骤”后才重新鉴权执行；模型重新生成永远需要独立明确动作。

若停止到达时原应用事务已经开始提交，不能强杀形成半迁移；仅允许原授权文件集合内必要的事务一致性恢复与回读，不启动下一阶段的额外业务命令。页面明确“正在确认已提交结果”，不承诺停止即回滚。已完整应用只回读原结果。撤权或绑定变化仍禁止新的写入，半迁移进入受保护阻断，维护者需恢复合法授权后通过同一受控入口处理，不能绕权继续。

### 保留、过期与清理

已有执行副本及备份删除时限为上界，不延长配置。首期恢复窗口为轮次可靠终结后最多 7 天，并取当前部署现有成果保留期限与该窗口的较早值；原记录已存在更早到期时间时沿用较早值。窗口内读取、重启、自动或手动重试均不续期。保留期限未配置或依赖成果不可用时，禁止承诺可恢复，返回 retention_unconfigured 或 artifact_unavailable；不从缺失配置推导无限保留。

active 执行及提交中的事务不被普通清理删除；到期时禁止领取新的续接，只读核验已经提交的结果。已完成事务释放成果保护引用；半迁移或未完成事务保留最小恢复证据并标记清理阻断，由授权维护者明确处置，不自动清理或创建永久备份。到期事件、受阻清理及保护引用可审计。必要受控处置流程在 Change 中实现并验证权限，不能以本需求授权实际删除数据。

最小诊断和关联摘要默认保留 90 天，遵循观测标准；行为事件沿现有 180 天，聚合沿 1 年，不延长明细。到期后无成果时仅说明不可恢复，不重跑模型；不承诺已清除所有外部存储副本。记录或成果因合法删除消失时明确返回不可用。

### 兼容与接口能力

后端暴露逻辑操作身份、阶段、操作版本、执行尝试终态、原始原因、成果/应用引用、自动/手动次数、next_retry_at、expires_at 和允许动作。具体 URI、表结构由 OpenSpec 设计确定。GET/读取仅查询事实，不隐式触发模型或治理写入；恢复提交携带操作版本与幂等键，并在服务端重新校验所有资格。

支持范围由 backend、worker、controller 的 schema 读写范围与命令能力交集决定，不要求三者版本号字面相同。缺心跳或能力未知时阻断新执行与写入恢复；允许读取可靠历史结果。旧记录只读兼容，补迁移需可验证、幂等且保留原记录，不能借补字段虚构原阶段。SQLite 与 MySQL 路径都要验证唯一约束、领取及重试计数一致性。

### UI 与关联需求归属

本需求交付可信恢复能力、动作提交与最小操作详情/续接确认契约；REQ-0046 拥有共用消息文案和整体反馈布局。复用原会话及同一动作族组件，不各自新建重复状态区。无新能力时 REQ-0046 仍可独立展示原事实；本需求交付时最小操作详情和可用动作须可验收，不以关联需求未实施为由呈现假按钮。prototype/web 为局部模拟原型，包含状态切换、只读核验和续接确认；不映射到生产写入。
