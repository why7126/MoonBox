# 治理命令持久化阶段与幂等恢复闭环业务流程

## 主流程

```text
卡片或原会话发起 req-review / bug-review
  → 当前权限/绑定/对象锁 + schema/能力交集预检
  → 持久化操作身份及原基线
  → 生成成果（独立执行尝试）
  → 固化成果引用/指纹 → 业务校验
  → 领取唯一应用事务 → 逐文件写入及迁移 → Workflow Sync
  → 事实源回读 → 保存唯一可信结果 → 页面读取
```

每个箭头前后都可能中断；文件、操作记录与数据库之间不假定跨存储原子。恢复先回读已提交事实，再判断下一步。现有候选和 writer 是成果/应用事实源，统一阶段是带版本的投影及决策，不能另造一份可绕过原门禁的成功状态。

## 中断与恢复分支

| 检查点 | 必需证据 | 允许下一步 | 阻断条件 |
|---|---|---|---|
| 准备 | 命令/对象/绑定/权限、baseline、operation | 生成 | 记录不完整、能力未知 |
| 生成中/结束 | 已确认执行终态、成果清单及指纹 | 完整成果校验；不完整则明确重新生成 | unknown 或仍有活跃租约 |
| 校验完成 | 校验版本与源版本一致 | 应用剩余步骤 | 撤权、并发修改、指纹失配 |
| 部分应用 | 原写入日志、围栏、前后文件摘要 | 同一事务安全重放和同步 | 新成果冲突、权限或绑定变化 |
| 同步完成 | 同步证明、唯一应用、当前源版本 | 回读确认 | 回读不一致 |
| 已确认完成 | 原结果版本、应用凭据 | 返回原结果/刷新页面 | 当前读取失败仅影响展示 |

## 重试与停止

自动重试预算、2/10/30 秒退避、7 天上限和保留配置取较早值统一引用 requirement.md §10。每操作累计 3 次自动重试；服务重启不重置，先持久化领取再执行。瞬时超时先回读，结果不明不盲写。手动续接需可恢复判定和明确确认，只允许一次事务尝试。

主动停止在应用前使剩余写入等待确认；已经开始的事务仅进行原授权范围内一致性恢复。未知或仍运行不能接管；撤权/绑定变化不能绕过。停止不是撤销、重新生成或扩大授权。到期后不再领取新恢复，半迁移数据保护与管理员受控处置分开记录。

## 请求与事件顺序

相同键相同输入读取原操作；相同键不同输入冲突。能力查询返回 operation_version；提交带 expected_version 和恢复动作。服务端重新鉴权、校验版本、领取唯一执行权；并发请求只能一份副作用。客户端拒绝用迟到的旧版本覆盖新业务结果；无法确认排序时重新读取，不根据消息顺序猜测成功。

## 与父需求的差异

REQ-0027 提供入口至真实写入链；本需求在其上补充跨阶段持久化及恢复策略。BUG-0044/0047 的门禁、记录完整性和原终态保留继续沿用，展示组件与 REQ-0046 对接。不会增加 Sprint、OpenSpec、发布或归档的自动授权。

## 状态一致性与观测

Chat 原轮次终态保持不变；操作阶段由合法成果事实推进；页面 loading/error 不回写业务状态。每次决策关联操作、attempt、候选、应用和可信 request/task trace；直接 API 无前端事件也可追踪。观测失败只记脱敏降级，不把非业务日志失败当作未应用。运行身份和成果引用不写公开日志。
