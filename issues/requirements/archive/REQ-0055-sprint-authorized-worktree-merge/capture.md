# 继承迭代操作权限的工作区成果确认合入

## 一句话

任务 worktree 成果通过当前版本验收和候选合并验证后，由具有所属迭代操作权限的用户确认，可信集成服务串行合入主线并更新治理投影。

## 最新决策与归属

来源为同会话多轮探索及用户最终修订。最终采用人工确认合入，明确取代此前自动合入提议；默认继承所属迭代操作权限，仅查看迭代不获得确认权。用户确认该能力作为独立验收需求新增；REQ-0047 提供持久化恢复基础，REQ-0048 提供验收环境编排，均不重复实现。

## 权限与确认

- 服务端沿 worktree、REQ/BUG/Change、所属 Sprint 解析权限；统一复用迭代操作授权规则，不建立独立审批人名单，不仅凭前端按钮或角色名称判断。
- 有该迭代有效操作权限即可确认；其他迭代权限、工作区创建者或执行者身份不自动授权。具备该迭代操作权限的发起者可以确认自己的成果，不额外要求双人审批。
- 空间、仓库与对象权限仍有效；查看权限不可升级为合入权限。迭代归属缺失、不明确或链路变化时先修复归属，不能猜测。
- 确认绑定来源提交、目标提交、候选结果与验证证据，不永久授权整个工作区；实际执行前重新核对权限和版本。撤权阻断执行，来源/目标/候选变化重新验证并再次确认。
- 服务端返回能否确认及原因；有权限但验收失败与无权限分别展示，不允许确认绕过验证。

## 交付流程

1. 固定属于当前交付链路的提交，处理未提交成果，不混入其他任务修改。
2. 工作区验收通过；在受管理的临时集成工作树准备与当前目标主线的合并候选，保留来源提交历史，首期不自动变基或压缩提交。
3. 校验组合后的代码、治理文档、测试及生成物，证据绑定精确版本。
4. 用户审阅差异、验证与影响并确认；取得仓库集成锁，再次检查权限、版本及主目录人工修改。
5. 串行合入主线并记录实际 Git 结果，同步治理文件与看板投影。执行完成、合入完成、正式归档分别记录。
6. 主线推进时重建候选并复验、再确认；冲突返回原任务工作树处理。权限或输入不明保留成果及明确阻塞。

## 一致性与恢复

- Git 与数据库不假定原子事务。合并操作持久化来源、目标、候选、确认人/时间、授权依据、执行代次和检查点；重复请求与响应丢失续接同一操作。
- Git 已合入、数据库回写失败时核对实际提交后补记，不重复合并、不强制重置主线。
- 主目录有会被覆盖的人工修改时阻断，不自动 stash 或覆盖；执行前后使用有效恢复引用。
- 仅处理配置的本地主线，不自动推送远程、发布或代替正式归档。公共注册表与 Sprint 汇总由主线受控流程更新，正式规格通过归档生效。
- 验收和交付引用有效时保护恢复点；合入不立即删除 worktree，清理须确认无活动任务、未提交/未合入成果及恢复依赖。

## 看板与验收

显示待验证、待确认、排队合入、合入中、已合入、冲突/返修/待恢复等实际状态；主看板以主目录正式事实叠加执行进度，不把分支完成等同正式交付。

验收覆盖迭代操作权限继承、仅查看拒绝、同权限发起者自确认、跨迭代拒绝、关联缺失、撤权与确认竞争、版本变化失效、组合验证失败阻断、多人重复确认幂等、同仓库合并串行、主目录人工修改保护、Git成功数据库失败恢复、刷新后记录一致。

## 非目标与待细化

不新增终端 TUI、独立审批角色或自动合入策略，不重建隔离验收环境。迭代操作权限当前具体映射、任务跨迭代或迭代关闭处理、审阅页面及复验范围在 PRD 细化；不默认放宽现有权限。

## 优先级依据

P1：并行工作区成果进入主线的权限和可靠交付闭环，优先级待正式评审。
