# 继承迭代操作权限的工作区成果确认合入业务流程

## 主流程

```text
工作树成果 -> 固定提交与交付范围 -> 解析唯一 Sprint 与操作资格
  -> 工作区验收 -> 临时集成树构建候选 -> 组合验证 -> 待有权成员确认
  -> 确认绑定版本/证据 -> 同仓库排队 -> 重验权限、版本、主目录与恢复保护
  -> 受控合入 -> 核对 Git 结果 -> 持久记录 -> 主看板更新 -> 后续独立归档
版本变化 -> 重新验证并确认；权限变化 -> 阻断；冲突 -> 原开发树返修
Git/DB 中断 -> 待恢复 -> 核对实际提交 -> 只补未完成记录或保留未知状态
```

### 迭代操作资格与既有实现映射

当前静态依据：`src/backend/app/governance/scope.py` 的 `authorize(write=True)` 使用有效空间、所有者或管理员/编辑者、仓库绑定；`visible` 与 `chat_object_access.can_read` 表达对象可见性；`src/backend/app/chat/policy.py` 还施加命令和治理阶段限制，不能把某次 `write_allowed` 布尔值直接当永久合入权。未发现独立 Sprint 写权限字段，本需求不宣称已有此权限表。

首期共用“迭代操作能力”解析：有效可写空间与仓库 + 当前 Sprint/链路/Change/工作区访问 + 唯一正式 Sprint 归属 + 操作类型所需门禁。合入默认继承该能力，不增设审批名单；已有其他对象限制继续取交集。能力接口的最终名称在 Change 定义，前端不能硬编码角色名单。

| 迭代状态 | 首期合入资格 |
|---|---|
| planning / active / in_progress | 正式纳入且验收和候选验证通过后可进入确认；planning 不因尚未启动额外阻断 |
| completed / closed / archived | 只读追溯，拒绝新候选及未执行合入；保留旧证据 |
| 缺失、重复、无法解析、取消或未知状态 | 阻断并说明归属/状态不可确认 |

关闭迭代中的遗留成果经现有治理流程明确重新纳入有效迭代后才重建候选、复验和确认；不自动改迭代、重新打开迭代或沿用旧授权。关闭/撤权发生在队列等待期间时执行前拒绝；若 Git 已完成仅做事实对账，不通过回滚来抹去已完成结果。上述为本次需求细化的首期规则，待正式需求评审。

## 状态与异常分支

读取失败保持上次完整展示并标记过期；权限拒绝不变更业务状态；重复提交返回原操作；异步请求迟到不得覆盖另一工作区/候选；未知执行结果保留待核实，不伪造失败或成功。执行前重新确认权限与输入版本，清理不等于交付或归档。

## 动作与浮层矩阵

| 动作 | 浮层 | selector 种子（data-testid） | 状态及行为 |
|---|---|---|---|
| 查看候选差异 | drawer | merge-diff | 来源 / 目标 / 候选 / 证据；只读 |
| 确认合入 | confirm | merge-confirm | 待确认 / 无操作权限 / 证据过期 / 提交中 / 已接受 |
| 返回返修 | dialog | merge-repair | 保留来源树 / 旧候选失效；不改写已合入结果 |
| 查看恢复状态 | drawer | merge-recovery | 核对中 / 待补记 / 结果未知 / 已完成 |

每个浮层有关闭按钮和 Esc 路径；关闭只退出查看，不取消服务端已接受操作。提交中禁重复提交；提交错误保留上下文。确认类动作因文件写入/合入副作用需要明确确认；轻量工作区选择不额外确认。实现采用共享按钮/弹窗族，错误信息与主操作不重叠。

## 实现一致性补充（2026-10-29）

固定来源和目标后创建双父组合候选，由部署批准的隔离模板检查 SQLite/MySQL 8.4、应用和浏览器。未配置模板或检查未通过时不能确认。当前具有迭代操作权限且可访问相应对象的人确认，执行前再次核验权限与版本。同仓库串行合入，主线变化使后续确认失效。Git 完成后独立同步主目录注册表的 workspace_integration 与 Sprint 合入记录；同步失败可续接且不重复合并。治理修改保持可审阅的未提交状态，不自动提交人工修改；正式规格仍只在归档合并时生效。

实施与逐项验收以 `openspec/archive/2026-10-29-add-sprint-authorized-worktree-merge/` 为证据源；本补充不提前签署尚未完成的验收项。
