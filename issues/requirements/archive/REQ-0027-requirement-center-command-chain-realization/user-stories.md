# 需求中心卡片全命令产品链路真实化用户故事

## 用户故事与追溯

| 编号 | 用户故事 | 成功判断 | 对应要求与验收 |
|---|---|---|---|
| US-001 | 产品负责人希望在卡片分析需求，不意外改写治理状态 | 显示只读模式，聊天诱导写入也被服务端拒绝 | FR-001/002；AC-001/009 |
| US-002 | 产品负责人希望生成可重新打开的 PRD | 真实文件可读、生成时间与索引同步，重试不重复创建 | FR-003/006；AC-002/010/011 |
| US-003 | 产品负责人希望完善文档后再送审 | 六件套和适用原型齐全，校验通过才待评审 | FR-003；AC-003 |
| US-004 | 评审人希望明确选择通过、拒绝或延后 | 取消无写入，结论和理由落盘；拒绝不进入 Sprint | FR-004；AC-004 |
| US-005 | 项目负责人希望把通过评审的需求加入合规迭代 | 多 active 显式选；保留容量；REQ/Sprint 双向关联 | FR-004；AC-005 |
| US-006 | 项目负责人希望从正式 Sprint 生成关联 Change | 中文文档、身份唯一、执行时间为空、同 Sprint 范围一致 | FR-003/005；AC-006 |
| US-007 | 开发协作者希望区分受理、启动和开发完成 | 真实启动显示研发中，完成门禁后验收中；REQ 仍 in_sprint | FR-005；AC-007 |
| US-008 | 验收协作者希望凭真实验收归档需求 | 所有关联 Change 已归档才 done；部分失败可恢复 | FR-005/006；AC-008/012 |
| US-009 | 协作者希望断网、重复点击和并发修改不会损坏文件 | 同一操作可查询；版本冲突不覆盖；恢复不重复执行 | FR-006/007；AC-010/011/013 |
| US-010 | 运维与验收协作者希望按安全标识追踪故障 | 请求、任务、节点可关联，界面/直接 API 归因分开，内容脱敏 | FR-008；AC-014/015 |

## 权限与边界

复用既有项目权限，不新设角色或假定“产品负责人”天然具有写权限。用户故事中的身份表示职责，实际执行以服务端授权结果为准。对象会话复用由 REQ-0039 承接；BUG、独立 Change、文件导入与生产维护不进入本需求验收范围。
