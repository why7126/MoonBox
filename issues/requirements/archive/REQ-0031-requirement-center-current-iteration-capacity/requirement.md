# 需求中心显示当前迭代容量已使用与总容量

## 1. 背景与价值

需求中心已经承载 REQ、BUG 和 Change 的生命周期看板，并与 Sprint 规划、Scope、进度及状态追溯形成主入口。用户在看板中关注当前迭代时，除了对象数量和阶段分布，还需要快速判断当前迭代容量是否接近或超过规划容量。

当前 capture 明确提出：“显示当前迭代容量（2个当前迭代），已使用容量/总容量”。这说明需求中心需要在存在一个或多个当前迭代时，展示每个当前迭代的容量消耗情况，避免只看到卡片数量却无法判断迭代承载压力。

本需求作为 REQ-0012 前台需求中心的体验补充，优先级为 P1：它不改变研发流程状态机，但会提升 Sprint 规划和需求中心日常巡检的可见性。

## 2. 目标用户

- 产品负责人：进入需求中心后判断当前迭代容量是否已被占满、超量或仍有余量。
- 研发负责人：在需求、缺陷和 Change 进入迭代后，快速识别当前迭代负载。
- 验收与项目协同成员：查看当前迭代范围时理解卡片数量背后的容量压力。

## 3. 范围

### 3.1 首版包含

- 在需求中心展示当前迭代容量信息，核心格式为“已使用容量 / 总容量”。
- 支持同时存在 2 个当前迭代的场景，两个迭代的容量信息均可识别。
- 容量展示与 Sprint 事实源保持一致，至少包含 Sprint ID、已使用容量、总容量和容量状态。
- 当前迭代容量信息随项目切换、手动刷新和稳定快照更新。
- 对容量缺失、默认容量、显式容量覆盖和超量状态提供稳定展示。

### 3.2 首版不包含

- 不新增 Sprint 容量编辑入口。
- 不新增容量分配、自动排期或资源人天预测能力。
- 不改变 Sprint 容量默认值、覆盖策略或 `scripts/add-sprint-scope-item.py --capacity-person-days` 的事实源职责。
- 不把容量显示结果作为自动阻止需求流转、自动拒绝纳入 Sprint 或自动调整 Scope 的依据。
- 不改变 REQ、BUG、Change 现有阶段模型、卡片主动作和权限边界。

## 4. 功能要求

### FR-001 当前迭代识别

需求中心应识别当前项目下处于当前迭代语义的 Sprint。首版至少覆盖已由需求中心或后端聚合识别为当前迭代的 Sprint，支持同时返回 2 个当前迭代。

当存在 1 个当前迭代时，展示该迭代容量；当存在 2 个当前迭代时，必须并列或分组展示两者，不能静默合并、覆盖或只展示其中一个。

当前迭代的判断口径应在后续需求完善阶段与 Sprint 状态字段、需求中心默认筛选和当前迭代卡片需求对齐，避免同一页面出现“当前迭代”定义不一致。

### FR-002 容量口径

容量展示应包含：

- `已使用容量`：当前迭代已纳入 Scope 的 REQ、BUG 和 Change 对应容量合计。
- `总容量`：Sprint 当前有效总容量，优先使用显式容量配置；没有显式配置时使用项目 Sprint 默认容量规则。
- `容量状态`：正常、接近上限、已超量或待核实。

已使用容量不得用卡片数量替代；总容量不得在缺少事实源时随意猜测。容量单位应沿用 Sprint 容量治理中的“人天”口径，展示文案可简化为数值比例，但详情或提示中应能说明单位来源。

### FR-003 多当前迭代展示

同时存在 2 个当前迭代时，需求中心应为每个迭代展示独立容量项，至少包括 Sprint ID 和“已使用 / 总容量”。如果页面空间受限，可采用横向紧凑卡片、指标条或下拉详情，但两个迭代必须在首屏统计区域或当前迭代相关区域可被用户发现。

不得把两个当前迭代的已使用容量直接相加后只展示一个总数，除非同时保留分项明细。若展示汇总，汇总必须明确标注统计范围，避免用户误以为是单个 Sprint 容量。

### FR-004 缺失、默认与超量状态

当总容量来自默认规则时，应提供轻量提示，说明该值为默认容量。显式容量存在时，展示应以显式值为准。

当已使用容量超过总容量时，应在不打断用户工作的前提下给出风险提示，例如颜色、图标、短文案或 tooltip。超量提示只表达风险，不自动阻止用户继续查看、筛选或打开文档。

当容量事实源缺失、字段冲突或无法计算时，应展示“容量待核实”或等价状态，并保留当前迭代 ID；不得显示为 0/0 或把异常静默吞掉。

### FR-005 刷新与一致性

容量信息应纳入需求中心稳定快照或等价数据聚合结果。用户手动刷新、切换项目、切换当前迭代筛选或外部 Sprint Scope 变化后，容量展示应与最新事实源保持一致。

刷新失败时，页面应保留上一次成功展示的容量信息，并给出轻量失败提示；不得因为容量聚合失败清空整个看板。

### FR-006 权限与安全

容量展示只应基于当前用户有权访问的项目和 Sprint 范围。无权访问的项目、空间或 Sprint 不得通过容量数值、异常提示或请求响应泄露。

容量聚合、日志与行为采集不得记录本机路径、敏感配置、完整文档正文、Authorization、Cookie 或真实客户敏感数据。

## 5. UI 约束

- 沿用 REQ-0012 需求中心现有视觉体系、设计 token、统计区和工具栏布局。
- 容量信息应靠近当前迭代相关统计或筛选区域，避免分散到卡片内部造成重复噪音。
- 展示格式优先使用短标签或紧凑指标，例如 `sprint-006 18 / 30 人天`。
- 当前存在 2 个迭代时，两个容量项视觉权重应一致，不默认把其中一个降为隐藏项。
- 超量、接近上限和待核实状态应有可辨识视觉反馈，但不得使用强遮罩或阻断式弹窗。
- 窄屏下容量项允许换行或进入可展开区域，但不能被完全隐藏。
