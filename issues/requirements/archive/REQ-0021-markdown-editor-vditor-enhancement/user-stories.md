# 用户故事

## US-001 采集阶段增强编辑

作为产品负责人，我希望在需求中心打开采集池对象的 `capture.md` 时，可以使用 Vditor 编辑 Markdown 内容，以便快速写出包含结构、图片、表格、代码块和公式的需求素材。

验收要点：

- 仅采集阶段、文档名为 `capture.md`、且具备编辑权限时展示增强编辑器。
- 保存内容仍为 Markdown 文本。
- `trace.md` 和非采集阶段 Markdown 文档保持只读。

## US-002 图片上传与回显

作为需求记录者，我希望在编辑 `capture.md` 时可以插入图片，并在上传成功后立即看到 Markdown 中的图片引用，以便把原型截图、标注图或设计参考放入采集材料。

验收要点：

- 上传过程有明确状态反馈。
- 上传失败不丢失当前编辑内容。
- 不写入本机绝对路径、临时私有地址或对象存储凭据。

## US-003 表格、代码和公式编辑

作为研发协作者，我希望 capture 初稿支持表格、代码块和数学公式，以便在早期需求中表达技术边界、数据结构、公式说明和验收矩阵。

验收要点：

- 表格工具可插入并保存 Markdown 表格。
- 代码块可编辑并预览高亮，但不得执行代码。
- 公式渲染失败时保留原始 Markdown/LaTeX 文本。

## US-004 主题与抽屉适配

作为前台需求中心用户，我希望 Vditor 编辑器看起来仍像 MoonBox 的一部分，以便在深浅主题、右侧抽屉和移动端场景中获得一致体验。

验收要点：

- 工具栏、编辑区、预览区、公式、代码块和上传反馈适配深浅主题。
- 桌面端适配既有 420px-760px 抽屉宽度。
- 长表格、长代码行、长公式和图片预览不遮挡保存动作。
