# P03-01 需求研发流转看板需求文档 v4.0.5

## v4.0.6 Archive Consistency Patch 需求

- 需求中心工具栏新增手动刷新图标按钮，用于用户主动刷新 9 个阶段实时情况。
- 手动刷新必须保留当前搜索、对象类型、负责人、优先级和 Sprint 筛选。
- 刷新中按钮展示 loading 语义并避免重复点击；刷新失败不得清空当前看板，仅显示轻量失败提示。
- 空间二级浮层不展示标题、搜索框、组织分组或用户菜单摘要；空间项使用轻量列表行，展示空间名称、中文角色和成员数。
- 前台品牌区版本徽标使用当前产品版本 `v0.1.0`，通过共享版本常量注入。

## v4.0.5 Patch 需求

- 用户菜单入口统一命名为“切换空间”。
- 用户 Hover“切换空间”时，自动在一级用户菜单右侧展示空间列表。
- 从一级菜单移动到空间列表期间，一级用户菜单持续显示；空间列表支持短延时防误关闭。
- 验收：无需点击即可展开空间列表；空间列表打开期间一级菜单不可消失；既有搜索、单选与空间设置能力不变。

## v4.0.4 Patch 需求

- 用户菜单中的组织/空间入口改为无全屏遮罩的轻量浮层；空间按组织分组，支持搜索、单选、当前项勾选和创建/加入入口。
- 用户菜单新增“空间设置”，作用于当前空间；使用居中分栏弹窗，左侧包括常规、成员与权限、Agent、Skill、集成、高级设置，右侧显示具体配置项。
- 常规配置支持空间名称、标识、描述与默认时区，并提供取消、保存和成功反馈。
- 验收：点击外部或 Escape 可关闭浮层；任一时刻仅一个空间选中；设置菜单可切换右侧内容；保存后关闭并提示；其他看板能力不变化。

## 1. 页面目标
以单一看板统一管理 Requirement 与 Bug，从原始 Capture 到研发、验收和归档的完整生命周期。

## 2. 阶段模型
1. 采集池：人工/Capture/req-capture/bug-capture 创建；必须存在 `capture.md`、`trace.md`。
2. 规划中：人工/req-generate/bug-generate 生成；新增 `requirement.md`。
3. 待评审：人工/req-review/bug-review 完善；新增 `user-stories.md`、`business-flow.md`、`acceptance.md`、`prototype/`。
4. 已通过：评审结论通过后新增 `review.md`。
5. 迭代规划：由 `sprint-propose` 生成迭代建议。
6. 待开发：由 `req-opsx`/`bug-opsx` 生成 OpenSpec 多件套。
7. 研发中：由 `opsx-apply`/`sprint-apply` 流入，展示已完成任务数/总任务数。
8. 验收中：展示测试进度、失败项、待人工验收数；仅全部任务和验收项完成时显示“完成/归档”。
9. 已完成：只读归档，保留全链路 Trace。

## 3. 卡片信息
ID、类型、标题、优先级、负责人、来源、阶段产物、更新时间、阻塞状态、研发/测试进度及阶段主动作。

## 4. 关键规则
- 看板支持全部/需求/Bug 筛选。
- 阶段主动作根据类型自动选择 req-* 或 bug-* Skill。
- 缺少阶段必需文档时禁止流转，并指出缺失项。
- 验收中未完成测试或人工验收时，不显示完成归档入口。

## 共通布局与交互要求

- 页面不设置右侧内容区顶部全局导航栏。
- 用户菜单与主题切换固定在左侧边栏底部。
- MoonBox 品牌区显示当前产品版本 `v0.1.0`，通过共享版本常量注入。
- 左侧边栏支持收起至 72px、展开至 224px。
- 收起后保留图标、悬停提示和当前菜单高亮。
- 视觉遵循 MoonBox UI 指南：浅色背景 `#F6F7FB`、品牌靛蓝 `#14213D`、强调金 `#B8863E`、细线分隔、近直角、无厚重阴影。
- 所有状态流转必须具备权限校验、前置条件校验、二次确认、幂等控制和审计记录。
- Requirement 与 Bug 共享生命周期框架，但允许根据对象类型调用不同 Skill。


## V3 交互升级

### 用户菜单
- 点击侧边栏底部用户区域打开二级菜单。
- 菜单包含：当前空间、切换空间、创建空间、个人信息、修改密码、退出登录。
- 点击菜单外区域、收起侧边栏或完成跳转后自动关闭。
- 切换空间前检查未保存内容；存在未保存内容时弹出确认。
- 创建空间需要 `workspace:create` 权限。
- 个人信息和修改密码在独立页面或抽屉中打开。
- 退出登录必须二次确认，并清除本地会话与敏感缓存。
- 菜单支持键盘操作、焦点管理、Esc关闭以及无障碍标签。

### 侧边栏
- 产品版本号更新为 `v1.3.0`。
- 用户菜单与主题入口继续固定在侧边栏底部。

### 看板卡片调整
- “更新于 x 小时前”使用 9px 辅助字号，弱化层级，不得与正文、标签或阶段动作竞争注意力。
- 已进入“迭代规划”及后续阶段的对象必须显示迭代标签。
- 迭代标签格式为 `Sprint {编号}`，例如 `Sprint 25`。
- 未纳入迭代的对象不得显示空迭代标签。
- 对象被移出迭代时，标签同步移除并写入 `trace.md`。
- 跨迭代调整时，卡片标签实时更新，历史迭代记录保留在对象详情中。

# V4.0.1 Patch Change

基于 V4 原版本，仅进行以下两项修改：

1. 已进入“迭代规划”及后续阶段的卡片，将 Sprint 标签放置在卡片右上角，与对象 ID 位于同一信息行；标签格式统一为 `sprint-xxx`，编号不足三位时左侧补零，例如 `sprint-025`。
2. 9 列 Kanban Column Header 在页面纵向滚动时固定停留在页面标题区域下方（距视口顶部 76px）；横向滚动看板时，表头与对应列同步移动。

## 验收标准

- 未进入迭代的卡片不显示 Sprint 标签。
- 已进入迭代的卡片仅在右上角显示一个 `sprint-xxx` 标签，元数据区不重复显示。
- 表头触碰标题区域下沿后停止上移，并在看板有效区域内持续可见。
- 横向滚动后，可见表头与其下方卡片列保持水平对齐。
- 吸顶过程不新增占位行、不产生额外灰色空白区域、不复制第二套表头。
- 除上述两项外，V4 的布局、信息架构、设计系统、组件、数据、状态模型与既有交互保持不变。

# V4.0.2 管理后台视觉体系统一

## 目标

整个需求看板采用 MoonBox 平台运营后台 v1.0.5 的视觉体系，使平台运营端与产品研发端形成一致的品牌体验。

## 视觉要求

- 默认深色主题：背景 `#0A0C1B`、内容面板 `#12142B`、层级面板 `#0E1023`、强调金 `#CBA35C`。
- 浅色主题沿用管理后台映射：背景 `#F6F7FB`、白色面板、深靛文字与 `#B8863E` 强调金。
- Sidebar 展开 224px、收起 72px；版本号使用细金色边框；用户头像使用圆形暖金弱底。
- 标题区、统计区、工具栏、看板列、卡片、标签与按钮统一细线、近直角、低阴影的组件风格。
- Requirement 与 Bug 继续使用蓝色、红色左边框表达对象差异。
- 主题开关可在暗色和亮色之间即时切换，并作用于整个页面。

## 验收标准

- 页面所有主要可见组件均使用管理后台 Design Token，不残留原浅色硬编码背景。
- 深色主题为默认，主题切换后文字、面板、边框和交互态均清晰可读。
- Sidebar、品牌区、版本标识、导航高亮、用户区与管理后台框架一致。
- 9 阶段顺序、卡片数据、字段与阶段动作保持 v4.0.1。
- Sprint 标签和表头吸顶能力完整保留。

# V4.0.3 组织空间与用户菜单 Patch

## 本次目标

1. 主题切换不再作为 Sidebar 底部独立入口，仅放在用户菜单内。
2. 新增组织空间管理交互，支持用户在多组织、多空间之间明确切换。

## 功能要求

- 用户菜单依次提供个人资料、修改密码、进入后台、切换空间、设置空间、界面主题和退出登录；进入后台仅对具备后台访问权限的用户展示。
- “切换空间”使用 hover 打开右侧二级浮层，不展示额外标题、搜索框、组织分组或用户菜单摘要。
- 空间列表平铺展示空间名称、中文角色、成员数、当前项勾选和创建或加入空间入口。
- 切换空间后更新用户区空间名称，保存最近选择并给出成功反馈。
- 组织设置与空间设置入口遵循既有权限体系；无权限用户仅可查看和切换已加入空间。
- 抽屉支持点击遮罩、关闭按钮与 `Esc` 关闭。

## 验收标准

- Sidebar 底部不再显示独立主题行；用户菜单内仅有一个主题开关。
- 用户可以从用户菜单进入组织空间管理，并完成组织筛选、空间搜索与单选切换。
- 任一时刻最多一个空间处于选中状态；切换后当前空间信息同步回显。
- 除上述两项外，v4.0.2 的视觉体系、导航、9 阶段看板、数据、Sprint 标签与吸顶滚动逻辑保持不变。
