# 前台用户菜单栏个人资料功能

## 背景

MoonBox 前台需求中心已经具备左侧边栏、用户菜单、当前空间展示、主题切换、进入后台、退出登录和受保护头像读取能力。当前用户菜单中的“个人资料”仍缺少可用弹窗，前台用户无法在需求中心内直接维护自己的头像和昵称。

前台需求中心是产品研发流转的主工作台，用户头像和昵称会影响菜单识别、协作上下文和当前用户展示。本需求聚焦前台用户菜单栏中的个人资料能力，仅允许修改当前登录用户自己的头像和昵称，并在保存成功后刷新前台当前用户上下文与用户菜单展示。

## 目标用户

- 前台需求中心使用者：需要在需求中心内快速维护自己的头像和昵称。
- 具备后台访问权限的用户：需要前后台共用同一当前用户资料，但在前台只进行轻量资料维护。
- 协作查看者：需要在用户菜单和后续协作上下文中看到清晰的当前用户展示信息。

## 范围

### 包含

- 前台需求中心用户菜单“个人资料”入口从占位项升级为弹窗入口。
- 个人资料以 `rc-*` 风格 Modal 或等价前台弹窗形态打开。
- 当前登录用户可以修改自己的头像。
- 当前登录用户可以修改自己的昵称。
- 昵称允许清空；清空后保存为空值或等价空状态，前台用户菜单回退展示用户名。
- 昵称最长 128 个字符，保存时去除首尾空白。
- 头像上传复用现有对象存储链路和受保护头像读取链路。
- 保存成功后直接使用保存接口返回的最新用户摘要更新前台当前用户上下文，不强制重新拉取需求中心上下文。
- 保存成功后刷新前台用户菜单头像、昵称或用户名展示，并同步当前会话缓存中的用户摘要。

### 不包含

- 不支持修改密码；前台个人资料弹窗不得包含密码字段或密码修改流程。
- 不支持后台用户管理、角色管理、账号状态管理、用户列表编辑或重置密码。
- 不支持修改用户名、角色、权限、空间、组织、最近登录时间或其他用户管理字段。
- 不支持编辑他人资料。
- 不支持头像裁剪、旋转、滤镜、美化、批量上传或图库选择。
- 不覆盖后台个人资料页面或弹窗；后台个人资料由 REQ-0011 承接。
- 不覆盖微信小程序、移动端或桌面端。

## 功能要求

### FR-001 前台用户菜单个人资料入口

前台需求中心 MUST 在左侧边栏底部用户菜单中提供“个人资料”菜单项。

用户点击“个人资料”后，系统 MUST 关闭或收起当前用户菜单，并打开个人资料弹窗。该入口 MUST 保持现有用户菜单分组、图标密度、hover 行为和 `rc-*` 视觉体系，不得破坏“切换空间”“设置空间”“界面主题”“进入后台”“退出登录”等既有菜单能力。

当前侧边栏处于收起态时，系统 SHOULD 延续现有菜单策略；如收起态不展示完整用户菜单，则个人资料入口不需要额外展开独立入口。

### FR-002 前台个人资料弹窗

系统 MUST 以 `rc-*` 风格展示个人资料弹窗，弹窗内容仅包含头像和昵称相关信息。

弹窗 SHOULD 展示当前登录用户的只读用户名或账号摘要，用于帮助用户确认正在编辑自己的资料。弹窗 MUST NOT 展示密码、角色编辑、账号状态、权限、空间数、用户管理操作或后台管理字段。

弹窗 MUST 支持取消、关闭和保存操作。用户取消或关闭弹窗时，系统 MUST 放弃未保存的昵称和头像变更。

### FR-003 头像上传与即时预览

个人资料弹窗 MUST 支持当前用户上传或更换头像。

头像上传 MUST 复用现有对象存储上传链路，支持 JPG、PNG、WebP，单文件大小不超过 2MB。对象读取 MUST 继续通过带 Bearer token 的后端代理接口完成，前端不得直连 MinIO 私有对象或暴露临时凭据。

头像上传 MUST 具备 `idle -> uploading -> done/failed` 状态机。上传中 MUST 禁用重复选择和重复提交；上传失败时 MUST 在弹窗内显示受控错误提示，并允许用户重新选择文件。

头像上传成功后，前端 MAY 使用临时 object URL 做同会话即时预览，但最终保存到用户资料中的 `avatar_url` MUST 是后端返回的持久头像 URL，不得保存 `blob:` URL。

### FR-004 昵称修改

个人资料弹窗 MUST 支持当前用户修改昵称。

昵称允许为空，最长 128 个字符。保存时系统 MUST 去除首尾空白；用户清空昵称时，系统 MUST 保存为空值或等价空状态。前台用户菜单展示 MUST 优先使用昵称；昵称为空时回退展示用户名。

昵称校验失败时，系统 MUST 在弹窗内提示用户修正，并保留用户已输入内容。

### FR-005 保存与当前用户上下文刷新

用户点击保存时，系统 MUST 在保存期间禁用重复提交，并展示保存中状态。

保存成功后，系统 MUST 直接使用保存接口返回的最新用户摘要更新前台当前用户上下文，包括昵称、头像地址、头像首字或等价展示字段。系统 MUST 同步刷新前台用户菜单展示，确保无需刷新页面即可看到最新头像和昵称。

如果前端本地会话缓存了当前用户摘要，系统 MUST 同步刷新缓存，避免页面刷新后回退到旧头像或旧昵称。

保存失败时，系统 MUST 保留弹窗内当前输入内容，展示受控错误提示，并允许用户修正后重试。错误提示不得泄露数据库错误、对象存储内部路径、堆栈、密钥或敏感配置。

### FR-006 与现有前后台资料能力复用

系统 SHOULD 复用现有当前用户资料更新接口或对其进行前台可用封装。资料更新目标 MUST 以后端认证上下文中的当前用户为准，不得允许前端通过请求体指定任意目标用户。

系统 SHOULD 复用后台个人资料中的头像上传经验，包括单头像预览位、上传或更换按钮、格式与大小提示、上传失败提示和持久 URL 保存约束。但前台弹窗的 CSS、文案层级和交互反馈 MUST 使用 `rc-*` 前台视觉体系，不得直接套用后台 `admin-*` 视觉类导致前后台样式混杂。

## UI 约束

- 个人资料必须在前台需求中心内以弹窗呈现，不新建独立页面。
- 弹窗视觉必须保持现有 `rc-*` UI/UE：深色默认主题、细线边框、低阴影、近直角、紧凑表单密度和当前前台用户菜单浮层风格。
- 弹窗内只展示一个头像预览位，不得同时出现多个头像图标造成视觉重复。
- 上传按钮应随状态显示“上传”“更换”或“上传中”等等价文案。
- 昵称输入应简洁，错误提示贴近输入区域。
- 保存为主操作，取消为次操作；上传中或保存中不得产生布局跳动、文本溢出或按钮内容重叠。
- 弹窗应支持点击关闭按钮或取消按钮关闭；是否支持点击遮罩或 Esc 关闭可在 `/req-complete` 阶段结合现有 `rc-*` 弹窗模式明确。
