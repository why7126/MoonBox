# User Stories

## US-001 从前台用户菜单打开个人资料

作为前台需求中心使用者，我希望在左侧用户菜单中点击“个人资料”即可打开资料弹窗，以便不离开需求中心维护自己的展示信息。

验收要点：

- 用户菜单中的“个人资料”可点击，不再只是占位项。
- 点击后关闭用户菜单并打开个人资料弹窗。
- 弹窗保持 `rc-*` 前台视觉，不混入后台用户管理页面样式。

## US-002 修改头像并即时预览

作为前台需求中心使用者，我希望在个人资料弹窗中上传或更换头像，并在保存前看到预览，以便确认头像是否正确。

验收要点：

- 头像支持 JPG、PNG、WebP，单文件不超过 2MB。
- 上传中禁用重复选择和保存，失败后允许重试。
- 上传成功后在弹窗内即时回显，保存时使用持久头像 URL。

## US-003 修改昵称并支持清空回退

作为前台需求中心使用者，我希望修改昵称，也可以清空昵称并回退显示用户名，以便按自己的偏好管理展示名称。

验收要点：

- 昵称最长 128 个字符，保存时去除首尾空白。
- 昵称为空时保存为空值或等价空状态。
- 前台用户菜单优先显示昵称，昵称为空时显示用户名。

## US-004 保存后刷新当前用户上下文

作为前台需求中心使用者，我希望保存成功后页面立即显示新的头像和昵称，以便无需刷新页面即可确认修改已生效。

验收要点：

- 保存成功后直接使用接口返回的最新 user 更新前台当前用户上下文。
- 用户菜单头像、昵称或用户名立即刷新。
- 本地会话缓存同步刷新，页面刷新后不回退旧资料。

## US-005 失败时可恢复操作

作为前台需求中心使用者，我希望上传失败、保存失败或登录态失效时看到清晰提示，并能重试或重新登录，以便不中断当前工作。

验收要点：

- 上传失败和保存失败均在弹窗内展示受控错误。
- 保存失败时保留用户已输入内容。
- 登录态失效时复用既有登录态处理，不泄露内部错误。
