# 空间级 Agent、模型与思考程度配置

## 一句话

后台支持配置 Agent、模型、思考程度的层级可用矩阵，并支持按空间授权；前台空间设置可配置启用项和默认值。

## 原始描述

用户反馈：“新增功能：后台支持配置Agent、模型、思考程度列表，不同Agent有不同的模型列表，不同的模型有不同思考程度列表；后台支持配置不同的空间允许使用的Agent，模型，思考程度列表；前台的空间设置支持配置启用的Agent、模型、思考程度列表，支持配置默认值。”

## 分类与拆分

- 类型：REQ。
- 不拆分原因：后台全局能力矩阵、后台空间授权、前台空间设置与默认值共同构成同一条“空间可用执行配置”闭环，后续可在 PRD 中拆成子能力与验收项。
- 相似检查：`REQ-0035-chat-agent-model-reasoning-selector` 已交付聊天框选择能力，本需求补齐配置来源、空间授权和默认值管理，属于后续扩展；`REQ-0017-admin-space-management` 已交付空间管理基础能力，本需求为其配置子能力，不重复创建空间管理基础功能。

## 初步范围

- 后台支持维护 Agent 列表。
- 后台支持为不同 Agent 配置可用模型列表。
- 后台支持为不同模型配置可用思考程度列表。
- 后台支持按空间配置允许使用的 Agent、模型与思考程度范围。
- 前台空间设置支持在授权范围内配置启用的 Agent、模型与思考程度。
- 前台空间设置支持配置默认 Agent、默认模型与默认思考程度。
- 运行对话时应使用空间配置、启用范围和默认值约束聊天框选择与执行参数。

## 待澄清

- [ ] Agent、模型、思考程度配置是否需要支持排序、启停、描述、供应商、模型能力标签和可见性。
- [ ] 空间级授权与前台空间设置之间的权限边界：前台是否只能从后台授权范围内启用子集。
- [ ] 既有会话在默认值或授权范围变更后的兼容策略：保留历史配置、提示重选，还是自动回退。
- [ ] 是否需要区分管理员后台配置、空间管理员配置和普通成员可见范围。

## 建议验收要点

1. 后台可配置 Agent → 模型 → 思考程度的层级列表，保存后可被空间授权使用。
2. 后台可为指定空间配置允许使用的 Agent、模型与思考程度范围，越权项不可在前台启用。
3. 前台空间设置可配置启用的 Agent、模型与思考程度列表，并可设置默认值。
4. 聊天框展示项受空间启用范围约束，默认值能正确预选并进入发送 API 与执行链路。
5. 当配置被停用、删除或授权收窄时，前台提供清晰回退、禁用或提示，不产生不可执行配置。
6. 配置变更应具备必要的请求日志、行为事件和任务链路追溯，且不记录完整 Prompt、密钥或敏感上下文。
