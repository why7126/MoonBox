# Agent 运行环境版本治理与多空间隔离

## 一句话

统一 Agent 运行环境的不可变镜像版本，以空间级运行目录隔离执行数据，明确同一仓库在多空间中的绑定策略，并提供环境诊断摘要与多空间回归。

## 原始描述

用户提出：“Agent 运行环境版本治理与多空间隔离：统一不可变镜像版本、空间级运行目录、同仓库绑定策略、环境诊断摘要及多空间回归”。

## 分类与拆分

- 类型：REQ；这是运行环境与空间隔离能力的交付需求。
- 保持单条：镜像版本、运行目录、仓库绑定、诊断与回归共同构成多空间 Agent 执行闭环，可在后续 PRD 中分解验收场景。
- 初判优先级：P1；运行环境一致性与多空间隔离影响 Agent 执行可靠性，待评审确认。
- 相关需求：`REQ-0040-space-agent-model-reasoning-config` 关注空间可用 Agent、模型与思考程度，本需求关注执行环境、仓库与运行数据隔离，交付和验收闭环独立。

## 初步范围

- 为 Agent 运行环境定义统一、可追溯的不可变镜像版本及升级或回退边界。
- 每个空间使用独立运行目录，隔离工作区、缓存及运行产物，并明确清理生命周期。
- 明确同一仓库被多个空间绑定时的身份、工作副本、读写与并发策略。
- 提供可脱敏的环境诊断摘要，便于确认镜像版本、空间运行目录状态、仓库绑定和执行前置条件。
- 覆盖至少两个空间、同仓库绑定、版本切换与隔离边界的回归场景。

## 待澄清

- [ ] 镜像版本的发布、锁定、升级和回退粒度是全局、空间还是执行会话。
- [ ] 同仓库多空间绑定是允许独立工作副本、限制单空间绑定，还是提供可配置策略。
- [ ] 空间目录中哪些内容需要持久化，空间删除或解绑后如何清理。
- [ ] 环境诊断摘要面向管理员、空间成员还是执行日志，以及允许展示哪些脱敏字段。

## 建议验收要点

1. 同一指定版本的 Agent 运行环境可按不可变镜像标识启动，执行记录可追溯实际版本。
2. 不同空间的运行目录及产物互不越界；同空间重复执行遵守明确的复用和清理规则。
3. 同一仓库跨空间绑定时，读写、并发与权限行为符合已确认策略，不会串用另一空间的运行状态。
4. 诊断摘要能定位版本、目录和绑定异常，同时不泄漏密钥、完整本机路径或敏感上下文。
5. 多空间回归覆盖正常执行、同仓库冲突、版本变更、失败恢复与隔离边界。
