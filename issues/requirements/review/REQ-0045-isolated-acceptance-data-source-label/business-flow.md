# 隔离验收环境在需求中心显示数据源标识业务流程

## 主流程

```text
维护人员部署服务并声明环境类型
  → 用户进入需求中心或刷新
  → 后端鉴权并读取授权项目的稳定治理快照
  → 同一上下文响应携带来源类别、项目身份、短快照摘要和卡片数据
  → 页面在标题旁显示来源标识，并渲染对应看板
```

## 状态与异常分支

| 条件 | 页面结果 | 后续动作 |
|---|---|---|
| 隔离验收环境声明有效 | 标题旁持续显示“隔离验收数据”及脱敏快照摘要 | 用户可阅读卡片，但能辨识其为隔离副本 |
| 正常环境声明有效 | 显示中性的正常项目数据来源提示 | 用户按既有权限使用看板 |
| 声明缺失或与绑定不一致 | 显示“数据来源待确认” | 用户可重试或联系维护人员核对部署 |
| 刷新失败且保留旧卡片 | 标明“上次成功读取的快照” | 重试，旧卡片不冒充当前事实 |
| 空间或项目切换 | 清除旧来源与卡片的当前态，再接收新项目同次响应 | 迟到响应丢弃 |
| 无权限 | 延用权限错误态，不展示无权项目的来源信息 | 重新选择有权项目或登录 |

## 事实源与边界

- 部署配置是环境类型声明来源；授权项目治理快照是卡片、Sprint 和 Change 阶段的事实源。
- `snapshot_revision` 可转为短版本供人工核对，不证明数据已与源工作区实时同步。
- 页面 URL、端口、容器目录名和卡片状态均不能推断环境类型。
- 原 REQ-0013 的数据聚合和九阶段映射保持不变；本需求只增加来源说明和刷新一致性展示。
