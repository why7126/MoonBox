# 隔离验收环境在需求中心显示数据源标识用户故事

## US-001 验收人员识别隔离数据

作为验收人员，我进入需求中心时希望在标题旁立即看到“隔离验收数据”，即使当前页面使用常规地址，也不会把隔离副本中旧的 Change 阶段当作项目当前事实。

验收要点：标识持续可见；深浅主题与 1440px、390px 视口可读；不依赖颜色独立传达含义。

## US-002 项目负责人核对正常数据

作为项目负责人，我切回正常服务并刷新页面后，希望标识和卡片一起更新，以便确认已归档 Change 显示在“已完成”，且 Sprint 归属来自同一快照。

验收要点：标识、项目、短快照版本和卡片同次响应更新；迟到请求不会覆盖已切换项目。

## US-003 协作者识别未知来源

作为协作者，当来源配置缺失或接口失败时，我希望看到“数据来源待确认”或“上次成功读取的快照”，而不是误以为页面显示的是当前正常数据。

验收要点：未知、失败和旧快照文案可区分；存在重试入口；不暴露内部路径与配置。

## US-004 维护人员复核部署声明

作为部署维护人员，我希望隔离验收服务必须显式声明环境类型，并能通过安全的响应字段确认当前页面标识与服务声明一致。

验收要点：不根据 URL、目录名或端口猜测身份；配置不可信时返回未知态；响应仅包含受控枚举和脱敏摘要。
