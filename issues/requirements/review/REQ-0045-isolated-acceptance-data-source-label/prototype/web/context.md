# 隔离验收环境在需求中心显示数据源标识原型说明

## 页面清单与定位

仅覆盖前台需求中心主看板。原型为结构和状态示意，不是生产页面截图或像素级复刻稿；PNG 在实现阶段按实际页面导出，本阶段暂不要求。

## 区域与组件层级

```text
需求中心页面壳
├─ 标题区
│  ├─ “需求研发流转看板”标题
│  ├─ 数据来源状态标识（隔离 / 正常 / 待确认 / 旧快照）
│  └─ 项目名称与短快照版本（可用时）
├─ 主操作区（现有“新建 Capture”）
├─ 现有筛选与统计区
└─ 现有九阶段看板与卡片
```

来源标识是页面级组件，不能放在单张卡片中。主操作区和看板原有交互保持可用。

## 状态矩阵与触发

| 状态 | 触发 | 标题区 | 卡片区 |
|---|---|---|---|
| 首次加载 | 进入页面或切换项目 | “正在确认数据来源” | 保持既有加载态 |
| 隔离验收 | 服务端可信声明且上下文响应成功 | “隔离验收数据”，项目和短版本 | 同次响应的卡片 |
| 正常项目 | 服务端可信声明且上下文响应成功 | “正常项目数据”，项目和短版本 | 同次响应的卡片 |
| 来源待确认 | 声明缺失、冲突或响应不兼容 | “数据来源待确认” | 按接口允许的范围显示，不宣称正常 |
| 旧快照 | 手动或自动刷新失败且保留旧卡片 | “上次成功读取的快照”，提供重试 | 旧卡片明确标注非当前事实 |
| 无权限 | 授权失败 | 沿用无权限提示，不展示无权项目身份 | 不展示无权卡片 |

手动刷新、自动刷新和空间或项目切换均触发新上下文请求。切换时旧项目标识与卡片退出当前态；迟到响应不得覆盖新项目。隔离与未知状态均有文本，无障碍名称与可见文本一致。短版本不表达实时同步或生成时间。

## 数据依赖与 Mock/API 边界

- `prototype.html` 只用静态示例展示位置和文案；所有标识值均为 Mock，不构成环境判断逻辑。
- 正式实现由同一次受授权需求中心上下文响应提供来源受控枚举、项目名称、`snapshot_revision` 和卡片。环境身份由服务端可信部署声明确定，前端不得从 URL、端口或内容推断。
- 公开字段和日志只含受控类别及脱敏摘要，不含本地绝对路径、挂载配置、凭证或原始治理文档。
- 对接阶段同步 OpenAPI、生成客户端、API 索引与部署配置说明。

## 响应式与视觉验收焦点

- 1440px：标题、标识、短版本和“新建 Capture”均在首屏可见；标识不挤压主操作，筛选区与看板列头位置稳定。采样标题、标识和按钮的字体、间距、颜色、边框、换行及可访问名称。
- 1024px：标题区允许换行，标识与项目版本保持关联，不覆盖筛选。
- 390px：标题、标识和主操作可分行；长项目名截断或换行，禁止横向溢出与交互重叠。
- 深浅主题分别检查隔离、正常、未知、旧快照；颜色不能是唯一状态提示。

## 后续 UI Contract 入口

Change 设计须确定标题区稳定 selector、标识状态属性、UI Skeleton、设计 token、Mock/API 边界和 1440px 截图及 computed style 证据。当前原型的“刷新”仅示意既有动作，不新增弹窗或动作族。
