# 隔离验收环境在需求中心显示数据源标识

## 一句话

需求中心在使用隔离验收数据时明确显示可信的环境与数据源标识，避免将隔离副本中的旧状态误认作项目工作区的当前事实。

## 原始描述

用户确认曾出现服务数据源与归档工作区不一致：隔离验收服务占用常规需求中心地址，页面把已归档 Change 显示为“验收中”，且提示缺少 Sprint 归属。用户要求记录“隔离验收环境在需求中心显示数据源标识”。

## 分类与拆分

- 类型：REQ；现有页面没有声明运行环境及数据来源，需要新增可识别的产品展示能力。
- 保持单条：可信环境身份、页面提示和切换后刷新验证共同形成一个交付闭环。
- 初判优先级：P2；影响状态判断和验收效率，最终分级待评审确认。

## 初步范围

- 隔离验收环境的需求中心持续显示醒目的环境标识，并提供脱敏的数据来源或快照版本信息。
- 环境类型由服务端可信部署配置声明，页面不根据目录名称、URL 或卡片内容猜测。
- 正常服务与隔离服务切换后，页面刷新应同步更新标识与治理卡片状态。
- 不向前端、日志或公开错误信息暴露宿主机绝对路径、挂载细节、密钥或客户数据。

## 建议验收要点

1. 隔离验收服务即使使用常规页面地址，需求中心仍清晰标明“隔离验收数据”。
2. 正常服务显示可信的正常环境标识或不显示隔离警示，不把隔离数据误称为正式事实。
3. 切换数据源并刷新后，标识、Sprint 归属与 Change 阶段来自同一次可信快照；旧状态不得继续作为当前结果展示。
4. 无法确认环境身份或快照来源时显示明确的未知态，不伪称正常环境；所有展示字段均脱敏。

## 待澄清

- [ ] 环境标识只在需求中心展示，还是纳入全部治理页面的统一页面壳。
- [ ] 面向用户的快照信息采用生成时间、短版本号，还是两者组合。
