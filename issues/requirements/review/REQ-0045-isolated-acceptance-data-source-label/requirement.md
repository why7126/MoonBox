# 隔离验收环境在需求中心显示数据源标识

## 背景

需求中心目前从授权项目的治理快照读取 REQ、BUG、Sprint 和 Change，并提供刷新状态与 `snapshot_revision`。页面没有向用户说明该快照来自项目正常治理目录还是隔离验收副本。一次 BUG 验收中，隔离服务使用了常规页面地址，已归档的 Change 仍显示“验收中”；切回正常服务后，页面才显示“已完成”。地址、项目名称和“已同步”不足以证明数据来源。

本需求使用户在阅读卡片前就能识别隔离验收数据，并在来源不可确认时看到明确的不确定状态。首期只调整需求中心，不改变治理事实、状态机或归档流程。

## 目标用户

- 产品负责人和验收人员：需要判断当前看板能否作为项目工作区的交付事实。
- 开发与测试协作者：需要区分隔离副本的旧状态与正常服务的当前状态。
- 部署维护人员：需要在服务切换后快速确认页面读取的数据来源。

## 目标与成功标准

- 隔离验收服务即使使用常规页面地址，需求中心标题旁仍持续显示“隔离验收数据”。
- 正常服务不显示隔离警示；来源未确认时不得以正常环境呈现。
- 页面标识、快照摘要和卡片数据来自同一次授权的需求中心上下文响应，服务切换并刷新后同步更新。
- 页面和公开响应不泄漏宿主机绝对路径、容器挂载详情、凭证或治理文档原文。

## 范围

### 包含

- 在需求中心页面标题旁展示数据源标识，覆盖桌面与窄屏、深浅主题及加载、错误状态。
- 由服务端可信部署配置声明环境类型，并随需求中心上下文返回受控的来源类别：正常项目数据、隔离验收数据或来源待确认。
- 复用当前上下文的项目身份及 `snapshot_revision`，展示可读的短快照标识；短标识只用于核对，不作为权限或事实新旧的证明。
- 服务或项目切换、手动刷新、后台自动刷新时，标识与卡片来自同一次响应；请求失败时不得把旧标识当作当前来源。
- 覆盖隔离、正常、未知、接口失败、迟到响应和跨项目切换的前后端验证。

### 不包含

- 不将标识扩展到 Chat、Spec、任务中心、管理后台或所有治理页面。
- 不新增环境选择器、服务切换按钮、隔离环境创建与清理能力。
- 不改变 REQ、BUG、Sprint、Change 的状态推导、归档门禁或事实源目录。
- 不向用户显示完整快照哈希、文件路径、挂载配置、内部环境变量或原始异常。
- 不新增数据库表、持久行为事件或长任务 Task Trace；如设计阶段扩大采集范围，须重新评估观测声明。

## 功能要求

### FR-001 服务端可信来源声明

需求中心上下文接口应返回由服务端确定的受控来源类别。隔离验收部署必须显式声明自身身份，不得由前端依据 URL、目录名称、卡片内容或端口猜测。服务端无法确认身份、配置缺失或配置与当前数据绑定不一致时，返回“来源待确认”，不得默认为正常项目数据。

### FR-002 标题旁持续标识

页面标题旁展示当前来源：隔离验收数据使用醒目但不遮挡操作的标识；正常项目数据使用中性标识或清晰的正常状态说明；来源待确认时显示明确警示。标识不能只依赖颜色表达，需有可读文本和无障碍名称。新建 Capture、筛选和看板列头仍保持原有操作位置与可读性。

### FR-003 快照与项目核对

标识附近可显示当前项目名称和截短的快照版本，帮助用户核对所见数据。项目名称来自当前授权项目，快照版本来自同一次上下文响应；短版本只提供识别线索，不声称数据已与源工作区实时一致。无可信生成时间时不显示“数据生成于”时间文案。不得显示宿主机路径、挂载源、完整内部配置或敏感标识。

### FR-004 刷新与切换一致性

首次加载、手动刷新、自动刷新及项目或空间切换时，页面应把来源标识、快照摘要和治理卡片作为同一响应版本处理。迟到响应不得覆盖用户已切换的项目。刷新失败时标识应说明当前显示的是上次成功读取的快照或进入不可确认状态，不得继续写“当前正常数据”。

### FR-005 未知与错误状态

当接口暂时不可用、来源声明缺失或响应不兼容时，页面应显示安全的未知态及重试入口，不静默隐藏来源提示。若保留旧卡片以便阅读，必须标注其为旧快照。无权限时沿用现有权限提示，不暴露项目或部署细节。

### FR-006 接口、部署与验证

接口字段使用稳定枚举和脱敏展示值。实现时同步 OpenAPI 来源、`docs/03-api-index.md`、客户端生成物、部署配置示例及相关测试；部署配置应说明正常与隔离环境如何声明身份。验证至少覆盖隔离服务占用常规地址、正常服务恢复、项目切换、来源未知、刷新失败、权限不足和安全脱敏。

## UI 约束

- 标识放在“需求研发流转看板”标题旁，属于页面级信息，不放在单张卡片里，也不遮挡“新建 Capture”。
- 深浅主题与 1440px 桌面、390px 窄屏均须清晰可读；窄屏允许标识换行，但页面标题与主操作不能被挤出可见区域。
- 隔离和未知态应有不同文本与视觉层级；正常态不可使用与警示同等强度的危险色。
- 页面已有加载、刷新、错误与空间切换状态应与来源标识一致，不产生“已同步”但来源未知的矛盾表述。
- 若后续提供参考稿或原型，需在 Change 设计中建立对应 UI Contract 与视觉证据；当前 PRD 不规定像素级复刻。

## 产品数据采集与链路观测

- 依据：`docs/standards/product-data-collection-observability.md`。
- `product_data_collection_observability.status: applicable`；`affected_layers: [web, api, request_logs]`。
- 原因：需求中心上下文响应增加可信环境与快照摘要，Web 展示并随既有请求刷新；沿用请求日志，不记录完整路径、配置、凭证或治理内容。
- 验证：接口与页面在正常、隔离、未知环境中字段一致且脱敏；请求日志只保留受控类别和必要请求摘要。当前不增加 `usage_events`、`task_traces` 或 `task_trace_spans`；若后续新增用户动作或异步任务，应重新评估。
