# 用户故事

## US-001 工作台用户识别现代 Ops 产品气质

作为 AI 创业者或产品负责人，我希望登录后的 MoonBox 工作台呈现更现代、更高效的 Ops 工具气质，以便我能快速判断它是一个可用于日常研发治理的生产系统。

验收要点：

- 工作台首屏必须明显区别于公开首页的品牌叙事页，优先呈现任务、状态、导航和操作能力。
- 深色主题应体现现代工具台层级，避免只依赖大面积品牌插画或营销式文案。
- 金色强调应保留 MoonBox 识别度，但不应压过状态色、信息层级和操作反馈。

## US-002 产品团队统一品牌分层边界

作为 MoonBox 产品团队，我希望明确公开页、登录页、工作台、管理后台和产品手册的视觉策略，以便后续需求不会继续在旧品牌规则和现代 Ops 风格之间摇摆。

验收要点：

- 需求文档必须说明品牌分层方案，至少覆盖公开品牌页和登录后产品工作台。
- 后续设计系统文档必须声明旧视觉规则的保留范围、替换范围和过渡策略。
- 新增页面或重构页面必须能根据所属场景选择正确 token 和组件规范。

## US-003 研发治理用户高效扫描看板

作为项目负责人，我希望需求中心、任务中心和 Agent 工作流页面使用高密度、低干扰的视觉层级，以便我能快速发现阻塞、优先级、阶段数量和下一步动作。

验收要点：

- 看板、列表和统计区域必须支持快速扫描 ID、标题、状态、负责人、优先级、更新时间和主动作。
- 统计卡应能表达趋势或风险提示，不只是静态数字。
- 空态、错误态和 loading 状态必须有稳定布局，不造成页面跳动。

## US-004 执行者获得一致的组件反馈

作为开发、测试或 Agent 执行者，我希望按钮、筛选、Popover、抽屉、弹窗、toast 和状态标签在前后台保持一致，以便我能稳定理解每个交互是否已生效、是否受限、是否需要补证。

验收要点：

- 相同语义的组件必须使用一致图标、文案、尺寸、边框、hover、active、focus、disabled 和 loading 表达。
- 筛选 Popover、用户菜单、右侧抽屉和确认弹窗必须有明确退出路径。
- 状态变更类操作不得使用浏览器原生 `window.confirm`。

## US-005 设计系统维护者可逐步迁移

作为设计系统维护者，我希望现代 Ops 视觉升级支持分阶段迁移，以便先验证需求中心和工作台 Shell，再逐步扩展到管理后台和其他页面。

验收要点：

- 迁移计划必须明确试点页面、核心路径、全量迁移和回退策略。
- 每阶段必须有视觉截图、computed style、组件测试或人工验收证据。
- 新旧 token 并存期间不得让同一页面出现明显风格冲突。
