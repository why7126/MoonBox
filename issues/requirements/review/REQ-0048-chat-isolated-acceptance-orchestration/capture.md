# Chat 隔离验收环境编排与原操作续接

## 背景与目标

用户确认将 BUG-0045 的现有验收接入修复与新增平台编排拆分推进。在原 Chat 会话中准备隔离环境、运行当前代码的测试并交回逐项证据，避免每次切换桌面。复用 REQ-0044 的验证任务、浏览器 runner、依赖制品、鉴权和证据能力，不重建浏览器系统。

## 首期范围

1. 独立 MySQL：按验收任务创建隔离实例、网络与临时卷；项目声明版本，健康检查后执行迁移和合成数据初始化；短期凭据只注入对应进程，默认不映射宿主端口，不复用真实业务库。
2. 本轮代码测试应用：固定包含本轮未提交修改的代码快照、依赖锁文件、镜像、迁移、测试数据及验收计划指纹；按受控模板构建并启动 Web 与 Python 后端，核对部署版本再验收；源码变化使相关证据失效。
3. 短期测试身份：平台在隔离应用创建最小权限测试身份与登录态，按任务隔离并过期回收；不复制个人登录状态或暴露凭据给模型、日志与证据。
4. 原操作续接：环境、验证任务、AC、证据绑定原会话与业务操作；存活轮次接收工具结果，结束轮次保留原终态并建立关联续接尝试；检查点、幂等、执行占用与权限复核支持刷新和 worker 重启。主动停止不自动恢复模型；人工问答由 BUG-0046 承接。
5. 资源回收：以所有权标记、租约、超时、取消与终态管理应用、数据库和网络；崩溃后回收过期孤儿资源；清理幂等、禁止触碰其他任务资源。证据按独立保留策略保存，清理失败可诊断重试。

上述五项组成同一任务专属环境的准备、执行、恢复和回收闭环，保持一条需求。优先级暂定 P1：核心自主验收闭环能力，待正式评审确认。

## 非目标与关联边界

首期限定当前 Web、Python 后端及 SQLite/MySQL 的受控模板；不提供任意镜像或任意 Compose 托管，不执行生产部署，不复制真实客户数据，不解除模型执行隔离。外部服务按 AC 声明，测试替身与真实调用分开；真实模型调用沿用授权及预算，不无限重试。

BUG-0045 负责已有验证能力部署接入、测试依赖供应、能力预检与结果回传，可使用预配置目标独立交付。本需求负责自动供应测试应用和数据库环境；复用其调用契约。REQ-0047 提供身份与恢复原则，不能将其已完成状态等同本需求恢复能力已实现。REQ-0045 仅管理数据源标识，不重复其交付。

## 初步验收要点

- 在产品 Chat 内完成环境准备、真实 MySQL 测试、当前版本浏览器验收与逐 AC 证据回传；BUG-0055 可作为获授权的回归样本，不重放历史写入命令。
- 同代码/计划幂等请求复用原任务；输入不同拒绝误复用；跨空间任务不串库、身份、目录与证据。
- 数据库失败只阻塞相关 AC；浏览器和命令证据分类，旧版本证据不冒充当前通过。
- 页面刷新、worker 重启、响应丢失和重复回调不重复部署或重复初始化；失去权限、绑定变化或输入冲突时停止相关续接。
- 取消、超时及崩溃回收可验证；清理失败留诊断，证据留存与临时资源生命周期分离。
