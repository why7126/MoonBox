# 规则修改说明与安全归档

## 1. 要解决的问题

现有归档检查在历史规则的同一条文被改动时会阻断。BUG-0063 已于 2026-10-23 归档，生效规则已改为同条文后继核验正常验收，不再要求独立兼容证明。它是历史背景，不是待归档候选或新版放行样本。此前方案把“空间所有者确认规则修改”当成放行条件，让产品负责人多做一次含义不清的批准，仍不能代替验收或归档检查。

新版让用户看懂修改前后、理由、仍禁止的情况和验收缺口；系统复用现行的独立验收、归档权限、完整历史与写入前检查作出判断。**不设置“确认本次修改”“拒绝”“撤销确认”产品动作，也不自动归档。**

## 2. 用户与价值

- 产品负责人：在对象阻断项查看差异和处理建议，无须额外批准规则文本。
- 验收人员：对受影响场景测试并签署；查看差异不能代签。
- 归档执行者：在缺证据、历史断链、权限或版本变化时看到具体原因；条件满足后重试原归档命令。

## 3. 范围与非目标

首版只为当前尚未归档且确实修改了已归档条文的对象提供差异说明；BUG-0063 作为已归档历史样本，只用于核对旧记录可读，不作为新归档正例。候选预检、产品与 CLI 写入前复核、归档历史逐边验证共享判断；中断恢复沿用原操作身份和检查点。对象阻断项提供“查看修改”，不在 Composer 或项目操作区放常驻按钮。

不允许任意规则替换、删除或重命名条文、弱化身份/权限/证据/独立签署/完整历史/并发保护、模糊文本推断或跨项目复用结果。旧确认、运维制品审阅、首次启用及签名记录只读保留，不转化为新版准入；本需求不重新审批或归档 BUG-0063，不自动关闭 sprint-012 或执行生产部署。

## 4. 业务规则

### FR-001 看清具体修改

归档发现历史条文被改时，阻断项显示“规则内容已修改，需检查后继续”和“查看修改”。抽屉展示原规则、修改后、增加的允许情形、修改理由、仍禁止的情况、受影响对象和验收结果。无相关修改时不出现入口。原条文、完整差异或影响范围无法确定时维持阻断。

### FR-002 复用现行归档判断

查看差异只解释当前对象对历史条文做了什么，不新增兼容证明、精确文本白名单或人工规则批准。是否可归档以已生效规则和现有共享门禁为准：正常验收及独立签署、对象身份、项目权限、连续历史、交付材料和写入前版本检查各自生效。删除、重命名、弱化旧保护或其他不明改动须通过现行验收与归档规则判断；页面不能凭文本相似、旧确认或按钮自行放行。

### FR-003 独立验收与既有权限

沿用原归档入口的项目权限，不新增规则修改批准人。验收人员对受影响场景独立签署；未签署或证据过期仍阻断。系统展示项目、对象、原新版本和影响范围；最终判断由现有验收与归档流程绑定当前输入。查看差异、旧确认记录和 Agent 回复均不是验收签署。

### FR-004 版本变化与重新检查

页面显示待检查、可继续、验收待签署、版本变化、权限不足及结果未知。“重新检查归档”只刷新诊断，不发送 Chat 草稿或执行归档。正文、影响范围、验收证据、项目绑定、当前权限或历史在写入前变化时，旧预检结果按现有门禁失效并提示重新检查。错误与关闭后保留对象会话、草稿和附件。

### FR-005 归档前保护与恢复

产品、CLI 和后台写入共用当前生效的验收签署、既有归档权限及历史完整性门禁；差异展示不成为新的写入许可。预检后发生并发修改必须拒绝。已完成历史保留当时的差异、验收与归档事实，不改写旧版确认和证明记录；旧版已完成边按原版本只读核验。中断恢复只续原操作的剩余步骤，结果不明时阻断，不重复合并或迁移。

### FR-006 安全切换与交付独立

新版复评和实施验收完成前维持旧门禁。切换时同时撤去确认按钮和新确认写入口、不再发行额外的规则修改确认或证明，并验证旧证明仍可读。真实旧进行中操作只按原检查点回读，不自动转成新版结果。REQ-0050 的交付验收与已归档的 BUG-0063 分离；不能以 BUG-0063 旧轮次代替本版验收。旧方案 28 项通过只代表历史实现，本版须重新逐项验收。

## 5. 页面流程

对象归档诊断指出规则修改 → 用户点击“查看修改”对照差异与缺口 → 验收人员在原流程完成受影响场景的独立签署 → 用户点击“重新检查归档” → 通过后另行执行原归档命令。窄屏差异单列展示；加载、错误和焦点返回复用现有 Chat 组件。

## 6. 验收与依赖

执行标准见 `acceptance.md` AC-L01—L12，页面动作见 `prototype/web/context.md`。依赖现有项目权限、归档诊断、独立验收、历史链与恢复能力；BUG-0063 的已生效规则是当前基线。本版须同步活动 Change 的规格、设计、实现、测试及受影响 API、数据库、UI、安全文档；不得直接改已生效 `openspec/specs/`。

## 7. 产品数据采集与观测

参照 `docs/standards/product-data-collection-observability.md`。`product_data_collection_observability: applicable`；`affected_layers: usage_events, request_logs, governance_archive, task_traces, task_trace_spans`。查看行为与请求结果做脱敏记录，归档事实关联差异版本和验收签署；旧确认审计只读保留。Task Trace 仅用于实际长流程归档和恢复；单次查看差异为短请求，不另建任务链。对象存储 schema 不变，沿用附件链路。验证需核对关联、错误隔离及脱敏；遥测不能代替权限或签署。
