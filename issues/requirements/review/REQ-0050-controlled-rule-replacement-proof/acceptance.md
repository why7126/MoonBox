# 规则修改说明与安全归档验收标准

## 验收范围与状态

保留 AC-L01—L12 追溯编号，按精确差异、独立验收、写入前复核、页面可理解及历史安全收敛取证。同一有效样本可支持多个结论，不为每项重复搭建环境。旧版 28 项通过与上一版“所有者确认”的证据不能自动计入本版。

| 编号 | 可复核结果 | 证据与边界 |
|---|---|---|
| AC-L01 修改发现 | 至少一个当前未归档隔离样本修改历史同条文时，阻断项指出原文、修改内容及影响对象；无相关修改时不出现入口。 | 真实预检及对象页面；标题或文本相似不能放行。 |
| AC-L02 规则边界 | 差异说明不新增独立兼容证明或文本白名单；删除/重命名、弱化身份/权限/证据/签署/历史链/并发保护及不明差异仍按当前生效门禁判断，页面不得自行放行。 | 当前未归档样本的正反例；与已生效归档判断一致，人工点击或旧确认不能覆盖拒绝项。 |
| AC-L03 无额外批准 | 页面没有“确认本次修改”“拒绝”“撤销确认”，新归档路径也不要求空间所有者另作规则确认；原归档权限与独立验收仍生效。 | 真实页面、API、CLI 与后端检查；旧确认记录只读。 |
| AC-L04 版本失效 | 正文、影响范围、受影响验收、项目绑定、当前权限或历史链变化后，预检与提交拒绝沿用旧结果；结果未知有明确提示。 | 逐类变化和版本竞争样本；不以旧确认记录补救。 |
| AC-L05 独立验收 | 受影响场景有测试结果和独立验收人员签署；未签署或证据缺失阻断归档。 | 验收记录及真实拒绝；原有效 AC 不因局部阻断被抹除。 |
| AC-L06 分项诊断 | 用户在对象阻断项完成“查看修改→重新检查”；分别看到规则、验收、权限及其他门禁，不出现常驻治理按钮。 | 真实页面；查看和重新检查均不发送命令或归档。 |
| AC-L07 提交前复核 | 产品、CLI 与后台写入前共用当前签署、权限、完整链及其他生效门禁；预检后并发变化必须拒绝。 | 隔离真实归档与并发注入；Sprint 关闭另行判断。 |
| AC-L08 历史与恢复 | 只有成功归档形成可复用后继事实；断链、篡改、重复身份或结果不明阻断；移除确认不改变旧操作身份。 | 共享归档路径正反例与历史回读；复用现有中断回归。 |
| AC-L09 页面易懂 | 抽屉展示“原规则／修改后／修改理由／仍禁止／受影响验收”，不用旧版审批术语。 | 桌面和窄屏、深浅主题；长文、空态和加载错误复用组件回归。 |
| AC-L10 操作安全 | 抽屉可关闭、Esc 与焦点返回正确；错误或关闭后 Chat 会话、草稿和附件保持。 | 真实交互与组件回归；至少一次成功上传后被门禁拒绝仍保留附件。 |
| AC-L11 安全切换 | 旧已完成记录只读可查；旧确认及旧审批写入口不能重新放行或绕过新版门禁；真实旧进行中操作只按原身份回读。 | 历史回读、旧入口拒绝和恢复回归；BUG-0063 没有产品旧操作。 |
| AC-L12 交付独立 | REQ-0050 自身交付不以已归档 BUG-0063 的候选预检为前提；BUG-0063 的已完成历史不会因 REQ-0050 改写。 | REQ-0050 当前态与 BUG-0063 已归档历史分别核对；不自动关闭 sprint-012。 |
