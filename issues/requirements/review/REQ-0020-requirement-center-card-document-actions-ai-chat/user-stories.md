# 用户故事

## US-001 Capture 新建

作为产品负责人，我希望在需求中心直接创建 Requirement 或 Bug Capture，以便新想法和缺陷反馈能立即进入采集池。

验收要点：
- 标题为空时阻止提交并展示校验提示。
- 创建成功后展示反馈，并在采集池插入新卡片。
- 创建失败时保留表单内容，不产生错误卡片。

## US-002 卡片文档查看

作为项目协作者，我希望直接点击卡片中的 Markdown 或 HTML 关联文档，以便快速查看需求、设计、原型或任务材料。

验收要点：
- Markdown 文件从右侧抽屉打开。
- HTML 文件从新 Tab 打开。
- 文件缺失、类型不符或权限不足时有明确异常反馈。

## US-003 卡片阶段动作

作为项目负责人，我希望卡片按钮自动匹配当前阶段和对象类型，以便按治理流程推进 req、bug、sprint 和 opsx 命令。

验收要点：
- Requirement 与 Bug 使用不同 Slash Command 映射。
- 执行中按钮 Loading 并锁定，避免重复提交。
- 成功后按状态机流转，失败后保持原阶段。

## US-004 AI 聊天协同

作为空间成员，我希望通过全局 AI 聊天抽屉发送问题或接收卡片动作反馈，以便把命令执行上下文和异常信息集中在一个地方。

验收要点：
- 悬浮按钮可打开右侧 AI 聊天抽屉。
- Enter 发送，Shift+Enter 换行。
- 卡片动作能把对象 ID、标题、类型、阶段和建议命令带入聊天上下文。

## US-005 生成、完善与导入

作为产品负责人，我希望生成或完善需求时可以选择 AI 自动生成或导入文件，以便复用已有文档并减少重复录入。

验收要点：
- 生成阶段只允许单个 `requirement.md` 或 `bug.md`。
- 完善阶段允许 ZIP 或约定文档集合。
- 文件校验失败时不执行命令、不流转状态，并在 AI 聊天显示原因。

## US-006 迭代与研发进度

作为项目负责人，我希望已评审卡片能选择迭代，并在研发或验收阶段查看 `tasks.md` 进度，以便掌握从 Sprint 到归档的进展。

验收要点：
- 加入迭代前必须选择未关闭 Sprint 或合法新 Sprint。
- 研发中展示只读任务进度。
- 验收中仅允许受限勾选，满足门禁后才能完成归档。

## US-007 归档详情与阶段文案

作为协作者，我希望卡片标题和归档入口都能打开新 Tab 详情，并看到统一的“已评审”阶段文案。

验收要点：
- 标题与“查看归档”均打开详情新 Tab。
- “已通过”在看板、筛选、统计、详情中统一更名为“已评审”。
- 底层 `approved` 状态语义不改变。
