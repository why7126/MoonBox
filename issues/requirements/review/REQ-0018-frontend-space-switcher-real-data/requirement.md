# 前台空间切换列表真实数据接入

## 背景

MoonBox 前台需求中心已经具备用户菜单、切换空间浮层、当前空间回显和本地最近选择能力。当前空间切换列表虽然从需求中心上下文接口读取 `workspaces` 字段，但后端首版仍基于项目治理配置组装单个工作空间，并未接入后台空间管理模块中的真实空间、成员、状态和角色数据。

REQ-0017 已完成后台空间管理模块，提供空间、产品、成员、负责人、状态、配额、有效期、审计和申请审批等后台治理能力。前台空间切换列表需要与该后台空间事实源打通，使用户只能在自己已加入的真实空间之间切换，并在冻结空间场景中获得明确只读提示。

本需求只处理“切换已有空间”的真实数据接入与前台上下文一致性；空间创建、加入申请和审批流程由 REQ-0019 承接。

## 目标用户

- 前台普通成员：需要看到自己已加入的空间，并在空间之间快速切换。
- 空间管理员：需要确认自己管理的空间在前台可见，并能识别冻结空间的只读状态。
- 产品负责人：需要前台需求中心的空间上下文与后台空间管理事实源一致，避免 Mock 或治理配置空间造成误导。

## 范围

### 包含

- 前台空间切换列表接入后台空间管理真实数据源。
- 仅展示当前登录用户已加入的空间。
- 默认不展示回收中空间。
- 冻结空间可展示、可切换查看，但必须标记只读或冻结状态。
- 切换空间后同步当前空间、用户菜单空间名称、需求中心上下文和最近选择。
- 本地保存的最近选择失效时，自动回退到用户可访问的默认空间。
- 提供前台安全的数据接口或 BFF 聚合能力，不直接暴露后台管理专用接口给普通前台用户。
- 覆盖权限、空态、错误态和数据一致性测试。

### 不包含

- 不实现创建空间、加入空间申请、审批或撤回流程；这些能力归属 REQ-0019。
- 不实现后台空间管理的编辑、冻结、恢复、删除、配额、续期、负责人移交或成员管理操作。
- 不改变 REQ-0012 既有需求中心 9 阶段看板结构、视觉体系和用户菜单主流程。
- 不支持可申请加入空间的搜索或推荐列表。
- 不支持回收中空间切换、跨空间数据迁移、一空间多产品或自定义角色权限。
- 不处理 REQ-0017 当前态索引漂移；该治理事项已单独创建。

## 功能要求

### FR-001 前台可访问空间列表

系统 MUST 基于后台空间管理事实源返回当前登录用户已加入的空间列表。空间可见范围仅限用户作为负责人或成员加入的空间，不包含未加入但可申请加入的空间。

返回字段 MUST 至少包含空间 ID、空间名称、唯一标识、成员数、当前用户角色、空间状态和是否当前空间。字段命名应与现有前台 `Workspace` 结构兼容，或在前端进行明确映射。

### FR-002 前台安全接口边界

系统 MUST 通过前台安全接口或需求中心 BFF 聚合接口提供空间切换数据。普通前台用户不得直接调用后台管理专用 `/api/v1/admin/spaces` 获取全部空间列表。

接口 MUST 复用当前登录态、权限校验、统一响应结构和错误处理，不得返回后台高风险操作权限、配额详情、审计记录、删除原因、负责人内部 ID 等前台切换不需要的信息。

### FR-003 空间状态处理

正常空间 MUST 可切换并作为默认可用状态展示。

冻结空间 MUST 可展示并允许切换查看，但前台 MUST 明确标记“已冻结”或“只读”，并在当前空间上下文中保留只读语义。后续写入、Agent 执行或其他受限能力不得仅靠前端隐藏绕过服务端状态校验。

回收中空间 MUST 默认不出现在前台切换列表中；如果用户最近选择的空间已进入回收中，系统 MUST 回退到其他可访问空间或展示无可用空间状态。

### FR-004 当前空间选择与失效回退

前端 MUST 保留最近选择空间能力，但本地保存的空间 ID 必须经过接口返回的可访问空间列表校验。

当本地保存的空间不存在、用户已被移出该空间、空间进入回收中或接口返回不可访问时，前端 MUST 清理或覆盖无效选择，并回退到接口指定默认空间或列表首个可访问空间。

### FR-005 切换后的上下文一致性

用户切换空间后，前端 MUST 同步更新侧边栏用户区空间名称、空间切换浮层当前项、需求中心当前空间上下文、统计、筛选结果和看板数据。

若首版需求中心治理对象仍是项目级聚合数据，系统 MUST 至少保证当前空间摘要、权限态和入口可见性来自真实空间；若看板对象已具备空间归属字段，则 MUST 按当前空间过滤或由接口返回当前空间范围内的数据。

### FR-006 空态、错误态和无权限态

当用户没有任何已加入空间时，前台 MUST 展示明确空态，并引导用户进入 REQ-0019 的创建或加入空间流程入口；在 REQ-0019 未实现前，该入口可保持不可用或展示待实现提示，但不得伪造可切换空间。

接口失败、登录失效、权限不足或空间数据解析失败时，前端 MUST 展示可恢复错误态，例如重试或重新登录。错误态不得展示内部堆栈、本机路径、数据库错误详情、密钥、token 或后台审计原文。

### FR-007 UI 展示与交互

空间切换浮层 MUST 延续 REQ-0012 已验收的轻量列表行交互，不新增全屏遮罩、复杂搜索或组织分组。

每个空间项 SHOULD 展示空间名称、当前用户角色、成员数和当前项勾选。冻结空间需使用低干扰状态标记表达只读，不得挤压空间名称或破坏浮层宽度。

### FR-008 测试与文档同步

本需求后续完成阶段 MUST 补齐前后端测试，覆盖已加入空间过滤、冻结空间展示与切换、回收中空间隐藏、最近选择失效回退、无空间空态、接口失败和普通用户不能读取后台全量空间列表。

如新增或修改 API，MUST 同步 API 文档、OpenAPI 来源和客户端调用约束；如涉及权限或状态边界，MUST 同步安全相关测试。

## UI 约束

- 继续沿用前台需求中心用户菜单和右侧空间二级浮层，不新增独立页面。
- 空间列表保持紧凑列表行；名称为主信息，角色、成员数、冻结标记为辅助信息。
- 当前空间继续以勾选图标表达，不使用重色块或大面积高亮。
- 冻结空间标记必须在深浅主题下可读，并避免与当前空间勾选冲突。
- 空列表和错误态应放在空间浮层内的自然位置，不改变一级用户菜单布局。
- “创建或加入空间”入口保留在浮层底部，但具体流程由 REQ-0019 定义。

## 关联需求

- REQ-0012-frontend-requirement-center：本需求延续其前台需求中心、用户菜单和空间切换交互。
- REQ-0013-requirement-center-real-data-integration：本需求在其真实数据 BFF 基础上进一步接入真实空间事实源。
- REQ-0017-admin-space-management：本需求复用后台空间、成员、状态和产品绑定事实源。
- REQ-0019-space-creation-join-application-flow：空间创建与加入申请流程由该需求承接，不纳入本需求范围。
