# 现象

MoonBox 产品逻辑要求前台和后台用户都必须登录后才能访问系统，且所有用户登录后默认进入前台。当前 `/login` 前台登录入口复用后台管理员认证接口，导致角色为“前台用户”的账号即使密码正确，也会被后台权限规则拒绝，并提示“账号不可用或无后台权限。”

# 复现步骤

1. 在后台用户管理中创建或准备一个角色为“前台用户”的账号，账号状态为“正常”或“待激活”。
2. 打开 MoonBox 前台登录入口 `/login`。
3. 使用该前台用户账号和密码提交登录。
4. 观察登录结果、跳转目标和错误提示。

# 期望 vs 实际

## 期望

- 前台与后台用户均通过统一登录入口登录。
- 账号状态为“正常”或“待激活”时，允许用户完成登录。
- “待激活”用户首次登录成功后自动激活为“正常”。
- 登录成功后默认进入前台。
- 若当前用户是后台管理员或超级管理员，则前台用户菜单栏展示“进入后台”入口。
- 点击“进入后台”时，系统再次基于当前用户角色校验后台权限，后台管理员或超级管理员可进入后台。
- 普通前台用户不展示后台入口，且不能访问后台页面或后台 API。
- 已冻结、已删除、账号不存在或密码错误的用户不得登录。

## 实际

- 前台登录入口调用后台管理员登录接口。
- 后端认证逻辑要求登录用户角色必须为“后台管理员”。
- 角色为“前台用户”的账号被拒绝，无法登录进入前台。
- 登录错误提示带有后台权限语义，和前台登录场景不匹配。

# 影响范围

- 阻断前台用户登录 MoonBox 前台。
- 统一登录产品逻辑无法成立，前台入口与后台权限边界混淆。
- 需求中心等前台页面仍依赖后台管理员鉴权，导致普通前台用户即使具备业务使用资格，也无法访问前台能力。
- 后续涉及登录态、用户菜单、进入后台入口、后台 API 鉴权、前端 session 存储、OpenAPI、认证文档和测试用例同步。

# 严重等级说明

严重等级为 high。该缺陷阻断前台用户登录核心路径，并使“所有用户登录后默认进入前台，后台角色额外进入后台”的产品模型无法落地；同时涉及认证和权限边界，修复时必须保持后台接口的最小权限校验，避免将普通前台用户误授权为后台用户。
