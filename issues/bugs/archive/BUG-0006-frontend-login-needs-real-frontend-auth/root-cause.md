# 根因分析

## 直接原因

前台 `/login` 入口复用了后台管理员登录能力。前端提交登录时调用后台登录客户端函数，后端登录接口又要求用户角色必须为“后台管理员”，因此角色为“前台用户”的账号即使处于“正常”或“待激活”状态，也会被后台权限规则拒绝。

## 根本原因

当前认证模型把“登录系统”和“进入后台”两个概念耦合在同一条后台管理员认证链路中：

- 登录入口没有体现统一用户登录语义。
- 前台 session 只是后台 session 的本地镜像，不具备独立服务端认证能力。
- 需求中心等前台接口仍依赖后台管理员鉴权，导致前台访问权限被后台角色误限制。
- 现有测试将前台登录成功断言为调用后台登录接口，说明错误契约已经固化。

## 触发条件

- 使用角色为“前台用户”的账号访问 `/login`。
- 账号密码正确，且账号状态为“正常”或“待激活”。
- 登录请求进入现有后台管理员认证接口。

## 缺陷分类

- 类型：design / auth / permission
- 层级：前端登录入口、后端认证接口、前台接口鉴权、测试契约
- 风险：认证权限边界调整，必须避免将普通前台用户误授权为后台用户。
