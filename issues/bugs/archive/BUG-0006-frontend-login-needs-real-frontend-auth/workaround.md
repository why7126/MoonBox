# 临时规避方案

## 当前可用规避

短期只能使用具备“后台管理员”角色且状态为“正常”或“待激活”的账号登录前台入口。该方式可以进入当前前台需求中心，但不符合产品目标，因为它要求前台用户拥有后台角色。

## 不建议的规避

- 不建议把普通前台用户临时改成后台管理员来绕过登录失败，这会扩大后台权限。
- 不建议前端仅保存本地 `frontendSession` 绕过服务端认证，因为前台接口仍需服务端鉴权，且会形成不可撤销的伪登录态。
- 不建议放宽后台认证接口，让“前台用户”通过后台管理员接口登录后台；这会破坏后台权限边界。

## 正式修复方向

建立统一登录能力：所有“正常”或“待激活”用户可登录，首次登录成功后“待激活”自动激活为“正常”，登录后默认进入前台；后台管理员或超级管理员在前台用户菜单中显示“进入后台”，点击进入后台时再执行后台权限校验。
