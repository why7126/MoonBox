# 成果完成证明与执行保护一致性验收标准

## 验收状态与分层

当前自动验收状态和报告见下方“验收结果回填”，具体版本边界见 Change 返修台账；不以历史过程记录推断当前未完成。根因内存验证不是修复回归通过。隔离样本自动化、真实正常首次成功、历史恢复、部署版本、UI 证据分别记录。修改共享治理数据的验证串行执行，保留原记录，不用真实评审反复试错。

## 功能与回归验收

### AC-001 正常完成可靠交接

- [ ] 原评审应用核验完成后，操作、证明与保护最终收敛；不打开看板也能完成交接；重复触发无重复应用。
- 根因：RC-2。证据：服务/数据库集成断言，独立正常样本及记录关联。

### AC-002 提交窗口故障与重启

- [ ] 在应用核验成功、保护确认之前注入进程中断；重启后安全补偿，原执行终态不变，无新增模型调用或重复文件迁移。
- 根因：RC-2。证据：可控故障注入、重启前后状态及副作用计数。

### AC-003 无关文件变化

- [ ] 历史完成后只改变不属于该操作及必要依赖的文档，历史证明仍可核验且保护收敛；覆盖原 E6 场景。
- 根因：RC-1。证据：相关性判定测试、摘要与准入断言。

### AC-004 相关依赖冲突

- [ ] 改动必要依赖、成果、项目绑定或存在较新操作时，旧证明不得授权覆盖；返回具体原因与可读差异，保留历史完成事实。
- 根因：RC-1/3。证据：并发/版本集成样本及拒绝原因。

### AC-005 重复请求与响应丢失

- [ ] 核验请求重复或响应丢失后再次查询/核验返回同一结果，不重复模型、应用、同步迁移；请求处理中动作去重。
- 根因：RC-2。证据：幂等键、调用次数和应用唯一性断言。

### AC-006 权限与未知占用

- [ ] 撤权、跨对象/项目操作、占用未知或执行未确认结束时不解锁，不因 approved/applied 单字段放行；证据按原权限可见。
- 根因：RC-1/2。证据：权限及围栏负向测试。

### AC-007 缺损与篡改证明

- [ ] 证明缺失、对象/轮次/应用关联错误或相关摘要被篡改时安全拒绝，不补空证明；原因区分缺失、冲突与无法核验。
- 根因：RC-1/3。证据：证明负向样本与错误契约断言。

### AC-008 多轮迟到与恢复历史

- [ ] 同对象多操作、旧事件迟到、失败/停止后恢复不覆盖新操作；原终态与首次成功/恢复完成区分，历史完成与当前准入分别返回。
- 根因：RC-1/2。证据：状态组合及版本顺序断言。

### AC-009 状态矛盾检测与解释

- [ ] 已核验但未解除保护、无活动执行却持续占用触发有界核对；重启保留核对进度，仍失败返回原因与最近核验事实，不无限重试或重复通知。
- 根因：RC-2/3。证据：调度/重试边界及观测记录。

### AC-010 与 REQ-0046 联合投影

- [ ] 可信已评审对象保持已评审列并叠加异常，加入迭代仍按独立准入控制；Chat/卡片/详情同源，核验和查看入口定位同一原操作。
- 根因：RC-3。证据：后端契约断言及 REQ AC-023—026 双视口证据。

### AC-011 当前样本受控恢复

- [ ] 在保留旧记录且核对后续相关修改前提下，通过正式核验处理本例；可安全恢复则收敛，不安全则给具体冲突原因。不能手工解锁或重跑评审，记录实际处置结论。
- 根因：RC-1/2/3。证据：原样本只读前后摘要、正式处置审计；与隔离样本分开。

### AC-012 范围回归与可观测性

- [ ] 覆盖 source req-review 与 bug-review，并按完成证明能力矩阵回归共享入口；opsx-archive 独立分支不退化。用户核验关联请求/任务，后台补偿不伪造用户事件，不泄漏原文/凭证。
- 根因：RC-1/2/3。证据：能力矩阵、接口回归、部署指纹和脱敏观测摘要。

## 验收门禁与协作边界

AC-001—009/012 由 BUG 后端实现负责；AC-010 与 REQ-0046 联合验收，不能仅有前端模拟截图就关闭；AC-011 给出原现场安全处置结论，不要求强行释放已真实冲突的保护。正常/无关变更样本必须实际解除保护，不能所有场景都以拒绝为通过。具体收敛时限、重试预算、必要依赖集合在 Change 设计中固定后再验收，不臆造当前 SLA。

新增后端字段或接口时同步 API 文档、OpenAPI/客户端；需要持久化任务/版本/重试字段时同步 DB 迁移及 SQLite/MySQL 验证；后台工作进程变化同步部署；权限变化保持原边界。UI 交付与视觉门禁由 REQ-0046 承接，本 BUG 不创建重复原型。

## 验收后归档衔接补充

再次验收产生的报告与 trace 运行正文属于派生输出，不得使归档恢复记录自失效；交付输入、链路身份、真实证据完整性及并发变化仍受门禁保护。验收收尾后必须通过产品与 CLI 共用的正式准入，验收 passed 不等于归档 ready。错误须区分交付输入变化、旧记录过期、规格基线缺证、身份冲突和记录损坏。

关联链路先归档后，验收证据按唯一已完成归档身份定位，继续核对原内容哈希；活动目录仍存在、归档身份歧义、未完成或证据被篡改时仍阻断。

跨日归档补充：确认准备日期与实际目录日期耦合、迁移后自动验收计划仅查活动目录导致人工统计回退。由原 BUG 链路修复，验收覆盖跨日、中断重试、重复恢复及证据篡改拒绝；正式 REQ 收尾不得重复合并规格。
