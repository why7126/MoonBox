# 需求中心阶段提前迁移与会话分裂临时处理方案

## 临时规避

1. 从需求中心发起治理命令后，留在原 Chat，等当前轮次明确完成，并检查业务校验和同步结果，再执行下一步；卡片已移列不能作为完成依据。
2. 后续命令优先在同一原会话中输入完整对象 ID。原会话仍运行时保留草稿，不在其他会话重复发送。
3. 已出现多个会话时先查看各轮次状态，确认没有仍在执行的同对象任务，再选择一条可访问会话继续。不要直接删除会话或手动清空活动轮次字段。
4. 失败、停止、未知且已有产物时，先核对轨迹、实际文档和治理校验结果；无法确认终态时暂停后续写入。不要凭助手过程说明认定成功，也不要盲目重跑或回滚已有效成果。

## 限制

此方案依赖人工等待，不能从根本上阻止双标签页或其他用户并发。当前没有已验证的一键安全合并会话方案。本次不执行停止、删除、合并、重试或数据修改。

## 退出条件

正式修复通过 acceptance.md 的完成门禁、原会话续用、对象互斥及异常恢复验收后，不再依赖人工串行规避。
