# 根因分析

## 根因状态

status: confirmed

确认范围为本地原始治理快照的 YAML 解析失败，以及已测量的全量读取开销。未确认实际部署的全部长时间等待、错误写入者或 Docker 性能影响；这些不作为已确认根因。

## 现象

需求中心刷新缓慢，MD 文档抽屉缓慢或无法加载。用户随后提供完整提示“需求中心数据暂时不可用：项目文件正在变化或暂不可解析，请重试”，与本地 503 / 2603 响应一致。

## 已确认根因

1. `issues/requirements/_registry.yaml` 中 REQ-0026 的 `related_change` 比相邻字段多缩进两格，YAML 无法解析。全项目快照强依赖需求注册表，因此同项目 BUG 文档也无法读取。语法错误和文件变化被统一折叠为 503 / 2603，用户无法从提示区分永久解析错误和短暂变化。
2. 看板与单文档读取每次都构造全量快照、校验并创建及删除临时文件树；未变化的文档也重复处理。看板另有全量业务解析开销。该实现解释实测的本地等待，但不能据此推断实际部署的额外耗时。

错误由哪个写入操作引入尚未知，不归责于任何具体脚本或 Agent。

## 修复方向

- 修正非法注册表；治理写入入口对候选 YAML 先解析，再进行保持一致性的写入，避免持久化半成品；具体入口须通过写入证据确定。
- 在不绕过权限、对象可见性、绑定版本与写入围栏的前提下，评估稳定快照或派生结果复用、减少单文档全量物化、降低未变化轮询成本。
- 让用户可区分暂时变化与不可解析；错误详情仅包含安全相对路径和位置，不暴露内部绝对路径或文档正文。
- 性能优化方案通过 OpenSpec 设计确定，本命令不实施修复。

## 验证闭环

已完成“原始副本失败 → 仅纠正缩进 → 两条接口成功”的本地对照。功能和性能修复后的回归、浏览器观察、部署验证均未执行，详见 acceptance.md。

## 证据缺口与补证

实际部署表现：在 Network 开启 Preserve log，分别刷新看板和打开 MD，记录环境、发生时间、请求路径、状态码、总耗时、首字节等待、request_id；同步记录 Console 错误，并按 request_id 关联后端分段耗时，以区分前端、代理和应用等待。

返回格式：环境 / 时间 / 操作 / method 与 path / status / 总耗时 / 首字节等待 / request_id / 错误与分段耗时摘要。删除敏感参数、Token、Cookie、Authorization、个人信息和文档正文。

错误写入来源：后续只读检查目标字段附近的 diff 与对应时段写入事件；没有事件证据前保持未知。这一缺口不阻断对已证实解析故障和读取开销的修复评审。
