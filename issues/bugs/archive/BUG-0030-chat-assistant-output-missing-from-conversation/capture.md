# Chat 工作台已有助手输出事件但对话正文为空

## 现象

Chat 工作台中，助手文字已作为执行轨迹事件保存，但对话区没有对应的助手正文。用户只能看到工具调用与轮次状态，难以直接阅读本轮已产生的输出。

## 复现步骤

1. 在本地产品打开 BUG-0027 关联的 Chat 对象会话，查看 2026-10-05 15:47:48 与 21:16:05 发起的两轮归档命令。
2. 在“对话”页检查两轮用户消息之后的助手正文；分别显示“已停止”和“状态未知”，均无正文。
3. 打开各轮“轨迹”；前者读取到 221 条事件并包含多段助手文字，后者读取到 16 条事件并包含助手文字增量。

## 期望 vs 实际

- 期望：已持久化的助手输出能在对应轮次的对话区被看到；未确认终态时清楚标识输出是否为部分内容，且不误报完成。
- 实际：两轮轨迹已有助手输出事件，对话区均没有对应正文。状态未知轮次仍提示不要重复发送命令。

## 影响范围与初判

- 已在同一对象会话的“已停止”和“状态未知”轮次观察到；其他状态、会话和环境尚待验证。
- 严重度初判为 `high`：核心对话输出不可见，并可能伴随执行终态待确认；目前未证明输出事件丢失或治理操作失败。
- 代码显示轨迹输出与对话助手消息分别保存；是否因终态恢复、消息落库或其他条件导致本例缺失，留待轮次级证据确认。
- 产品数据采集与链路观测：`applicable`，影响 Chat 消息、执行事件和任务链路的关联诊断；后续验证需核对同一轮次的状态、输出事件数、助手消息是否存在，观测摘要不得包含完整 Prompt 或回复正文。

## 附件与证据

- 用户提供的 Chat 工作台截图；不将截图中的聊天原文复制入仓库。
- 2026-10-05 产品只读取证：上述两轮在轨迹中有助手输出，在对话区无助手正文；待补充轮次级落库与恢复事件证据。
