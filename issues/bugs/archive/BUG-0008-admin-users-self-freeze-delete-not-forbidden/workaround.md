# 临时规避

## 可用规避

在正式修复前，后台管理员进行用户管理操作时，应避免对当前登录账号执行冻结或删除。

建议临时操作约束：

1. 管理员先通过右上角账号菜单或 `/api/v1/auth/me` 确认当前登录账号。
2. 用户管理页面中遇到当前账号行时，只允许编辑资料或执行与自助入口一致的个人资料/密码操作。
3. 冻结或删除后台管理员账号时，由另一个具备后台权限的管理员执行，且先确认目标账号不是操作者本人。
4. 若误冻结或误删除当前账号，应由其他仍可登录的后台管理员或运维人员恢复账号状态；若没有可用管理员，需要通过数据库或初始化流程人工恢复。

## 局限

- 该规避依赖人工识别当前账号，不能阻止直接 API 调用。
- 前端仍可能显示危险操作入口，误操作风险没有消除。
- 后端仍缺少最终权限裁决，不能满足安全验收要求。

## 结论

临时规避只能降低人工误操作概率，不能替代正式修复。正式修复必须以后端 `403 Forbidden` 为准，并同步前端操作态与回归测试。
