# 管理后台登录用户不能冻结和删除自己

## 现象

管理后台当前登录用户可以对自己的账号执行冻结或删除操作，缺少后端强制拒绝和前端危险操作保护。该问题可能导致管理员误操作后立即失去后台访问能力，并造成账号管理、审计追踪和运维恢复风险。

## 复现步骤

1. 使用后台管理员账号登录管理后台。
2. 进入管理后台用户管理页面。
3. 在用户列表中定位当前登录账号。
4. 尝试点击当前账号行的冻结或删除操作。
5. 直接调用当前账号对应的后端冻结或删除接口。

## 期望结果

- 后端对当前登录用户冻结自己的请求必须返回 `403 Forbidden`。
- 后端对当前登录用户删除自己的请求必须返回 `403 Forbidden`。
- 前端对当前账号行应隐藏或禁用冻结、删除操作，避免触发确认弹窗或危险 API 调用。
- API 回归测试覆盖当前用户自冻结、自删除拒绝场景，并确认冻结/删除其他非系统用户仍保持原行为。
- 前端回归测试覆盖当前账号行的冻结/删除入口不可用，以及非当前账号仍可执行既有操作。

## 实际结果

当前实现已保护系统内置超级管理员和已删除用户，但未明确保护“当前登录用户本人”。普通后台管理员定位到自己的用户行时，前端仍可能暴露冻结或删除入口；后端接口也可能继续进入状态更新流程，而不是以 `403 Forbidden` 拒绝。

## 影响范围

- 影响端：管理后台 Web、后台用户管理 API。
- 影响角色：后台管理员，尤其是非系统内置管理员。
- 影响操作：冻结用户、删除用户，以及由冻结/删除引发的会话撤销和账号不可用。
- 不应影响：编辑个人资料、修改密码、冻结/删除其他非系统用户、系统内置超级管理员保护。

## 严重等级说明

严重等级为 `high`。这是账号生命周期和权限安全缺陷，可能让管理员通过自冻结或自删除造成自身后台访问中断；一旦发生在生产环境，恢复依赖其他管理员或运维介入，具备较高可用性和安全治理风险。
