# Chat 未知轮次重复创建执行容器临时处置

## 当前结论

暂无已经验证、且不影响正常Chat任务的零中断临时规避。推荐保持现状并尽快实施有界恢复；不反复删除moonbox-chat-session，因为下一恢复循环会再次创建。

## 可选应急措施及边界

若后台资源消耗已经影响使用，可在独立明确授权、确认没有正常任务并接受Chat执行暂停后，临时停止chat-worker。此举影响全部Chat任务处理，仅抑制触发源，不修复旧轮次；启动后恢复循环可能立即继续。当前命令未执行该动作，也未验证该应急措施。

执行前检查队列、运行轮次、其他维护活动和服务依赖；如存在任务或状态不确定，先保留现场，不强杀。恢复服务后核对健康、队列处理、旧unknown和容器事件，不能仅凭容器启动判断问题解决。

## 禁止用作规避的动作

- 无权威终态时直接改chat_turns.status或清除active_turn。
- 全局prune、按moonbox前缀批量删除，或删除卷、宿主数据、session历史。
- 重放原业务命令来“补完成”，或把工具完成事件当作轮次成功。
- 绕过沙箱检查、放宽权限或删除凭据。

## 安全取证与恢复

只保留脱敏轮次关联、时间、错误类别、尝试和创建计数；不保存原始对话和凭据。隔离复现须先登记临时Docker资源，证据收集后精确清理并检查零残留。历史运行数据保留，待修复后通过受控恢复验证，不在本阶段自动修正。
