# 临时规避方案

## 当前可用规避

无完整产品内规避方案。

管理员可临时通过以下方式降低误判风险：

1. 对角色和状态保持人工二次确认，避免仅凭颜色快速判断账号状态。
2. 需要确认账号最近变更时，通过后端接口响应、数据库记录或后续审计事件辅助判断 `updated_at`。
3. 对冻结、删除等高风险操作，在执行前结合用户详情、操作确认弹窗和操作原因复核目标账号。

## 规避限制

- 临时规避依赖人工检查，不能解决列表扫描效率低和状态语义弱的问题。
- 用户列表页面仍不展示更新时间，管理员无法直接在列表中完成最近变更判断。
- 时间字段仍可能因接口字符串形态不一致而出现展示不统一。

## 建议修复方向

后续修复应优先限定在管理后台用户列表前端展示层：

- 增加角色标签样式。
- 为不同用户状态提供明显的标签语义、图标或可区分样式。
- 增加统一时间格式化函数，覆盖最近登录时间、创建时间和更新时间。
- 在创建时间后增加更新时间列，并同步 `colgroup` 宽度、表格最小宽度和单测断言。
