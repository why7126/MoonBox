## 验收标准评审决定

批准固定参考规模下 context 暖/冷 P95 ≤ 3/5 s、真实首卡可见 P95 ≤ 4/6 s，每组至少 20 个样本，使用 nearest-rank。它们是修复目标，不是从单次旧样本推导的可达性保证。修复前重新采集同环境基线，精确记录版本、权限、数据和缓存口径。

本次收紧 AC-003/004 的索引次数为“每次请求的同一快照”，不强制跨请求共享缓存。AC-006 的未解释差额保留待验证，不能仅标记盲区就判通过。AC-007 的扩充规模、并发负载、内存预算及重复运行窗口由 Change 设计在测试前固定；未明确这些参数不得完成资源验收。历史原始样本不能重建时明确说明，以新正常 HTTP 样本验证完整计时，不伪称还原旧请求。

## 保留的证据边界

- E3—E7 属不同采样；分析器有开销、累计计时嵌套，直接治理目录与 HTTP 物化目录不同，不能相加还原 27 秒或推出端到端提速比例。
- 只读后处理 9.403 s 不等同原请求未分段的约 9.47 s；reconcile、外部核对、条件写入、提交与并发等待占比仍待测量。
- 首次约 20 个可见对象、后续 25 个和诊断 189 卡口径不同；四个后端文件版本相同不代表完整前端部署一致。
- 无固定版本冷暖分布、修复回归或旧 BUG-0016 回归提交证据；原始 HAR、截图、profile 未保存。现有脱敏会话摘要可支持机制评审，不能冒充可重放附件。
- 临时规避仅减少额外加载，效果未量化。其他三个 BUG 继续独立跟踪，不扩张本条确认范围。
