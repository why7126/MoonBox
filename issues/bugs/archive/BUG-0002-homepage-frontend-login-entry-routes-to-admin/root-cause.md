# 根因分析

## 直接原因

首页两个前台 CTA「打开第一个项目」和「开启 MoonBox」共用 `openAdmin()` 处理函数，该函数直接将浏览器路径推进到 `/admin`，随后触发应用路由进入管理后台登录页。

因此：

- 点击「打开第一个项目」会进入 `/admin`。
- 点击「开启 MoonBox」也会进入 `/admin`。
- 当前未登录后台会展示管理后台登录页，而不是首页已有的前台登录页。

## 根本原因

前台登录入口与管理后台入口的路由语义没有隔离：

- 首页已有前台登录页展示逻辑，通过 `#login` 控制前台登录表单显隐。
- 首页 CTA 命名和用户语义属于前台入口，但实现上复用了后台入口行为。
- 应用顶层路由将 `/admin` 明确识别为后台路由，未登录时展示管理后台登录。
- 现有首页测试将两个 CTA 跳转 `/admin` 写成期望，导致错误行为被测试固化，未能暴露回归。

## 触发条件

- 用户访问本地 Web 首页。
- 用户点击首页「打开第一个项目」或「开启 MoonBox」。
- 当前浏览器没有有效后台管理会话，或不应通过首页 CTA 进入后台。

## 已验证事实

- 首页 `openAdmin()` 使用 `window.history.pushState(null, "", "/admin")`。
- 首页两个 CTA 均绑定 `onClick={openAdmin}`。
- 应用顶层路由将 `/admin` 识别为后台路由；无后台会话时展示 `AdminLoginPage`。
- 首页测试当前断言两个 CTA 点击后 `window.location.pathname` 为 `/admin`，测试期望与产品期望不一致。
- 需求中心用户菜单中已有带权限判断的「进入后台」入口，适合作为后台入口的明确路径。

## 分类

- 缺陷类型：前端路由缺陷
- 影响层级：首页前台入口、前台登录体验、后台入口权限语义
- 非根因：后台认证接口、后台登录页本身、后端权限校验、部署反向代理
