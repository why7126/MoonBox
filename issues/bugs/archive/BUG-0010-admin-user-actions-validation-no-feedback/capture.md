# 现象

用户管理页编辑用户时点击「保存」可能没有任何响应；重置密码、冻结、解冻、删除等确认操作在未填写操作原因时点击「确认」也没有任何响应或可见错误提示。

# 复现步骤

1. 进入管理后台用户管理页。
2. 打开某个用户的编辑弹窗，修改可编辑字段后点击「保存」。
3. 打开重置密码、冻结、解冻或删除确认弹窗。
4. 不填写操作原因，直接点击「确认」。

# 期望 vs 实际

期望：保存被阻断时应显示明确原因；操作原因未填写或不足 4 个字时，应在弹窗内展示校验错误，并让用户知道如何修正。

实际：保存和确认操作可能被前端校验或禁用态静默拦截，用户看起来像点击后无响应。

# 初步证据

- 用户编辑弹窗中，`submit` 在 `!validUsername || isSaving` 时直接返回；编辑态用户名输入框禁用，但保存仍受用户名合法性影响。
- 确认弹窗中，错误提示只在 `reason.length > 0 && reason.trim().length < 4` 时显示；空原因时「确认」按钮被禁用，点击不会触发错误提示。
