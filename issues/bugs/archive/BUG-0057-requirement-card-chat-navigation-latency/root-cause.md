# 会话准备导航延迟根因分析

## 根因状态

status: confirmed

确认范围：写动作会话准备同步重复读取治理快照，前端等待准备返回后才导航，构成可复现的秒级导航延迟机制。源码路径、当前两条自然线上请求及历史 bug-opsx 准入条件重构共同支持此判断。历史截图21.27秒的唯一来源、精确占比和历史数据库等待仍未知。修复已在sprint-016的fix-object-session-preparation-latency实现并完成性能/安全自检，正式验收以Change证据清单为准。

## 现象

用户截图的 bug-opsx 对象会话准备 POST 等待21.27秒，200、reused_conversation=true、idle。该现象不与历史消息读取或消息提交请求混合。修复前自然样本仍表现为秒级准备等待。

## 已确认根因

prepare_object_session 的入口一致性检查与动作预检重复读取源/投影快照，reconcile 可产生额外读取。已有会话查询在其后，前端又等待返回才导航，导致复用空闲会话仍承担同步快照成本。E15 两条真实认证、数据库与原服务请求，响应/准备/审计 ID 一致：总耗时7045.404/6380.159ms，快照占97.40%/96.93%。E16 当前归档态409，内存重构准入后两条原路由200、idle、reused，七组门禁正反例符合预期。

## 已排除假设与边界

| 判断 | 支持范围及限制 |

| 浏览器排队或下载主导截图等待 | 对应阶段仅微秒/毫秒，不解释21.27秒等待；不据此定位后端函数。 |
| 新建会话主导这些样本 | 返回复用已有会话；当前自然样本已测会话查询为毫秒级。 |

| idle代表没有协调工作 | 不成立；idle是最终状态，协调发生在返回前。 |
| 历史重构等价完整线上重演 | 不成立；仅重构必要准入条件，夹具变换成本单列，历史负载与部署未完整复原。 |

## 验证闭环与剩余未知

当前同请求阶段关联与自然请求采样已补齐，临时钩子已移除，原服务摘要、健康与业务入口已核对。无需重复要求采集已经获得的线上阶段证据。

历史21.27秒原请求缺关联ID和阶段记录，无法事后精确拆解；历史独占性、版本回归及未测动作仍未知。这些限制不扩写为已确认机制的外推结论。若出现关键反证，应重新评估机制状态；不为等待不可恢复的历史分段而无限重复查询。

诊断与修复分别取证。本轮已实施性能修复，同条件对照和自然浏览器证据已齐备；正式逐项验收状态见 [验收计划](acceptance.md)。

## 修复方向

实现保留每次完整字节新鲜度验证，合并同物理目录源/投影的重复读取，沿用权限/epoch围栏并在协调边界重新读取；协调范围未收窄。增加有界冷态并行、准备Trace的SQLite锁升级保护及前端取消隔离。完整验收条件不变。

## 快速打开返修后的解释范围

当前修复把完整写准备移出点击导航路径，并保留发送时最新准入；因此入口加速不是完整写准备成本已消失的证明。10次自然导航及冻结数据对照见原Change的evidence/fast-open；发送前协调、命令快照及候选检查3次副本样本合计5.45–8.81秒。历史21.27秒精确归因仍未知，原限定机制confirmed不扩大。
