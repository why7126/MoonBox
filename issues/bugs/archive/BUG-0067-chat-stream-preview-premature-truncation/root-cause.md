# Chat 流式正文预览过早截断根因分析

## 根因状态

status: confirmed

确认范围是已有样本的正文预览截断与误导提示；不包含轮次收尾状态、所有存储模式或尚未运行的回归场景。

## 现象

执行中短正文仅展示半句话并提示“输出内容不完整”；最终答复出现后该提示消失。原始样本、时间及复现路径见 bug.md。

## 已确认根因

流式输出按小粒度增量存储，但正文预览以固定 21 个片段作为上限，混淆了片段数量与正文体量。读到第 21 个片段便设置 truncated，未检查实际是否仍有未读正文；前端再将此标记无条件映射为泛化缺失提示。

## 修复方向

保留有界查询和内存预算，以正文体量、明确分页及是否仍有内容判断预览是否截短；不能简单删除限制改为无界读取。正常生成、预览范围受限与真实内容缺口分别表达，完整内容读取入口沿用权限边界。最终答案选择与去重保持现有语义。API 是否需增加原因字段在 Change 设计中确定，并同步相应文档与客户端。
