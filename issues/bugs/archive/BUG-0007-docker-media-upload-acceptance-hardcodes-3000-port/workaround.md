# 临时规避

## 可用规避

在正式修复前，涉及 Docker media-upload 的验收可以临时采用以下方式降低误阻塞：

1. 不使用 `:3000` 作为固定入口，改为读取当前环境的 `HOST_PORT_WEB`，默认按 `18102` 验证 Web 同源入口。
2. 不假设 `admin / 默认密码` 可登录本地持久库。
3. 验收前创建或确认一个本次专用测试账号，并使用该账号完成 `/api/v1/auth/login`、`/api/v1/auth/avatar` 上传、受保护读取和回显校验。
4. 若只能人工验收，应在验收记录中明确写出实际 Web 端口、测试账号来源、是否复用历史持久库，以及不依赖默认管理员密码的说明。

## 不推荐规避

- 不建议清空 `data/runtime/backend` 来让默认管理员密码重新生效。这样会掩盖持久库状态下的真实验收风险，并可能删除本地调试数据。
- 不建议把 Docker Web 端口改回 `:3000`。这违反 MoonBox `18101-18199` 端口规范，也会重新引入本机端口冲突。
- 不建议继续在验收文档中记录真实管理员密码、真实账号密码或 `.env` 中的敏感值。

## 剩余风险

临时规避只能避免当前验收被错误阻塞，不能防止后续需求继续从旧知识库或 Sprint 口径复制 `:3000` 和默认管理员密码假设。正式修复仍需要同步治理文档、最佳实践、验收模板和相关命令策略。
