# 容器名不应自动追加 -1 后缀

## 现象

项目通过 Docker/Compose 启动后，生成的容器名出现自动追加 `-1` 后缀的情况。用户期望容器名称按项目约定展示，不带额外的 `-1` 后缀。

## 复现步骤

1. 在目标环境使用项目提供的 Docker/Compose 启动方式启动服务。
2. 查看启动后的容器列表与容器名称。
3. 对比期望容器名与实际容器名，确认是否出现 `-1` 后缀。

## 期望结果

- 容器名符合项目约定，不自动追加 `-1` 后缀。
- 容器名在本地、部署或治理相关 Compose 场景中保持可识别、稳定且便于运维排查。

## 实际结果

- 用户反馈当前容器名存在追加 `-1` 后缀的表现。
- 当前尚未确认具体发生环境、受影响服务清单、启动命令和 Compose 文件来源。

## 影响范围

- 影响 Docker/Compose 环境中的容器识别与运维排查。
- 可能影响脚本、文档、验收步骤或人工操作中对固定容器名的引用。
- 如后续确认存在多副本或 Compose 命名策略约束，需要评估去除后缀是否会影响扩缩容或并行环境运行。

## 严重等级说明

严重等级暂定为 `medium`。该问题影响部署与运维体验，并可能造成脚本或验收引用不一致；但当前未收到服务不可用、数据丢失或安全风险证据。若后续补证显示固定容器名导致启动失败、脚本阻断或生产部署不可控，应在缺陷完善阶段重新评估严重等级。

## 待补证

- 具体环境：本地 Docker Compose、生产 Compose、CI 或其他部署方式。
- 启动命令、Compose 文件来源和项目名设置方式。
- 受影响服务清单、当前实际容器名、期望容器名。
- 是否存在多副本、并行环境或 Compose v2 命名兼容性要求。
