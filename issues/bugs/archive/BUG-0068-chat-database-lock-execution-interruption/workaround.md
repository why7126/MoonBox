# Chat 数据库锁阻塞临时处置边界

## 当前可用处置

没有已验证能消除数据库锁竞争的临时修复。服务恢复后可通过“重新连接”读取原轮次与已保存输出；这是信息恢复，不会续跑任务，也不能证明锁问题已消失。

## 操作顺序

1. 保留原任务与完成保护，记录失败时刻和脱敏错误码。
2. 页面失败时避免连续刷新或重复提交；等待已有请求结束，再只读重连一次。
3. 核对原轮次终态、已保存事件和Change任务；仍为stopped或缺完成证明时，不宣布交付完成。
4. 后续经评审制定恢复路径，先评估已有产物与重复执行风险。

## 禁止作为规避方案

不直接修改数据库状态、清除active_turn或执行保护；不无限放大锁超时；不无界重试；不删除数据库journal/WAL；不把重启共享服务、切换数据库模式或重跑原apply当作本命令默认动作。

## 已验证与限制

浏览器重连曾恢复读取167条事件，随后仍观察到间歇性锁竞争。未验证减少标签页能消除故障，不宣称该措施有效；无服务配置或业务数据改动。

## 源码修复状态

本次Change完成事务隔离与双库验证；现有服务尚未部署新代码，现场仍采用原只读核验与保护策略。部署需按独立发布流程，不能以本次通过自动重启服务或重跑原apply。
