# Chat 同轮助手回复排在用户提问之前

## 现象与影响

REQ-0046 关联 Chat 会话中，同轮助手归档恢复回复显示在用户提问之前：助手显示 2026-10-21 08:32:34，用户显示 08:32:35。问题是对话因果顺序与时间语义错误，不代表归档操作倒序执行。

严重等级 medium：影响核心对话阅读、轮次理解及结果追溯；当前没有消息丢失、数据损坏或业务归档失败的证据。通用消息投影和排序路径可影响其他 REQ、BUG 及普通会话，不能以当前对象特判解决。

## 复现步骤与触发条件

1. 创建 Chat 轮次；用户消息入库发生在轮次创建后的下一秒（可在后续测试中控制时钟或插入延迟，不依赖偶发等待）。
2. 产生助手输出，经事件虚拟投影或完成后的助手消息路径查询对话。
3. 检查同轮记录：轮次时间为 T，用户保存时间为 T+1 秒，助手对外时间被设为 T。
4. 前端合并消息并以 created_at 升序排列，得到助手在前、用户在后。

原始样本已经通过截图、数据库只读查询和代码核对确认。分页、刷新和恢复等扩展场景列为待执行的回归矩阵，本轮不宣称已逐项复现或修复。

## 期望与实际

| 维度 | 期望 | 当前问题 |
|---|---|---|
| 同轮顺序 | 用户提问先于助手回复 | 时间比较优先，跨秒时角色兜底失效 |
| 消息时间 | 明确区分消息时间与轮次开始时间 | 助手 created_at 被复用或覆盖为轮次时间 |
| 全链路顺序 | API 分页、前端合并、投影及恢复采用同一确定性契约 | 后端与前端各按时间和不同的平局规则排序 |
| 历史兼容 | 历史倒置样本也能正确展示，保留原始事实 | 只更新当前记录或只改前端无法覆盖完整链路 |

## 已确认根因

根因状态：confirmed。确认范围为原始样本的倒置机制；具体引入提交和各扩展场景的实际发生率尚未确认。

1. `service.identity()` 分别取当前秒级 UTC 时间；admission 先取得轮次身份，经过准入、材料和上下文处理后，再为用户消息生成身份。两次取时没有必须同秒的约束。
2. `persist_output()` 把助手消息 created_at 写成 turns.created_at；`message_page()` 对已有助手消息也重新投影为轮次时间，虚拟助手同样使用该值。即便真实回复晚于提问，对外时间仍可能更早。
3. 前端 merge 先比较 created_at，只有相等才应用同轮 user 优先。因此 T 与 T+1 秒的样本必然倒置；同秒多数情况下正常，掩盖了跨秒缺陷。
4. 后端分页先按该时间降序，再按 turn_id、role、id 平局排序；前端按时间升序、同轮角色及 id 排序。仅交换 DOM 顺序或改一个比较分支，不能解决分页边界与多轮一致性。

## 已排除与尚未确认

- 排除原始样本的时区显示差异：UTC 数据统一换算到北京时间后与截图完全对应。
- 排除原始样本的不同轮次误配：数据库两条消息关联同一轮。
- 排除纯 CSS 位置错误作为该样本的解释：数据时间与排序表达式已直接解释倒置。
- 未确认具体由哪个历史提交引入；BUG-0030 是模块关联，不作为因果归责。BUG-0052 的完成保护问题不属于本次根因。
- 流式转持久化、分页并发、刷新和恢复属于需验证的通用边界，不据静态代码断言每个场景均已发生故障。

## 通用修复范围

1. 建立完整、确定性的会话轮次排序与轮内排序契约；同轮先用户后助手，跨轮具备稳定平局键。服务端分页与前端正向展示使用相容的同一顺序，而非仅时间相等时做角色修补。
2. 分离排序键与显示时间。定义轮次开始、消息产生/保存、更新时间的语义；历史助手时间不可靠时明确兼容或降级口径，不编造回复发生时间，不靠批量改写时间掩盖错误。
3. 将实际消息、虚拟助手输出、流式增量和恢复后的持久消息纳入同一身份与排序规则，保证转换和重复请求幂等、输出不丢失。
4. 分页覆盖同轮被切开的边界、加载更多、重复页及新输出到达的情况；比较后端全量期望顺序与客户端合并结果，避免重复、漏项、跳位和跨轮串联。具体分页策略及字段设计留待 OpenSpec。
5. 修复历史样本与新建通用样本，不绑定 REQ-0046、归档命令、单个时间值或会话。保留现有权限、状态、输出部分完成标识及业务正确性门禁。
