# Chat 同轮助手回复排在用户提问之前

## 现象

Chat 工作台同一轮运行中，助手回复出现在用户提问上方。用户在 REQ-0046 关联会话发现：助手标时 2026/10/21 08:32:34，用户标时 08:32:35，回复被排在提问之前。归档结果与消息显示顺序是不同问题，本缺陷不重新执行归档。

## 复现步骤

1. 在 Chat 工作台发送一条消息，使轮次建立与用户消息保存跨过秒边界；原始反馈来自 REQ-0046 的归档恢复轮次。
2. 等待助手输出投影或持久消息出现，观察同轮提问与回复顺序。
3. 对比轮次创建时间、用户消息时间、助手消息时间及同轮关联，检查前后端排序规则。
4. 刷新、分页加载和恢复是待补充回归场景，不声称本次已逐项复现。

## 期望与实际

- 期望：同轮用户提问始终先于助手回复；多轮顺序确定，前端合并、后端分页、流式展示和恢复口径一致。
- 实际：助手时间采用轮次创建时间，早于跨秒保存的用户消息；前端优先比较时间，仅同时间才按角色排序，导致倒置。
- 时间展示应区分轮次开始与消息产生时间，不以改写历史时间或给当前消息打补丁替代稳定排序契约。

## 已有证据与原因线索

同会话上一轮只读取证已确认：数据库中用户与助手属于同一轮，轮次创建及助手 created_at 为 2026-10-21T00:32:34+00:00，用户 created_at 为 2026-10-21T00:32:35+00:00；与截图北京时间相符。仅记录脱敏时间与关联结论，不保存会话正文、账户或运行标识。

- `src/backend/app/chat/admission.py`：先创建轮次，后用独立 identity 时间保存用户消息。
- `src/backend/app/chat/assistant_output.py`：persist_output 采用 turns.created_at；message_page 对助手实际消息和虚拟投影使用轮次创建时间并参与分页排序。
- `src/web/src/components/chat/ConversationMessages.tsx`：merge 优先比较 created_at，同轮角色优先级只在时间相等时生效。
- 用户附件 `codex-clipboard-026926de-d884-4e4c-b01e-aa2f7aaa819b.png` 留在对话中，不复制含聊天正文的原图入仓库。

## 影响范围与修复方向

严重度初判 medium：核心对话因果顺序错误，影响阅读和结果归属理解；现有证据未表明数据丢失或归档失败。该机制适用于通用 Chat，不能仅修改 REQ-0046 当前轮次。

统一服务端分页与客户端合并的轮次、轮内排序规则；稳定处理时间相同与跨秒情形，将显示时间语义与排序键分开。兼容已有历史消息、事件虚拟投影及后续持久化，避免重复、跳位、遗漏和跨轮串联。具体字段与迁移方案在后续设计中确定。

## 建议回归与验收范围

- 同秒与跨秒保存、同时间多轮：同轮用户在前、助手在后，跨轮稳定。
- 后端分页边界切开同轮、前端加载更多及重复拉取：无遗漏、重复、乱序。
- 流式增量输出、虚拟投影转持久消息：位置和身份稳定，不重复追加。
- 刷新、重新进入会话、停止或中断后恢复、重复恢复：同轮关联与排序一致。
- 前后端接口与真实产品展示联合核验；使用新建通用样本并回读历史倒置样本，不能仅测准备成功或单个比较函数。
- 明确消息显示时间、轮次开始时间及历史兼容语义；保留原始事实，不伪造回复早于提问的时间解释。
