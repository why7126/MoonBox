# 临时规避方案

当前没有已验证、能自动纠正所有状态投影的规避方案。

1. 在修复前，通过执行任务的真实进度、Change tasks 与验证证据共同判断研发情况；看到“准备开发态”时先核对是否已有执行中的 apply，避免因卡片陈旧而重复发起。
2. 任务只有在实现与验证通过后才勾选；不要为了移动卡片提前勾选、手工伪造完成状态或提前执行 验收态 完成同步。
3. 当文件状态已经更新时可刷新页面并核对 context；若文件仍为 提议态，刷新本身不能补足启动事实。
4. 不建议把单文件手工改成 进行态 当作长期修复，因 Sync 与看板仍可能分歧。

适用范围：临时人工核对与避免重复操作，不承诺修复看板或恢复自动流转。正式修复验收通过后停止依赖人工核对流程。本方案不涉及生产命令、数据库、部署或权限变更。
