# 评审恢复记录缺失导致成果未应用与卡片未流转临时处理方案

## 当前结论

暂无已验证的一键恢复方案。现有事实源仍为待评审，应保留失败轮次、Diff 和恢复基线，避免反复发送同一评审消耗模型或产生重复成果。

## 临时处理

1. 查看原轮次轨迹及成果，明确“未应用”的事实；不根据助手成功措辞进入 Sprint。
2. 由授权维护人员核对部署名单与已验证修复版本。更新前检查活动和未知轮次，按部署流程处理；本命令不执行部署或重启。
3. 修复后优先核查已有成果是否满足受控恢复条件：对象归属、基线与当前版本、权限、候选范围及无重复应用；不满足则明确阻断并选择重新评审。
4. 只有后端应用与事实源回读一致后，才允许卡片完成型迁移。

## 禁止性边界

不直接补空 operation.json、不手工改数据库或移动卡片、不删除基线/成果、不绕过完成门禁。不能将重启直接当成当前失败轮次自动恢复的保证。

## 退出条件

正式修复通过 acceptance.md 的隔离与真实产品验收，受影响历史轮次有明确处置结果，部署版本与验证证据一致。长期恢复能力归属 REQ-0047；本临时方案不提前承诺该能力。
