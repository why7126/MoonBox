# 需求中心首屏加载延迟验收标准

## 验收状态与样本契约

所有项目均未执行修复验收。以下量化阈值已由本次 bug-review 批准为修复验收目标，不是既有 SLA 或已达标结果；后续调整须记录理由并复审，不能用局部微基准替代页面实测。

基准参考规模为 4,342 个治理文件、约 14.9 MB、189 张授权卡片，记录实际版本及归档比例；修复前后使用相同数据副本、镜像依赖、机器资源、权限、前端筛选及负载。当前会话只有单次旧样本，验收前须重新建立可比基线。

冷样本定义为应用相关缓存未建立，暖样本为相同快照完成一次请求后复用；明确操作系统页缓存是否清理，未清理不得称磁盘冷启动。每组至少 20 个独立测量样本，分别报告中位数、P95（nearest-rank）、最大值、错误率；固定单标签页，另测代表性并发。原始证据脱敏，记录请求关联 ID 与版本，保存到后续 Change 的验收证据目录。

## 回归检查

- [ ] **AC-001 用户可见等待改善。** 在上述固定样本下，暖缓存 context 总耗时 P95 ≤ 3 s，冷缓存 ≤ 5 s；从导航开始至目标筛选下首张真实卡片可见 P95 分别 ≤ 4 s / 6 s。所有样本无错误或卡片缺失；同时报告与新采集基线的差值，不把骨架屏或过期缓存显示算作完成。
- [ ] **AC-002 快照复用与一致性。** 未变快照的重复请求证明全量扫描成本下降，记录文件读取/扫描次数和耗时。修改治理文档、注册表、归档位置后，下一次已完成有效请求反映变更；读取期间并发修改触发既有一致性处理，不能返回混合版本。权限、写入栅栏与执行状态核验均保持有效。测试覆盖全部扫描根目录，不仅当前可见对象。
- [ ] **AC-003 归档索引等价。** 每次请求的同一快照、同一授权范围内，每个唯一归档目录集合的索引构建至多一次，171 个样本查找结果与原逻辑一致；覆盖活动目录优先、完整 ID、重复归档回退、缺失对象、不合法路径和符号链接边界。分别报告原逻辑与优化路径耗时，不沿用探索的数值作为修复结果。
- [ ] **AC-004 注册表索引等价。** 每次请求的同一快照内 REQ 与 BUG 注册表各至多解析一次，106 个样本的完整 ID 映射一致；覆盖短 ID 重复/歧义、非法注册表、对象删除和快照更新，保留原失败语义。对跨用户缓存复用验证无越权身份或状态泄漏。
- [ ] **AC-005 看板与刷新功能完整。** 全量、Sprint 和其他既有筛选下对象集合、标题、关联 Change、动作可用性与原行为一致；按用户权限验证可见范围。执行占用、完成核验和权限变化后能更新，失败提示可理解；单页刷新不重叠，切换项目/离开页面不回填旧响应。正常和代表性并发下均无状态错误。
- [ ] **AC-006 原始耗时盲区闭环。** 在正常 HTTP 路径以同一 request_id 关联快照、物化、解析、reconcile/reconcile_external、逐卡投影、提交和序列化计时，明确各项嵌套关系与未覆盖差额；给出差额归属及测量误差说明；若仍有未解释差额则标记待验证，本项不得通过，不能把只读子集 9.403 s 等同旧样本 9.47 s。禁止将嵌套累计耗时相加。
- [ ] **AC-007 规模与资源回归。** 对参考规模及扩充归档样本执行相同冷暖方案，报告全量/可见对象数、文件读取、YAML 解析、SQL 次数、响应字节、CPU 和峰值内存。证明没有通过丢卡片、越权缓存或持续增长的缓存换取速度；资源预算由 Change 设计明确，超出须说明并复审。
- [ ] **AC-008 文档与接口边界一致。** 若仅内部索引优化，验证现有响应契约及客户端兼容；若采用分页/裁剪或新增观测，更新对应 OpenAPI、客户端、API 文档、观测声明与测试。没有 DB 迁移、部署或安全策略变更时写出 N/A 原因，不凭空增加变更。
