首轮隔离修复验收8/8通过，晚间真实后台并发复发后已进入返修，旧结果保留为历史；新增 AC-010 尚待完成。逐项当前结论及方法以关联Change证据包为准。以下量化阈值已由本次 bug-review 批准为修复验收目标，不是既有 SLA 或当前已达标结果；后续调整须记录理由并复审，不能用局部微基准替代页面实测。

历史参考规模为 4,342 个治理文件、约 14.9 MB、189 张授权卡片。用户于2026-10-27确认采用当前固定副本：6,265个文件、18,454,665字节、213张授权卡片；保留原时延目标，修复前后使用相同数据副本、镜像依赖、机器资源、权限、前端筛选及负载。扩容经用户确认改为现有10,000文件及32MiB上限内成功读取，并验证超限安全拒绝；不提高安全上限。正式样本及摘要见关联Change验证记录。

冷样本定义为应用相关缓存未建立，暖样本为相同快照完成一次请求后复用；明确操作系统页缓存是否清理，未清理不得称磁盘冷启动。每组至少 20 个独立测量样本，分别报告中位数、P95（nearest-rank）、最大值、错误率；固定单标签页，另测代表性并发。原始证据脱敏，记录请求关联 ID 与版本，保存到后续 Change 的验收证据目录。

本轮结果：context/MD暖读配对P95改善64.95%/56.63%；浏览器暖100次与冷30次首卡P95为2.742/2.442秒，HTTP为2.242/2.008秒。修复版本资源四组通过；历史对照超预算与空库首次初始化另列，见[Change验证记录](../../../../openspec/changes/fix-requirement-center-context-load-latency/verification.md)及[逐AC报告](../../../../openspec/changes/fix-requirement-center-context-load-latency/evidence/acceptance/20261027124209183130-5049da30/summary.md)。
