# 需求中心首屏加载延迟临时规避

## 可用措施与限制

目前没有已验证能消除首屏等待的临时规避。以下仅减少重复请求及操作干扰，收益未量化，不能视为修复：

| 操作 | 适用条件与预期 | 边界 |
|---|---|---|
| 关闭重复打开的需求中心标签页，只保留一个工作页 | 减少额外可见页轮询和竞争 | 单页仍会刷新，不保证首屏加速 |
| 请求加载中等待本轮完成，避免反复刷新或切换项目重试 | 避免人为重复触发相同聚合工作 | 异常失败应按实际错误处理，不无限等待 |
| 已有卡片时继续在当前页查看，避免无必要重新进入 | 减少人为重载 | 不能把旧画面当作当前权限或完成状态；需要最新信息时等待同步后操作 |

不删除治理归档，不禁用快照一致性、授权或执行栅栏，不把历史状态永久缓存为成功。此命令未修改轮询配置、服务参数或业务数据；没有额外回滚步骤。修复通过验收后撤销上述操作建议即可。

## 继续出现长等待时

优先由 Agent 在已有权限内采集同一请求的状态码、request_id、Timing 与阶段耗时，记录环境、版本、文件/对象规模、冷暖状态及负载，按 [验收标准](acceptance.md) 对照。不要提交 Cookie、Authorization、账号标识或业务正文。网络失败与历史页面可见分开记录，不将单次连接失败认定为产品不可访问。
