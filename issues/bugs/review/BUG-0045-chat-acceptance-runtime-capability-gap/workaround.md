# Chat 验收能力缺口临时处理方案

## 临时方案

在正式修复前，可使用已授权且具备依赖和浏览器的独立测试环境续接当前 Change。BUG-0028 已实际采用桌面隔离环境补验；这只能证明该次源码交付通过，不能证明产品执行器恢复。

1. 记录当前 Change、任务勾选、版本及未完成验证项，确认原轮次已结束，避免两个环境并发写同一对象。
2. 在授权环境核对 Python、前端锁文件与目标平台、浏览器启动和测试入口；使用隔离合成数据，不复制生产凭证或业务数据库。
3. 只补齐受阻检查，保留输入指纹与证据来源；如果源码已变化，重验受影响项。不得沿用不匹配版本的旧证据。
4. 校验全部任务及验收材料后再执行正式状态同步。回到 Chat 核对事实源，不能仅看轮次“已完成”。

## 限制与恢复

此方案需要额外环境，不能修复产品内预检、任务调度和证据回传。若无授权完整环境，明确保持验收受阻，不编造通过、不勾完任务；可独立实施部分继续。测试入口或能力不足不要求用户提供密码。

不要直接开放执行器任意网络、挂载 Docker socket/个人浏览器配置或向产品镜像临时安装未固定依赖。启用验证 worker 属于正式部署修复方案，需后续 Change 与部署验证，本命令不执行。

## 退出条件

本缺陷的产品内能力矩阵、任务续接和真实浏览器验证全部通过后，结束跨环境临时续接；保留证据及可回滚的已验证镜像版本。
