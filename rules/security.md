# 安全开发规范

## 1. 认证与权限

- 管理端、公开端、移动端、内部接口必须区分权限边界。
- 任何写操作、上传、删除、导出、后台任务触发必须鉴权。
- 管理后台用户自助修改密码必须校验当前密码、新密码规则和确认密码一致性；成功后必须撤销该用户既有服务端会话，响应、日志、审计和前端持久化不得保存明文密码、密码哈希或可复用凭证。
- 权限策略变化必须进入 OpenSpec Change，并补充测试。

## 2. 文件上传安全

- 所有上传必须经过后端校验。
- 必须限制文件大小、MIME Type、扩展名。
- 禁止使用用户原始文件名作为对象 Key。
- 禁止信任前端传入的文件路径。
- 上传失败不得暴露内部路径、密钥或完整堆栈。

## 3. 对象存储安全

- 真实 AccessKey、SecretKey、Token 不得提交 Git。
- 本地真实 env 文件可存在于工作区；只要处于 Git ignore 覆盖范围且未 staged/tracked、未被复制进 docs、OpenSpec archive、release、Mintlify 或日志，其存在本身不构成归档阻断。
- `.env.example` 只能放示例值。
- 对外访问优先使用签名 URL 或受控公开策略。
- 存储桶和对象前缀遵循最小权限原则。

## 4. 输入与数据安全

- API 请求体必须使用 Schema 校验。
- 查询条件必须做长度、类型、枚举和权限校验。
- SQL 查询必须参数化。
- 日志、导出、测试数据不得包含真实用户或客户敏感信息。
- 根因分析、人工补证、测试失败、Network、Console、容器日志和截图证据 MUST 脱敏；不得写入真实密码、Token、Cookie、Authorization header、真实 `.env` 原文、真实客户数据、未脱敏日志、本机绝对路径、系统用户名或用户主目录。证据化根因分析见 `rules/root-cause-evidence.md`。

## 5. AI 禁止行为

AI 生成代码时不得：

```text
□ 硬编码密钥
□ 绕过鉴权
□ 关闭上传校验
□ 提交真实数据文件或真实环境文件
□ 生成危险命令执行逻辑
□ 把生产域名、连接串或客户数据写进文档示例
```

## 6. Git 推送前安全检测

推送到 Git 仓库前 SHOULD 运行 `/git-check` 或等价脚本：

```bash
python scripts/git-check.py
```

该命令默认检查 staged + tracked 文件，复用环境文件 ignore 策略，并检测真实环境文件、运行时数据、数据库文件、大文件、密钥/Token/连接串、本机绝对路径和不应进入 Git 的本地数据。本机绝对路径视为隐私数据，命中时必须作为 error 阻断。检测报告必须脱敏，不得完整输出密钥、Token、Cookie、Authorization header、数据库连接串、真实 `.env` 行或客户隐私数据。

需要完成选择性暂存、提交、正式发布标签和远程同步时使用 `/git-sync`。默认按明确交付范围提交；暂存后复核差异并执行 `/git-check`。`.gitignore` 只影响未跟踪文件，已跟踪的禁入文件必须单独处理索引及待推送历史风险，不得删除本地数据或通过强制推送覆盖远端。

## 实现权限字段与审计边界

实现权限兼容治理字段别名时，仅解析服务端可信根目录；同义字段冲突、类型非法、来源或 Sprint 不匹配时拒绝实现权限。兼容不能绕过成员、Sprint 双向成员、Change 阶段、治理候选或撤权规则。BUG 的父需求字段不替代 BUG 来源身份。

执行器 profile 与服务端 scope 不一致时阻断。权限决策留痕只保存标识、稳定原因与输入版本摘要，不保存原始提示词、凭证、完整治理内容或路径。请求被执行器确认与真实运行边界验证分别记录，不将其中之一冒充另一项。

采集或探索阶段的 REQ/BUG 对象 Chat 默认使用只读执行权限；在分析对话中请求生成或归档不得凭提示词升级权限。正式治理写入仅在对应受控候选处于运行态且绑定版本、对象、操作者均匹配时授权，候选结束后恢复只读判定。

归档恢复只对原对象身份与授权项目开放：活动 Change 移入 OpenSpec 过渡目录或正式归档目录后，须同时核对唯一目录、原归档私有日志、Change 来源与 Sprint 范围，以及正式规格树的预期指纹，才允许同对象重进续做。缺日志、指纹漂移、关联来源不符或目录不唯一时保持只读并保留现场。归档命令退出成功后若本轮再次改写正式规格，Chat 终态必须为 `failed / archive_recovery_blocked`；未知轮次重连也应用同一门禁。

归档恢复指纹的合法前进仅接受完整连续的已完成归档记录：原/目标全树哈希相接、目录唯一、增量及最终规格结果有效，旧记录完整保留。同条文后继仍核验正常验收，不再将独立兼容证明或规则替代证明作为普通归档准入条件。缺损归档/验收证据、未知写入或并发变化仍拒绝；读取端不执行仓库代码、不写恢复记录。历史证明工具保留为可选审查工具，不删除历史 journal/manifest。

## 当前规则修改归档保护（REQ-0050 v6）

当前规则修改只展示原新差异和验收缺口，不新增规则批准人或独立人员签署。允许继续检查的前提是当前版本逐项测试结果与证据有效，且项目权限、完整唯一归档链、范围、历史和写入前并发检查均通过；缺失、失败、过期、断链、篡改或变化继续阻断。Agent 文字、页面查看、旧确认及遥测不能充当验收证据。Sprint 最终关闭的验收报告规则另行生效。

## 历史受控规则替代授权边界（已退出当前业务流程）

受控规则替代只接受部署审查过的精确规则例外扩展，身份、完整唯一归档链、证据、兼容条件、并发、权限、独立签署、完整范围、历史和恢复幂等性不可豁免。Agent 可准备候选但不能自行签署。批准权限来自当前有效空间所有者的人类会话，需在事务写入前复核会话、空间及项目绑定。

信任根位于仓库外且运行身份不可写；签名私钥与在线 socket 不进入 Agent 挂载。运维制品授权和所有者转换授权使用不同密钥用途。首次启用未完成时不签发普通替代批准，正式启用不复用隔离测试凭据。授权事件不可变，状态投影使用版本比较；领取后撤销不代表回滚。所有归档写入口需共享项目围栏与提交前复核，外部任意文件写入通过摘要变化阻断，不宣称 OS 锁可以阻止外部编辑器。

行为事件、请求日志和 Task Trace 不构成授权证据；遥测不可用不能伪造业务失败，签名或权威状态不可用则禁止取得新写资格。历史密钥保留用于验签，受信撤销仍阻断依赖恢复。不得将私钥、会话、原始 Prompt 或私有路径写入公开验收证据。

## Chat 分块保存与恢复边界

Chat 的无运营配额不解除部署保护。每次结果、文件列表或正文读取重新校验当前用户、空间和历史引用权限；游标绑定轮次/内容流/比较范围且不充当授权。快照使用目录描述符及不跟随符号链接策略，硬链接和特殊文件拒绝。准备恢复只有在确认尚未向执行器发送启动请求时才可复用原轮次；启动请求已发送但未确认的状态保持未知，不自动重发。容器内存与交换空间合计1GiB，128进程、1CPU、只读根与既有网络/沙箱保护保留。


## 已验收规格演进的准入实现

同名MODIFIED条文的业务演进遵循REQ-0050 v6：共享门禁核验可解析新旧条文与完整唯一已完成前驱，非追加修改要求当前结构化验收有效，且受影响规格全文在验收输入范围内。旧确认、精确文本例外或仅选取部分章节不能代替完整验收。删除与重命名不由本兼容路径新增支持。准入ready只是检查结论，不授予写权限；现有项目、来源评审、Sprint范围、撤权、跨项目、历史链、项目围栏及写前版本检查仍独立生效。

## 托管 Git 工作区执行边界

工作区物理路径仅由服务端仓库绑定和持久身份解析，不接受客户端路径或角色。linked worktree 执行器不得写共享 Git 管理目录、公共治理注册表或其他交付链路；私有只读 Git 视图仅包含当前 HEAD 可达对象。恢复和合入均在写入前复核当前权限与固定版本，未知执行状态不能按超时释放占用。用户确认不是永久授权；权限撤销后仅允许内部对已发生的精确 Git 结果进行只读核验及状态对账，不继续新的 Git 写入。
