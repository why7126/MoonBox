# moonbox-rollout

工作区恢复点与操作日志，复用 `chat/snapshot_store.py`、`content_store.py` 的分块正文存储。恢复点保存独立文件清单，删除会话不会破坏仍被恢复点引用的代码内容，也不会复活被删除的聊天正文。

- `execution.py` 按可写阶段发布写前/写后点；只读不发布，同内容、范围和 Git 基线复用完整点。
- `catalog.py` 串行发布与保护，默认保留最近 10 个未保护变更点；配置 `MOONBOX_WORKSPACE_RECOVERY_KEEP` 必须为正整数。初始、在途、恢复前及人工保护另计。轮转移除对应可恢复清单，内容回收独立执行，不按天删除历史。
- `restore.py` 比较原版本、结束版本和当前文件；仅撤销未被后续编辑的选定文件，先保存保护点和持久操作，再逐文件执行与记录。重试检查原操作，已完成项不覆盖后续人工修改。
- `restore_io.py` 使用目录描述符、不跟随链接、校验内容和模式后替换文件；多文件不宣称原子事务，外部编辑器也不遵守数据库占用锁。
- `recovery_tree.py` 将完整恢复点提取到独立恢复用途目录，不占开发链路名额，不直接用于新开发；链接等不支持正文恢复的项明确计数。

采集范围版本由 `moonbox_exec_server/scope.py` 定义；Git ignore 不缩小授权普通文件的保护范围。凭证、Git 管理、数据库和构建缓存排除；开发树不能改共用注册表、Sprint、正式规格或治理维护日志。恢复不还原 Git 暂存区、业务数据库、对象存储和容器运行态。

元数据、清单、正文块位于同一业务数据库；SQLite 离线备份同时覆盖它们，并重放独立删除意图。数据库自动备份份数仍由 `MOONBOX_CHAT_LOCAL_SNAPSHOT_LIMIT` 管理，和恢复点数量无关。MySQL 继续走既有数据库备份制度，未新增对象存储后端。

`migration.py` 逐清单、正文块和摘要核验历史完整 v2 版本后纳入恢复点，并保留历史保护引用。原采集范围不可证明的旧版本仅支持明确文件恢复，不允许推断为完整项目恢复目录；旧摘要和损坏正文继续保留历史，不标记可完整恢复。
